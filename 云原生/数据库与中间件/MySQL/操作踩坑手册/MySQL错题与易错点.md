# MySQL 错题与易错点

> 只记录容易混淆、曾经理解错误、以后需要重点避免的知识点。
> 不重复记录完整知识讲解。

---

## 1. `COUNT(*)` ≠ `COUNT(column)`

❌ 错误理解：

> 两者都是统计行数，所以完全一样。

✅ 正确理解：

> `COUNT(*)` 统计行；`COUNT(column)` 统计该列**非 NULL** 的值。

**易错点：**

> 遇到 NULL 时，两者结果可能不同。

---

## 2. `NULL` 不能使用 `=` 判断

❌ 错误理解：

```sql
WHERE score = NULL
```

可以查询 NULL。

✅ 正确理解：

```sql
WHERE score IS NULL
```

或者：

```sql
WHERE score IS NOT NULL
```

**易错点：**

> `NULL` 不是普通的具体值。

---

## 3. `JOIN ... ON` 与 `WHERE` 的作用不能混淆

❌ 错误理解：

> `ON` 和 `WHERE` 都是在筛选，所以放哪里都一样。

✅ 正确理解：

> `ON` 主要描述**表之间如何匹配**；`WHERE` 主要对连接后的结果进行过滤。

**易错点：**

> 尤其是 `LEFT JOIN`，条件放在 `ON` 和 `WHERE` 中可能得到不同结果。

---

## 4. 窗口函数不会像 `GROUP BY` 一样减少行数

❌ 错误理解：

> 使用窗口函数之后，每组只剩下一行。

✅ 正确理解：

> 窗口函数通常在**保留原有行**的基础上计算额外结果。

例如：

```sql
ROW_NUMBER() OVER (
    PARTITION BY class_name
    ORDER BY score DESC
)
```

仍然保留每个学生。

---

## 5. `PARTITION BY` ≠ `GROUP BY`

❌ 错误理解：

> `PARTITION BY` 就是窗口函数版本的 `GROUP BY`，会把数据合并。

✅ 正确理解：

```text
GROUP BY
→ 分组 + 合并
→ 行数可能减少

PARTITION BY
→ 分区 + 保留原行
→ 行数通常不减少
```

例如：

```sql
SELECT
    name,
    class_name,
    score,
    AVG(score) OVER (
        PARTITION BY class_name
    ) AS class_avg
FROM student;
```

结果中每个学生仍然存在，只是每一行增加了自己班级的平均分。

**易错点：**

> `PARTITION BY` 是告诉窗口函数“哪些行属于同一个分区”，不是把这些行合并成一行。

---

## 6. 联合索引的顺序不能随便交换

❌ 错误理解：

> 有 `(name, age)`，所以查询 `age` 也应该一样能使用这个索引。

✅ 正确理解：

联合索引：

```text
(name, age)
```

通常支持：

```text
name
name + age
```

但不能因为存在 `(name, age)`，就认为单独查询 `age` 也能同样高效地利用这个联合索引。

**易错点：**

> 联合索引的字段顺序本身就是索引结构的一部分。

---

## 7. `Using filesort` 不等于“使用了一个文件排序”

❌ 错误理解：

> `Using filesort` 表示 MySQL 创建了一个文件进行排序。

✅ 正确理解：

> `Using filesort` 表示执行过程中需要进行额外的排序操作。

它不等于：

> 一定发生了磁盘文件排序。

---

## 8. `Using temporary` 不等于永久临时表

❌ 错误理解：

> `Using temporary` 就是数据库创建了一个永久临时表。

✅ 正确理解：

> 表示查询执行过程中需要使用临时结构辅助完成操作。

**易错点：**

> `Using temporary`、`Using filesort` 都只是执行计划中的执行特征，不能单独看到它们就判断 SQL 一定很慢。

---

## 9. `key_len` 不是“使用了几个字段”

❌ 错误理解：

> `key_len = 208` 就是使用了 208 个字段。

✅ 正确理解：

> `key_len` 表示实际使用的索引部分长度，单位是**字节**。

它受到：

```text
数据类型
字符集
NULL 属性
```

等因素影响。

**易错点：**

> `key_len` 是字节长度，不是字段数量。

---

## 10. 覆盖索引的核心是“避免回表”

❌ 错误理解：

> 覆盖索引就是一个特别快的索引。

✅ 正确理解：

> 如果查询所需要的数据都能直接从二级索引中获得，就不需要再回聚簇索引查找完整记录。

**易错点：**

> 覆盖索引的核心概念是**避免回表**，而不是简单理解成“速度快”。

---

## 11. 二级索引不是直接保存完整数据行

❌ 错误理解：

> 二级索引里面保存了整条记录。

✅ 正确理解：

InnoDB 二级索引通常包含：

```text
索引字段
+
主键值
```

如果查询还需要索引中没有的其他字段，就需要通过主键回到聚簇索引获取完整记录。

这就是：

> **回表**

---

## 12. 普通 `SELECT` ≠ 所有情况下都是快照读

❌ 错误理解：

> 所有 SELECT 都是 MVCC 快照读。

✅ 正确理解：

普通：

```sql
SELECT ...
```

通常是一致性读/快照读。

而：

```sql
SELECT ...
FOR UPDATE;
```

属于：

> **当前读**

会读取最新版本，并涉及锁。

**易错点：**

```text
普通 SELECT
→ 通常快照读

SELECT ... FOR UPDATE
→ 当前读 + 锁
```

---

## 13. Read View 不是锁

❌ 错误理解：

> Read View 锁住了当前事务能看到的数据版本。

✅ 正确理解：

> Read View 是用于进行**版本可见性判断**的视图/规则，不是锁。

简单记：

```text
Read View
→ 决定“我能看到哪个版本”

Undo Log
→ 提供旧版本
```

---

## 14. MVCC ≠ 完全没有锁

❌ 错误理解：

> 使用 MVCC 后数据库就不需要锁。

✅ 正确理解：

> MVCC 主要解决一致性读取；锁仍然负责并发修改、当前读等场景。

简单记：

```text
MVCC
→ 我应该看到哪个版本？

Lock
→ 谁现在可以修改/操作？
```

---

## 15. `ROLLBACK` 只回滚当前事务中的未提交修改

❌ 错误理解：

> `ROLLBACK` 可以把数据库恢复到很久以前的状态。

✅ 正确理解：

> `ROLLBACK` 回滚的是**当前事务中尚未提交的修改**。

例如：

```sql
START TRANSACTION;

UPDATE student
SET score = score + 10
WHERE id = 1;

ROLLBACK;
```

只撤销这次事务中的修改。

---

## 16. `AUTO_INCREMENT` ≠ ID 连续

❌ 错误理解：

> 自增主键一定是 `1,2,3,4,5...` 连续的。

✅ 正确理解：

> `AUTO_INCREMENT` 用于自动生成唯一标识，并不保证业务上的连续编号。

例如：

```text
1
2
3
5
8
9
```

完全可能出现。

**易错点：**

> 自增 ID 主要解决唯一标识问题，不应该依赖它实现业务编号连续。

---

## 17. 窗口函数的分区排名与三个排名函数的区别

❌ 错误理解：

> `PARTITION BY class_name` 只是辅助排序，所有学生仍然放在一起排名；`ORDER BY score DESC` 中的 `score` 可能是班级平均分。

✅ 正确理解：

`PARTITION BY class_name` 表示**按班级划分分区，每个班级独立排名**。

`ORDER BY score DESC` 表示**按每个学生自己的成绩降序排列**，不是按班级平均分排序。

例如：

| 姓名 | 班级 | 成绩 | RANK() |
| -- | -- | -: | -----: |
| 张三 | 一班 | 95 |      1 |
| 李四 | 一班 | 85 |      2 |
| 王五 | 一班 | 85 |      2 |
| 赵六 | 二班 | 90 |      1 |

赵六虽然只有 90 分，低于一班张三的 95 分，但赵六在二班，因此在二班内部排名第 1。

**三个排名函数的区别：**

假设同一个班级的成绩降序排列为 `95、85、85、70`：

| 函数             | 排名结果      | 特点       |
| -------------- | --------- | -------- |
| `RANK()`       | `1、2、2、4` | 并列后跳号    |
| `DENSE_RANK()` | `1、2、2、3` | 并列后不跳号   |
| `ROW_NUMBER()` | `1、2、3、4` | 每行分配唯一序号 |

**易错点：**

> `PARTITION BY` 决定分区范围，`ORDER BY` 决定分区内的排序依据。不要把个人成绩和班级平均分混淆，也不要混淆三个排名函数的跳号规则。
