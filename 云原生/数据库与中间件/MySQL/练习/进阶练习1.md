# MySQL 综合实战：电商订单系统

## 一、业务背景

假设你正在开发一个简化版电商系统，需要管理：

* 用户
* 商品
* 商品分类
* 库存
* 订单
* 订单明细
* 支付记录

核心关系：

```text
用户
 │
 ├──────────< 订单
 │             │
 │             ├────< 订单明细 >──── 商品
 │             │                       │
 │             │                       ├──── 商品分类
 │             │                       │
 │             │                       └──── 库存
 │             │
 │             └────< 支付记录
```

建议数据库：

```sql
CREATE DATABASE mall
    DEFAULT CHARACTER SET utf8mb4
    COLLATE utf8mb4_0900_ai_ci;

USE mall;
```

# 第一阶段：数据库与表设计

### 任务 1：设计用户表

创建 `user` 表，要求：

| 字段         | 要求           |
| ---------- | ------------ |
| id         | BIGINT，主键，自增 |
| username   | 用户名，唯一，不能为空  |

要求你考虑：

* 主键选择
* `BIGINT` vs `INT`

* 时间字段
* 字符集与排序规则

# 第十二阶段：并发问题

这个任务非常重要。

## 任务 19：模拟超卖

假设：

```text
商品库存 = 1
```

两个客户端同时购买：

```text
客户端 A：购买 1 件
客户端 B：购买 1 件
```

思考：

> 如果代码是：

```sql
SELECT stock
FROM product_stock
WHERE product_id = 1;
```

然后：

```sql
UPDATE product_stock
SET stock = stock - 1
WHERE product_id = 1;
```

会不会超卖？

---

然后分别尝试：

### 方案 A：悲观锁

```sql
SELECT ...
FOR UPDATE;
```

### 方案 B：乐观锁

利用：

```text
version
```

### 方案 C：条件更新

```sql
UPDATE product_stock
SET stock = stock - 1
WHERE product_id = 1
  AND stock > 0;
```

然后思考三种方案的区别。

# 最终综合任务

最后给你一个真正接近后端开发工作的任务。

## 🏆 任务 24：实现完整下单系统

要求设计并实现：

```text
用户
 ↓
商品
 ↓
库存
 ↓
订单
 ↓
订单明细
 ↓
支付
```

完整流程：

```text
用户提交订单
      ↓
校验商品是否存在
      ↓
校验商品是否上架
      ↓
检查库存
      ↓
锁定库存
      ↓
创建订单
      ↓
创建订单明细
      ↓
计算订单金额
      ↓
创建支付记录
      ↓
事务提交
```

然后考虑异常：

```text
商品不存在
库存不足
商品已下架
订单创建失败
支付创建失败
并发下单
重复提交订单
```

你需要考虑：

* 主键
* 唯一索引
* 普通索引
* 联合索引
* 外键是否使用
* 事务
* MVCC
* 行锁
* 悲观锁
* 乐观锁
* 隔离级别
* 死锁
* SQL 优化
* 幂等性
