## 二、最常踩的坑：502 Bad Gateway

### 问题描述

浏览器访问 `http://39.102.213.11/CloudPlatform/` 或 `/iot-api/` 时，页面返回 `502 Bad Gateway`，Nginx 无法连接后端。

### 底层原因

Nginx 容器通过 `proxy_pass` 转发请求到后端 `8080` 端口。如果**宿主机内网 IP 发生变化**（阿里云 ECS 重启或网络环境抖动），Nginx 配置中写死的旧 IP 就会失效，导致连接后端失败。

### 解决方案（按顺序尝试）

#### 1. 确认后端是否存活

```bash
ss -tlnp | grep 8080
```

有 `LISTEN` 说明后端正常，否则查看后端状态：

```bash
systemctl status iot-api
```

#### 2. 测试 Nginx 容器能否访问后端

```bash
docker exec docker-nginx-1 curl -s -o /dev/null -w "%{http_code}" http://172.27.119.137:8080/
```

- 返回 **200**：说明 IP 没变，只需重载 Nginx 配置：
  
  ```bash
  docker exec docker-nginx-1 nginx -s reload
  ```

- 返回 **000** 或超时：说明宿主机内网 IP 变了，立即更新。

#### 3. 更新 Nginx 配置中的宿主机 IP

```bash
NEW_IP=$(ip addr show eth0 | grep 'inet ' | awk '{print $2}' | cut -d/ -f1)
sed -i "s/172\.[0-9.]*:8080/$NEW_IP:8080/g" /opt/nginx/conf.d/default.conf
sed -i "s/172\.[0-9.]*:8081/$NEW_IP:8081/g" /opt/nginx/conf.d/default.conf
docker exec docker-nginx-1 nginx -s reload
```

### 预防措施

- 每次服务器重启后，先执行上述检查。
- 如果经常出现，考虑使用 `host.docker.internal` 替代固定 IP（需要 Docker 版本支持）。

## 三、前端登录失败 / 页面空白 / 404

### 问题描述

登录接口返回 `404 Not Found`，或页面加载后白屏，控制台报错 `app.xxxx.js:404`。

### 底层原因

前端 `baseURL` 配置与 Nginx 代理路径不匹配。当前正确路径为 `/iot-api`，但前端代码中可能写死为 `/api` 或 `localhost`，导致请求直接发到前端静态服务器或错误路径，后端接口不可达。

### 解决方案

#### 1. 检查当前 JS 文件中的 baseURL

```bash
grep -o 'baseURL:"[^"]*"' /opt/iot-frontend/CloudPlatform/js/app.*.js
```

#### 2. 如果输出包含 `/api`（错误），强制修改

```bash
# 找到最新 app 文件
NEW_APP=$(ls -t /opt/iot-frontend/CloudPlatform/js/app.*.js | head -1 | xargs basename)
sed -i 's|baseURL:"/api"|baseURL:"/iot-api"|g' /opt/iot-frontend/CloudPlatform/js/$NEW_APP
chattr +i /opt/iot-frontend/CloudPlatform/js/$NEW_APP
docker exec docker-nginx-1 nginx -s reload
```

#### 3. 确认 index.html 引用的 JS 文件与修改一致

```bash
grep -oP 'src="/CloudPlatform/js/app\.[0-9a-f]+\.js"' /opt/iot-frontend/CloudPlatform/index.html
```

如果引用的不是刚才修改的文件，需要更新 index.html：

```bash
sed -i "s|app\.[0-9a-f]*\.js|$NEW_APP|g" /opt/iot-frontend/CloudPlatform/index.html
```

### 永久解决

让前端同学在 **源码** `src/utils/request.js` 中直接写死：

```javascript
baseURL: '/iot-api'
```

打包后必须验证：

```bash
grep -o 'baseURL:"[^"]*"' dist/js/app.*.js
```

必须输出 `baseURL:"/iot-api"`，否则不要上传。

## 四、前端更新后页面不刷新

### 问题描述

前端重新打包上传后，浏览器访问仍然是旧页面，强制刷新、无痕模式均无效。

### 底层原因

浏览器缓存了旧版 `index.html`，而新上传的 `index.html` 中引用的 JS 文件名可能**没有变化**或**浏览器未重新获取**。此外，Nginx 容器以只读方式挂载宿主机目录时，宿主机文件更新可能未被容器感知。

### 解决方案

#### 1. 确认服务器返回的 index.html 是否为最新

```bash
curl -s http://localhost/CloudPlatform/ | grep -oP 'src="/CloudPlatform/js/app\.[0-9a-f]+\.js"'
```

对比本地 `dist/index.html` 中的引用，看文件名是否一致。

#### 2. 如果文件名一致但页面未更新，检查 JS 文件内容是否更新

```bash
curl -s http://localhost/CloudPlatform/js/app.xxxxx.js | grep -o 'baseURL:"[^"]*"'
```

#### 3. 如果内容也是新的，问题在浏览器缓存

- 使用**无痕模式**打开。
- `Ctrl+Shift+Del` 清除所有时间段的缓存和 Cookie。
- `Ctrl+F5` 强制刷新。
- 注销 Service Worker：`chrome://serviceworker-internals` → 找到站点 → Unregister。

#### 4. 如果容器内文件未同步（只读挂载导致）

重建 Nginx 容器，使用**读写挂载**：

```bash
docker rm -f docker-nginx-1
docker run -d --name docker-nginx-1 \
  --restart=always \
  -p 80:80 \
  -v /opt/nginx/conf.d:/etc/nginx/conf.d \
  -v /opt/iot-frontend:/opt/iot-frontend \
  nginx:latest
```

### 预防措施

- 前端上传文件后，立即执行服务器端验证。
- 确保 Nginx 配置中静态文件有 `Cache-Control: no-cache` 头（针对 HTML）。

## 五、数据库连接失败 / 启动报错

### 问题描述

后端启动日志出现 `Unknown database 'cloud_platform'` 或 `Access denied for user 'clouduser'`，服务反复重启。

### 底层原因

1. **数据库不存在**：云上 MySQL 可能丢失了业务库。
2. **权限不足**：`clouduser` 没有该库的访问权限。
3. **配置文件错误**：`application.properties` 中的数据库名或密码错误。

### 解决方案

#### 1. 检查数据库是否存在

```bash
docker exec -i mysql_8.0 mysql -u root -p123456 -e "SHOW DATABASES;"
```

若没有 `cloud_platform`，需要从备份恢复。

#### 2. 恢复数据库（从本地上传 SQL 文件）

```powershell
scp cloud_platform.sql root@39.102.213.11:/root/
```

```bash
docker exec -i mysql_8.0 mysql -u root -p123456 -e "CREATE DATABASE IF NOT EXISTS cloud_platform CHARACTER SET utf8mb4;"
docker exec -i mysql_8.0 mysql -u root -p123456 cloud_platform < /root/cloud_platform.sql
```

#### 3. 授权给 clouduser

```bash
docker exec -i mysql_8.0 mysql -u root -p123456 -e "GRANT ALL PRIVILEGES ON cloud_platform.* TO 'clouduser'@'%'; FLUSH PRIVILEGES;"
```

#### 4. 检查外部配置文件

```bash
grep "spring.datasource.url" /opt/iot-backend/application.properties
```

确保数据库名、用户名、密码与实际一致。

### 预防措施

- 定期备份数据库（`mysqldump`）。
- 将数据库初始化脚本纳入版本管理，并使用 Flyway 自动迁移。

## 六、后端 403 拦截登录 / WebSocket / API

### 问题描述

登录接口返回 `403 Forbidden`，WebSocket 连接被拒，或新接口无权限。

### 底层原因

Spring Security 配置中没有放行对应路径。常见于 Nginx 代理路径与后端真实路径不匹配时（如 `/iot-api/auth/login` 被转发为 `/auth/login` 但安全配置中放行的是 `/api/auth/login`）

### 解决方案

#### 1. 确认安全配置中已放行对应路径

在 `SecurityConfig.java` 的 `authorizeHttpRequests` 块中添加：

```java
.requestMatchers("/ws/**").permitAll()        // WebSocket
.requestMatchers("/stream/**").permitAll()    // 流媒体
.requestMatchers("/api/auth/login").permitAll()  // 登录
```

#### 2. 如果路径因 Nginx 重写而改变

检查 Nginx 配置：

```nginx
location /iot-api/ {
    proxy_pass http://172.27.119.137:8080/api/;  # 注意结尾的 /api/，会剥离 /iot-api 前缀
}
```

确保后端的 `SecurityConfig` 中放行的是重写后的路径（如 `/api/auth/login`）。

#### 3. 临时绕过（仅限测试）

直接放行所有请求：

```java
.anyRequest().permitAll()
```

## 七、WebSocket 连接报错

### 问题描述

前端控制台打印 `WebSocket connection to 'ws://.../ws/events' failed` 或 `403/502`。

### 底层原因

1. **Nginx 未配置 WebSocket 代理**：需要升级 HTTP 连接。
2. **Spring Security 拦截 WebSocket 握手**。
3. **后端没有实现 WebSocket 端点**。

### 解决方案

#### 1. Nginx 配置添加 WebSocket 支持

```nginx
location /ws/ {
    proxy_pass http://172.27.119.137:8080/ws/;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```

#### 2. 后端实现原生 WebSocket 端点

```java
@Configuration
@EnableWebSocket
public class WebSocketConfig implements WebSocketConfigurer {
    @Override
    public void registerWebSocketHandlers(WebSocketHandlerRegistry registry) {
        registry.addHandler(new SimpleWebSocketHandler(), "/ws/events")
                .setAllowedOriginPatterns("*");
    }
}
```

#### 3. 安全配置放行 `/ws/**`

```java
.requestMatchers("/ws/**").permitAll()
```

#### 4. 避免连接后发送纯文本消息

在后端 `SimpleWebSocketHandler` 中**不要发送 `"connected"` 等非 JSON 消息**，否则前端 `JSON.parse` 会报错。

## 八、MySQL 容器 root 密码遗忘

### 问题描述

执行 `docker exec -it mysql_8.0 mysql -u root -p` 时密码错误。

### 解决方案

#### 1. 查找启动时环境变量

```bash
docker exec mysql_8.0 env | grep MYSQL_ROOT_PASSWORD
```

#### 2. 如果未设置，尝试空密码

```bash
docker exec -it mysql_8.0 mysql -u root
```

#### 3. 如果仍失败，重置密码（需重启）

```bash
docker exec -it mysql_8.0 bash
# 在容器内
mysql -u root --skip-grant-tables
FLUSH PRIVILEGES;
ALTER USER 'root'@'localhost' IDENTIFIED BY '新密码';
exit
```

然后重启容器。

## 九、文件权限问题导致 403 Forbidden

### 问题描述

访问静态资源（CSS/JS）返回 `403 Forbidden`，但文件存在。

### 底层原因

文件或目录权限不足（如 `700`），Nginx 进程无法读取。

### 解决方案

```bash
chmod -R 755 /opt/iot-frontend/CloudPlatform/
```

### 预防措施

每次上传文件后执行权限修复。

## 十、配置文件被锁定（Operation not permitted）

### 问题描述

写入 `/opt/nginx/conf.d/default.conf` 或 `application.properties` 时提示 `Operation not permitted`。

### 底层原因

之前为了防止误覆盖执行了 `chattr +i` 锁定文件。

### 解决方案

```bash
chattr -i 文件路径
```

修改完成后可重新锁定。

## 十一、前端部署文件不一致导致混乱

### 问题描述

服务器上存在多个版本的 JS 文件，`index.html` 引用的文件不存在或 `baseURL` 错误。

### 底层原因

前端多次上传时未完整覆盖，导致新旧文件混杂。

### 解决方案

1. **删除所有旧 JS 文件**（保留 index.html）：
   
   ```bash
   cd /opt/iot-frontend/CloudPlatform/js
   ls -t app.*.js | tail -n +2 | xargs rm -f
   ```

2. **修改 index.html** 中的引用，指向唯一保留的新文件。
3. **验证**：`grep -oP 'src="/CloudPlatform/js/app\.[0-9a-f]+\.js"' index.html`。

### 预防措施

- 前端每次部署应**完整覆盖** `dist/` 目录，不要增量上传。
- 上传后立即验证。

## 十三、快速恢复脚本（备用）

```bash
#!/bin/bash
# 解锁并恢复 Nginx 配置
chattr -i /opt/nginx/conf.d/default.conf 2>/dev/null
cat > /opt/nginx/conf.d/default.conf << 'EOF'
server {
    listen 80;
    server_name _;
    location = /iot-api/ { return 200 '{"status":"ok"}'; add_header Content-Type application/json; }
    location /iot-api/ { proxy_pass http://172.27.119.137:8080/api/; ... }
    location /live/ { proxy_pass http://172.27.119.137:8081/live/; ... }
    location /CloudPlatform/ { alias /opt/iot-frontend/CloudPlatform/; ... }
    location / { return 301 /CloudPlatform/; }
}
EOF

# 修复前端权限
chmod -R 755 /opt/iot-frontend/CloudPlatform/

# 重载 Nginx
docker exec docker-nginx-1 nginx -s reload

# 重启后端
systemctl restart iot-api
```
