## 校园网到阿里云完整迁移与部署手册

---

### 一、迁移背景与目标

- **源服务器**：学校实验室 Ubuntu 22.04（内网 IP `202.199.6.249`）
- **目标服务器**：阿里云 ECS Ubuntu 22.04（公网 IP `39.102.213.11`）
- **目标**：将整个 CloudPlatform 平台（前端、后端、数据库、EMQX、MinIO、SRS、Nginx）完整迁移到云服务器，实现公网访问，彻底解决校园网 IP 限制和校外访问问题。
- **约束**：云服务器能上网，但 Docker Hub 访问偶发超时；大部分文件传输依赖个人电脑 SCP 中转。
- **参与人员**：后端开发、运维（你）、团队成员（使用平台）。

### 二、云服务器初始化

#### 1. 实例配置

- **配置**：2 核 CPU、4 GB 内存、40 GB 系统盘（高效云盘）。
- **操作系统**：Ubuntu 22.04 LTS（与学校服务器一致，命令无缝衔接）。
- **网络**：按使用流量计费，带宽峰值设为 100 Mbps（测试期间流量费约 0.8 元/GB，实际月费预计 10-20 元）。
- **系统优化**：为避免 Java 应用和 Docker 容器因内存不足被 OOM Killer 杀死，手动开启 2 GB Swap：
  
  ```bash
  sudo fallocate -l 2G /swapfile
  sudo chmod 600 /swapfile
  sudo mkswap /swapfile
  sudo swapon /swapfile
  echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
  ```

  - **解释**：Swap 即虚拟内存，在物理内存不足时使用磁盘空间临时存放数据，可防止进程突然崩溃

#### 2. 安全组规则

在阿里云控制台 → 网络与安全 → 安全组 → 配置规则 → 入方向，添加以下规则（仅开放必要端口，遵循最小权限原则）：

| 端口 | 协议 | 授权对象 | 用途 |
|------|------|----------|------|
| 22 | TCP | 0.0.0.0/0 (或限定 IP) | SSH 远程连接 |
| 80 | TCP | 0.0.0.0/0 | 前端 + 后端 API（Nginx 代理） |
| 1883 | TCP | 0.0.0.0/0 | MQTT 设备通信 |
| 1935 | TCP | 0.0.0.0/0 | RTMP 视频推流 |
| 8082 | TCP | 0.0.0.0/0 | 前端备用端口（直接访问静态页面） |
| 9001 | TCP | 0.0.0.0/0 | MinIO 控制台（可后续限制 IP） |

> **注意**：生产环境建议将 SSH、数据库等端口对公网关闭，或通过跳板机/VPN 访问。

#### 3. 安装 Docker

```bash
# 使用官方脚本安装最新版 Docker（含 Docker Compose 插件）
curl -fsSL https://get.docker.com | sudo sh
# 将当前用户加入 docker 组，避免每次使用 sudo
sudo usermod -aG docker $USER
# 刷新组权限（或退出重新登录）
newgrp docker
# 设置 Docker 开机自启
sudo systemctl enable --now docker
# 验证安装
docker --version
```

*预期输出*：`Docker version 27.x.x, build ...`

### 三、镜像与数据库迁移

#### 1. 迁移 Docker 镜像

由于云服务器直接 `docker pull` 偶发超时，采用 **“学校服务器打包 → 个人电脑中转 → 云服务器加载”** 的可靠离线方案。

- **在学校服务器上打包镜像**（已运行的容器镜像已存在本地）：
  
  ```bash
  docker save mysql:8.0 nginx:latest emqx/emqx:latest minio/minio:latest ossrs/srs:5 -o all_images.tar
  ```

  打包后文件约 1.6 GB，存放于 `/home/neu/all_images.tar`。

- **下载到个人电脑（Windows）**：
  
  在 PowerShell 中执行：

  ```powershell
  scp neu@202.199.6.249:/home/neu/all_images.tar C:\Users\Lenovo\Desktop\
  ```

  输入学校服务器 `neu` 用户的密码，等待传输完成。若校园网不稳定，可多次重试或使用 `rsync`

- **上传到云服务器**：
  
  ```powershell
  scp C:\Users\Lenovo\Desktop\all_images.tar root@39.102.213.11:/root/
  ```
  
  输入云服务器 root 密码

- **云服务器加载镜像**：
  
  ```bash
  docker load -i /root/all_images.tar
  docker images   # 验证镜像列表
  ```

#### 2. 迁移数据库

- **在学校服务器上导出数据库**：
  
  ```bash
  docker exec mysql_8.0 mysqldump -u root -p123456 cloud_platform > /home/neu/cloud_platform.sql
  ```

  生成的文件约几十 MB，包含表结构和数据。

- **通过电脑中转**：先用 `scp` 下载到桌面，再上传到云服务器 `/root/` 目录。

- **云服务器启动 MySQL 容器**：
  
  ```bash
  docker run -d --name mysql_8.0 \
    --restart=always \
    -p 3306:3306 \
    -e MYSQL_ROOT_PASSWORD=123456 \
    -v /opt/mysql:/var/lib/mysql \
    mysql:8.0
  ```
  
  数据卷挂载到 `/opt/mysql`，实现持久化

- **导入数据库**：
  
  ```bash
  docker exec -i mysql_8.0 mysql -u root -p123456 -e "CREATE DATABASE IF NOT EXISTS cloud_platform CHARACTER SET utf8mb4;"
  docker exec -i mysql_8.0 mysql -u root -p123456 cloud_platform < /root/cloud_platform.sql
  ```
  
  验证导入：`docker exec -i mysql_8.0 mysql -u root -p123456 -e "SHOW TABLES FROM cloud_platform;"` 应显示 27 张表（初始版本）

#### 3. 创建业务数据库用户

后端服务使用低权限用户 `clouduser` 连接数据库，避免直接使用 root：

```bash
docker exec -i mysql_8.0 mysql -u root -p123456 << 'EOF'
CREATE USER IF NOT EXISTS 'clouduser'@'%' IDENTIFIED BY 'cloudpass123';
GRANT ALL PRIVILEGES ON cloud_platform.* TO 'clouduser'@'%';
FLUSH PRIVILEGES;
EOF
```

**为什么不用 root**：遵循最小权限原则，限制安全风险。

### 四、核心服务部署

所有容器需要访问宿主机的后端（8080）或 SRS（8081），容器内的 `127.0.0.1` 指向容器自己，无法访问宿主机。因此，我们需要知道宿主机的内网 IP（云服务器内部局域网 IP），通过 `ip addr show eth0` 获取，本例为 `172.27.119.137`。

#### 1. EMQX（MQTT Broker）

```bash
docker run -d --name emqx \
  --restart=always \
  -p 1883:1883 \
  -p 18083:18083 \
  -e EMQX_DASHBOARD__DEFAULT_PASSWORD=123456 \
  emqx/emqx:latest
```

- Dashboard 访问：`http://39.102.213.11:18083`，账号 `admin`，密码 `123456`。

#### 2. MinIO（对象存储）

```bash
docker run -d --name minio \
  --restart=always \
  -p 9000:9000 \
  -p 9001:9001 \
  -e MINIO_ROOT_USER=admin \
  -e MINIO_ROOT_PASSWORD=admin123456 \
  -v minio_data:/data \
  minio/minio server /data --console-address ":9001"
```

- 控制台：`http://39.102.213.11:9001`，账号 `admin`，密码 `admin123456`。

#### 3. SRS（流媒体服务器）

```bash
docker run -d --name srs \
  --restart=always \
  -p 1935:1935 \
  -p 8081:8080 \
  -p 1985:1985 \
  -p 8000:8000/udp \
  ossrs/srs:5
```

- 注意：SRS 的 HTTP 服务默认使用 8080，但宿主机 8080 已被后端占用，因此映射为 `8081:8080`。

#### 4. Nginx（反向代理）

- **创建配置目录**：
  
  ```bash
  mkdir -p /opt/nginx/conf.d
  ```

- **创建自定义配置文件** `/opt/nginx/conf.d/default.conf`（内容见第五部分）。
- **启动容器**：
  
  ```bash
  docker run -d --name docker-nginx-1 \
    --restart=always \
    -p 80:80 \
    -v /opt/nginx/conf.d:/etc/nginx/conf.d:ro \
    -v /opt/iot-frontend:/opt/iot-frontend:ro \
    nginx:latest
  ```

  挂载配置和前端文件目录，`ro` 表示只读。

### 五、Nginx 最终配置详解

```nginx
server {
    listen 80;
    server_name _;

    # 1. 代理前端发出的 /api/ 请求（如登录 /api/auth/login）
    # 注意：proxy_pass 末尾没有斜杠，因此请求路径原样转发
    location /api/ {
        proxy_pass http://172.27.119.137:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 2. 代理后端自身的 /iot-api/ 接口（标准入口）
    location /iot-api/ {
        proxy_pass http://172.27.119.137:8080/iot-api/;
        # 尾斜杠对齐，路径正确拼接
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 3. 流媒体 HLS 分发
    location /live/ {
        proxy_pass http://172.27.119.137:8081/live/;
        proxy_set_header Host $host;
    }

    # 4. 前端静态页面（Vue 应用）
    location /CloudPlatform/ {
        alias /opt/iot-frontend/CloudPlatform/;   # 实际目录路径
        try_files $uri $uri/ /CloudPlatform/index.html;   # 支持 Vue Router history 模式
        index index.html;
    }

    # 5. 根路径重定向到前端首页
    location / {
        return 301 /CloudPlatform/;
    }
}
```

**配置要点**：

- `location /api/` 必须放在 `location /CloudPlatform/` 之前，因为 Nginx 按顺序匹配。
- `alias` 与 `root` 的区别：`alias` 将请求路径 `/CloudPlatform/` 精确映射到指定目录，适合子路径部署。
- `try_files` 回退到 `index.html`，解决单页应用刷新 404 问题。

### 八、401 登录错误深度排查与完整解决实录

**核心故障现象**：无论使用原始 `admin` 还是新建的 `superadmin`，登录接口始终返回 `{"code":401,"message":"用户名或密码错误"}`，而后端健康检查、数据库连接均正常。

#### 1. 确认请求路径与代理转发（301 → 403）

- **现象**：前端登录请求 `POST /api/auth/login` 被 Nginx 重定向到 `/CloudPlatform/`，返回 301。
- **排查**：`curl -I http://39.102.213.11/api/auth/login` 返回 301，说明请求被 Nginx 的 `/` 规则捕获并重定向到前端首页。
- **原因**：Nginx 配置中最初缺少 `location /api/` 处理规则。
- **修复**：添加 `location /api/` 代理规则并重载 Nginx：
  
  ```bash
  docker exec docker-nginx-1 nginx -s reload
  ```

- **新现象**：返回 403 Forbidden。

#### 2. 解决 Spring Security 权限拦截（403 → 401）

- **原因**：后端 `SecurityConfig.java` 中未放行 `/api/auth/login` 路径。
- **尝试本地修改代码打包**：项目合并冲突、Lombok 版本问题导致编译失败（找不到符号 `getStationId()` 等）。
- **尝试 Nginx 重写**：将 `/api/` 重写为 `/iot-api/`，但后端仍返回 403，因为安全配置中未针对重写后的路径放行。
- **最终方案**：**使用学校服务器上已验证可用的 JAR 包** 直接替换云服务器 JAR。学校 JAR 包含正确安全配置（已放行登录接口）。
  
  ```bash
  # 在学校服务器上生成 JAR 副本
  scp /opt/iot-backend/app.jar 个人电脑
  # 上传到云服务器
  scp app_school.jar root@39.102.213.11:/opt/iot-backend/
  # 替换
  sudo cp /opt/iot-backend/app_school.jar /opt/iot-backend/app.jar
  sudo systemctl restart iot-api
  ```

- **结果**：403 消失，变为 401，说明认证流程已启动，密码验证失败。

#### 3. 深入排查密码验证失败（401 持续存在）

**现象**：即使使用正确的用户名密码，依然 401。

**3.1 重设密码与 BCrypt 生成**  

使用 Python 生成标准 BCrypt 密文并更新数据库：

```bash
pip3 install bcrypt -q
HASH=$(python3 -c "import bcrypt; print(bcrypt.hashpw(b'123456', bcrypt.gensalt(prefix=b'2a')).decode())")
docker exec -i mysql_8.0 mysql -u root -p123456 -e "UPDATE cloud_platform.sys_user SET password='${HASH}' WHERE username='superadmin';"
```

多次尝试后仍然 401。

**3.2 关键日志线索**  

```bash
journalctl -u iot-api -n 100 --no-pager | grep -i -E "Authentication|BCrypt|Password"
```

输出：

```
Encoded password does not look like BCrypt
```

这表明 Spring Security 的 `BCryptPasswordEncoder` 无法识别数据库中的密码格式。

**3.3 根因定位：密码字段被 Shell 截断**

直接查看数据库中 `superadmin` 的密码字段：

```sql
SELECT password FROM cloud_platform.sys_user WHERE username='superadmin';
```

结果：

```
password
a2
```

完整的 BCrypt 密文（约 60 字符）被截断为 `a2` 两个字符。

**原因分析**：在 shell 中执行 `UPDATE` 时，密文中的 `$` 符号在双引号或未正确转义时被解释为变量引用，导致密文被破坏。例如：

```bash
docker exec ... -e "UPDATE ... SET password='$2a$12$...'" 
```

`$2a` 会被 shell 当作变量 `$2`（值为空）和字面量 `a`，最终写入的只是 `a2`。

**3.4 修复密码截断：严格使用单引号保护**  

```bash
HASH=$(python3 -c "import bcrypt; print(bcrypt.hashpw(b'123456', bcrypt.gensalt(prefix=b'2a')).decode())")
docker exec -i mysql_8.0 mysql -u root -p123456 -e "UPDATE cloud_platform.sys_user SET password='${HASH}' WHERE username='superadmin';"
```

**关键点**：`'${HASH}'` 中，外层的单引号阻止了密文内部的 `$` 被展开。验证密码字段恢复为完整 60 字符的 BCrypt 密文。

**3.5 密码格式兼容性问题：`{bcrypt}` 前缀** 

- **背景**：学校 JAR 包的 `PasswordEncoder` 是直接的 `BCryptPasswordEncoder`，**不识别 `{bcrypt}` 前缀**。而某些在线生成器或教程会建议添加 `{bcrypt}` 前缀。
- **解决**：确保数据库中的密码字段**不包含** `{bcrypt}` 前缀，直接存放 `$2a$...` 原始密文。

**3.6 最终验证**  

```bash
sudo systemctl restart iot-api
sleep 15
curl -X POST http://127.0.0.1:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"superadmin","password":"123456"}'
```

返回 `{"code":200,"data":{"accessToken":"eyJ..."}}`，登录成功。

#### 4. 排查方法论总结

1. **分层隔离**：逐步确认请求是否到达后端（301→403→401），逐层剥离 Nginx、Spring Security、密码验证问题。
2. **日志驱动**：`grep BCrypt` 直接定位“密码格式不合法”。
3. **数据验证**：直接查询数据库字段内容，发现截断问题，这是关键转折点。
4. **环境对比**：利用学校服务器的可用 JAR 包快速排除应用层逻辑问题。
5. **Shell 陷阱意识**：特殊字符 `$` 在命令行中的转义，是本次耗时最长的隐蔽错误。

### 九、踩坑汇总

| 问题现象 | 根因 | 解决方案 |
|----------|------|----------|
| Docker 拉取镜像超时 | 网络不稳定 | 学校服务器离线打包，个人电脑中转上传 |
| Nginx 502 Bad Gateway | 容器内 `127.0.0.1` 不通宿主机 | 使用宿主机内网 IP `172.27.119.137` |
| 前端页面空白，JS 报 `Unexpected token '<'` | 前端文件权限不足（缺少执行位） | `chmod -R 755 /opt/iot-frontend/CloudPlatform/` |
| 登录返回 301 重定向 | Nginx 缺少 `/api/` 代理规则 | 添加 `location /api/` 并置于前端规则之前 |
| 登录返回 403 | Spring Security 未放行登录路径 | 替换学校 JAR 包（已包含正确安全配置） |
| 登录返回 401 | 密码字段被 `$` 截断 | 更新密码时使用单引号保护完整密文 |
| 登录返回 401（持续） | 密码字段误加 `{bcrypt}` 前缀 | 移除前缀，仅保留 BCrypt 原始密文 |
| 本地打包失败 | 代码合并冲突 + Lombok 缺失 | 直接使用学校 JAR 包替换 |
| 数据库升级后启动失败 | 新表结构与 JPA 实体不匹配 | 暂时使用 `ddl-auto=update` 或手动调整实体 |
