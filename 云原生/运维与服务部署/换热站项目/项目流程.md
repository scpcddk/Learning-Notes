# 换热站边缘计算平台 — 整体数据流概述

---

## 一、数据从哪里来

### 1. 传感器数据（温度、压力、流量等）
- **来源**：换热站现场的 PLC/RTU 设备或 Jetson 连接的传感器
- **采集方式**：Jetson 边缘盒子通过串口/Modbus/GPIO 读取实时数据

### 2. 视频流
- **来源**：换热站现场摄像头（USB 摄像头或网络摄像头）
- **采集方式**：Jetson 通过 FFmpeg 抓取摄像头画面

### 3. 业务配置数据
- **来源**：系统管理员通过前端页面录入
- **内容**：站点信息、设备信息、告警规则、巡检计划等

图中为总体方案；录像到 MinIO 等链路须以实际实现和联调结果为准，SRS 不会默认自动把录像上传到 MinIO。

**核对采集、录像和回放的设备映射**

设备在采集主题、数据库与页面的编号可能由不同模块映射，录像又按流名归档。交接时写一行「站点编号 → 设备编号 → MQTT 主题 → 视频流名 → 回放对象前缀」，并标明映射来自哪份配置。若只有某站点不显示，优先核对这一行和查询时间范围；若所有站点一起失败，再查共享入口、Broker 或后端进程。更新映射后用新旧样本各查一次，避免页面仍引用旧编号。


## 三、数据的四种流向

四条链路各选一个样本。演示前记下站点、设备、时间或流名，页面、后端和中间件都用同一标识核对。测试记录与真实站点数据分开。


### 流向 1：传感器数据（MQTT → 后端 → MySQL → 前端）

```
Jetson 传感器
    │
    │ MQTT 发布到 EMQX
    │ 主题: station/1/data
    │ 内容: {"temperature":55.2, "pressure":1.2}
    ▼
EMQX (1883)
    │
    │ 后端订阅该主题
    ▼
Spring Boot 后端
    │
    │ 解析 JSON，写入数据库
    ▼
MySQL (cloud_platform.sensor_data)
    │
    │ 前端调用 /iot-api/sensor/... 查询
    ▼
前端页面展示实时曲线/数值
```

**验收样本**　用已知值和唯一编号核对主题、消息、数据库行和页面

**排查断点**　Broker 有消息但库中无记录时，查订阅、解析与入库

采集时间、Broker 到达时间、数据库写入时间和页面刷新时间需要分开记录。统一时区后，才能判断设备迟报、后端堆积或页面查询窗口不对。保留一个成功样本和一个故障样本，前者用来在迁移或重启后复测，后者用来定位最早丢失证据的一段。


### 流向 2：视频流（RTMP → SRS → HLS → 前端播放）

```
Jetson 摄像头
    │
    │ FFmpeg 推 RTMP 流
    │ rtmp://202.199.6.249:1935/live/device1
    ▼
SRS 流媒体服务器 (1935)
    │
    │ 自动转封装为 HLS (.m3u8)
    │ http://202.199.6.249:8081/live/device1.m3u8
    ▼
Nginx 反向代理 (80)
    │ /live/ → 转发到 SRS
    ▼
前端页面
    │ 调用 /iot-api/stream/device1 获取播放地址
    │ 使用 hls.js 加载 HLS 地址
    ▼
用户浏览器实时观看
```

**验收样本**　SRS 有对应流名，外部入口能取 m3u8 与分片，页面实际出画面

**排查断点**　内网能播、外网失败时，查反代、HTTPS 和分片路径


### 流向 3：历史录像存储（SRS 录像 → MinIO → 前端回放）

```
SRS 录制直播流
    │
    │ 录像文件 (.mp4 或 .ts) 保存到本地磁盘
    ▼
后端定时任务 / 手动触发
    │
    │ 上传录像文件到 MinIO (videos 桶)
    │ 同时在 MySQL 写入录像索引记录
    ▼
MinIO 对象存储 (9000)
    │
    │ 前端请求回放 → 后端生成预签名 URL
    ▼
前端页面播放历史录像
```

**验收样本**　对象存在，后端关联正确时间和对象键，授权链接可播

**排查断点**　对象存在却查不到历史时，分开核对元数据和签名


### 流向 4：用户操作数据（前端 → 后端 → MySQL）

```
管理员通过前端页面操作
    │
    │ HTTP POST/PUT/DELETE
    │ /iot-api/stations, /iot-api/alarm-rules ...
    ▼
Spring Boot 后端
    │
    │ 读写 MySQL
    ▼
MySQL (cloud_platform)
    station, device, alarm_rule, inspection_plan ...
    │
    │ 查询结果返回前端
    ▼
前端页面刷新展示
```

**验收样本**　用授权账号完成一次隔离配置变更，重新查询并核对

**排查断点**　请求成功但页面旧，查后端写入、查询条件和页面缓存

**联调时保留一条可追溯时间线**

例如先记某站点测试事件的采集时间，再记后端查询和页面首次显示的时间。录像按流名和时间范围查找，不用传感器值推测某段录像一定存在。若前端提示失败，记下是哪条链路尚未通过，避免对正常的服务做无关重启。


---

## 四、总结一句话

> [!TIP]
> **换热站现场的 Jetson 盒子采集传感器数据和摄像头视频，通过 MQTT 和 RTMP 协议分别推送到服务器的 EMQX 和 SRS；后端 Spring Boot 处理数据后存入 MySQL 和 MinIO，前端页面调用 API 展示实时数据、播放视频、查询历史记录。所有服务部署在一台 Linux 服务器上，通过 Nginx 统一入口，校园网内任意设备均可访问。**
