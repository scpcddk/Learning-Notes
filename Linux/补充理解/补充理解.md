# ==一.粘滞位（Sticky Bit）==

## 1.什么是粘滞位？

在现代 Linux 中，粘滞位对目录起作用，限制目录内文件的**删除和重命名**；权限字符串中显示为 `t`（同时有其他用户执行权限）或 `T`（没有该执行权限）

+ 核心规则：通常只有文件所有者、目录所有者或具有相应特权（如 `CAP_FOWNER`）的进程能删除或重命名该文件。粘滞位只是额外限制，并不授予操作权限；仍需满足父目录 `w+x`、路径搜索权限等条件

## 2.粘滞位的设置

### (1).表现形式

| 权限设置 | 表示 | 含义 |
| ---------- | ------ | ------ |
| 没有粘滞位 | `drwxrwxrwx` | 仅考虑传统权限且路径可搜索时，普通用户也可删除他人的文件 |
| 有粘滞位 | `drwxrwxrwt` | 普通用户通常只能删自己的文件；目录所有者和具有相应特权的进程例外 |

### (2).符号模式

```linux
chmod +t /project      # 添加粘滞位
chmod -t /project      # 移除粘滞位
```

### (3).数字模式

```linux
chmod 1777 /project    # 1 表示粘滞位，777 表示权限
chmod 1770 /project    # 也可以和其他权限组合
```

+ 四位八进制模式的首位是特殊权限位：SetUID=4、SetGID=2、Sticky=1，可相加。例如 `3770` 的首位 `3=2+1`，同时设置 SetGID 和粘滞位
+ `1777` 的首位 1 只设置粘滞位；首位为 0 表示不设置这些特殊权限

## 3.常见误区澄清

| 误区 | 真相 |
| ------ | ------ |
| 粘滞位保护文件不被修改 | ❌ 限制删除和重命名，不阻止对文件内容的写入；写入仍由文件权限及其他机制控制 |
| 粘滞位对文件有效 | ❌ 粘滞位**只对目录有效**，对文件无效 |
| 有粘滞位就不能删任何文件 | ❌ 满足目录操作权限等条件时，仍可删除自己的文件；目录所有者及特权进程还可删除他人的文件 |
