## 零、终极自救指南（内置帮助）

### 1. man 与 --help

#### 1.1 man 与 --help的作用

* 提供命令的**内置帮助手册**，解决参数记不清或用法不明的问题
* **无需联网**，系统自带，是 Linux 最强大的**自学工具**

#### 1.2 **两种使用方式**

| 方式 | 语法 | 特点 |
| :--- | :--- | :--- |
| **快速查看** | `command --help` | 输出常用参数速览（提纲式），适合快速回忆 |
| **完整手册** | `man command` | 输出详细手册（含选项、作者、BUG 说明等），内容最全 |

#### 1.3 典型示例

```bash
tar --help                # 快速看 tar 的压缩/解压参数
man find                  # 打开 find 的完整说明书（按 q 退出）
```

#### 1.4 man 页面内的操作

进入 `man` 页面后（屏幕变黑），可使用以下快捷键：

| 按键 | 作用 |
| :--- | :--- |
| `q` | **退出** man 手册（回到命令行）⭐ |
| `/关键词` | 向下搜索关键词（如 `/mtime`） |
| `n` | 跳转到下一个匹配项 |
| `空格键` 或 `PageDown` | 向下翻页 |
| `PageUp` | 向上翻页 |

> [!TIP]
> **核心心法**：遇到不会的命令，先敲 `command --help`；看不懂再敲 `man command`，按 `q` 退出来。这能覆盖日常 90% 的查命令需求，比翻笔记更快

## 一、文件管理

### 1. rm

#### 1.1 **rm的作用**

* **删除**一个文件或者目录
* **注意**：文件通过 rm 命令删除，则**无法恢复**。在 `ext4/xfs` 等常见文件系统上删除后很难恢复，务必谨慎；如需误删保护，可使用 `trash-cli` 等工具

#### 1.2 rm的语法

`rm [options] name...`

#### 1.3 rm的参数

| 参数 | 作用 |
| :--- | :--- |
| `-i` | 删除前逐一**询问确认** |
| `-f` | **强制删除**，忽略不存在的文件，不提示确认（⚠️ 即使文件只读也直接删） |
| `-r` | 将目录及以下之档案逐一删除 |

#### 1.4 rm的示例

* **删除文件与目录**

```bash
# rm  test.txt 
rm：是否删除文件 "test.txt"? y  
# rm  homework  
rm: 无法删除目录"homework": 是一个目录  
# rm  -r  homework  
rm：是否删除 目录 "homework"? y 
# rm  -r  *     ( * 代表当前目录下所有非隐藏文件与目录)
删除当前目录下文件与目录
```

### 2. mv

#### 2.1 **mv的作用**

* 为文件或目录**改名**、或将文件或目录**移入其它位置**

#### 2.2 **mv的语法**

| 命令格式 | 运行结果 |
| :--- | :--- |
| `mv source_file` (文件) `dest_file` (文件) | 将源文件名 `source_file` 改为目标文件名 `dest_file` |
| `mv source_file` (文件) `dest_directory` (目录) | 将文件 `source_file` 移动到目标目录 `dest_directory` 中 |
| `mv source_directory` (目录) `dest_directory` (目录) | 若目录名 `dest_directory` **已存在**，将 `source_directory` 移动到目录 `dest_directory` 中；若目录名 `dest_directory` **不存在**，则将 `source_directory` 改名为 `dest_directory` |
| `mv source_directory` (目录) `dest_file` (文件) | **出错** |

* **注意**：需要先执行显示隐藏文件命令，否则，隐藏文件以及隐藏文件夹不会被移动到新目录。（英语点号开头的文件/夹会被作为隐藏文件/夹处理）

#### 2.3 mv的参数

| 参数 | 作用 |
| :--- | :--- |
| `-b` | 当目标文件或目录存在时，在执行覆盖前，会为其创建一个备份 |
| `-i` | 如果指定移动的源目录或文件与目标的目录或文件同名，则会先**询问**是否覆盖旧文件，输入 `y` 表示直接覆盖，输入 `n` 表示取消该操作 |
| `-f` | 如果指定移动的源目录或文件与目标的目录或文件同名，不会询问，**直接覆盖**旧文件 |
| `-n` | 不要覆盖任何已存在的文件或目录 |
| `-u` | 当源文件比目标文件新或者目标文件不存在时，才执行移动操作 |

### 4. cat

#### 4.1 **cat的作用**

* **连接文件并打印**到标准输出设备上，**查看和连接**文件

#### 4.2 cat的语法

`cat [选项] [文件]`

#### 4.3 cat的参数

| 参数 | 作用 |
| :--- | :--- |
| `-n` | 显示行号，会在输出的**每一行前加上行号** |
| `-b` | 显示行号，但只**对非空行进行编号** |
| `-s` | **压缩连续的空行**，只显示一个空行 |
| `-E` | 在每一行的末尾显示 `$` 符号 |
| `-T` | 将 Tab 字符显示为 `^I` |
| `-v` | 显示一些非打印字符 |

#### 4.4 **cat的使用**

* **显示文件内容**：`cat filename` 将指定文件的内容输出到终端上(可多个)
* **连接文件**：`cat file1 file2 > combined_file` 将 `file1` 和 `file2` 的内容连接，并将结果输出到 `combined_file` 中
* **创建文件**：`cat > filename`，输入文本，按 `Ctrl+D` 保存并退出
* **覆盖写入**: `cat > filename` ，清空原内容，写入新内容（文件不存在则新建）
* **在终端显示文件**：将 `cat` 与管道（`|`）结合使用，显示其他命令的输出，例如 `ls -l | cat` 会将 `ls -l` 的输出通过 `cat` 打印到终端上
* **追加重定向**：`cat >> filename`，将标准输入追加到文件 `filename` 的末尾
* **清空 `/etc/test.txt` 文档内容**：`cat /dev/null > /etc/test.txt`

#### 4.5 echo的写入

* **覆盖**写入（**新建/替换**）

  ```bash
  echo -e "2026-04-29\n今天学了Linux基础命令，很有成就感！" > diary/day1.txt
  ```

* **追加**写入（**补充**内容）

  ```bash
  echo -e "2026-04-30\n今天搞懂了>和>>" >> diary/day1.txt
  ```

### 5. chmod

#### 5.1 **chmod的作用**

* **控制**用户对文件或目录的**权限**
  * 文件所有者、所属组和其他用户对文件的访问权限
  * 只有文件所有者和超级用户可以修改文件或目录的权限

#### 5.2 chmod的权限说明

##### (1) chmod的权限身份分类

| 身份 | 代号 | 说明 |
| :--- | :--- | :--- |
| **文件所有者** | u (user) | 文件的创建者或拥有者 |
| **所属组** | g (group) | 文件所有者所在的用户组 |
| **其他用户** | o (others) | 除了 u 和 g 以外的所有用户 |
| **所有用户** | a (all) | 等同于 u + g + o |

##### (2) chmod的权限位与数字对应

每个权限位对应一个数字（八进制）：**r=4, w=2, x=1，无权限为 0** ，将一组的三位相加得到一个 0-7 的数字

| 二进制 | 八进制 | 权限 | 说明 |
| :--- | :--- | :--- | :--- |
| 111 | 7 | rwx | 读 + 写 + 执行 |
| 110 | 6 | rw- | 读 + 写 |
| 101 | 5 | r-x | 读 + 执行 |
| 100 | 4 | r-- | 只读 |
| 011 | 3 | -wx | 写 + 执行 |
| 010 | 2 | -w- | 只写 |
| 001 | 1 | --x | 只执行 |
| 000 | 0 | --- | 无权限 |

#### 5.3 chmod的语法

`chmod [选项] 权限模式 文件...`
`chmod [选项] --reference=参考文件 文件...`

| 选项 | 说明 |
| :--- | :--- |
| `-c` | 仅在该文件权限**确实被更改**时，才显示其更改动作 |
| `-f` | 若该文件权限无法被更改，**不要显示错误讯息**（静默模式） |
| `-v` | 显示权限变更的**详细资料**（无论是否更改都显示） |
| `-R` | **递归**修改：对当前目录下的所有文件与子目录进行相同的权限变更 |
| `--help` | 显示辅助说明 |
| `--version` | 显示版本信息 |

#### 5.4 **chmod的权限模式**

##### (1) **chmod的符号模式**

`[ugoa...][[+-=][rwxX]...][,...]`

* `+` 表示**增加**权限、`-` 表示**取消**权限、`=` 表示**唯一设定**权限
* `r` 表示可**读取**，`w` 表示可**写入**，`x` 表示可**执行**，`X` 表示只有当该文件是个子目录或者该文件已经被设定过为可执行
  * **`x` 的含义**:
    * **文件**：能否运行
    * **目录**：能否进入 (`cd`)

##### (2) chmod的八进制语法

* **组合方式**:
  * 所有者权限(第一位)
  * 组权限(第二位)
  * 其他用户权限(第三位)

##### (3) **chmod的示例**

* **符号模式实例**

| 命令 | 说明 |
| :--- | :--- |
| `chmod a+r file` | 给 **所有用户** 增加 **读** 权限 |
| `chmod a-x file` | 删除 **所有用户** 的 **执行** 权限 |
| `chmod a+rw file` | 给 **所有用户** 增加 **读写** 权限 |
| `chmod +rwx file` | 给 **所有用户** 增加 **读写执行** 权限（`+` 等价于 `a+`） |
| `chmod u=rw,go= file` | 所有者设为 **读写**，**清空** 组和其他用户的**所有权限** |
| `chmod -R u+r,go-r docs` | **递归**：对 `docs` 目录：所有者 **增加读**，组和其他用户 **删除读** |

* **数字模式实例**

| 命令 | 权限分解 | 说明 |
| :--- | :--- | :--- |
| `chmod 664 file` | `u=rw-` (6), `g=rw-` (6), `o=r--` (4) | 所有者/组：读写；其他：只读 |
| `chmod 0755 file` | `u=rwx` (7), `g=r-x` (5), `o=r-x` (5) | 所有者：读写执行；组/其他：读执行（前导 `0` 表示无特殊权限） |
| `chmod 4755 file` | `4` (SetUID) + `755` | 设置 **SetUID** 位，其他同 `755`。执行时临时拥有所有者权限 |

* **高级组合（配合 `find`）**

| 命令 | 说明 |
| :--- | :--- |
| `find path/ -type d -exec chmod a-x {} \;` | 递归删除 **所有目录** 的执行权限（不影响文件） |
| `find path/ -type d -exec chmod a+x {} \;` | 递归允许所有用户 **浏览/进入** 目录 |
| `find path/ -type f -exec chmod 644 {} \;` | 递归将所有 **文件** 权限设为 `644` |

##### (4) **chmod的删除与写入的区别**（父目录权限优先）⭐

* **删/增/重命名文件**：取决于**父目录**的 `w` 权限（修改目录清单）
* **修改文件内容**：取决于**文件本身**的 `w` 权限
* **结论**：**文件即使只读（`444`），只要父目录可写（`777`），依然可以强制删除！**（除非父目录设置了粘滞位 `t`，如 `/tmp`）

> [!TIP]
> **一句话实战**：脚本跑不了 `chmod +x run.sh`；文件删不掉别盯着文件，去检查它**上一级文件夹**的写权限

### 6. 重定向与管道

#### 6.1 **重定向的作用**

| 符号 | 作用 | 示例 |
| :--- | :--- | :--- |
| `>` | **覆盖**写入文件 | `echo "hello" > file.txt` |
| `>>` | **追加**写入文件 | `echo "world" >> file.txt` |
| `<` | 从文件**读取**输入 | `sort < names.txt` |
| `2>` | **重定向**错误输出 | `ls /nofile 2> error.log` |
| `&>` | 同时**重定向**标准输出和错误 | `java -jar app.jar &> app.log` |

#### 6.2 **管道 `|` 的作用**

* 把**左边**命令**输出**的内容，像水一样通过水管，直接送给**右边**命令当**输入**，常用于组合过滤和分析

```bash
# 查找 Java 进程
ps aux | grep java

# 统计 ERROR 日志行数
cat app.log | grep ERROR | wc -l

# 实时查看 SpringBoot 日志中带 "Exception" 的部分
tail -f app.log | grep Exception
```

#### 6.3 xargs的作用

* `xargs`将标准输入**转换为命令参数**，常用于配合管道

```bash
# 删除找到的文件
find . -name "*.log" | xargs rm -f

# 复制找到的文件到备份目录
find . -name "*.conf" | xargs -I {} cp {} /backup/

# 统计多个文件行数
ls *.txt | xargs wc -l
```

### 8. touch

#### 8.1 **touch的作用**

#### 8.2 touch的语法

`touch [选项] 文件名`

#### 8.3 touch的常用选项

| 选项 | 说明 |
| :--- | :--- |

### 9. find

#### 9.1 **find 的作用**

* 在指定**目录下递归搜索文件和目录**，支持按名称、类型、大小、时间等条件筛选

#### 9.2 find 的语法

`find [搜索路径] [匹配条件] [处理动作]`

#### 9.3 find 的常用条件参数

| 参数 | 作用 |
| :--- | :--- |
| `-name "*.txt"` | 按**文件名**匹配（区分大小写） |
| `-iname "*.txt"` | 按文件名匹配（**忽略大小写**） |
| `-type f` | 只找**文件** |
| `-type d` | 只找**目录** |
| `-size +100M` | 找大于 100MB 的文件 |
| `-mtime -7` | 7天内**修改过**的文件 |
| `-mtime +30` | 30天前修改过的文件 |

#### 9.4 find 的常用处理动作

| 参数 | 作用 |
| :--- | :--- |
| `-exec 命令 {} \;` | 对搜索结果执行命令（`{}` 代表占位符） |
| `-delete` | 删除找到的文件 |

#### 9.5 find 的典型示例

```bash
find . -name "*.log" -type f -mtime +30 -delete  # 删掉30天前的log文件
find /var -type f -size +1G                       # 找大于1GB的大文件
find . -name "*.conf" -exec cp {} /backup/ \;    # 找到所有conf复制到备份目录
```

### 11. chown

#### 11.1 **chown 的作用**

* 修改文件或目录的**所有者**和**所属组**（⭐ 配合 `chmod`）

#### 11.2 chown 的语法与示例

```bash
chown user:group file.txt   # 同时修改所有者和组
chown user file.txt         # 只修改所有者

```

## 二、文档编辑

### 1. vi/vim

#### 1.1 **vi/vim的作用**

* **程序编辑**的能力，可以主动的以字体颜色辨别语法的正确性，方便程序设计

#### 1.2 **vi/vim的使用**

##### (1) **vi/vim的命令模式**

用户刚刚启动 vi/vim，便进入了命令模式。此状态下敲击键盘动作会被 Vim 识别为命令，而非输入字符

| 类别 | 命令 | 功能描述 |
| :--- | :--- | :--- |
| **光标移动** | `h` / `j` / `k` / `l` | **左/下/上/右移动一个字符** |
| | `Ctrl + f` | 向下翻一页 |
| | `Ctrl + b` | 向上翻一页 |
| | `0` 或 `Home` | 移动到行首 |
| | `$` 或 `End` | 移动到行尾 |
| | `gg` | **移动到文件第一行** |
| | `G` | **移动到文件最后一行** |
| | `nG` | **移动到第 n 行** |
| **搜索替换** | `/word` | **向下搜索** `word` |
| | `?word` | **向上搜索** `word` |
| | `n` | 重复上一次搜索（同方向） |
| | `N` | 反向重复上一次搜索 |
| | `:%s/old/new/g` | **全文替换 old 为 new** |
| | `:n1,n2s/old/new/g` | 第 n1 到 n2 行替换 |
| **删除** | `x` | 删除光标处字符（向后） |
| | `X` | 删除光标前字符（向前） |
| | `dd` | 删除（剪切）**当前行** |
| | `ndd` | 删除（剪切）向下 n 行 |
| | `d$` | 删除光标到行尾 |
| | `d0` | 删除光标到行首 |
| **复制粘贴** | `yy` | 复制**当前行** |
| | `nyy` | 复制向下 n 行 |
| | `p` | **粘贴**到光标下方 |
| | `P` | 粘贴到光标上方 |
| **撤销重做** | `u` | **撤销上一次操作** |
| | `Ctrl + r` | **重做** |
| **重复** | `.` | 重复上一个动作 |
| **保存退出** | `:w` | 保存 |
| | `:q` | 退出 |
| | `:wq` | **保存并退出** |
| | `:q!` | 强制退出不保存 |

##### (2) vi/vim的输入模式

在命令模式下按下 `i` 就进入了输入模式，使用 `Esc` 键可以返回到普通模式

### 3. pwd

#### 3.1 **pwd的作用**

* **显示当前用户所在的工作目录的完整路径**

#### 3.2 pwd的语法

`pwd [--help][--version]`

#### 3.3 pwd的参数

| 选项 | 说明 |
| :--- | :--- |
| `-L` | 显示**逻辑路径**（默认行为），解析符号链接 |
| `-P` | 显示**物理路径**，不解析符号链接 |
| `--help` | 显示帮助信息 |
| `--version` | 显示版本信息 |

#### 3.4 pwd的实际应用

* **符号链接目录中时**：

  ```bash
  $ ln -s /var/www/html myweb
  $ cd myweb
  $ pwd   # 直接输入命令
  /home/username/myweb    # 逻辑路径
  $ pwd -P
  /var/www/html          # 物理路径
  ```

* **脚本中使用**:

  ```bash
  #!/bin/bash
  CURRENT_DIR=$(pwd)
  echo "当前目录是: $CURRENT_DIR"
  ```

#### 3.5 pwd的注意事项

* `pwd`和`echo $PWD`有什么区别?
  * `pwd` 是内置命令，而 `$PWD` 是环境变量。大多数情况，它们输出相同，但 `pwd` 命令可以带选项（如 `-P`），而 `$PWD` 总是显示逻辑路径
* 为什么需要 `-P` 选项？
  * 当你在一个符号链接目录中工作时，有时需要知道实际的物理位置而不是符号链接路径，这时 `-P` 选项就很有用
* `pwd` 命令会失败吗？
  * 正常情况下不会，但如果当前目录被删除（在另一个终端会话中）,可能会显示错误

#### 3.6 pwd的实践建议

* **在脚本中使用 `pwd -P`**：确保脚本在任何情况下都能获取到正确的物理路径
* **结合其他命令使用**：常与 `cd`、`ls` 等命令配合使用
* **注意符号链接**：当路径中有符号链接时，明确知道自己需要的是逻辑路径还是物理路径

#### 3.7 pwd的逻辑路径与物理路径区别

| 维度 | 逻辑路径 | 物理路径 |
| :--- | :--- | :--- |
| **定义** | 通过盘符、挂载点、符号链接等逻辑标识的路径 | 硬件存储设备上的真实区块、扇区、磁道等地址 |
| **是否依赖文件系统** | 是，是文件系统层面的抽象 | 是，是存储介质层面的具体位置 |
| **用户是否直接感知** | 是（如 `C:\Users\123\a.txt`） | 否（如磁盘第 1000～2000 号扇区） |
| **是否可变** | 会变（如更换盘符、软链接、挂载点） | 相对稳定（同一文件物理位置一般不随意变动） |
| **映射关系** | 逻辑路径 → 文件系统 → 物理路径 | 直接对应硬件地址 |
| **核心总结** | 方便人机交互，屏蔽硬件细节，支持灵活的组织结构（如分区、移动、软链接） | 用于底层存储管理、数据恢复、性能优化（如考虑磁盘寻道时间、扇区布局） |

## 七、系统管理

### 1. sudo

#### 1.1 **sudo的作用**

* **授权用户以其他用户**（通常是 root 用户）**的身份执行命令**

#### 1.2 sudo的语法

`sudo [选项] 命令`

#### 1.3 sudo的参数

* **-i**: 模拟初始登录，**加载目标用户的环境**
* **-s**: 运行shell
* **-u user**: **以指定用户身份运行**
* **-l**: 列出当前用户可执行的sudo
* **-v**: 验证用户凭据（延长sudo会话）
* **-k**: 撤销sudo凭据缓存

#### 1.4 sudo的配置文件

sudo 的配置存储在 /etc/sudoers 文件中，应该使用 visudo 命令编辑：
`sudo visudo`

* 常见配置示例：

```bash

```

#### 1.5 sudo的常见问题

用户不在 sudoers 文件：

```bash
# 需要 root 用户将目标用户加入 sudo 组：

```

缓存时间调整：
修改 /etc/sudoers 中的 timestamp_timeout（单位：分钟）：
`Defaults timestamp_timeout=30`

#### 1.6 **su vs sudo**

##### (1) su与sudo的区别

| 特性 | `su` | `sudo` |
| :--- | :--- | :--- |
| **需要密码** | **目标用户**密码（如 root 密码） | **当前用户**密码 |
| **会话持续** | 直到手动执行`exit` | 单次命令或短时间缓存（默认5分钟） |
| **配置复杂度** | 简单，无需配置 | 需要配置`/etc/sudoers` |
| **安全性** | 需共享 root 密码，风险高 | 更细粒度的权限控制，遵循最小权限原则 |
| **审计** | 有限，仅记录切换动作 | 更详细的日志（记录每条命令、参数、结果） |
| **切换用户** | **完整切换用户环境**（相当于重新登录） | 仅以目标用户身份执行命令，**不切换环境变量** |
| **执行粒度** | 切换后**所有命令**都具备目标用户权限 | 可**精确控制**能执行哪些命令（如`sudo /bin/ls`） |
| **日志记录** | 仅记录切换动作（如`su: session opened`） | 记录每次执行的命令、参数、工作目录、结果 |
| **免密配置** | 无法免密 | 可在`/etc/sudoers`配置`NOPASSWD` |
| **回退风险** | 容易忘记退出 root 会话，长时间保持高风险 | 默认单条命令有效，缓存超时后自动失效 |

##### (2) su与sudo的核心选择建议

* **日常管理** → **`sudo`**：细粒度、可审计、不需要知道 root 密码，提供了更好的安全性和审计能力
* **临时批量操作** → **`su -`**：连续执行多个系统维护命令时更高效
* **安全敏感环境** → **禁用`su`**，只允许`sudo`并记录所有操作日志

##### (3) su与sudo的常见误区说明

* `su`默认**不加载目标用户的环境变量**（如`PATH`、`$HOME`），推荐使用 **`su -`**（带连字符）才会完整切换环境
* `sudo`默认**保留当前用户的部分环境变量**（如 `$PATH`），除非使用`sudo -i`或`sudo -s`模拟登录环境

### 2. top

#### 2.1 **top的作用**

* 提供了一个**动态的、交互式**的实时视图，**显示系统的整体性能信息以及正在运行的进程的相关信息**

#### 2.2 top的语法

`top [-] [d delay] [q] [c] [S] [s] [i] [n] [b]`

#### 2.3 top的参数

| 参数 | 作用 |
| :--- | :--- |
| `-d <秒数>` | 指定 top 命令的刷新时间间隔，单位为秒 |
| `-n <次数>` | 指定 top 命令运行的次数后自动退出 |
| `-p <进程ID>` | 仅显示指定进程ID的信息 |
| `-u <用户名>` | 仅显示指定用户名的进程信息 |
| `-H` | 在进程信息中显示线程详细信息 |
| `-i` | 不显示闲置（idle）或无用的进程 |
| `-b` | 以批处理（batch）模式运行，直接将结果输出到文件 |
| `-c` | 显示完整的命令行而不截断 |
| `-S` | 累计显示进程的 CPU 使用时间 |

#### 2.4 top的显示信息

##### (1) top的总体系统信息

* **uptime**：系统的运行时间和平均负载
* **tasks**：当前运行的进程和线程数目
* **CPU**：总体 CPU 使用率和各个核心的使用情况
* **内存**（Memory）：总体内存使用情况、可用

##### (2) top的进程信息

* **PID**：进程的标识符
* **USER**：运行进程的用户名
* **PR**（优先级）：进程的优先
* **NI**（Nice值）：进程的优先级调整值
* **VIRT**（虚拟内存）：进程使用的虚拟内存大小
* **RES**（常驻内存）：进程实际使用的物理内存大小
* **SHR**（共享内存）：进程共享的内存大
* **%CPU**：进程占用 CPU 的使用率
* **%MEM**：进程占用内存的使用率
* **TIME+**：进程的累计 CPU 时间

##### (3) top的功能和交互操作

* **按键命令**：在 top 运行时可以使用一些按键命令进行操作，如按下 "k" 可以终止一个进程，按下 "h" 可以显示帮助信息等
* **排序**：可以按照 CPU 使用率、内存使用率、进程 ID 等对进程进行排序
* **刷新频率**：可以设置 top 的刷新频率，以便动态查看系统信息

| `-au` | 显示较详细的资讯 |
| `-aux` | 显示所有包含其他使用者的进程 |

#### 4.4 ps的显示信息

* `au(x)` 输出格式 :`USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND`
  * `USER`: 行程拥有者
  * `PID`: pid
  * `%CPU`: 占用的 CPU 使用率
  * `%MEM`: 占用的记忆体使用率
  * `VSZ`: 占用的虚拟记忆体大小
  * `RSS`: 占用的记忆体大小
  * `TTY`: 终端的次要装置号码 (minor device number of tty)
  * `STAT`: 该行程的状态:
    * `D`: 无法中断的休眠状态 (通常 IO 的进程)
    * `R`: 正在执行中
    * `S`: 静止状态
    * `T`: 暂停执行
    * `Z`: 进程已终止，但父进程尚未通过 wait() 系统调用回收其进程描述符资源
    * `W`: 没有足够的记忆体分页可分配
    * `<`: 高优先序的行程
    * `N`: 低优先序的行程
    * `L`: 有记忆体分页分配并锁在记忆体内 (实时系统或捱A I/O)
  * `START`: 行程开始时间
  * `TIME`: 执行的时间
  * `COMMAND`:所执行的指令

### 5. kill

#### 5.1 **kill的作用**

* **用于终止正在运行的进程**

#### 5.2 kill的语法

`kill [options] <PID>`

* `<PID>` 是要终止进程的进程 ID

#### 5.3 kill的参数

* **-l**：列出所有可用的信号
  * **SIGKILL（信号9）**：**立即结束**进程，不能被捕获或忽略
  * **SIGTERM（信号15）**：**正常结束**进程，可以被捕获或忽略
  * **SIGSTOP（信号19）**：暂停进程，不能被捕获、忽略或结束
  * **SIGCONT（信号18）**：继续执行被暂停的进程
  * **SIGINT（信号2）**：通常是Ctrl+C产生的信号，可以被进程捕获或忽略
* **-\<signal>**：发送特定的信号给目标进程，如 -9 表示发送 KILL 信号，即强制终止进程

#### 5.4 kill的基本用法

##### (1) kill的终止进程

默认情况下，kill命令发送SIGTERM（信号15），这可以请求进程终止。如果进程没有捕获这个信号，它将被终止
`kill PID`

##### (2) kill的发送指定信号

通过 -s 选项可以发送指定的信号
`kill -s SIGNAL PID`

##### (3) kill的杀死进程组

使用 -9 选项可以杀死整个进程组
`kill -9 -PID`

#### 5.5 kill的注意事项

* 在使用 kill 命令时，需要具有相应的权限，否则可能无法终止进程
* 某些进程可能需要发送多次信号才能终止，比如一些守护进
* 强制杀死进程可能会导致数据丢失或其他副作用，因此应谨慎使用

## 十一、其他命令

### 1. apt

#### 1.1 **apt的作用**

* 一个在 Debian 和 Ubuntu 中的 Shell 前端**软件包管理器**
* apt 命令提供了**查找、安装、升级、删除**某一个、一组甚至全部**软件包**的命令
* apt 命令执行**需要超级管理员权限**(root)

#### 1.2 apt的语法

`apt [options] [command] [package ...]`

* **options**：可选，选项包括 -h（帮助），-y（当安装过程提示选择全部为"yes"），-q（不显示安装的过程）等等
* **command**：要进行的操作
* **package**：安装的包名

#### 1.3 apt的常用命令

| 分类 | 命令 | 作用 |
| :--- | :--- | :--- |
| **更新软件源** | `sudo apt update` | 从仓库**获取最新的软件包列表**（不安装/升级,只是更新了一个"购物清单/价格表"） |
| **升级软件包** | `sudo apt upgrade` | **升级所有已安装的软件包**（保留旧依赖关系） |
| | `sudo apt full-upgrade` | 升级软件包，必要时删除冲突包以完成升级 |
| **升级单个包** | `sudo apt install --only-upgrade <package_name>` | 仅升级指定的已安装软件包 |
| **安装软件包** | `sudo apt install <package_name>` | **安装单个软件包** |
| | `sudo apt install <pkg1> <pkg2> <pkg3>` | 同时安装多个软件包 |
| **删除软件包** | `sudo apt remove <package_name>` | **删除软件包**（保留配置文件） |
| | `sudo apt purge <package_name>` | **删除软件包并清除配置文件** |
| | `sudo apt autoremove` | **自动清理**不再需要的依赖和库文件 |
| **查询与显示** | `apt list --upgradable` | 列出所有可更新的软件包及版本信息 |
| | `apt list --installed` | 列出所有已安装的软件包 |
| | `apt list --all-versions` | 列出所有已安装包的全部可用版本 |
| | `sudo apt show <package_name>` | 显示软件包的详细信息（版本、大小、依赖等） |
| | `sudo apt search <keyword>` | 在仓库中搜索匹配关键字的软件包 |

* `sudo apt update && sudo apt upgrade -y`两个命令**组合**起来，一键升级
* `sudo apt install <package_name> --no-upgrade` 想安装一个软件包，但软件包已经存在，不升级它,可以使用`–no-upgrade`
* `sudo apt install <package_name> --only-upgrade`只想升级，不要安装可以使用`--only-upgrade`

### 2. htop

#### 2.1 **htop的主要特点**

* **彩色显示**：不同颜色区分不同类型的进程和系统状态
* **可视化布局**：直观展示 CPU、内存和交换空间使用情况
* **鼠标支持**：可以直接用鼠标点击操作
* **进程树视图**：可以查看进程的层级关系
* **自定义排序**：可按各种指标对进程排序
* **进程操作**：可直接终止、调整优先级等

#### 2.2 htop的常用快捷键

| 快捷键 | 功能描述 |
| :--- | :--- |
| `F1` 或 `h` | 显示帮助 |
| `F2` 或 `S` | 进入设置菜单 |
| `F3` 或 `/` | 搜索进程 |
| `F4` 或 `\` | 过滤进程 |
| `F5` 或 `t` | 显示进程树 |
| `F6` 或 `<` | 选择排序字段 |
| `F7` 或 `[` | 降低进程优先级 |
| `F8` 或 `]` | 提高进程优先级 |
| `F9` 或 `k` | 终止进程 |

| `H` | 显示/隐藏用户线程 |

| `P` | 按 CPU 使用率排序 |

#### 2.3 htop的高级功能

##### (1) htop的进程树视图

按 F5 或 t 可以切换到进程树视图，显示进程间的父子关系

##### (2) htop的进程过滤

按 F4 或 \ 可以输入过滤条件，只显示符合条件的进程

##### (3) htop的多选操作

用空格键标记多个进程后，可以批量操作（如终止）

##### (4) htop的自定义显示

* 按 F2 进入设置菜单
  * 调整显示的列
  * 更改颜色主题
  * 设置刷新间隔
  * 配置其他显示选项

##### (5) htop的系统监控

* htop 顶部区域提供了丰富的系统监控信息：
  * CPU 使用率（按核心）
  * 内存和交换空间使用情况
  * 系统负载平均值

#### 2.4 htop与 top 命令对比

##### (1) htop与top的性能对比

| 特性 | htop | top |
| :--- | :--- | :--- |
| 界面 | 彩色，直观 | 单色，基本 |
| 鼠标支持 | 是 | 否 |
| 进程树视图 | 支持 | 不支持 |
| 排序方式 | 多种，可动态调整 | 有限 |
| 进程操作 | 更丰富 | 基本 |
| 自定义 | 高度可配置 | 有限 |
| 资源占用 | 稍高 | 较低 |

* htop提供了更丰富的功能和更友好的界面，适合交互式使用；top更轻量，适合脚本中使用
* 绿色通常表示正常运行的进程，红色可能表示高资源占用或僵尸进程
* 按 F2 进入设置，在 "Display options" 中调整 "Show program path" 选项查看完整的命令行

##### (2) htop优于 top 的独有特点

* **可视化CPU/内存条形图**：在顶部直观显示每个CPU核心的使用率和内存占用百分比
* **鼠标点击支持**：可直接用鼠标点击选择进程或操作菜单项
* **无需输入PID即可发送信号**：选中进程后直接按 F9 发送终止信号（如SIGKILL）
* **支持水平和垂直滚动**：可左右滚动查看被终端截断的完整命令行，上下滚动浏览进程列表
