# 一、终极自救指南（内置帮助）

## 1.1 man 与 --help

### 1.1.1 man 与 --help的作用

* 提供命令的**内置帮助手册**，解决参数记不清或用法不明的问题
* 本地帮助**无需联网**；精简系统可能需要另行安装 `man` 和相应手册包。Shell 内置命令还可使用 `help 命令`（如 `help cd`）

### 1.1.2 **两种使用方式**

| 方式 | 语法 | 特点 |
| :--- | :--- | :--- |
| **快速查看** | `command --help` | 输出常用参数速览（提纲式），适合快速回忆 |
| **完整手册** | `man command` | 输出详细手册（含选项、作者、BUG 说明等），内容最全 |

### 1.1.3 典型示例

```bash
tar --help                # 快速看 tar 的压缩/解压参数
man find                  # 打开 find 的完整说明书（按 q 退出）
```

### 1.1.4 man 页面内的操作

进入 `man` 页面后（屏幕变黑），可使用以下快捷键：

| 按键 | 作用 |
| :--- | :--- |
| `q` | **退出** man 手册（回到命令行）⭐ |
| `/关键词` | 向下搜索关键词（如 `/mtime`） |
| `n` | 跳转到下一个匹配项 |
| `空格键` 或 `PageDown` | 向下翻页 |
| `PageUp` | 向上翻页 |

> [!TIP]
> **核心心法**：遇到不会的命令，先敲 `command --help`；看不懂再敲 `man command`，按 `q` 退出来。这能覆盖日常 90% 的查命令需求，比翻笔记更快

# 二、文件管理

## 2.1 rm

### 2.1.1 **rm的作用**

* **删除**一个文件或者目录

> [!WARNING]
>
> `rm` 不会将文件放入回收站。在 `ext4`、`xfs` 等文件系统上，误删后可能很难恢复。需要回收站功能时，可使用 `trash-cli` 等工具。

### 2.1.2 rm的语法

`rm [options] name...`

### 2.1.3 rm的参数

| 参数 | 作用 |
| :--- | :--- |
| `-i` | 删除前逐一**询问确认** |
| `-f` | **强制删除**，忽略不存在的文件，不提示确认（⚠️ 即使文件只读也直接删） |
| `-r` | 将**目录及以下之档案**逐一删除 |

### 2.1.4 **rm的示例**

* **删除文件与目录**：

```bash
# rm  test.txt 
rm：是否删除文件 "test.txt"? y  
# rm  homework  
rm: 无法删除目录"homework": 是一个目录  
# rm  -r  homework  
rm：是否删除 目录 "homework"? y 
# rm  -r  *     ( * 代表当前目录下所有非隐藏文件与目录)
删除当前目录下文件与目录
```

## 2.2 mv

### 2.2.1 **mv的作用**

* 为文件或目录**改名**、或将文件或目录**移入其它位置**

### 2.2.2 **mv的语法**

| 命令格式 | 运行结果 |
| :--- | :--- |
| `mv source_file` (文件) `dest_file` (文件) | 将源文件名 `source_file` 改为目标文件名 `dest_file` |
| `mv source_file` (文件) `dest_directory` (目录) | 将文件 `source_file` 移动到目标目录 `dest_directory` 中 |
| `mv source_directory` (目录) `dest_directory` (目录) | 若目录名 `dest_directory` **已存在**，将 `source_directory` **移动**到目录 `dest_directory` 中；若目录名 `dest_directory` **不存在**，则将 `source_directory` **改名**为 `dest_directory` |
| `mv source_directory` (目录) `dest_file` (文件) | **出错** |

> [!WARNING]
> **注意**：`mv source_directory dest_directory` 会连同目录内的隐藏文件一起移动，无需先执行 `ls -a`。但 Bash 默认的通配符 `*` 不匹配点号开头的隐藏项，因此 `mv source_directory/* dest_directory/` 通常会遗漏它们；显示隐藏文件不会改变通配符的匹配规则。

### 2.2.3 mv的参数

| 参数 | 作用 |
| :--- | :--- |
| `-b` | 当目标文件或目录存在时，在执行覆盖前，会为其创建一个备份 |
| `-i` | 如果指定移动的源目录或文件与目标的目录或文件同名，则会先**询问**是否覆盖旧文件，输入 `y` 表示直接覆盖，输入 `n` 表示取消该操作 |
| `-f` | 如果指定移动的源目录或文件与目标的目录或文件同名，不会询问，**直接覆盖**旧文件 |
| `-n` | 不要覆盖任何已存在的文件或目录 |
| `-u` | 当源文件比目标文件新或者目标文件不存在时，才执行移动操作 |

## 2.3 cp

### 2.3.1 **cp的作用**

* 用于**复制**文件或目录

### 2.3.2 cp的语法

`cp [options] source dest      //文件或目录路径`

### 2.3.3 cp的参数

| 参数 | 作用 |
| :--- | :--- |
| `-r` 或 `-R` | **递归复制**目录及其内容（用于复制目录） |
| `-i` | **交互模式**，覆盖前提示用户确认 |
| `-f` | 目标文件无法打开写入时，尝试删除目标再复制；不表示绕过文件系统权限，也不一定取消 `-i` 的询问 |
| `-v` | 显示**详细**的复制过程（verbose） |
| `-p` | 保留文件的原始属性（如权限、时间戳等） |
| `-a` | 归档模式，等同于 `-dpR`，保留所有文件属性和递归复制目录 |
| `-u` | 仅当源文件比目标文件新时才复制（更新模式） |
| `-l` | 创建硬链接而不是复制文件 |
| `-s` | 创建符号链接（软链接）而不是复制文件 |

## 2.4 cat

### 2.4.1 **cat的作用**

* **连接文件并打印**到标准输出设备上，==**查看和连接**== 文件

### 2.4.2 cat的语法

`cat [选项] [文件]`

### 2.4.3 cat的参数

| 参数 | 作用 |
| :--- | :--- |
| `-n` | 显示行号，会在输出的**每一行前加上行号** |
| `-b` | 显示行号，但只**对非空行进行编号** |
| `-s` | **压缩连续的空行**，只显示一个空行 |
| `-E` | 在每一行的末尾显示 `$` 符号 |
| `-T` | 将 Tab 字符显示为 `^I` |
| `-v` | 显示一些非打印字符 |

### 2.4.4 **cat的使用**

* **显示文件内容**：`cat filename` 将指定文件的内容输出到终端上(可多个)
* **连接文件**：`cat file1 file2 > combined_file` 将 `file1` 和 `file2` 的内容连接，并将结果输出到 `combined_file` 中
* **创建文件**：`cat > filename`，输入文本，按 `Ctrl+D` 保存并退出
* **覆盖写入**: `cat > filename` ，清空原内容，写入新内容（**文件不存在则新建**）
* **追加重定向**：`cat >> filename`，将标准输入追加到文件 `filename` 的末尾
* **在终端显示文件**：将 `cat` 与管道（ `|` ）结合使用，显示其他命令的输出，例如 `ls -l | cat` 会将 `ls -l` 的输出通过 `cat` 打印到终端上
* **清空 `/etc/test.txt` 文档内容**：`cat /dev/null > /etc/test.txt`

### 2.4.5 echo的写入

* **覆盖**写入（**新建/替换**）

  ```bash
  echo -e "2026-04-29\n今天学了Linux基础命令，很有成就感！" > diary/day1.txt
  ```

* **追加**写入（**补充**内容）

  ```bash
  echo -e "2026-04-30\n今天搞懂了>和>>" >> diary/day1.txt
  ```

## 2.5 chmod

### 2.5.1 **chmod的作用**

* **控制**用户对文件或目录的**权限**
  * 文件所有者、所属组和其他用户对文件的访问权限
  * 只有文件所有者和超级用户可以修改文件或目录的权限

### 2.5.2 chmod的权限说明

#### 2.5.2.1 chmod的权限身份分类

| 身份 | 代号 | 说明 |
| :--- | :--- | :--- |
| **文件所有者** | u (user) | 文件当前记录的所有者 |
| **所属组** | g (group) | 文件自身记录的所属组，不一定是所有者的主组 |
| **其他用户** | o (others) | 除了 u 和 g 以外的所有用户 |
| **所有用户** | a (all) | 等同于 u + g + o |

#### 2.5.2.2 chmod的权限位与数字对应

每个权限位对应一个数字（八进制）：**r=4, w=2, x=1，无权限为 0** ，将一组的三位相加得到一个 0-7 的数字

| 二进制 | 八进制 | 权限 | 说明 |
| :--- | :--- | :--- | :--- |
| 111 | 7 | rwx | 读 + 写 + 执行 |
| 110 | 6 | rw- | 读 + 写 |
| 101 | 5 | r-x | 读 + 执行 |
| 100 | 4 | r-- | 只读 |
| 011 | 3 | -wx | 写 + 执行 |
| 010 | 2 | -w- | 只写 |
| 001 | 1 | --x | 只执行 |
| 000 | 0 | --- | 无权限 |

### 2.5.3 chmod的语法

`chmod [选项] 权限模式 文件...`
`chmod [选项] --reference=参考文件 文件...`

| 选项 | 说明 |
| :--- | :--- |
| `-c` | 仅在该文件权限**确实被更改**时，才显示其更改动作 |
| `-f` | 若该文件权限无法被更改，**不要显示错误讯息**（静默模式） |
| `-v` | 显示权限变更的**详细资料**（无论是否更改都显示） |
| `-R` | 递归修改指定目录及其内容的权限 |
| `--help` | 显示辅助说明 |
| `--version` | 显示版本信息 |

### 2.5.4 **chmod的权限模式**

#### 2.5.4.1 **chmod的符号模式**

`[ugoa...][[+-=][rwxX]...][,...]`

* `+` 表示**增加**权限、`-` 表示**取消**权限、`=` 表示**唯一设定**权限
* `r` 表示可**读取**，`w` 表示可**写入**，`x` 表示可**执行**，`X` 表示只有当该文件是个子目录或者该文件已经被设定过为可执行
  * **`x` 的含义**:
    * **文件**：能否运行
    * **目录**：能否进入 (`cd`)

#### 2.5.4.2 chmod的八进制语法

**组合方式**:

* 所有者权限(第一位)
* 组权限(第二位)
* 其他用户权限(第三位)

#### 2.5.4.3 **chmod的示例**

* **符号模式实例**

| 命令 | 说明 |
| :--- | :--- |
| `chmod a+rw file` | 给 **所有用户** 增加 **读写** 权限 |
| `chmod +rwx file` | 省略身份时受当前 `umask` 限制；若要明确给所有用户增加权限，使用 `chmod a+rwx file` |
| `chmod u=rw,go= file` | 所有者设为 **读写**，**清空** 组和其他用户的**所有权限** |
| `chmod -R u+r,go-r docs` | **递归**：对 `docs` 目录：所有者 **增加读**，组和其他用户 **删除读** |

* **数字模式实例**

| 命令 | 权限分解 | 说明 |
| :--- | :--- | :--- |
| `chmod 664 file` | `u=rw-` (6), `g=rw-` (6), `o=r--` (4) | 所有者/组：读写；其他：只读 |
| `chmod 0755 file` | `u=rwx` (7), `g=r-x` (5), `o=r-x` (5) | 所有者：读写执行；组/其他：读执行（前导 `0` 表示无特殊权限） |
| `chmod 4755 file` | `4` (SetUID) + `755` | 对支持 SetUID 的可执行程序，执行时通常将有效 UID 设为文件所有者；Linux 忽略脚本的 SetUID，`nosuid` 等条件也可能使其不生效 |

* **高级组合（配合 `find`）**

| 命令 | 说明 |
| :--- | :--- |
| `find path/ -type d -exec chmod a-x {} \;` | 递归删除 **所有目录** 的执行权限（不影响文件） |
| `find path/ -type d -exec chmod a+x {} \;` | 给目录增加搜索权限，可进入目录或按名称查找目录项。列出目录项还需读权限 |
| `find path/ -type f -exec chmod 644 {} \;` | 递归将所有 **文件** 权限设为 `644` |

#### 2.5.4.4 **chmod的删除与写入的区别**（父目录权限优先）

* **删/增文件**：在传统权限检查下，需要**父目录**的 `w`（修改目录清单）和 `x`（搜索目录项）权限，且路径上的各级目录需可搜索
* **重命名/移动文件**：需要源、目标父目录相应的 `w+x` 权限；同目录改名时是同一个父目录
* **修改文件内容**：取决于**文件本身**的 `w` 权限
* **结论**：文件即使只读（`444`），也可能被有父目录 `w+x` 权限的用户删除；`rm -f` 只取消部分提示，不能绕过权限。粘滞位、只读挂载、immutable 属性等仍可能限制删除；有粘滞位时，文件所有者、目录所有者或具有相应特权的进程仍可删除

> [!TIP]
> **一句话实战**：脚本缺执行权限可用 `chmod u+x run.sh`；文件删不掉，先检查父目录的 `w+x`、路径搜索权限及粘滞位等限制

## 2.6 重定向与管道

### 2.6.1 **重定向的作用**

| 符号 | 作用 | 示例 |
| :--- | :--- | :--- |
| `>` | **覆盖**写入文件 | `echo "hello" > file.txt` |
| `>>` | **追加**写入文件 | `echo "world" >> file.txt` |
| `<` | 从文件**读取**输入 | `sort < names.txt` |
| `2>` | 重定向错误输出 | `ls /nofile 2> error.log` |
| `&>` | 同时重定向标准输出和错误 | `java -jar app.jar &> app.log` |

### 2.6.2 **管道 `|` 的作用**

* 把**左边命令的标准输出**送给右边命令的标准输入，常用于组合过滤和分析；默认不包含标准错误。Bash 中可用 `2>&1 |` 或 `|&` 同时传递标准错误

```bash
# 查找 Java 进程
ps aux | grep java

# 统计 ERROR 日志行数
cat app.log | grep ERROR | wc -l

# 实时查看 SpringBoot 日志中带 "Exception" 的部分
tail -f app.log | grep Exception
```

> `wc -l` 统计换行符。末尾没有换行符的最后一段文本不会计入。[GNU wc 手册](https://www.gnu.org/software/coreutils/manual/html_node/wc-invocation.html)

### 2.6.3 xargs的作用

* `xargs`将标准输入**转换为命令参数**，常用于配合管道

```bash
# 删除找到的文件
find . -type f -name "*.log" -print0 | xargs -0 -r rm -f --

# 复制找到的文件到备份目录
find . -type f -name "*.conf" -print0 | xargs -0 -r -I {} cp -- {} /backup/

# 统计多个文件行数
find . -maxdepth 1 -type f -name "*.txt" -print0 | xargs -0 -r wc -l --
```

`-print0` 与 `xargs -0` 用空字符分隔文件名，可处理空格、引号和换行；GNU `xargs -r` 在没有输入时不执行命令。普通的 `find ... | xargs ...` 会错误拆分特殊文件名。

## 2.9 find

### 2.9.1 **find 的作用**

* 在指定**目录下递归搜索==文件和目录==**，支持按名称、类型、大小、时间等条件筛选

### 2.9.2 find 的语法

`find [搜索路径] [匹配条件] [处理动作]`

### 2.9.3 find 的常用条件参数

| 参数 | 作用 |
| :--- | :--- |
| `-name "*.txt"` | 按**文件名**匹配（**区分大小写**） |
| `-iname "*.txt"` | 按**文件名**匹配（**忽略大小写**） |
| `-type f` | 只找**文件** |
| `-type d` | 只找**目录** |
| `-size +100M` | 找大于 100MB 的文件 |
| `-mtime -7` | 7天内修改过的文件 |
| `-mtime +30` | 30天前修改过的文件 |

> [!NOTE]
> `-mtime`
> **-（减号）**：代表“小于”（距今不满多少天）
> **+（加号）**：代表“大于”（距今超过多少天）
> **没有符号**：代表“正好等于”那个天数区间

### 2.9.4 find 的常用处理动作

| 参数 | 作用 |
| :--- | :--- |
| `-exec 命令 {} \;` | 对搜索结果执行命令 |
| `-delete` | 删除找到的文件 |

**`-exec`中**：

+ `{}` 是占位符，代表找到的每个文件
+ `\;` 表示对每个文件单独执行一次命令
+ `+` 表示在系统参数长度限制内分批传给命令，通常比逐个执行更高效

**区别**:

| 写法 | 含义 | 适用场景 |
|---|---|---|
| `-exec cmd {} \;` | 对每个文件单独执行一次命令 | 命令不支持多文件参数时 |
| `-exec cmd {} +` | 尽量合并文件参数，必要时分批执行 | 命令支持多文件参数时，效率更高 |

### 2.9.5 **find 的典型示例**

```bash
find . -name "*.log" -type f -mtime +30 -delete  # 删掉30天前的log文件
find /var -type f -size +1G                       # 找大于1GB的大文件
find . -name "*.conf" -exec cp {} /backup/ \;    # 找到所有conf复制到备份目录
```

## 2.10 ln

### 2.10.1 **ln 的作用**

* **创建硬链接或软链接**（符号链接），软链接相当于 Windows 的快捷方式

### 2.10.2 ln 的语法与示例

| 命令 | 作用 |
| :--- | :--- |
| `ln -s /usr/bin/python3 /usr/bin/python` | 创建**软链接**（推荐，可跨文件系统） |
| `ln original.txt hard.txt` | 创建硬链接（指向同一 inode） |

**软链接用法**：`ln -s 源文件/目录 链接名`；不加 `-s` 创建的是硬链接。相对的软链接目标按链接所在目录解析；硬链接通常不能跨文件系统，也不能指向目录。

## 2.11 chown

### 2.11.1 **chown 的作用**

* 修改文件或目录的**所有者**和**所属组**（配合 `chmod`）

### 2.11.2 chown 的语法与示例

```bash
chown user:group file.txt   # 同时修改所有者和组
chown user file.txt         # 只修改所有者
chown :group file.txt       # 只修改所属组
chown -R user:group dir/    # 递归修改目录下所有文件
```

## 5.2 cd

### 5.2.1 **cd的作用**

* 改变当前工作目录的命令，**切换到指定的路径**


### 5.2.2 **cd的参数**

| 语法 | 含义 | 说明 |
| :--- | :--- | :--- |
| **`cd`**（省略目录名） | 切换到当前用户的 **home 目录** | 等同于 `cd ~`(刚登录终端时的默认位置) |
| **`cd ~`** | **home 目录**的路径简写 | `cd ~/Downloads` 可进入家目录下的“下载”文件夹 |
| **`cd .`** | **当前目录** | 通常配合相对路径使用（如 `cd ./folder`）；单独执行 `cd .` 则停留在原地（无变化） |
| **`cd ..`** | **上一层目录**（父目录） | `cd ..` 返回上一级；连续多次使用来切换到更高级的目录 |
| **`cd -`** | **上一个访问的目录**（即 $OLDPWD） | `cd -` 可在当前目录和上一次目录间来回切换，执行后终端会显示切过去的路径 |
| **`cd $VAR_NAME`** | 通过**环境变量**的值来指定目标路径 | `cd $HOME`（效果同 `cd ~`）；`cd $MY_WORK`（需提前定义好该变量） |

> [!TIP]
> `cd -` 会切换到上次目录并打印路径；`cd "$OLDPWD"` 通常静默切换。引用变量可避免路径中的空格被拆分；Bash 的 `cd` 没有 `-v` 选项。

### 5.2.3 cd的语法

`cd [dirName]`  
(`dirName`：要切换的目标目录,相对路径或绝对路径)

* 换到**绝对路径**：指定完整的目录路径来切换到目标目录
  * `cd /path/to/directory`
* 换到**相对路径**：指定相对于当前目录的路径来切换到目标目录
  * `cd relative/path/to/directory`
  * 假设当前目录是 `/home/user/project`，且目标目录都存在。`cd ./test` 以当前目录 `.` 为起点，进入 `/home/user/project/test`。`cd ../test` 以父目录 `..` 为起点，进入 `/home/user/test`。切换后可用 `pwd` 确认位置。

## 5.3 pwd

### 5.3.1 **pwd的作用**

* **显示当前用户所在的工作目录的完整路径**

### 5.3.2 pwd的语法

`pwd [-L | -P]`（Bash 内置命令）；GNU 外部命令另支持 `--help`、`--version`。

### 5.3.3 pwd的参数

| 选项 | 说明 |
| :--- | :--- |
| `-L` | 显示**逻辑路径**，保留路径中的符号链接名称（Bash 内置 `pwd` 通常默认使用） |
| `-P` | 显示**物理路径**，解析符号链接，输出不含符号链接路径分量的绝对路径 |
| `--help` | 显示帮助信息 |
| `--version` | 显示版本信息 |

### 5.3.4 pwd的实际应用

* **符号链接目录中时**：

  ```bash
  $ ln -s /var/www/html myweb
  $ cd myweb
  $ pwd   # 直接输入命令
  /home/username/myweb    # 逻辑路径
  $ pwd -P
  /var/www/html          # 物理路径
  ```

* **脚本中使用**:

  ```bash
  #!/bin/bash
  CURRENT_DIR=$(pwd)
  echo "当前目录是: $CURRENT_DIR"
  ```

### 5.3.5 pwd的注意事项

* `pwd`和`echo $PWD`有什么区别?
  * Bash 有内置 `pwd`，系统通常也有外部 `pwd`。`$PWD` 通常记录 Shell 的逻辑工作目录，也可能被手动修改；`pwd -P` 会查询物理目录。Bash 内置命令用 `help pwd` 查看帮助，GNU 外部命令可用 `env pwd --help`；GNU 外部 `pwd` 通常默认使用 `-P`，与 Bash 默认行为不同
* 为什么需要 `-P` 选项？
  * 当你在一个符号链接目录中工作时，有时需要知道实际的物理位置而不是符号链接路径，这时 `-P` 选项就很有用
* `pwd` 命令会失败吗？
  * 正常情况下不会，但如果当前目录被删除（在另一个终端会话中）,可能会显示错误

### 5.3.6 pwd的实践建议

* **需要解析符号链接时使用 `pwd -P`**：仍应检查退出状态，目录被删除或权限不足时可能失败
* **结合其他命令使用**：常与 `cd`、`ls` 等命令配合使用
* **注意符号链接**：当路径中有符号链接时，明确知道自己需要的是逻辑路径还是物理路径

### 5.3.7 pwd的逻辑路径与物理路径区别

| 维度 | 逻辑路径 | 物理路径 |
| :--- | :--- | :--- |
| **定义** | 保留 Shell 进入目录时使用的符号链接名称 | 解析符号链接后的目录绝对路径 |
| **示例** | `/home/alice/myweb`（`myweb` 是软链接） | `/var/www/html`（该软链接的目标） |
| **查看方式** | `pwd -L` | `pwd -P` |
| **用途** | 保留用户操作时的目录视图 | 确认解析符号链接后的目录位置 |

这里的“物理路径”仍然是文件系统路径，**不是磁盘区块、扇区或磁道地址**。

# 八、系统管理

## 8.1 sudo

### 8.1.1 **sudo的作用**

* **授权用户以其他用户**（通常是 root 用户）**的身份执行命令**

### 8.1.2 sudo的语法

`sudo [选项] 命令`

### 8.1.3 sudo的参数

* **-i**: 模拟初始登录，**加载目标用户的环境**
* **-s**: 运行shell
* **-u user**: **以指定用户身份运行**
* **-l**: 列出当前用户可执行的sudo
* **-v**: 验证用户凭据（延长sudo会话）
* **-k**: 撤销sudo凭据缓存

### 8.1.4 sudo的配置文件

sudo 的配置存储在 /etc/sudoers 文件中，应该使用 visudo 命令编辑：
`sudo visudo`

* 常见配置示例：

```bash
# 允许用户免密码执行所有命令
username ALL=(ALL) NOPASSWD: ALL
# 允许用户组执行特定命令
%wheel ALL=(ALL) /bin/systemctl, /usr/bin/apt
```

### 8.1.5 sudo的常见问题

用户不在 sudoers 文件：

```bash
# 需要 root 用户将目标用户加入 sudo 组：
usermod -aG sudo username  # Ubuntu/Debian
usermod -aG wheel username # CentOS/RHEL
```

**缓存时间调整：**

修改 `/etc/sudoers` 中的 `timestamp_timeout`（单位：分钟）：
`Defaults timestamp_timeout=30`

### 8.1.6 **su vs sudo**

#### 8.1.6.1 su与sudo的区别

| 特性 | `su` | `sudo` |
| :--- | :--- | :--- |
| **需要密码** | **目标用户**密码（如 root 密码） | **当前用户**密码 |
| **会话持续** | 启动的 Shell 持续到退出 | 单次命令；`sudo -i`/`sudo -s` 启动的 Shell 同样持续到退出，认证缓存时长由配置决定 |
| **配置复杂度** | 简单，无需配置 | 需要配置`/etc/sudoers` |
| **安全性** | 需共享 root 密码，风险高 | 更细粒度的权限控制，遵循最小权限原则 |
| **审计** | 有限，仅记录切换动作 | 更详细的日志（记录每条命令、参数、结果） |
| **切换用户** | 启动目标用户的 Shell；`su -` 才模拟登录环境 | 命令进程以目标身份运行；环境由 sudoers/PAM 等策略决定，`sudo -i` 模拟登录环境 |
| **执行粒度** | 切换后**所有命令**都具备目标用户权限 | 可**精确控制**能执行哪些命令（如`sudo /bin/ls`） |
| **日志记录** | 仅记录切换动作（如`su: session opened`） | 记录每次执行的命令、参数、工作目录、结果 |
| **免密配置** | root 切换用户通常无需密码，其他认证规则可由 PAM 配置 | 可在`/etc/sudoers`配置`NOPASSWD` |
| **认证缓存** | 通常不提供 sudo 式的凭据缓存 | 缓存过期会影响下一次认证，**不会结束已启动的命令或 root Shell** |

#### 8.1.6.2 su与sudo的核心选择建议

* **日常管理** → **`sudo`**：细粒度、可审计、不需要知道 root 密码，提供了更好的安全性和审计能力
* **临时批量操作** → **`su -`**：连续执行多个系统维护命令时更高效
* **安全敏感环境** → **禁用`su`**，只允许`sudo`并记录所有操作日志

#### 8.1.6.3 su与sudo的常见误区说明

* 普通 `su` 不模拟完整登录，但通常仍会调整 `HOME`、`SHELL` 等变量；`su -` 会更完整地初始化登录环境，具体还受 PAM 和 Shell 配置影响
* `sudo -i` 模拟目标用户登录；`sudo -s` 只启动 Shell，默认不是登录 Shell。`PATH` 可能被 sudoers 的 `secure_path` 覆盖，不能假定保留原值
* `sudo -i` 通常将 `HOME`、`SHELL`、`USER`、`LOGNAME` 初始化为目标用户的值；`SUDO_USER` 等变量记录调用者。认证缓存时长应查本机 `timestamp_timeout`，不要把不同发行版或构建的默认值混用

## 8.2 top

### 8.2.1 **top的作用**

`top` 定期刷新系统资源和进程信息，可持续观察 CPU、内存和进程状态。输入 `top` 启动，按 `q` 退出。

| 命令 | 展示方式 | 进程 `%CPU` 的统计区间 |
| :--- | :--- | :--- |
| [`ps aux`](#84-ps) | 一次性进程快照 | 从进程启动到本次查询 |
| `top` | 定期刷新 | 相邻两次刷新之间 |

**教学示例**。单线程 Java 进程运行了 10 分钟，前 9 分钟几乎不占用 CPU，最后 1 分钟占满一个逻辑 CPU。

- `ps aux` 约为 **10%**，即累计约 1 分钟 CPU 时间除以经过的 10 分钟。 [procps-ng ps(1)](https://man7.org/linux/man-pages/man1/ps.1.html#STANDARD_FORMAT_SPECIFIERS)
- `top` 约为 **100%**，前提是最近一次刷新区间完整落在忙碌的那一分钟内，并且以一个逻辑 CPU 的执行时间为 100%。 [procps-ng top(1)](https://man7.org/linux/man-pages/man1/top.1.html)

### 8.2.2 top的语法

`top [-] [d delay] [q] [c] [S] [s] [i] [n] [b]`

### 8.2.3 top的参数

| 参数 | 作用 |
| :--- | :--- |
| `-d <秒数>` | 指定 top 命令的刷新时间间隔，单位为秒 |
| `-n <次数>` | 指定 top 命令运行的次数后自动退出 |
| `-p <进程ID>` | 仅显示指定进程ID的信息 |
| `-u <用户名>` | 仅显示指定用户名的进程信息 |
| `-H` | 在进程信息中显示线程详细信息 |
| `-i` | 不显示闲置（idle）或无用的进程 |
| `-b` | 以批处理（batch）模式运行，直接将结果输出到文件 |
| `-c` | 显示完整的命令行而不截断 |
| `-S` | 累计显示进程的 CPU 使用时间 |

### 8.2.4 top的总体系统信息

以下为用户提供的 WSL Ubuntu 实操输出节选。

```text
top - 21:23:16 up  1:42,  0 user,  load average: 0.00, 0.00, 0.00
Tasks: 8 total, 1 running, 7 sleeping, 0 stopped, 0 zombie
%Cpu(s): 0.0 us, 0.0 sy, 0.0 ni, 100.0 id, 0.0 wa, 0.0 hi, 0.0 si, 0.0 st
```

| 首行字段 | 含义 |
| :--- | :--- |
| `21:23:16` | 采样时的 Linux 系统时间 |
| `up 1:42` | Linux 已运行 1 小时 42 分钟 |
| `0 user` | 记录到的登录会话为 0。WSL 中的 Shell 可以没有相应的登录记录。 |
| `load average` | 系统平均负载 |

顶部还会显示物理内存和交换空间（Swap）的使用情况。

#### 8.2.4.1 系统平均负载（`load average`）

三个值分别对应 1、5、15 分钟。内核对任务数做指数加权平均，主要统计 `R`（运行或等待 CPU）和 `D`（不可中断等待）。`S`（可中断睡眠）排除在统计范围外。 [Linux proc_loadavg(5)](https://man7.org/linux/man-pages/man5/proc_loadavg.5.html) · [内核负载计算](https://github.com/torvalds/linux/blob/master/kernel/sched/loadavg.c)

短期值高于长期值时，近期负载相对较高。要确认它是否持续上升，可对同一时间尺度连续采样。平均负载反映任务数量，用逻辑 CPU 数作参照。CPU 使用率则通过采样期间的 CPU 时间占比来判断。

示例显示 `0.00`，表示负载低到在当前精度下显示为零，此时仍可能有任务运行。

##### 8.2.4.1.1 同一负载下的 CPU 执行占比

教学示例。假设服务器有 4 个逻辑 CPU，两种任务分布分别维持足够长时间，忽略其他系统活动。CPU 执行占比以全部逻辑 CPU 的总时间为基准。

| 情形 | 任务分布 | 平均负载趋近 | CPU 执行占比 |
| :--- | :--- | ---: | ---: |
| CPU 计算压力 | 4 个正在执行，4 个等待 CPU，共 8 个 `R` | 8.00 | 100%（4/4） |
| I/O 等待压力 | 1 个 `R` 正在执行，7 个 `D` 在等 I/O | 8.00 | 25%（1/4） |

#### 8.2.4.2 任务状态（`Tasks`）

`Tasks` 显示本次刷新的状态计数，线程模式下按线程统计。据同次输出，8 个进程中 `top`（PID `2101`）处于 `R`，其余 7 个处于睡眠状态。 [procps-ng top(1)](https://man7.org/linux/man-pages/man1/top.1.html)

#### 8.2.4.3 CPU 时间分配（`%Cpu(s)`）

`%Cpu(s)` 汇总各逻辑 CPU 在采样区间内的时间分配。进程列表中的 `%CPU` 按进程统计。 [procps-ng top(1)](https://man7.org/linux/man-pages/man1/top.1.html#2._SUMMARY_Display)

| 字段 | 含义 |
| :--- | :--- |
| `us` | nice 值小于或等于 `0` 的任务使用的用户态时间 |
| `sy` | 内核态执行时间，例如处理系统调用 |
| `ni` | nice 值大于 `0` 的任务使用的用户态时间 |
| `id` | 普通空闲时间 |
| `wa` | 记为 I/O 等待的 CPU 空闲时间 |
| `hi` | 处理硬件中断的时间 |
| `si` | 处理软中断的时间 |
| `st` | 虚拟 CPU 等待宿主机调度的时间（`steal time`） |

WSL 示例显示 `100.0 id`，按显示精度看，几乎全部 CPU 时间记为普通空闲。 [Linux 内核 CPU 时间记账](https://github.com/torvalds/linux/blob/master/kernel/sched/cputime.c)

##### 8.2.4.3.1 文件读取时的 CPU 时间

以默认 nice 值运行的 Java 程序读取文件时，涉及三种计时。

1. 内核处理读取请求的 CPU 时间计入 `sy`。 [Linux 系统调用手册](https://man7.org/linux/man-pages/man2/syscall.2.html)
2. 等待磁盘读取期间，CPU 若空闲，内核可能将这段时间计入 `wa`。命中页缓存时，可直接从内存读取。 [Linux CPU 时间统计](https://man7.org/linux/man-pages/man5/proc_stat.5.html)
3. Java 线程处理读到的数据，用户态执行时间计入 `us`。

#### 8.2.4.4 高负载与高 I/O 等待示例

假设服务器有 4 个逻辑 CPU。模拟输出仅列出相关字段。

```text
load average: 8.00, 7.50, 6.00
%Cpu(s): 5.0 us, 5.0 sy, 20.0 id, 70.0 wa
```

1. **负载偏高**。三个值都高于逻辑 CPU 数 `4`，短期值最高。负载同时计入 `R` 和 `D`。

2. **CPU 执行时间占比较低**。这次采样中，`us + sy = 10%`，`wa` 占 `70%`。

3. **优先排查存储 I/O**。持续观察 `wa`，对照同一时段的读写延迟、请求队列和 `D` 状态任务。

> [!WARNING]
>
> `100% - id` 还包含 `wa` 和 `st`。计算 CPU 实际执行时间时需扣除这两项，定位存储问题则需结合存储侧指标。 [Linux CPU 时间统计](https://man7.org/linux/man-pages/man5/proc_stat.5.html)

### 8.2.5 top的进程信息

| 字段 | 含义 |
| :--- | :--- |
| `PID` | 进程 ID |
| `USER` | 运行进程的用户名 |
| `PR` | `top` 显示的调度优先级 |
| `NI` | 影响普通任务调度权重的 nice 值 |
| `VIRT` | 虚拟内存大小 |
| `RES` | 当前驻留在物理内存中的大小 |
| `SHR` | `RES` 中可能与其他进程共享的部分 |
| `%CPU` | 最近一次刷新间隔内的进程 CPU 使用率 |
| `%MEM` | `RES` 占系统物理内存的比例 |
| `TIME+` | 累计 CPU 时间 |

#### 8.2.5.1 `PR` 与 `NI`

用户提供的同次 WSL 实操中，Codex 进程的相关字段如下。

```text
PID  PR  NI  COMMAND
991  20   0  codex
```

默认 `NI` 为 `0`，普通任务（如 `SCHED_OTHER`）的 `PR` 通常可按 `20 + NI` 读取。实时任务采用不同的优先级表示，`top` 可能显示 `rt`。顶部的小写 `ni` 表示 CPU 时间占比。 [Linux 进程统计手册](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html) · [procps-ng top(1)](https://man7.org/linux/man-pages/man1/top.1.html)

`NI` 的范围是 `-20` 到 `19`。同组的普通任务竞争同一个逻辑 CPU 时，`NI` 较小的任务通常获得较大的 CPU 时间份额。实际调度还受任务运行状态和分组影响。 [Linux 调度手册](https://man7.org/linux/man-pages/man7/sched.7.html)

> [!NOTE]
>
> 独占一个逻辑 CPU 时，即使 `NI = 10`，计算线程也可用掉接近全部执行时间。

#### 8.2.5.2 调度权重示例

假设 Java 和 Python 都采用普通调度策略，在同一调度组内竞争同一个逻辑 CPU。以下为模拟输出。

```text
PID     PR  NI  S  %CPU  COMMAND
1001    20   0  R  45.0  java
1002    30  10  R  10.0  python
```

- Java 的 `NI` 较小，通常具有更高的权重。希望 Python 在竞争时获得更多 CPU 时间，可在权限允许时**调小 `NI`**。 [Linux 调度手册](https://man7.org/linux/man-pages/man7/sched.7.html)
- `45.0%` 和 `10.0%` 只描述本次刷新间隔的 CPU 用量。 [procps-ng top(1)](https://man7.org/linux/man-pages/man1/top.1.html)

### 8.2.6 top的功能和交互操作

* **按键命令**：在 top 运行时可以使用一些按键命令进行操作，如按下 "k" 可以终止一个进程，按下 "h" 可以显示帮助信息等
* **排序**：可以按照 CPU 使用率、内存使用率、进程 ID 等对进程进行排序
* **刷新频率**：可以设置 top 的刷新频率，以便动态查看系统信息

## 8.4 ps

### 8.4.1 **ps的作用**

* **查看进程在查询时的状态快照**。要持续观察变化，可用 [`top`](#82-top)。
* **信息来源**。Linux 上的 procps-ng `ps` 从 `/proc` 虚拟文件系统读取内核提供的进程信息，例如 `/proc/<PID>/stat`。 [Linux 内核 `/proc` 文档](https://docs.kernel.org/filesystems/proc.html#process-specific-subdirectories)

#### 8.4.1.1 程序、进程与线程

| 概念 | 含义 | Spring Boot 示例 |
| :--- | :--- | :--- |
| 程序 | 保存在文件中的代码和资源 | 磁盘上的 `app.jar` |
| 进程 | 程序的运行实例，拥有自己的地址空间和 PID | 执行 `java -jar app.jar` 启动的 Java 进程 |
| 线程 | 进程内由内核独立调度的执行单位，共享进程的地址空间，各自有栈 | 主线程、请求处理线程等。 [Linux 线程手册](https://man7.org/linux/man-pages/man7/pthreads.7.html) |

同一个程序可启动多个进程。进程退出并被回收后，PID 可能分配给其他进程。

Docker 中，同一个镜像也可以创建多个容器。一个容器可以同时运行多个进程。 [Docker 笔记 §3.1](../../云原生/Docker/Docker.md#31-容器与宿主机的关系)

##### 8.4.1.1.1 线程共享与进程隔离

- **同一 JVM 内**，线程共享堆。一个线程取得对象引用后，就可以访问同一个对象。并发读写共享状态时，需要考虑同步与可见性。 [JVM 规范 §2.5.3](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-2.html#jvms-2.5.3) · [Java 语言规范 §17.4](https://docs.oracle.com/javase/specs/jls/se21/html/jls-17.html#jls-17.4)

- **不同 Java 进程间**，各进程有自己的虚拟地址空间，分别启动的 JVM 各有自己的堆。普通 Java 对象引用只在所属 JVM 内有效。

- **进程间通信**可以用网络套接字收发数据，也可以把同一块共享内存映射到各自的地址空间来交换数据。 [Linux 套接字手册](https://man7.org/linux/man-pages/man7/socket.7.html) · [POSIX 共享内存手册](https://man7.org/linux/man-pages/man7/shm_overview.7.html)

#### 8.4.1.2 同一个 JAR 启动两个实例

假设在两个终端中分别执行以下命令，两个实例均成功启动。

```bash
java -jar app.jar --server.port=8080
java -jar app.jar --server.port=8081
```

两条命令读取同一个 `app.jar`，分别启动一个 Java 进程，共 50 个线程。

| 实例 | PID（示例） | 监听端口 | 线程数（假设） |
| :--- | ---: | ---: | ---: |
| Java 进程 A | 2500 | 8080 | 20 |
| Java 进程 B | 2600 | 8081 | 30 |

两个实例各自运行。进程 A 退出时结束自己的线程，进程 B 可以继续监听 `8081`。 [Linux 进程退出手册](https://man7.org/linux/man-pages/man2/exit_group.2.html)

### 8.4.2 ps的语法

```bash
ps [options] [--help]
```

### 8.4.3 ps的参数

#### 8.4.3.1 常用选项

| 参数 | 作用 |
| :--- | :--- |
| `-A` | 列出所有的进程 |
| `-p PID` | 按进程 ID 查询指定进程，可核对进程身份和状态，查询本身不会发送信号 |
| `-w` | 显示加宽，可以显示较多的资讯 |
| `aux` | BSD 风格选项：显示所有用户的进程及详细信息，包含无控制终端的进程 |
| `-ef` | 标准风格选项，列出所有进程的完整格式信息 |
| `-T` | 按线程显示，可与 `-p PID` 组合查看指定进程中的线程 |

#### 8.4.3.2 `ps aux` 的三个选项

`ps aux` 将三个 BSD 风格选项连写，直接使用 `aux`。

| 选项 | 作用 |
| :--- | :--- |
| `a` | 取消 BSD 风格下只选当前用户进程的限制，可纳入其他用户有终端的进程。 |
| `u` | 使用面向用户的格式，显示 `USER`、`%CPU`、`%MEM` 等字段。 |
| `x` | 取消 BSD 风格下必须关联终端的限制，可纳入没有控制终端的进程。 |

`a` 和 `x` 一起使用时，选择当前环境中 `ps` 可见的全部进程，包括没有控制终端的后台服务。

`ps -aux` 有解析歧义。procps-ng 可将它解释为 `ps -a -u x`，其中 `x` 是用户名。找不到用户 `x` 时，可能按 `ps aux` 兼容处理。 [procps-ng ps(1)](https://man7.org/linux/man-pages/man1/ps.1.html#NOTES)

按命令行内容筛选的用法见 [3.2.4 grep 的典型示例](#324-grep的典型示例)。

### 8.4.4 ps的显示信息

#### 8.4.4.1 默认输出

procps-ng 默认选择与调用者有效用户 ID 相同、且关联同一个终端的进程。以下为用户提供的 WSL Ubuntu 实操输出。

```text
PID TTY          TIME CMD
 85 pts/0    00:00:00 bash
1880 pts/0   00:00:00 ps
```

| 字段 | 含义 |
| :--- | :--- |
| `PID` | 进程 ID |
| `TTY` | 进程关联的控制终端 |
| `TIME` | 累计使用的 CPU 时间，显示精度为秒。即使 Bash 已经运行很久，累计 CPU 时间也可能显示为 `00:00:00`。 |
| `CMD` | 可执行程序的名称 |

WSL 输出中的 `pts/0` 对应伪终端 `/dev/pts/0`，交互式 Bash 和从该终端执行的 `ps` 都可显示这个值。另一轮实操中，`/init` 的 `hvc0` 对应虚拟机控制台。`?` 表示进程没有控制终端，常见于后台服务。 [Linux 控制台参数](https://docs.kernel.org/admin-guide/kernel-parameters.html) · [procps-ng 字段说明](https://man7.org/linux/man-pages/man1/ps.1.html#STANDARD_FORMAT_SPECIFIERS)

`ps` 自身符合默认筛选条件，也会出现在输出里。据第二次查询的结果摘要，Bash 的 PID 仍为 `85`，`ps` 的 PID 变为 `1890`。

每次执行 `ps` 都会启动一个查询进程，完成后即退出。PID 由内核分配，两次 PID 的差值不足以推算期间创建的进程数。

#### 8.4.4.2 `ps aux` 输出

以下为同一 WSL 会话中用户提供的输出节选。

```text
USER     PID %CPU %MEM    VSZ   RSS TTY    STAT START TIME COMMAND
lenovo    85  0.0  0.1  11484 10752 pts/0 Ss   19:45 0:00 -bash
```

| 新增字段 | 含义 |
| :--- | :--- |
| `USER` | 进程的有效用户 |
| `%CPU` | 累计 CPU 时间除以进程启动以来的经过时间，以百分比显示。`0.0` 可以出现在大部分时间等待输入的进程上。 |
| `%MEM` | RSS 占系统物理内存的百分比 |
| `VSZ` | 虚拟地址空间大小，单位为 KiB |
| `RSS` | 当前驻留在物理内存中的大小，单位为 KiB。共享页可计入多个进程的 RSS，直接求和会重复计算。 |
| `STAT` | 进程的主状态及附加标志 |
| `START` | 进程开始的时刻或日期 |
| `TIME` | 累计 CPU 时间，包括用户态和内核态 |
| `COMMAND` | 命令及其参数在进程列表中的显示内容 |

另一轮 WSL 实操的输出中，Bash（PID `11`）的 `START` 为 `12:45`，表示启动时刻。`TIME` 为 `0:00`，表示累计 CPU 时间在秒级精度下显示为零。 [procps-ng 字段说明](https://man7.org/linux/man-pages/man1/ps.1.html#STANDARD_FORMAT_SPECIFIERS)

**启动时刻、累计 CPU 时间与经过时长**。假设服务在 10:00 启动，到 12:00 共用了 10 分钟 CPU。`ps aux` 的 `START` 和 `TIME` 都可能显示 `10:00`，分别表示 10 点启动和累计用了 10 分钟 CPU。用 `-o etime` 可查看经过的时长，本例为 2 小时。 [procps-ng 字段说明](https://man7.org/linux/man-pages/man1/ps.1.html#STANDARD_FORMAT_SPECIFIERS)

多个线程在不同逻辑 CPU 上并行时，进程累计的 CPU 时间可超过启动以来经过的时长。

#### 8.4.4.3 `STAT` 状态与附加标志

首字母表示采样时的主状态，后续字符补充进程属性。

| 主状态 | 含义 |
| :--- | :--- |
| `R` | 正在运行，或已就绪、等待 CPU 调度 |
| `S` | 可中断睡眠，正在等待事件，例如 Shell 等待输入 |
| `D` | 不可中断睡眠，常见于等待 I/O |
| `T` | 已停止，例如收到暂停信号 |
| `Z` | 僵尸状态，进程已退出，退出信息尚未被父进程回收 |
| `W` | 换页状态的历史标记，自 Linux 2.6 起已不再有效 |

- `s` 表示会话首进程，`+` 表示属于前台进程组，`l`（小写 L）表示多线程。
- `<` 表示高优先级，`N` 表示低优先级，`L` 表示有内存页锁定在内存中。

##### 8.4.4.3.1 实操状态解读

| 本次实操中的进程 | `STAT` | 解读 |
| :--- | :--- | :--- |
| Bash（PID `85`） | `Ss` | 可中断睡眠，且是会话首进程。 |
| `ps aux`（PID `2036`，据结果摘要） | `R+` | 正在运行或可运行，且属于前台进程组。 |
| PID `991`（据输出节选） | `Ssl` | 可中断睡眠，且是多线程的会话首进程。该行 `TTY` 为 `?`，表示没有控制终端。 |

#### 8.4.4.4 线程的运行与睡眠

- **`R`** 包括正在 CPU 上执行和已就绪、等待 CPU 调度。Java 线程持续计算时，通常显示为 `R`。
- **`S`** 表示可中断睡眠。线程可以等待输入、网络数据或同步条件，被唤醒后再进入可运行状态。空闲服务的线程长时间等待请求时，处于 `S` 可以是正常现象。
- **`D`** 表示不可中断睡眠，短时出现可对应正常 I/O。若备份任务在多次采样中仍处于 `D`，优先排查存储 I/O，结合读写延迟、请求队列和日志判断等待原因。 [procps-ng 状态码](https://man7.org/linux/man-pages/man1/ps.1.html#PROCESS_STATE_CODES)

`ps aux` 默认每个进程显示一行。`Sl` 中的 `S` 是此行的主状态，`l` 表示进程有多个线程。各线程的状态可通过 [8.4.5 的线程查询](#845-查看指定进程的线程)逐个观察。服务是否响应则要结合实际请求判断。 [Linux 线程信息手册](https://man7.org/linux/man-pages/man5/proc_pid_task.5.html)

#### 8.4.4.5 服务排查

先看进程在查询时的 `STAT`。要核对指定进程的状态和命令行，可用下方命令，将 `PID` 替换为实际编号。 [procps-ng ps(1)](https://man7.org/linux/man-pages/man1/ps.1.html)

```bash
ps -p PID -o pid,stat,args
```

`ps aux` 中的 `%CPU = 95.0` 表示进程启动以来，平均每经过 1 秒消耗约 0.95 秒 CPU 时间。它以单个逻辑 CPU 为基准，多线程并行时可超过 `100%`。进程进入等待后，之前的计算仍会影响这个平均值。 [procps-ng ps(1)](https://man7.org/linux/man-pages/man1/ps.1.html#NOTES)

服务变慢时，用 [`top`](#82-top) 观察近期 CPU 用量，并核对预期地址和端口的监听情况、HTTP 响应、请求量及同一时段的日志。批量计算和忙循环都可能表现为高 CPU 用量。

### 8.4.5 查看指定进程的线程

#### 8.4.5.1 查询线程

`ps -p PID` 按 PID 选择进程，默认显示进程级信息。加上 `-T` 后，输出会按线程展开。 [procps-ng 线程显示选项](https://man7.org/linux/man-pages/man1/ps.1.html#THREAD_DISPLAY)

WSL 实操中，PID `991` 在 `ps aux` 的 `STAT` 列带有 `l` 标志，可用下方命令展开查看。

```bash
ps -T -p 991
```

以下是用户提供的输出节选，只保留三个字段和前几行。

```text
PID    SPID    CMD
991     991    codex
991     993    codex-main
991     994    tokio-rt-worker
991     995    tokio-rt-worker
...
```

**按当前清单选择查询对象**。另一次 WSL 练习中，从 `ps aux` 清单里选了带 `l` 标志的 `/init`（PID `1`，`Sl+`）。据随后提供的 `ps -T -p 1` 输出，本次查询列出了两个线程，`SPID` 分别为 `1` 和 `8`，其中 `1` 是组长线程。这与清单中的多线程标志一致。

#### 8.4.5.2 线程字段

| 字段 | 含义 |
| :--- | :--- |
| `PID` | 所属进程的 ID，在这里对应 Linux 的线程组 ID（TGID） |
| `SPID` | 线程 ID（TID，也称 LWP ID），可以区分同名线程 |
| `CMD` | 线程模式下可显示线程名称，名称可能被截断 |

`SPID` 与 `PID` 相同的一行是组长线程。按用户提供的 Codex 计数摘要，查询 PID `991` 共列出 **40 个线程**，其中包含组长线程 `991`。 [Linux 线程信息手册](https://man7.org/linux/man-pages/man5/proc_pid_task.5.html) · [Linux 线程命名手册](https://man7.org/linux/man-pages/man2/PR_SET_NAME.2const.html)

常见默认列还有 `TTY` 和 `TIME`。可用 `-o` 显式选出 `stat` 字段查看各线程状态。若只显示表头，目标进程可能已退出。再次查询旧 PID 时，应留意 PID 复用。 [procps-ng 线程显示选项](https://man7.org/linux/man-pages/man1/ps.1.html#THREAD_DISPLAY)

#### 8.4.5.3 线程数与 CPU 并行度

可用的逻辑 CPU 数决定同一时刻能执行多少个线程。阻塞等待 I/O 等事件的线程被唤醒后，再参与调度。 [Linux 调度手册](https://man7.org/linux/man-pages/man7/sched.7.html#DESCRIPTION)

例如，一个有 40 个线程的进程可使用 4 个逻辑 CPU。若 2 个线程正在执行、其余都在等待，则当前有 2 个线程在 CPU 上运行。若有 10 个线程同时可运行，则最多 4 个同时执行，其余等待调度。

## 8.5 kill

### 8.5.1 **kill的作用**

* **向进程或进程组发送信号**，可用于请求终止、暂停、继续等操作

### 8.5.2 kill的语法

`kill [options] <PID>`

* `<PID>` 是要终止进程的进程 ID

### 8.5.3 kill的参数

* **-l**：列出所有可用的信号
  * **SIGKILL（信号9）**：强制终止，不能被捕获或忽略；处于不可中断睡眠的任务可能要等内核操作返回后才能退出
  * **SIGTERM（信号15）**：**请求进程退出**，可以被捕获或忽略
  * **SIGSTOP**：暂停进程，不能被捕获或忽略；暂停的进程仍可被 `SIGKILL` 终止
  * **SIGCONT（信号18）**：继续执行被暂停的进程
  * **SIGINT（信号2）**：通常是 `Ctrl+C` 产生的信号，可以被进程捕获或忽略
* **-\<signal>**：发送特定的信号给目标进程，如 `-9` 表示发送 `KILL` 信号，即强制终止进程。部分信号编号随体系结构变化，脚本中优先使用 `STOP`、`CONT` 等名称

### 8.5.4 kill的基本用法

#### 8.5.4.1 kill的终止进程

`kill PID` 默认发送 `SIGTERM`。需要停止进程时，先用 `ps -p PID` 核对进程，再发送 `SIGTERM`，让实现了退出处理的程序有机会清理资源。信号发出后，可再次查询进程状态，确认它是否已退出。

#### 8.5.4.2 kill的发送指定信号

通过 `-s` 选项可以发送指定的信号
`kill -s SIGNAL PID`

#### 8.5.4.3 kill的杀死进程组

负的目标编号表示**进程组 ID（PGID）**，不是任意成员的 PID；`-9` 只指定信号类型。例如先确认 PGID，再用 `kill -TERM -- -1234` 向 PGID 为 1234 的整个组请求终止；确需强制终止时使用 `kill -KILL -- -1234`。

### 8.5.5 kill的注意事项

* 在使用 kill 命令时，需要具有相应的权限，否则可能无法终止进程
* 信号可能被捕获、忽略或延迟处理；守护进程还可能被服务管理器重启。应查明原因，受 systemd 管理的服务优先使用 `systemctl stop 服务名`

> [!WARNING]
>
> `SIGKILL` 会跳过进程的退出清理，可能造成数据丢失。发送前应核对目标进程，并先尝试 `SIGTERM`。

## 8.7 service

### 8.7.1 **service 的作用**

* **管理系统服务**（启动、停止、重启、查看状态），适用于 SysV init 脚本（`/etc/init.d/`）
* 在 systemd 系统中（如 CentOS 7+/Ubuntu 16+），`service` 命令通常被**自动重定向**到 `systemctl`，作为一个向下兼容的便捷入口

### 8.7.2 service 的语法

`service [服务名] [动作]`

| 动作 | 说明 |
| :--- | :--- |
| `start` | **启动**服务 |
| `stop` | **停止**服务 |
| `restart` | **重启**服务（先停再启） |
| `reload` | **重载**配置文件（不中断服务，部分服务支持） |
| `status` | **查看**服务当前运行状态 |
| `--status-all` | **列出所有**服务及其状态（常配合 `grep` 筛选） |

### 8.7.3 service 的典型示例

```bash
# 重启 MySQL 服务

systemctl list-units --type=service --state=running
```

> [!TIP]
> **一句建议**：脚本里图省事可以用 `service`（少打几个字母），但**生产环境推荐用 `systemctl`**，因为功能更全（如 `enable`/`disable` 开机自启），且是未来的主流方向。

# 十二、其他命令

## 12.1 apt

### 12.1.1 **apt的作用**

* 一个在 Debian 和 Ubuntu 中的 Shell 前端**软件包管理器**
* apt 命令提供了 **查找、安装、升级、删除** 某一个、一组甚至全部**软件包**的命令
* 安装、删除及更新系统软件包索引等操作通常需要 root；`apt search`、`apt show`、`apt list` 等查询通常不需要提权

### 12.1.2 apt的语法

`apt [options] [command] [package ...]`

* **options**：可选，选项包括 `-h`（帮助），`-y`（当安装过程提示选择全部为"yes"），`-q`（不显示安装的过程）等等
* **command**：要进行的操作
* **package**：安装的包名

### 12.1.3 apt的常用命令

| 分类 | 命令 | 作用 |
| :--- | :--- | :--- |
| **更新软件源** | `sudo apt update` | 从仓库**获取最新的软件包列表**（不安装/升级,只是更新了一个"购物清单/价格表"） |
| **升级软件包** | `sudo apt upgrade` | 安装可用升级，必要时可新增依赖包，但不删除已安装包；需要删除包的升级会被暂缓 |
| | `sudo apt full-upgrade` | 升级软件包，必要时删除冲突包以完成升级 |
| **升级单个包** | `sudo apt install --only-upgrade <package_name>` | 仅升级指定的已安装软件包 |
| **安装软件包** | `sudo apt install <package_name>` | **安装单个软件包** |
| | `sudo apt install <pkg1> <pkg2> <pkg3>` | 同时安装多个软件包 |
| **删除软件包** | `sudo apt remove <package_name>` | **删除软件包**（**保留配置文件**） |
| | `sudo apt purge <package_name>` | **删除软件包并清除配置文件** |
| | `sudo apt autoremove` | **自动清理**不再需要的依赖和库文件 |
| **查询与显示** | `apt list --upgradable` | 列出所有可更新的软件包及版本信息 |
| | `apt list --installed` | 列出所有已安装的软件包 |
| | `apt list --all-versions` | 列出软件包的全部可用版本，并非仅限已安装包 |
| | `apt show <package_name>` | 显示软件包的详细信息（版本、大小、依赖等） |
| | `apt search <keyword>` | 在仓库中搜索匹配关键字的软件包 |

* `sudo apt update && sudo apt upgrade -y`两个命令**组合**起来，一键升级
* `sudo apt install <package_name> --no-upgrade` 想安装一个软件包，但软件包已经存在，不升级它,可以使用`–no-upgrade`
* `sudo apt install <package_name> --only-upgrade`只想升级，不要安装可以使用`--only-upgrade`

### 12.2.3 htop的高级功能

#### 12.2.3.1 htop的进程树视图

按 F5 或 t 可以切换到进程树视图，显示进程间的父子关系

#### 12.2.3.2 htop的进程过滤

按 F4 或 \ 可以输入过滤条件，只显示符合条件的进程

#### 12.2.3.3 htop的多选操作

用空格键标记多个进程后，可以批量操作（如终止）

#### 12.2.3.4 htop的自定义显示

按 F2 进入设置菜单：

* 调整显示的列
* 更改颜色主题
* 设置刷新间隔
* 配置其他显示选项

#### 12.2.3.5 htop的系统监控

htop 顶部区域提供了丰富的系统监控信息：

* CPU 使用率（按核心）
* 内存和交换空间使用情况
* 系统负载平均值

### 12.2.4 htop与 top 命令对比

#### 12.2.4.1 htop与top的性能对比

| 特性 | htop | top |
| :--- | :--- | :--- |
| **界面** | 彩色，直观 | 也支持颜色及可配置的图形显示 |
| **鼠标支持** | 是 | 否 |
| **进程树视图** | 支持 | 也支持 forest 视图（交互按键 `V`） |
| **排序方式** | 可按多个字段动态选择 | 也可选择排序字段 |
| **进程操作** | 更丰富 | 基本 |
| **自定义** | 高度可配置 | 有限 |
| **资源占用** | 稍高 | 较低 |

* htop提供了更丰富的功能和更友好的界面，适合**交互式使用**；top更轻量，适合**脚本中使用**
* 颜色含义随字段、仪表和配色方案变化，例如 CPU 条中的颜色可能区分用户态与内核态；不能用绿色/红色直接判定进程正常或异常
* 按 F2 进入设置，在 "Display options" 中调整 "Show program path" 选项查看完整的命令行

#### 12.2.4.2 htop 的交互优势（不都属于独有功能）

* **可视化CPU/内存条形图**：在顶部直观显示每个CPU核心的使用率和内存占用百分比
* **鼠标点击支持**：可直接用鼠标点击选择进程或操作菜单项
* **批量操作**：可用空格标记多个进程，再统一发送信号或调整 nice 值
* **无需输入PID即可发送信号**：选中进程后按 F9 打开菜单，选择信号并确认发送
* **支持水平和垂直滚动**：可左右滚动查看被终端截断的完整命令行，上下滚动浏览进程列表

## 12.3 curl

### 12.3.1 **curl的作用**

* 强大的命令行工具，用于在 Linux/Unix 系统中**传输数据**

### 12.3.2 curl的主要特点

* **多协议支持**：支持几乎所有主流网络协议
* **无界面操作**：纯命令行工具，适合脚本和自动化任务
* **功能丰富**：支持文件上传下载、表单提交、Cookie 处理等
* **跨平台**：在 Linux、macOS、Windows 上均可使用

### 12.3.3 curl的语法

`curl [options] [URL...]`

* **options**：各种可选参数，用于控制 curl 的行为
* **URL**：要访问的一个或多个网址

### 12.3.4 **curl的常用参数**

#### 12.3.4.1 curl的基本请求控制

| 选项 | 说明 | 示例 |
| :--- | :--- | :--- |
| `-X` | **指定 HTTP 方法** | `curl -X POST https://example.com` |
| `-d` | **发送 POST 数据** | `curl -d "name=John" https://example.com` |
| `-G` | 将 `-d` 数据作为 GET 参数发送 | `curl -G -d "q=keyword" https://search.com` |
| `-H` | 添加请求头 | `curl -H "Content-Type: application/json" https://api.com` |

#### 12.3.4.2 curl的输出控制

| 选项 | 说明 | 示例 |
| :--- | :--- | :--- |
| `-o` | **将输出保存到文件** | `curl -o output.html https://example.com` |
| `-O` | 使用远程文件名保存 | `curl -O https://example.com/file.zip` |
| `-s` | 静默模式（不显示进度） | `curl -s https://api.com/data.json` |
| `-v` | 显示详细通信过程 | `curl -v https://example.com` |

#### 12.3.4.3 curl的认证与安全

| 选项 | 说明 | 示例 |
| :--- | :--- | :--- |
| `-u` | 用户名密码认证 | `curl -u user:pass https://secure.com` |
| `-k` | 忽略 SSL 证书验证 | `curl -k https://self-signed.com` |
| `--cacert` | 指定 CA 证书 | `curl --cacert cert.pem https://secure.com` |

#### 12.3.4.4 curl的其他实用选项

| 选项 | 说明 | 示例 |
| :--- | :--- | :--- |
| `-L` | 跟随重定向 | `curl -L https://short.url` |
| `-I` | 只获取头部信息 | `curl -I https://example.com` |
| `--limit-rate` | 限制传输速度 | `curl --limit-rate 100K https://largefile.com` |

## 12.4 echo

### 12.4.1 **echo的作用**

* 在终端**显示文本**信息,直接输出字符串:`echo "Hello, World!"`
* **输出变量**,显示变量的值:

  ```bash
  name="Linux User"
  echo "Welcome, $name!"
  # 输出结果
  Welcome, Linux User!
  ```

* 不带引号的输出，引号不是必须的，但建议使用以避免特殊字符问题
* 输出到**文件** [写入](#245-echo的写入)
* **命令替换**:输出其他命令的执行结果
* **生成**格式化的**字符串**

### 12.4.2 echo的语法

`echo [选项] [字符串]`

### 12.4.3 echo的参数

#### 12.4.3.1 echo的常用选项

| 选项 | 说明 |
| :--- | :--- |
| `-n` | 不输出换行符 |
| `-e` | 启用转义字符解释 |
| `-E` | 禁用转义字符解释（默认） |

> 默认情况下，echo 会在输出后添加换行符

#### 12.4.3.2 echo的转义字符（需配合 `-e` 使用）

| 转义序列 | 含义 |
| :--- | :--- |
| `\n` | 换行 |
| `\t` | 制表符 |
| `\r` | 回车 |
| `\b` | 退格 |
| `\\` | 反斜杠 |
| `\"` | 双引号 |
| `\a` | 响铃 |

## 12.5 tail

### 12.5.1 **tail的作用**

* 用于**查看文件的内容**

### 12.5.2 tail的语法

`tail [参数] [文件]`

### 12.5.3 tail的参数

| 选项 | 说明 |
| :--- | :--- |
| `-f` | **循环读取**，实时追踪文件新增内容 |
| `-q` | 不显示处理信息（安静模式） |
| `-v` | 显示详细的处理信息 |

| `-q, --quiet, --silent` | 从不输出给出文件名的首部 |
