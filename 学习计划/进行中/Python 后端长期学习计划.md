# Python 后端长期学习计划

> **学习目标：** 掌握 Python 后端开发能力，为 AI 应用开发、LLM API 集成、Agent 工程和云原生应用打好基础。
>
> **学习原则：** 基础先行、项目驱动、边学边做、重视调试。不追求短期速成，不重复深挖已有的 Java 后端知识。
>
> **学习方式：** 讲解 → 示例 → 小任务 → 自己操作 → 检查 → 纠错 → 下一步。
>
> **进度规则：** 每个阶段以实际能力验收为准，不以看完教程或记住知识点为准。

---

## 一、整体学习路线

- [ ] 阶段 0：Python 基础查漏补缺
- [ ] 阶段 1：Python 工程基础
- [ ] 阶段 2：HTTP、REST API 与 FastAPI
- [ ] 阶段 3：请求校验、异常处理与接口设计
- [ ] 阶段 4：异步编程与后台任务
- [ ] 阶段 5：数据库与 ORM
- [ ] 阶段 6：测试、日志、配置与工程质量
- [ ] 阶段 7：Redis、缓存、任务队列与服务协作
- [ ] 阶段 8：Docker、Linux 与云原生部署
- [ ] 阶段 9：AI 应用后端专项
- [ ] 阶段 10：综合项目与独立交付

**建议顺序：** 先完成当前 ANIC 项目所需的最小后端能力，再补数据库、测试等通用能力；后续阶段逐步加深，而不是一次性学完所有内容再做项目。

## 二、各阶段详细计划

### 阶段 0：Python 基础查漏补缺

**目标：** 能够独立阅读、编写和调试常见 Python 代码。

- [ ] 基本语法、变量、数据类型与类型转换
- [ ] 条件判断、循环、推导式
- [ ] 字符串、列表、元组、字典、集合
- [ ] 函数、参数、返回值、作用域
- [ ] 模块、包、`import`
- [ ] 异常处理：`try`、`except`、`finally`、`raise`
- [ ] 文件读写、JSON、路径处理
- [ ] 类、对象、继承与组合
- [ ] 常用标准库：`pathlib`、`json`、`logging`、`datetime`
- [ ] 基本类型标注：`str`、`int`、`list`、`dict`、`Optional` 等

**验收标准：**
- [ ] 能独立编写小型 Python 程序
- [ ] 能读懂项目中的函数、类、模块和异常处理
- [ ] 遇到常见错误能定位到具体代码位置

**学习策略：** 先测试已有基础，只针对薄弱点补课，不重复学习已经掌握的内容。

### 阶段 1：Python 工程基础

**目标：** 能够建立结构清晰、依赖可管理的 Python 项目。

- [ ] 解释器、模块、包和导入机制
- [ ] 虚拟环境：`venv`
- [ ] 包管理：`pip`
- [ ] 依赖清单：`requirements.txt`
- [ ] 项目目录组织
- [ ] 环境变量与配置文件
- [ ] Git 基础：提交、分支、合并、冲突处理
- [ ] 代码格式与质量工具：`ruff`、类型检查基础
- [ ] 理解开发环境与运行环境的区别
- [ ] 理解 Windows、WSL、Linux 中 Python 环境的差异

**验收标准：**
- [ ] 能独立创建 Python 项目
- [ ] 能创建并激活虚拟环境
- [ ] 能安装、记录和复现项目依赖
- [ ] 能在另一套干净环境中重新运行项目

### 阶段 2：HTTP、REST API 与 FastAPI

**目标：** 能够开发基本的 Python HTTP 后端服务。

- [ ] HTTP 请求与响应
- [ ] GET、POST、PUT、PATCH、DELETE
- [ ] URL、路径参数、查询参数、请求体
- [ ] HTTP 状态码与请求头
- [ ] JSON 序列化与反序列化
- [ ] FastAPI 路由与参数声明
- [ ] Pydantic 请求模型和响应模型
- [ ] Uvicorn 的作用与启动方式
- [ ] 路由拆分与项目模块组织
- [ ] 自动生成的 OpenAPI / Swagger 文档
- [ ] `/health` 健康检查接口

**验收标准：**
- [ ] 能独立定义 GET、POST 接口
- [ ] 能接收 JSON 请求并返回 JSON
- [ ] 能启动和停止服务
- [ ] 能通过浏览器、curl 或接口工具测试接口
- [ ] 能解释 FastAPI 与 Uvicorn 的分工

**项目练习：** 完成 ANIC 的最小 HTTP 服务。

### 阶段 3：请求校验、异常处理与接口设计

**目标：** 能够设计稳定、清晰、可调试的后端 API。

- [ ] Pydantic 字段约束与数据校验
- [ ] 必填字段、默认值与可选字段
- [ ] 统一错误响应
- [ ] HTTP 异常与状态码选择
- [ ] 请求参数校验失败的处理
- [ ] 分页、筛选与排序基础
- [ ] 接口幂等性基础
- [ ] 请求 ID 与任务 ID
- [ ] 超时、重试与错误边界
- [ ] API 版本和兼容性基础
- [ ] OpenAPI 文档检查

**验收标准：**
- [ ] 能拒绝格式错误或缺少必要字段的请求
- [ ] 能正确返回 4xx、5xx 等错误状态
- [ ] 能区分客户端错误、业务错误和服务器错误
- [ ] 能设计清晰的请求和响应格式

### 阶段 4：异步编程与后台任务

**目标：** 能够处理 I/O 密集型任务、长时间任务和并发请求。

- [ ] 同步与异步的区别
- [ ] `async`、`await`
- [ ] 协程与事件循环基础
- [ ] `asyncio`
- [ ] `async def` 与普通 `def` 的适用场景
- [ ] 异步 HTTP 请求：`httpx`
- [ ] 并发请求、超时与取消
- [ ] 阻塞 I/O 与非阻塞 I/O
- [ ] FastAPI `BackgroundTasks` 的适用范围
- [ ] 长任务与 HTTP 请求生命周期
- [ ] 任务状态管理：pending、running、completed、failed
- [ ] 轮询查询任务结果
- [ ] 进程、线程、协程的区别

**验收标准：**
- [ ] 能编写异步 HTTP 请求
- [ ] 能理解多个 I/O 操作并发执行的基本机制
- [ ] 能实现提交任务、查询状态、获取结果的接口
- [ ] 能识别会阻塞事件循环的操作

**特别注意：** FastAPI 的后台任务不等于可靠的分布式任务队列。重要任务的持久化、重试和跨进程执行，需要在后续阶段学习。

## 四、学习方法与进度管理

每个知识点都遵循：

1. [ ] 理解它解决什么问题
2. [ ] 看一个最小示例
3. [ ] 自己完成一个小任务
4. [ ] 根据报错独立排查
5. [ ] 用自己的话解释原理
6. [ ] 在项目中实际使用
7. [ ] 记录常见错误与解决方法

**阶段完成标准：** 不以“听懂了”或“代码跑通一次”为唯一标准，而是至少能够自己完成一个小任务、解释关键机制，并处理一种常见错误。

**进度记录原则：**
- 只勾选真正完成并通过验证的项目。
- 项目开发中遇到的知识点，可以提前学习，但不代表整个阶段已完成。
- 不因为新增知识点而随意推翻已经确定的学习计划。
- 每完成一个阶段，再整理对应的操作手册、错题和实战记录。

## 五、与现有学习路线的关系

- **Java 后端：** 继续作为后端基本功与求职方向的重要基础。
- **Python 后端：** 重点服务 AI 应用、模型 API、Agent 工程与自动化。
- **Docker / Linux：** 与两条开发路线共用，重视实际部署能力。
- **AI 学习：** 将 LLM、Embedding、RAG、Tool Calling 等能力逐步集成到 Python 服务中。
- **机器学习 / 深度学习：** 按既定 AI 路线继续推进，不要求在 Python 后端阶段完成全部算法学习。

> 最终目标不是“学完 Python”，而是具备足够的 Python 工程能力，能独立开发、调试、测试和部署 AI 应用后端。
