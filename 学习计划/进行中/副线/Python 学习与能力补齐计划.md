# Python 学习与能力补齐计划

## 一、学习定位

Python 是我的辅助技术栈，主要服务于以下目标：

1. **ANIC 项目开发**：能够理解、修改和调试项目代码，掌握必要的后端接口开发与容器化部署。
2. **AI 应用开发**：能够调用大模型 API，处理 JSON、流式响应、结构化输出，并逐步掌握 RAG、Tool Calling 和 Agent 工程。
3. **AI Engineering 能力建设**：能够把模型能力整合进可运行、可测试、可部署的工程系统。
4. **系统性补齐 Python 基础**：在项目实践和 AI 学习积累一定经验后，针对薄弱知识进行系统复习和训练。

Python 学习不替代 Java 后端主线，也不额外增加一套与项目脱节的重型课程。

## 二、整体学习路线

```text
阶段一：跟着 ANIC 学 Python
          ↓
阶段二：跟着 AI 学 Python
          ↓
阶段三：Python 能力诊断
          ↓
阶段四：系统复习与查漏补缺
          ↓
阶段五：综合项目验证
```

以上是长期能力建设路线，不是严格的线性课程。前两个阶段可以交叉进行，系统补齐则放在积累了一定实践经验之后。

### 阶段一：跟着 ANIC 学 Python

以项目当前任务为驱动，遇到什么问题就学习什么知识。

重点内容：

- Python 基础语法与常用数据结构
- 函数、模块、导入与项目目录
- FastAPI、HTTP 接口、JSON 与 Pydantic
- 异步编程基础（项目需要时学习）
- 虚拟环境、依赖管理与启动调试
- Docker 镜像构建、容器运行、日志和端口排查

**阶段目标：** 能理解现有代码，独立完成小范围修改、调试和运行；能够参与项目的构建与部署，而不是只会复制命令。

### 阶段二：跟着 AI 学 Python

以 AI 应用开发任务为驱动，逐步学习相关 Python 能力。

重点内容：

- 使用 `httpx` 调用大模型 API
- 请求参数、JSON、HTTP 状态码、超时和异常处理
- 流式响应与 SSE
- Pydantic 与结构化输出
- 文件读取、文本处理与数据整理
- Embedding、RAG、Tool Calling 与 Agent
- 根据 AI 学习进度，逐步接触 NumPy、Pandas、scikit-learn 和 PyTorch

**阶段目标：** 能独立编写基本的 AI API 调用程序，理解关键代码，处理常见错误，并将 AI 能力整合进后端应用。

说明：NumPy、Pandas、机器学习和 PyTorch 不要求现在一次性学完，按照 AI 主线的实际进度逐步引入。

### 阶段三：Python 能力诊断

正式系统复习前，先诊断已经掌握的内容。

通过独立编码、解释原理、处理错误等方式，区分以下情况：

- **已掌握：** 能独立使用并解释原理，不重复系统学习。
- **基本掌握：** 看得懂，但独立编写或处理边界情况不够稳定，安排针对性练习。
- **未掌握：** 无法独立完成任务，回到基础讲解并逐步练习。
- **尚未接触：** 暂时不必为了完成清单而提前学习，根据实际需求决定何时引入。

### 阶段四：系统复习与查漏补缺

当 ANIC 和 AI 学习积累了一定的 Python 实践后，再系统梳理薄弱知识。

重点内容：

- 核心语法与数据结构
- 函数、作用域、返回值与参数
- 模块、包和导入
- 异常处理
- 文件、JSON 与路径操作
- 面向对象编程
- 工程化基础
- 常用进阶特性

本阶段不以重新看完一遍教程为目标，而是以独立编程能力为标准，补齐真正不会、理解不深或无法灵活使用的部分。

### 阶段五：综合项目验证

通过能够运行的综合项目，检验 Python 是否真正转化成工程能力。

项目能力逐步覆盖：

- FastAPI 接口开发
- 调用大模型 API
- 参数校验与结构化输出
- 异常处理与日志
- 配置管理和依赖管理
- 自动化测试
- Docker 构建、运行与问题排查

不要求一次性完成所有功能，可以在 ANIC 或后续 AI 项目中逐步积累。

## 四、学习方法

每次学习遵循以下流程：

```text
明确当前问题
    ↓
讲解原理
    ↓
查看可运行示例
    ↓
完成小任务
    ↓
自己独立操作
    ↓
检查与纠错
    ↓
回到项目实践
    ↓
记录掌握情况
```

具体要求：

1. **明确问题：** 当前任务为什么需要这个知识？
2. **讲解原理：** 先理解概念和使用场景，不默认已有相关基础。
3. **查看示例：** 通过最小、可运行的例子理解用法。
4. **完成小任务：** 针对当前知识安排一个适量练习。
5. **独立操作：** 尽量自己写代码、修改项目或排查问题。
6. **检查与纠错：** 检查代码结果、思路和错误原因。
7. **回到项目：** 将学到的知识应用于 ANIC 或 AI 项目。
8. **记录掌握情况：** 区分已掌握、需复习和未掌握。

不以阅读过教程、看懂示例或成功运行一次代码作为掌握标准。

## 五、系统补齐前的能力诊断

正式系统复习之前，先做一次 Python 能力诊断。

### 诊断方式

对每个知识点，结合以下方式检查：

- **独立编码：** 不照抄示例，完成一个小任务。
- **解释原理：** 说清楚为什么这样写、代码如何运行。
- **错误处理：** 能否发现并修复常见错误。
- **项目迁移：** 能否将知识用到实际代码中。

### 诊断结果分类

- [ ] **已掌握：** 能独立使用并解释原理，不重复系统学习。
- [ ] **基本掌握：** 看得懂，但独立编写或处理边界情况不够稳定，安排针对性练习。
- [ ] **未掌握：** 无法独立完成任务，回到基础讲解并逐步练习。
- [ ] **尚未接触：** 暂时不必为了完成清单而提前学习，根据实际需求决定何时引入。

### 诊断规则

在 ANIC、AI 学习和其他项目中已经实践过的 Python 知识，都可以作为诊断依据。

已掌握的内容不重复系统学习；不熟悉的内容通过针对性练习补齐；未掌握的基础内容再进行系统学习。

### 阶段二：AI 应用实践

**阶段目标：** 能够使用 Python 独立调用大模型 API，正确处理请求与响应，并逐步具备将 AI 能力集成到后端应用的能力。

- [x] 能区分请求头中的 `Content-Type: application/json` 与响应正文的 JSON 格式。
- [x] 能使用 `httpx` 发起基本的 HTTP 请求。
- [x] 能理解 `httpx.get()`、`httpx.post()` 等常见调用方式。

**验收任务：**

独立编写一个最小流式输出程序，能够逐步打印模型生成的文本，并在需要时保存完整答案；同时说明如何处理不包含文本的事件和结束标记。

- [ ] 能把结构化结果传递给后续业务逻辑。

**验收任务：**

让大模型生成一份具有明确字段的 JSON 数据，使用 Python 解析并通过 Pydantic 校验；对于格式不正确或缺失字段的情况，能够识别并处理。

**阶段二通过标准：**

### 阶段验收总原则

1. **独立性：** 关键任务不能完全依赖逐行照抄。
2. **理解性：** 能解释代码的主要执行过程和设计原因。
3. **纠错能力：** 遇到错误能够主动定位、分析和验证修复结果。
4. **迁移能力：** 能将已掌握的知识应用到相似但不完全相同的任务中。
5. **项目价值：** 学习成果应当能够实际服务于 ANIC、AI 应用或后续工程项目。
6. **合理取舍：** 不要求一次性精通全部 Python 生态；先掌握 P0，再根据实际项目补充 P1，P2 按需学习。
7. **避免重复：** 已经通过实际项目和独立任务证明掌握的内容，不再为了完成清单而重复学习。

最终判断标准不是清单打了多少勾，而是能否**独立编写、理解、调试和交付一个实际可运行的程序**。

## 七、与其他学习主线的关系

1. **Java 后端：** 继续作为后端基础与主要能力积累方向，不因学习 Python 而中断。
2. **ANIC：** 近期 Python 学习的第一驱动力，优先解决真实项目问题。
3. **AI 学习：** 在 LLM 基础、API、结构化输出、Embedding、RAG、Tool Calling、Agent 等主题中自然引入 Python。
4. **Linux 与 Docker：** 尽量复用已经学习的通用知识，不因为换成 Python 项目就重新学习整套容器知识。
5. **系统复习：** 放在有了一定项目和 AI 实践之后，基于诊断结果查漏补缺。

## 八、学习节奏与投入原则

- Python 不额外设定一套必须逐周完成的固定课程。
- 需要 Python 支撑 ANIC 时，优先学习当前任务涉及的内容。
- 需要 Python 支撑 AI 学习时，结合当前 AI 主题继续学习。
- 系统补齐阶段，根据能力诊断决定投入，不追求清单全部打勾。
- 如果当前任务不需要深入某个知识点，不为了计划完整而提前学习。
- 学习重点是独立编写、理解、调试和应用，而不是累计学习时长。

## 九、计划执行规则

1. **项目优先：** 优先处理当前 ANIC 或 AI 学习中的实际问题。
2. **按需学习：** 只在必要时引入新的 Python 知识，不提前铺开整套课程。
3. **先理解再操作：** 不把复制粘贴或照抄代码当成真正掌握。
4. **通过练习确认：** 重要知识必须经过独立任务检验。
5. **及时记录错题：** 记录错误原因、正确理解和复测结果。
6. **复用已有能力：** Java、Linux、Docker 和后端工程经验可以迁移的部分，不重复学习。
7. **循序渐进：** 当前任务能完成后，再逐步增加难度。
8. **控制额外负担：** 不让 Python 变成挤占 Java 后端、数学、AI 和其他主线的额外重型课程。
9. **系统补齐前先做能力诊断：** 对已经在 ANIC、AI 学习或其他项目中实践过的 Python 知识，通过独立编码、解释原理和错误处理判断掌握程度。已掌握的内容不重复系统学习；不熟悉的内容通过针对性练习补齐；未掌握的基础内容再进行系统学习。
10. **不反复修改计划：** 计划作为长期地图使用，除非目标或实际情况发生明显变化，否则不继续增加课程、细化清单或重新规划。

## 十、最终原则

**ANIC 驱动实践 → AI 驱动应用 → 能力诊断 → 系统补齐 → 综合项目验证。**

这条路线的目的不是成为只会写 Python 语法的人，而是逐步具备使用 Python 开发后端功能、构建 AI 应用、解决工程问题的能力。

当前阶段以 ANIC 的真实任务为起点；遇到具体 Python 问题时再深入学习。之后随着 AI 主线推进继续积累，最后再依据能力诊断系统补齐。

这份计划确定后，原则上不再反复调整，直接执行即可。
