> **项目名称：学生选课与成绩管理系统（后端版）**
>
> **项目定位：完整的 Java 单体后端练习项目**
>
> **核心目标：Spring Boot + MyBatis/MyBatis-Plus + MySQL + Git**
>
> **推进方式：以任务和验收结果为依据，不设置固定学习周期**

# 一、项目定位与学习目标

## 1. 项目定位

本项目不是简单的 CRUD Demo，也不追求复杂的企业级架构，而是通过一个具有完整业务逻辑的后端系统，将已经学习过的知识串联起来。

**最终目标：具备独立完成一个中小型 Spring Boot 单体后端项目的基础能力。**

项目需要覆盖：

1. Spring Boot 项目搭建与配置。
2. Spring MVC 请求处理。
3. Controller、Service、Mapper 分层设计。
4. MyBatis/MyBatis-Plus 数据访问。
5. MySQL 数据库设计、SQL 查询与索引。
6. Spring 声明式事务。
7. 参数校验、异常处理、统一响应。
8. 基础单元测试与集成测试。
9. Git 版本控制与开发流程。
10. 项目运行、调试和基础 Docker 部署。

## 2. 项目技术栈

| 技术 | 选择 | 用途 |
|---|---|---|
| Java | JDK 21 | 项目开发 |
| Spring Boot | 3.x | 后端框架 |
| Spring MVC | Spring Boot 集成 | HTTP 接口 |
| MyBatis-Plus | 3.x，选择兼容 Spring Boot 3 的 Starter | 基础 CRUD、分页 |
| MyBatis | MP 内置的 MyBatis 能力 | XML、复杂 SQL、结果映射 |
| MySQL | 8.x | 关系型数据库 |
| Maven | 与 Spring Boot 兼容的版本 | 依赖管理、构建 |
| Hibernate Validator | Spring Boot Validation Starter | 参数校验 |
| JUnit 5 | Spring Boot Test | 测试 |
| Git | 当前可用版本 | 版本控制 |
| Apifox / Postman | 二选一 | API 调试 |
| Docker / Compose | 当前可用版本 | 最终部署 |

**重要原则：**

- 优先使用 MyBatis-Plus 完成基础 CRUD。
- 使用原生 MyBatis XML 完成需要手写 SQL 的复杂业务。
- 不额外引入一套独立的 MyBatis Starter，避免与 MyBatis-Plus Starter 重复配置。
- 不使用代码生成器代替核心业务代码编写。
- 不依赖完整教程复制项目。

# 三、数据库设计

## 1. 核心业务表

项目首先使用 4 张业务表，不为了凑数量增加无意义的表。

| 表名 | 主要字段 | 功能 |
|---|---|---|
| `student` | id、student_no、name、age、gender | 学生信息 |
| `teacher` | id、teacher_no、name | 教师信息 |
| `course` | id、course_code、name、teacher_id、capacity、enrolled_count | 课程信息 |
| `enrollment` | id、student_id、course_id、score、created_at | 选课关系与成绩 |

### 表关系

```text
Teacher (教师)
    1
    │
    N
Course (课程)
    1
    │
    N
Enrollment (选课记录)
    N
    │
    1
Student (学生)
```

学生和课程是多对多关系，通过 `enrollment` 表建立联系。

成绩属于具体的选课记录，因此本项目将 `score` 放在 `enrollment` 中，未录入成绩时为 `NULL`。

## 2. 数据库设计要求

- [ ] 每张表有明确主键
- [ ] 学号具有唯一约束
- [ ] 教师工号具有唯一约束
- [ ] 课程编号具有唯一约束
- [ ] 学生和课程关系正确
- [ ] 选课记录建立必要的联合唯一约束
- [ ] 合理设计数据类型
- [ ] 合理使用 `NOT NULL`
- [ ] 正确设计外键或明确应用层完整性策略
- [ ] 为常见查询设计必要索引
- [ ] 使用 `EXPLAIN` 分析关键 SQL

### 关键约束

`enrollment` 需要具有：

```sql
UNIQUE (student_id, course_id)
```

防止同一名学生重复选择同一门课程。

课程容量应满足：

```text
0 <= enrolled_count <= capacity
```

成绩范围为：

```text
0 <= score <= 100
```

成绩尚未录入时允许为 `NULL`。

### 需要明确的业务规则

- 已有选课记录的学生和课程不能随意删除。
- 已录入成绩的选课记录不允许直接退课；如需撤销成绩，应先按业务规则处理。
- 课程容量不得设置为小于当前已选人数。
- 选课人数必须与有效选课记录保持一致。
- 退课成功后必须正确减少已选人数。

这些规则应由数据库约束与 Service 业务逻辑共同保证。

# 四、项目整体架构

## 1. 基础分层

```text
HTTP 请求
    ↓
Controller
    ↓
Service
    ↓
Mapper
    ↓
MySQL
```

每层承担不同职责：

| 层次 | 职责 |
|---|---|
| Controller | 接收请求、参数校验、返回响应 |
| Service | 业务逻辑、事务、规则检查 |
| Mapper | SQL 与数据库访问 |
| Entity | 数据库实体映射 |
| DTO | 接收请求参数 |
| VO | 定义响应数据结构 |
| Exception | 自定义异常 |
| Handler | 全局异常处理 |
| Common | 统一响应及公共组件 |

## 2. 推荐目录结构

```text
student-course-system/
├── pom.xml
├── README.md
├── .gitignore
├── sql/
│   ├── schema.sql
│   └── data.sql
├── docs/
│   ├── api.md
│   └── design.md
└── src/
    ├── main/
    │   ├── java/com/example/school/
    │   │   ├── SchoolApplication.java
    │   │   ├── controller/
    │   │   ├── service/
    │   │   │   └── impl/
    │   │   ├── mapper/
    │   │   ├── entity/
    │   │   ├── dto/
    │   │   ├── vo/
    │   │   ├── common/
    │   │   ├── exception/
    │   │   └── config/
    │   └── resources/
    │       ├── application.yml
    │       └── mapper/
    └── test/
        └── java/com/example/school/
```

目录可以根据业务实际进行调整，不要求创建没有使用到的空包。

### 4. 并发正确性

需要处理一个核心问题：

**课程只剩一个名额时，两位学生同时选课，不能出现超额选课。**

建议采用 MySQL 条件更新、行锁和唯一约束保证正确性。

例如：

```sql
UPDATE course
SET enrolled_count = enrolled_count + 1
WHERE id = ?
  AND enrolled_count < capacity;
```

Service 应检查受影响行数，再决定是否插入选课记录，并将两步操作放在同一个事务中。

还需要处理唯一约束冲突，确保发生失败时整笔事务正确回滚。

不要求使用分布式锁。

# 十五、项目开发方式

采用以下固定流程：

**需求分析 → 设计 → 独立编码 → 本地测试 → Code Review → 修改 → Git 提交 → 阶段验收**

执行原则：

1. 每次只推进一个明确任务。
2. 在你完成当前任务之前，不默认后续步骤已经完成。
3. 优先由你自己设计和编写代码。
4. AI 主要负责知识解释、设计讨论、代码审查和错误分析。
5. 不直接使用 AI 一次性生成整个项目。
6. 遇到不熟悉的 Spring 知识，围绕实际代码补充学习。
7. 只有当前阶段验收通过后，才标记为完成。
8. 保留错误记录，定期进行独立编码复习。
