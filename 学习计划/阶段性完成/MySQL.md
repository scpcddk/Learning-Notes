# 一、学习目标

## 1. 总体目标

系统掌握 MySQL 的使用、设计、优化和底层原理，形成能够支持实际 Java 后端项目开发的数据库能力。

学习结束后应具备：

1. 独立设计关系型数据库表结构。
2. 熟练编写基础与复杂 SQL。
3. 理解 MySQL 索引及 B+Tree 原理。
4. 能够分析 EXPLAIN 执行计划。
5. 理解事务、隔离级别、MVCC 和锁机制。
6. 理解 InnoDB 存储结构及核心日志。
7. 能够发现并优化常见慢 SQL。
8. 能够在 Spring Boot + MyBatis 项目中正确使用 MySQL。
9. 具备基础的数据库故障排查能力。
10. 建立完整的数据库知识体系，而不是孤立记忆 SQL 命令。

## 2. 能力层次

| 层次 | 能力要求 | 验收标准 |
|---|---|---|
| L1：基础操作 | 熟练使用 SQL | 独立完成 CRUD |
| L2：复杂查询 | 多表查询、子查询、窗口函数 | 独立解决业务查询问题 |
| L3：数据库设计 | 表关系、约束、范式 | 独立设计业务数据库 |
| L4：索引优化 | B+Tree、索引、EXPLAIN | 分析并优化查询 |
| L5：事务并发 | ACID、MVCC、锁 | 解释并复现并发问题 |
| L6：底层原理 | InnoDB、日志、Buffer Pool | 解释数据存储和事务提交 |
| L7：工程实践 | MyBatis、性能优化、排障 | 完成综合项目 |

# 十六、学习方法

## 1. 每个知识点的学习流程

```text
第一步：理解概念
       ↓
第二步：查看简单示例
       ↓
第三步：自己解释原理
       ↓
第四步：独立完成 SQL / 实验
       ↓
第五步：检查错误
       ↓
第六步：针对错误强化
       ↓
第七步：通过变式题验收
       ↓
第八步：整理笔记与错题
```

## 2. 学习要求

- 每次只推进一个主要知识点。
- 不把看懂示例当作已经掌握。
- 尽量先独立写 SQL，再检查。
- 不直接提供全部练习答案。
- 对错题先分析原因，再做变式训练。
- 不反复练习已经稳定掌握的简单内容。
- 原理知识必须尽可能结合实验验证。
- 不将计划中的任务视为已经实际执行。

## 3. 知识掌握标准

| 等级 | 标准 |
|---|---|
| 未学习 | 没有系统接触 |
| 已了解 | 知道基本概念 |
| 已理解 | 能解释作用与原理 |
| 已掌握 | 能独立完成练习 |
| 已熟练 | 能在不同场景正确使用 |
| 工程掌握 | 能在实际项目中应用和排查问题 |

**完成学习与真正掌握应分开记录。**

# 十七、复习机制

## 1. 复习周期

| 时间 | 任务 |
|---|---|
| 学习当天 | 简短总结与练习 |
| 2–3 天后 | 回忆核心概念 |
| 7 天后 | 变式练习 |
| 14 天后 | 错题复测 |
| 30 天后 | 综合复习 |
| 后续 | 通过项目和专项复习维持 |

不需要机械地为每个知识点安排完整周期；以实际遗忘程度调整。

## 2. 单次复习安排

建议 30–45 分钟。

- 5 分钟：回忆上次易错点。
- 10 分钟：基础知识检测。
- 15–20 分钟：重点练习或实验。
- 5–10 分钟：纠错与总结。

## 3. 错题记录格式

```markdown
## 错题编号

### 题目

### 我的错误答案

### 正确答案

### 错误原因

### 正确原理

### 变式练习

### 复测结果
```

# 二十、最终学习原则

**MySQL 学习不是以记住多少 SQL 命令为终点，而是以能够独立解决数据库问题为目标。**

整个计划遵循四个原则：

1. **先应用，后原理**：先能使用 SQL，再理解索引、事务与存储引擎。
2. **先理解，后优化**：先知道 SQL 如何执行，再研究为什么慢、如何优化。
3. **理论必须结合实验**：索引、MVCC、锁和日志等知识不能只靠背诵。
4. **最终回到工程实践**：把 MySQL 与 Spring Boot、MyBatis、实际项目结合。

**最终目标：从会写 SQL，提升到理解 MySQL 的运行机制，并能够独立完成数据库设计、开发、优化与基础排障。**
