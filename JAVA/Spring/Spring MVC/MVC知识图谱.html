SpringMVC 复习速查图

前端控制器 + 五大组件 + 请求流程 + 纯注解配置 | 前后端分离

一、核心概念
SpringMVC = 前端控制器(DispatcherServlet) + 可插拔策略组件
本质：继承 HttpServlet 的总控，协调各组件完成请求分发
五大核心组件：
1. DispatcherServlet — 前端总控（不干活，只协调）
2. HandlerMapping — 根据URL找到 Handler（如 RequestMappingHandlerMapping）
3. HandlerAdapter — 适配并执行 Handler（如 RequestMappingHandlerAdapter）
4. Handler — 真正的业务逻辑（@Controller 方法封装为 HandlerMethod）
5. HandlerExceptionResolver — 异常统一处理
前后端分离：返回值直接通过 HttpMessageConverter 转 JSON
不经过 ViewResolver，没有"视图渲染"环节
二、请求执行流程（9步）
1
请求进入 DispatcherServlet，调用 doDispatch()
2
HandlerMapping 找到 Handler，返回 HandlerExecutionChain（含拦截器链）
3
遍历 HandlerAdapters，找到支持该 Handler 的 Adapter
4
执行拦截器 preHandle（正序，返回 false 则终止）
5
Adapter 调用 Handler：解析参数(@RequestBody等) -> 反射执行 -> 处理返回值(@ResponseBody等)
6
执行拦截器 postHandle（逆序，此时响应未提交）
7
HandlerExceptionResolver 处理异常（如有）
8
执行拦截器 afterCompletion（逆序，资源清理，必定执行）
9
JSON 已写入 response，返回客户端
三、纯注解配置（替代 web.xml）
核心类：AbstractAnnotationConfigDispatcherServletInitializer
Servlet 3.0+ 容器通过 SPI 自动发现，替代 web.xml
三个必须重写的方法：
getRootConfigClasses() — 根容器（Service/DAO/数据源），排除 @Controller
getServletConfigClasses() — Web容器（Controller/拦截器/视图解析器）
getServletMappings() — URL映射，通常为 "/"
getServletFilters() — 注册过滤器（如 CharacterEncodingFilter UTF-8）
RootConfig
@Configuration
@ComponentScan(excludeFilters=@Controller)
管 Service/DAO/事务
WebConfig
@Configuration
@EnableWebMvc
@ComponentScan("controller")
管 Controller/拦截器
@EnableWebMvc 导入 DelegatingWebMvcConfiguration
自动注册 HandlerMapping、HandlerAdapter、参数解析器等
四、请求映射 & 参数绑定
@RestController = @Controller + @ResponseBody（所有方法直接返回JSON）
@RequestMapping 属性：value/path(路径) | method(方法) | params(参数限制) | headers(请求头) | consumes(请求Content-Type) | produces(响应Content-Type)
组合注解：@GetMapping | @PostMapping | @PutMapping | @DeleteMapping | @PatchMapping
参数绑定速查：
@RequestParam — 查询参数/表单参数（可设 required/defaultValue）
@PathVariable — 路径变量 /{id}，可正则匹配 /{id:\d+}
@RequestBody — JSON请求体转对象（需 Content-Type: application/json）
@RequestHeader — 请求头 | @CookieValue — Cookie
HttpServletRequest / HttpServletResponse / HttpSession — 直接注入
@SessionAttribute("key") — 只读自动转换 | @RequestAttribute — 请求域属性
GET 不应带请求体，Tomcat 会忽略，@RequestBody 无法绑定
实体类绑定无需注解：/search?name=Tom&age=20 自动填充到 UserQuery
五、拦截器 HandlerInterceptor
拦截器 vs 过滤器：拦截器属于 SpringMVC，可拿到 Handler；过滤器属于 Servlet 容器，更底层
三个方法：
preHandle(request, response, handler) — 前置，返回 true 放行，false 拦截
postHandle(request, response, handler, modelAndView) — 后置，逆序执行
afterCompletion(request, response, handler, ex) — 完成，必定执行（资源清理）
多个拦截器执行顺序（假设 Interceptor1、Interceptor2）：
preHandle-1 -> preHandle-2 -> 目标方法 -> postHandle-2 -> postHandle-1 -> afterCompletion-2 -> afterCompletion-1
栈式：正序进，逆序出
preHandle 返回 false：后续不执行，但之前已成功 preHandle 的 afterCompletion 仍会触发
Token 校验后：request.setAttribute("user", user) -> Controller 用 @RequestAttribute 获取
六、响应处理 & 全局异常
响应方式：
@ResponseBody — 返回值直接序列化为JSON
ResponseEntity<T> — 细粒度控制状态码、响应头
forward:/path — 转发（@Controller 方法返回）
redirect:/path — 重定向（@Controller 方法返回）
@RestController 或 @ResponseBody 方法中返回 "forward:..." 会被当成普通字符串写入响应体，不会转发
全局异常处理：@RestControllerAdvice + @ExceptionHandler
被 ExceptionHandlerExceptionResolver 扫描，按异常类型匹配最近的方法
建议定义统一返回体 Result，而非散装 Map
七、作用域 & 线程安全
作用域速查：
singleton（默认）— 容器唯一，所有请求共享 → Controller 默认单例，禁止可变成员变量
prototype — 每次获取新建，Spring 不管理销毁
request — 每个HTTP请求一个实例，需 proxyMode=TARGET_CLASS 注入单例
session — 每个用户会话一个实例
application — ServletContext 唯一
单例 Controller 安全原则：
不要定义可变成员变量 | 不要手动创建线程
需要状态 -> 放入 request/session Bean 或方法局部变量
八、高频问题 & 解决方案
参数接收失败 400
@RequestParam 未传参且未设 required=false 或 defaultValue
JSON 415/400
Content-Type 不是 application/json | 缺少 Jackson 依赖 | 字段名不匹配（驼峰/下划线）
跨域 CORS
局部：@CrossOrigin | 全局：WebMvcConfigurer.addCorsMappings()
中文乱码
CharacterEncodingFilter UTF-8 + forceEncoding=true | Tomcat server.xml URIEncoding="UTF-8"
静态资源 404
@EnableWebMvc 完全接管，需手动 addResourceHandlers("/static/**")
Controller 404
检查 @ComponentScan 包路径 | getServletMappings() 是否为 "/" | 方法是否标注 @RequestMapping
九、文件上传下载
上传：注册 MultipartResolver Bean（名称固定 multipartResolver）
customizeRegistration() 配置临时目录、最大文件大小
Controller 用 @RequestParam("file") MultipartFile file 接收
注意：@RequestBody 不能用于文件上传
下载：ResponseEntity<Resource> 返回文件流
Content-Disposition: attachment; filename*=UTF-8'' 兼容中文名
十、XML vs 注解映射（看懂即可）
web.xml 核心三块：编码过滤器(CharacterEncodingFilter) | DispatcherServlet | Servlet映射
spring-servlet.xml 核心：<context:component-scan> | <mvc:annotation-driven/>
映射关系：web.xml -> AbstractAnnotationConfigDispatcherServletInitializer | <mvc:annotation-driven/> -> @EnableWebMvc | <context:component-scan> -> @ComponentScan
十一、SpringMVC vs SpringBoot
原生 SpringMVC
外置 Tomcat，打包 war
手写 Initializer + Config
手动管理依赖版本
适合：理解底层原理、排查疑难杂症
SpringBoot
内嵌容器，jar 直接运行
自动配置 DispatcherServlet
starter 一站式管理依赖
自动注册 Jackson、静态资源、全局异常
