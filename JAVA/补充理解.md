# Java补充理解

## 一.Java 的文件组织规则

### 1.public类

+ 一个 .java 文件最多只能有一个 public 类，且文件名必须和这个 public 类的名字完全一样
+ 改法：
  + 拆成两个文件（推荐）
  + 去掉类名前的public，改成默认访问权限（什么都不写）

## 二.Java Thread

### 1. 什么是线程？

线程是程序内的**独立执行路径**。一个进程可以有多个线程，它们“同时”运行。

### 2. 为什么需要多线程？

避免一个任务阻塞其他任务。  
比如你的游戏：  

- **主线程**负责初始化、等待结束  
- **时钟线程**负责每秒 10 次驱动战场更新

### 3. 传统线程 vs 虚拟线程（JDK 21）

| 类型 | 传统线程 | 虚拟线程 |
| ------ | ---------- | ---------- |
| 创建方式 | `new Thread(task).start()` | `Thread.ofVirtual().start(task)` |
| 资源开销 | 大（操作系统线程） | 极小（JVM 管理） |
| 数量上限 | 几千个 | 轻松几十万个 |
| 适用场景 | 长时间运行的任务 | 高并发、短任务 |

### 4. 关键方法

- `start()`：启动线程，执行 `run()` 方法
- `sleep(ms)`：让当前线程休眠指定毫秒
- `interrupt()`：中断线程

### 5. 一句总结

> **线程 = 分身术，让程序同时做多件事。虚拟线程 = 轻量分身，大厂面试加分项。**

## 三.`removeIf`

### 1. 功能定位

在集合遍历时，**安全地边遍历边删除**满足条件的元素。
它完美取代了两种糟糕的旧写法：会崩溃的 `for-each` + `remove`，以及代码冗长的 `Iterator` 手动循环。

### 2. 语法拆解

```java
entities.removeIf(entity -> { ... });
//               ^^^^^^^^  ^^^^^^^^^^
//               集合调用    Lambda 表达式
```

- **`entities`**：调用者，即你的集合（如 `ArrayList`）。
- **`removeIf`**：`Collection` 接口提供的高阶方法（JDK 8+）。
- **`entity -> { ... }`**：Lambda 表达式，针对集合中的**每一个元素**都会执行一次。
- `entity` 是当前遍历到的元素（可随意命名）。
- `{ ... }` 代码块里是你的判断逻辑，**必须返回一个 `boolean` 值**：
- **`return true;`** → **删除**当前元素。
- **`return false;`** → **保留**当前元素。

### 3. 三种写法生死对比

| 写法 | 风险/缺点 | 结论 |
| ------ | ----------- | ------ |
| `for (E e : list) { if(条件) list.remove(e); }` | 💥 **并发修改异常**，程序直接崩溃。 | **绝对禁止** |
| `Iterator` 手动循环 + `it.remove()` | 代码冗长，手动管理迭代器，不优雅。 | 可用但不推荐 |
| `list.removeIf(e -> 条件)` | **零风险，语法简洁，逻辑清晰。** | ✅ **唯一推荐** |

### 4.底层原理

`removeIf` 的底层源码，实际上就是 JDK 帮你写好的**标准 `Iterator` 安全删除逻辑**：

```java
// 简化版 removeIf 源码逻辑
public boolean removeIf(Predicate<? super E> filter) {
Iterator<E> it = iterator(); // 内部创建迭代器
while (it.hasNext()) {
if (filter.test(it.next())) { // 调用你的 Lambda
it.remove();              // 用迭代器安全删除
}
}
return true;
}
```

**简单来说：JDK 替你干了“边遍历边删除”的脏活累活，并保证了安全。**

### 5.Lambda表达式

#### (1)语法

```java
(参数) -> { 代码 }
```

- 单参数可省略括号：`entity -> entity.getHp() <= 0`
- 单行表达式可省略 `{}` 和 `return`

#### (2)本质

把“判断规则”当作参数直接传给方法。

#### (3)传统 vs Lambda

- **传统**：手写循环 + `if` + `remove`（易崩溃）
- **Lambda**：只写规则，JDK 内部安全遍历删除

#### (4)**变量捕获限制**

在 Lambda 表达式 { ... } 内部，如果想使用外面的局部变量，这个变量必须是 **final（或者事实上不可变 effectively final）**

> [!NOTE]
> **本质原因**：JVM 通过“复制引用”的方式捕获变量，使得内外共享同一数据区域。为了防止多线程下的数据混乱，以及强制遵循函数式编程无副作用的原则，编译器直接要求外部变量必须是 final，从语法上斩断所有修改的念头。

+ 错误示例：

```java
int killCount = 0;
// 💥 编译器会狠狠报错：Variable used in lambda expression should befinal or effectively final
entities.removeIf(entity -> {
    if (entity.getHp() <= 0) {
        killCount++; // ❌ 绝对禁止：在 Lambda 内部修改外部的局部变量
        return true;
    }
    return false;
});
```

如果非要在 Lambda 内部计数，应该把变量定义为**类的成员变量**，或者使用线程安全的原子类 **AtomicInteger**

> [!NOTE]
> 局部变量住栈，Lambda 捕获其值的拷贝，故不可改；成员变量住堆，Lambda 捕获对象引用，故可改
> **普通 `int`（成员变量）**：单线程下可用，多线程下 `count++` 不原子，会丢更新
> **`AtomicInteger`**：提供 `incrementAndGet()` 等方法，底层用 CAS 保证原子操作，多线程下计数绝对准确

## 四.Java 构造方法 vs 普通方法

### 1.核心区别

| 特性 | 构造方法 | 普通方法 |
|------|----------|----------|
| 作用 | 创建并初始化对象 | 定义对象行为 |
| 名称 | **必须与类名完全相同** | 不能与类名完全相同 |
| 返回类型 | **没有**（`void` 也不写） | **必须声明**（无返回时写 `void`） |
| 修饰符 | 仅 `public/protected/private` | 还可加 `static/final/abstract` 等 |
| 调用方式 | 仅通过 `new` 或 `this()/super()` | 通过对象引用或类名调用 |
| 默认生成 | 不写时编译器自动生成无参构造 | 不自动生成 |
| 继承/重写 | **不能被继承，不能重写** | 可被继承、重写（多态） |
| 生命周期 | 每个对象只调用一次 | 可调用任意次数 |

---

### 2.代码示例

```java
// 1. 接口定义（函数式接口）
@FunctionalInterface
public interface UnitCreator {
    GameEntity create(Team team, double x, double y);
}

// 2. 实体类
public class Knight implements GameEntity {
    private Team team;
    private double x, y;

    // 构造方法：名称=类名，无返回类型
    public Knight(Team team, double x, double y) {
        this.team = team;
        this.x = x;
        this.y = y;
    }

    // 普通方法：有返回类型 void
    public void attack() {
        System.out.println("Knight attacks!");
    }

    // 普通方法：有返回类型 int
    public int getHealth() {
        return 100;
    }
}
```

## 五.Java 声明类型 vs 实际类型

### 1.🎯 核心定义

| 概念 | 代码中位置 | 是什么 | 举例 |
|------|------------|--------|------|
| **声明类型** | 等号左边 | 接口、抽象类或具体类本身 | `Queue`, `List`, `GameEntity` |
| **实际类型** | 等号右边 `new` 出来的 | 具体实现类 | `LinkedList`, `ArrayList`, `Soldier` |

### 2.📋 常见声明类型 → 实际类型对应表

| 声明类型 | 常见实际类型 | 说明 |
|----------|--------------|------|
| `Collection` | `ArrayList`, `LinkedList`, `HashSet` | 最笼统的容器接口 |
| `List` | `ArrayList`, `LinkedList`, `Vector` | 有序可重复列表 |
| `Set` | `HashSet`, `TreeSet` | 不重复集合 |
| `Queue` | `LinkedList`, `PriorityQueue` | 单端队列 |
| `Deque` | `ArrayDeque`, `LinkedList` | 双端队列 |
| `Map` | `HashMap`, `TreeMap`, `ConcurrentHashMap` | 键值对 |
| `Comparable` | `String`, `Integer` 等 | 可比较大小的对象 |
| `Runnable` | `Thread` 或 Lambda | 可执行的任务 |

### 3.🧠 项目实际应用示例

```java
// 声明类型：Queue（只暴露队列操作）
// 实际类型：LinkedList（具体干活）
private final Queue<Card> deckPool = new LinkedList<>();

// 声明类型：List（只暴露列表操作）
// 实际类型：ArrayList（具体干活）
private final List<Card> hand = new ArrayList<>();

// 声明类型：GameEntity（抽象父类）
// 实际类型：Soldier / Tower（具体子类）
GameEntity entity = new Soldier(...);
```

### 4.记忆

**声明类型 = 你能用它做什么（行为边界）**
**实际类型 = 它具体怎么做到这些（实现细节）**
