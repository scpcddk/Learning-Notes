## 1. 消息交互（OOAD 核心深挖）

- **消息的“四要素”标准定义**：一条完整的对象间消息必须包含 **①接收者（对象） + ②服务名（方法） + ③所需信息（参数） + ④返回报告（返回值）**。
- **交互的“物理基础”辨析**：
  - 交互必须依赖 **具体的对象实例**（堆内存中的物理载体）。
  - 为什么不是“语法”？语法（如 Java 的点号）只是编译期的**编码前提**，运行期 JVM 只看引用指向。
  - 为什么不是“消息内容”？内容只是数据，若接收者为 `null`，内容再完整交互也失败（抛出 `NullPointerException`）。
- **接口（规范层） vs 实例（物理层）**：
  - 接口定义的是“交互的合同/语法规范”（设计期）。
  - 具体对象实例提供的是“交互的物理基础”（运行期）。
  - 考试中问“基础”且选项有“具体对象”，必选后者。

## 2. 设计模式（GoF 分类与本质）

- **三大类型归属（高频匹配题）**：
  - **创建型**：单例模式（Singleton）、工厂方法（Factory Method）—— 关注对象**如何创建**。
  - **结构型**：适配器（Adapter）、装饰器（Decorator）—— 关注类和对象的**组合**。
  - **行为型**：策略模式（Strategy）、迭代器（Iterator）—— 关注算法封装和对象间**职责分配**。（==封装算法或遍历==）
- **策略模式 vs 普通多态（本质区分）**：
  - **普通多态**：依赖继承（`is-a`），子类重写父类方法，对象创建时类型即固定。
  - **策略模式**：依赖组合（`has-a`），核心是 **运行时动态切换算法**（通过 `setStrategy()` 方法），强调算法的独立封装和互换。
- **设计模式定义的“四要素”**：一个完整的模式包含 **①名称 + ②问题（何时使用） + ③解决方案（类结构） + ④效果（优缺点）**。选项中的“只提类结构”或“只提问题”都是片面的。

## 3. Java I/O 流（选型与底层行为）

- **读取大文本文件的最佳实践**：
  - 最优选：`new BufferedReader(new InputStreamReader(new FileInputStream("file.name")))`。
  - **BufferedReader** 提供内部缓冲区（默认 8KB），将大量磁盘 I/O 合并为少数几次，性能远优于无缓冲的 `InputStreamReader`。
- **写入字符 vs 字节的选型**：
  - 写**字符/文本**（处理编码）：优先用 **`PrintWriter`**（字符流）。
  - 写**原始字节/二进制**：用 **`PrintStream`**（如 `System.out`，虽能打文本但本质是字节流，非字符处理最佳实践）。
- **`PrintWriter` 构造器的合法用法（避坑）**：
  - ✅ `new PrintWriter(new File(".\\hai.txt"))` —— 直接接受 `File` 对象，正确。
  - ❌ `new PrintWriter(new OutputStreamReader(new File(...)))` —— `OutputStreamReader` 需要的是 `InputStream`（字节流），不能接受 `File` 对象，**类型不匹配，编译报错**。
  - ❌ `new PrintWriter(new OutputStream())` —— `OutputStream` 是抽象类，不能实例化，**编译报错**。
- **写入整数（`int`）的正确方式**：
  - 必须用 **`DataOutputStream`** 的 `writeInt(i)`，它会写入完整的 **4 个字节**。
  - **陷阱**：`FileOutputStream.write(i)` 只写入 **1 个低字节**（截断高位数据），不适合写整数。
- **文件不存在时的“自动创建”规则**：
  - **读取流**（`FileReader`、`FileInputStream`、`RandomAccessFile("r")`）：抛出 **`FileNotFoundException`**（不创建文件）。
  - **写入流**（`FileOutputStream`、`RandomAccessFile("rw")`）：**自动创建新文件**（不报错）。

## 4. 异常处理（继承体系与分类辨析）

- **根父类**：**`Throwable`**（`Exception` 和 `Error` 的共同父类）。若题目问“所有异常的父类”，必须选 `Throwable`，而非 `Exception`。
- **受检异常（Checked）**：编译器强制 `try-catch` 或 `throws`。代表：`IOException`、`ClassNotFoundException`。
- **非受检异常（Unchecked / RuntimeException）**：编译器不强制处理。代表：`NullPointerException`、`NumberFormatException`、`ClassCastException`。
- **程序员“不能/不应”处理的异常（高频坑）**：
  - **`ClassCastException`** 属于**逻辑错误**（如强转失败），正确做法是使用 `instanceof` **预防**，而不是用 `try-catch` 去捕获（治标不治本，掩盖设计缺陷）。
  - `NumberFormatException` 虽然在运行时家族中，但业务场景中**经常被主动捕获**（如提示用户输入格式错误），因此不属于“不能处理”的范畴。
- **常见具体场景异常**：
  - `ArrayList a; a.add("Hello");` → 抛出 **`NullPointerException`**（引用未初始化）。
  - 读取不存在文件 → 抛出 **`FileNotFoundException`**（注意不是 `IOException` 父类，而是具体子类）。
