## 1. Java 源文件与包导入机制（Package & Import）

- **源文件命名铁律**：Java 源文件（`.java`）的名称必须与文件中的 **`public` 类名完全一致，且严格区分大小写**。如果文件中没有 `public` 类，则文件名可以任意，但实际开发中极少这样做。
- **默认导入的包**：`java.lang` 包是**唯一**被隐式导入的包（包含 `String`、`System`、`Math` 等核心类），其他包（如 `java.util`、`java.io`）必须使用 `import` 语句手动导入。
- **`import` 通配符（`*`）的真相**：
  - `import java.util.*;` 只会导入该包下的**所有==类==**，**不会**导入子包中的类。
  - **编译后无运行时开销**：`*` 只是在编译阶段让编译器去查找类名，编译后的字节码中只包含实际用到的类，不会因为导入了整个包而导致程序变慢。
  - ==**一条 `import` 只能导入一个包**==，不能同时导入多个包（如 `import java.util.*; java.io.*;` 语法错误）。

## 2. 数据类型与转换（重温与深化）

- **基本数据类型（8种）**：`byte`、`short`、`int`、`long`、`float`、`double`、`char`、`boolean`。
- **引用数据类型**：`String`、数组、类、接口等。**`String` 绝对不属于基本数据类型**（它是 `java.lang` 包下的类）。
- **==隐式转换==（自动类型转换）条件**：① 两种类型兼容；② 目标类型取值范围 **≥** 源类型。
  - **特例（易错）**：`long` 可以隐式转换为 `float`，即使 `float` 精度较低（可能丢失精度），但 Java 规范允许，因为 `float` 的**数量级范围**更大。
- **显式转换（强制类型转换）注意点**：
  - 强制转换会**直接截断小数部分**（不是四舍五入）。
  - 当源数值超出目标类型范围时，会发生**高位截断/溢出**，产生垃圾数据，需自行保证数据安全。
  - **`boolean` 类型是“孤岛”**，不能与任何其他类型进行隐式或显式转换。

## 3. 常量（`final`）的深度定义

- **常量的本质**：使用 `final` 关键字修饰的变量，值一旦赋值就**不可修改**。
- **必须初始化**：`final` 变量要么在声明时赋值，要么在构造方法中赋值（**空白 final 变量**），否则编译报错。
- **命名规范**：常量名通常**全部大写**，单词间用下划线分隔（如 `MAX_VALUE`），这是行业标准，考试可能作为判断依据。
- **引用类型常量的陷阱**：`final` 修饰引用类型时，**引用不可变**（不能指向新对象），但**对象内部状态可变**（如 `final StringBuffer sb = new StringBuffer("A"); sb.append("B");` 是允许的）。

## 4. 运算符与字符串拼接（区分算术与连接）

- **`+` 运算符的双重身份**：
  - 如果**两边都是数值类型**，`+` 执行**算术加法**（如 `5 + 2` 输出 `7`）。
  - 如果**任意一边是==字符串==**，`+` 执行**字符串==拼接==**，且运算**从左到右**进行。
    - `5 + "1" + 2` → `"51" + 2` → `"512"`。
- **`++` 自增运算符的核心记忆**：
  - ==**当 `++` 单独成行时**==（如 `++count;` 或 `count++;`），前缀和后缀**没有任何区别**，都是 `count` 加 1。
  - **只有在赋值或参与运算时**，前缀（`++a`）才是“先加后用”，后缀（`a++`）是“先用后加”。

## 5. 流程控制语句选型（`if` vs `switch`）

- **`if` 语句**：擅长**范围判断**（如 `score >= 60`）和**复杂逻辑组合**（如 `a && b`），应用最广。
- **`switch` 语句**：擅长**单一变量的多个等值匹配**（如 `switch(day)`），分支越多代码结构越清晰。
- **效率对比**：传统上 `switch` 使用跳转表（O(1)），但现代 JVM 对 `if-else` 也有分支预测优化，两者性能差距已微乎其微。**实际开发中，可读性比微弱的性能差异更重要**。
- **顺序结构中的语句分类**：包含 **表达式语句**（赋值/方法调用）、**空语句**（单独一个分号）、**复合语句**（`{}` 包裹）、**调用语句**（函数调用，本质是表达式语句的一种）。

## 6. 异常处理与调试工具（明确分工）

- **异常处理的标准方式**：使用 **`try-catch` 块**捕获并处理异常，而不是仅仅在方法头写 `throws`（`throws` 只是将异常向上抛，不负责“处理”）。
- **`throws` 与 `try-catch`**：`throws` 是“甩锅”，`try-catch` 是“自己解决”。
- **调试工具（Debugger）**：允许程序员**单步执行**、**设置断点**、**查看变量值**，是定位运行时逻辑错误的**交互式工具**。
- **栈跟踪（Stack Trace）**：是程序崩溃时控制台打印的**错误信息**（哪一行、调用了什么方法），不是工具，只是调试时参考的“报告”。

## 7. 常用工具类细节（`StringTokenizer` 与包装类）

- **`StringTokenizer` 的分隔符陷阱**：
  - 如果显式指定了分隔符（如 `new StringTokenizer("...", ",")`），**只有逗号是分隔符**，空格会被当做普通字符保留在标记（Token）中。
  - 默认构造器（无参）才会以空白字符（空格、制表符等）作为分隔符。
  - **示例**：`"this is,a,test of tokens"` 以 `","` 分割 → 结果为 `"this is"`、`"a"`、`"test of tokens"`（共 3 个）。
- **包装类（Wrapper Classes）**：
  - 指将 Java 基本数据类型（`int`、`double`、`boolean` 等）“包装”成对象的类（如 `Integer`、`Double`、`Boolean`）。
  - 主要用途：让基本数据类型能参与集合（如 `ArrayList<Integer>`）操作，或调用 `toString()` 等方法。

## 8. Java 注释的三种形态（必须分清）

| 注释类型 | 标记符号 | 核心用途 | 工具处理 |
| :--- | :--- | :--- | :--- |
| **单行注释** | `//` | 临时解释或单行说明 | 编译器忽略 |
| **多行注释** | `/* ... */` | **给程序员看**的内部说明、算法思路、屏蔽代码块 | 编译器忽略，**不生成文档** |
| **Javadoc 注释** | `/** ... */` | ==**给外部使用者看**== 的官方 API 文档，描述类/方法/参数 | `javadoc` 命令解析，生成 HTML 文档 |

- **注意标记区别**：`/*`（1 个星号）与 `/**`（2 个星号）千万不能写混。`/**` 支持 `@param`、`@return`、`@throws` 等专用标签。
