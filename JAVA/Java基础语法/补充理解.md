# Java补充理解

## 一.Java 的文件组织规则

### 1.public类

+ 一个 .java 文件最多只能有一个 public 类，且文件名必须和这个 public 类的名字完全一样
+ 改法：
  + 拆成两个文件（推荐）
  + 去掉类名前的public，改成默认访问权限（什么都不写）

## 二.Java Thread

### 1. 什么是线程？

线程是程序内的**独立执行路径**。一个进程可以有多个线程，它们“同时”运行。

---

### 2. 为什么需要多线程？

避免一个任务阻塞其他任务。  
比如你的游戏：  

+ **主线程**负责初始化、等待结束  
+ **时钟线程**负责每秒 10 次驱动战场更新

---

### 3. 传统线程 vs 虚拟线程（JDK 21）

| 类型 | 传统线程 | 虚拟线程 |
| ------ | ---------- | ---------- |
| 创建方式 | `new Thread(task).start()` | `Thread.ofVirtual().start(task)` |
| 资源开销 | 大（操作系统线程） | 极小（JVM 管理） |
| 数量上限 | 几千个 | 轻松几十万个 |
| 适用场景 | 长时间运行的任务 | 高并发、短任务 |

---

### 4. 关键方法

+ `start()`：启动线程，执行 `run()` 方法
+ `sleep(ms)`：让当前线程休眠指定毫秒
+ `interrupt()`：中断线程

----=

### 5. 一句总结

> **线程 = 分身术，让程序同时做多件事。虚拟线程 = 轻量分身，大厂面试加分项。**

## 三.`removeIf`

### 1. 功能定位

在集合遍历时，**安全地边遍历边删除**满足条件的元素。
它完美取代了两种糟糕的旧写法：会崩溃的 `for-each` + `remove`，以及代码冗长的 `Iterator` 手动循环。

---

### 2. 语法拆解

```java
entities.removeIf(entity -> { ... });
//               ^^^^^^^^  ^^^^^^^^^^
//               集合调用    Lambda 表达式
```

+ **`entities`**：调用者，即你的集合（如 `ArrayList`）
+ **`removeIf`**：`Collection` 接口提供的高阶方法（JDK 8+）
+ **`entity -> { ... }`**：Lambda 表达式，针对集合中的**每一个元素**都会执行一次
+ `entity` 是当前遍历到的元素（可随意命名）
+ `{ ... }` 代码块里是你的判断逻辑，**必须返回一个 `boolean` 值**
+ **`return true;`** → **删除**当前元素
+ **`return false;`** → **保留**当前元素

---

### 3. 三种写法生死对比

| 写法 | 风险/缺点 | 结论 |
| ------ | ----------- | ------ |
| `for (E e : list) { if(条件) list.remove(e); }` | 💥 **并发修改异常**，程序直接崩溃。 | **绝对禁止** |
| `Iterator` 手动循环 + `it.remove()` | 代码冗长，手动管理迭代器，不优雅。 | 可用但不推荐 |
| `list.removeIf(e -> 条件)` | **零风险，语法简洁，逻辑清晰。** | ✅ **唯一推荐** |

---

### 4.底层原理

`removeIf` 的底层源码，实际上就是 JDK 帮你写好的**标准 `Iterator` 安全删除逻辑**：

```java
// 简化版 removeIf 源码逻辑
public boolean removeIf(Predicate<? super E> filter) {
Iterator<E> it = iterator(); // 内部创建迭代器
while (it.hasNext()) {
if (filter.test(it.next())) { // 调用你的 Lambda
it.remove();              // 用迭代器安全删除
}
}
return true;
}
```

**简单来说：JDK 替你干了“边遍历边删除”的脏活累活，并保证了安全。**

---

### 5.Lambda表达式

#### (1)语法

```java
(参数) -> { 代码 }
```

+ 单参数可省略括号：`entity -> entity.getHp() <= 0`
+ 单行表达式可省略 `{}` 和 `return`

#### (2)本质

把“判断规则”当作参数直接传给方法。

#### (3)传统 vs Lambda

+ **传统**：手写循环 + `if` + `remove`（易崩溃）
+ **Lambda**：只写规则，JDK 内部安全遍历删除

#### (4)**变量捕获限制**

在 Lambda 表达式 { ... } 内部，如果想使用外面的局部变量，这个变量必须是 **final（或者事实上不可变 effectively final）**

> [!NOTE]
> **本质原因**：JVM 通过“复制引用”的方式捕获变量，使得内外共享同一数据区域。为了防止多线程下的数据混乱，以及强制遵循函数式编程无副作用的原则，编译器直接要求外部变量必须是 final，从语法上斩断所有修改的念头。

+ 错误示例：

```java
int killCount = 0;
// 💥 编译器会狠狠报错：Variable used in lambda expression should befinal or effectively final
entities.removeIf(entity -> {
    if (entity.getHp() <= 0) {
        killCount++; // ❌ 绝对禁止：在 Lambda 内部修改外部的局部变量
        return true;
    }
    return false;
});
```

如果非要在 Lambda 内部计数，应该把变量定义为**类的成员变量**，或者使用线程安全的原子类 **AtomicInteger**

> [!NOTE]
> 局部变量住栈，Lambda 捕获其值的拷贝，故不可改；成员变量住堆，Lambda 捕获对象引用，故可改
> **普通 `int`（成员变量）**：单线程下可用，多线程下 `count++` 不原子，会丢更新
> **`AtomicInteger`**：提供 `incrementAndGet()` 等方法，底层用 CAS 保证原子操作，多线程下计数绝对准确

## 四.Java 构造方法 vs 普通方法

### 1.核心区别

| 特性 | 构造方法 | 普通方法 |
| ------ | ---------- | ---------- |
| 作用 | 创建并初始化对象 | 定义对象行为 |
| 名称 | **必须与类名完全相同** | 不能与类名完全相同 |
| 返回类型 | **没有**（`void` 也不写） | **必须声明**（无返回时写 `void`） |
| 修饰符 | 仅 `public/protected/private` | 还可加 `static/final/abstract` 等 |
| 调用方式 | 仅通过 `new` 或 `this()/super()` | 通过对象引用或类名调用 |
| 默认生成 | 不写时编译器自动生成无参构造 | 不自动生成 |
| 继承/重写 | **不能被继承，不能重写** | 可被继承、重写（多态） |
| 生命周期 | 每个对象只调用一次 | 可调用任意次数 |

---

### 2.代码示例

```java
// 1. 接口定义（函数式接口）
@FunctionalInterface
public interface UnitCreator {
    GameEntity create(Team team, double x, double y);
}

// 2. 实体类
public class Knight implements GameEntity {
    private Team team;
    private double x, y;

    // 构造方法：名称=类名，无返回类型
    public Knight(Team team, double x, double y) {
        this.team = team;
        this.x = x;
        this.y = y;
    }

    // 普通方法：有返回类型 void
    public void attack() {
        System.out.println("Knight attacks!");
    }

    // 普通方法：有返回类型 int
    public int getHealth() {
        return 100;
    }
}
```

## 五.Java 声明类型 vs 实际类型

### 1.🎯 核心定义

| 概念 | 代码中位置 | 是什么 | 举例 |
| ------ | ------------ | -------- | ------ |
| **声明类型** | 等号左边 | 接口、抽象类或具体类本身 | `Queue`, `List`, `GameEntity` |
| **实际类型** | 等号右边 `new` 出来的 | 具体实现类 | `LinkedList`, `ArrayList`, `Soldier` |

---

### 2.📋 常见声明类型 → 实际类型对应表

| 声明类型 | 常见实际类型 | 说明 |
| ---------- | -------------- | ------ |
| `Collection` | `ArrayList`, `LinkedList`, `HashSet` | 最笼统的容器接口 |
| `List` | `ArrayList`, `LinkedList`, `Vector` | 有序可重复列表 |
| `Set` | `HashSet`, `TreeSet` | 不重复集合 |
| `Queue` | `LinkedList`, `PriorityQueue` | 单端队列 |
| `Deque` | `ArrayDeque`, `LinkedList` | 双端队列 |
| `Map` | `HashMap`, `TreeMap`, `ConcurrentHashMap` | 键值对 |
| `Comparable` | `String`, `Integer` 等 | 可比较大小的对象 |
| `Runnable` | `Thread` 或 Lambda | 可执行的任务 |

---

### 3.🧠 项目实际应用示例

```java
// 声明类型：Queue（只暴露队列操作）
// 实际类型：LinkedList（具体干活）
private final Queue<Card> deckPool = new LinkedList<>();

// 声明类型：List（只暴露列表操作）
// 实际类型：ArrayList（具体干活）
private final List<Card> hand = new ArrayList<>();

// 声明类型：GameEntity（抽象父类）
// 实际类型：Soldier / Tower（具体子类）
GameEntity entity = new Soldier(...);
```

---

### 4.记忆

**声明类型 = 你能用它做什么（行为边界）**
**实际类型 = 它具体怎么做到这些（实现细节）**

## 七.Java Stream API 速查笔记

### 1.核心概念

| 特性 | 说明 |
| ------ | ------ |
| **不存储数据** | Stream 不是集合，是数据计算的"管道" |
| **不改变源数据** | 操作后原集合不变，返回新结果 |
| **惰性求值** | 中间操作不会执行，遇到终结操作才触发 |
| **一次性** | 流只能消费一次，用完即关闭 |
| **函数式** | 参数多为 Lambda，支持链式调用 |

```java
+--------------------+       +------+   +------+   +---+   +-------+
| stream of elements +-----> |filter+-> |sorted+-> |map+-> |collect|
+--------------------+       +------+   +------+   +---+   +-------+
```

---

### 2.创建 Stream

```java
// 1. 集合（最常用）
list.stream();
list.parallelStream();  // 并行流

// 2. 数组
Arrays.stream(array);
Arrays.stream(array, from, to); // 指定范围

// 3. 直接创建
Stream.of("a", "b", "c");
Stream.empty();                    // 空流
Stream.iterate(0, n -> n + 2).limit(10);  // 0,2,4,6...
Stream.generate(Math::random).limit(5);   // 5个随机数

// 4. 其他来源
"abc".chars();                     // IntStream
Files.lines(Paths.get("file.txt"));// 文件逐行
Pattern.compile(",").splitAsStream("a,b,c");
```

---

### 3.**中间操作**（返回 Stream，惰性执行）

| 方法 | 作用 | 示例 |
| ------ | ------ | ------ |
| `filter(Predicate)` | **过滤**保留符合条件的 | `.filter(x -> x > 10)` |
| `map(Function)` | 一对一**转换**,映射每个元素到对应的结果 | `.map(User::getName)` |
| `flatMap(Function)` | 一对多扁平化 | `.flatMap(list -> list.stream())` |
| `distinct()` | **去重**（基于 equals/hashCode） | |
| `sorted()` | 自然**排序** | |
| `sorted(Comparator)` | 自定义排序 | `.sorted(Comparator.reverseOrder())` |
| `peek(Consumer)` | 遍历查看（调试用） | `.peek(System.out::println)` |
| `limit(n)` | 获取指定数量的流,截取前 n 个 | |
| `skip(n)` | 跳过前 n 个 | |
| `takeWhile(Predicate)` | Java 9+ 满足条件时取 | |
| `dropWhile(Predicate)` | Java 9+ 满足条件时丢弃 | |

---

### 4.终结操作（触发执行，返回非 Stream 结果）

| 方法 | 返回类型 | 作用 |
| ------ | ---------- | ------ |
| `collect(Collector)` | 任意 | **收集结果**（最常用） |
| `forEach(Consumer)` | void | 挨个处理，不返回结果 |
| `forEachOrdered(Consumer)` | void | 有序遍历（并行时保序） |
| `toArray()` | Object[] | 转成数组 |
| `reduce(BinaryOperator)` | Optional | 归约聚合:把流里的所有元素，通过某种规则，合并成一个结果 |
| `count()` | long | 计数 |
| `anyMatch(Predicate)` | boolean | 是否有任意一个匹配 |
| `allMatch(Predicate)` | boolean | 是否全部匹配 |
| `noneMatch(Predicate)` | boolean | 是否全部不匹配 |
| `findFirst()` | Optional | 取第一个 |
| `findAny()` | Optional | 取任意一个（并行时更高效） |
| `min(Comparator)` | Optional | 最小值 |
| `max(Comparator)` | Optional | 最大值 |

### 5.Collectors 收集器大全

```java
// 1. 转集合
.collect(Collectors.toList());
.collect(Collectors.toSet());
.collect(Collectors.toCollection(LinkedList::new)); // 指定类型

// 2. 转 Map（key 不能重复，否则抛异常）
.collect(Collectors.toMap(User::getId, User::getName));
.collect(Collectors.toMap(
    User::getId, 
    u -> u, 
    (oldVal, newVal) -> oldVal  // 处理 key 冲突
));

// 3. 分组
.collect(Collectors.groupingBy(User::getDept));              // Map<<Dept, List<User>>
.collect(Collectors.groupingBy(User::getDept, Collectors.counting())); // 分组计数

// 4. 分区（布尔分组）
.collect(Collectors.partitioningBy(u -> u.getAge() > 18)); // Map<Boolean, List<User>>

// 5. 统计
.collect(Collectors.counting());      // 计数
.collect(Collectors.summingInt(User::getAge));     // 求和
.collect(Collectors.averagingInt(User::getAge));    // 平均
.collect(Collectors.summarizingInt(User::getAge)); // 全部统计信息

// 6. 最值
.collect(Collectors.maxBy(Comparator.comparing(User::getAge)));

// 7. 拼接字符串
.collect(Collectors.joining());           // 直接拼
.collect(Collectors.joining(", "));       // 逗号分隔
.collect(Collectors.joining(", ", "[", "]")); // [a, b, c]

// 8. 归约
.collect(Collectors.reducing(0, User::getAge, Integer::sum));
```

### 6.**常用代码模板**

#### (1)**过滤 + 转换 + 收集**

```java
List<String> names = users.stream()
    .filter(u -> u.getAge() >= 18)
    .map(User::getName)
    .distinct()
    .sorted()
    .collect(Collectors.toList());
```

#### (2)分组统计

```java
Map<String, Long> countByDept = users.stream()
    .collect(Collectors.groupingBy(User::getDept, Collectors.counting()));
```

#### (3)取 Top N

```java
List<User> top3 = users.stream()
    .sorted(Comparator.comparing(User::getScore).reversed())
    .limit(3)
    .collect(Collectors.toList());
```

#### (4)**拼接字符串**

```java
String ids = userList.stream()
    .map(u -> String.valueOf(u.getId()))
    .collect(Collectors.joining(","));
// 结果: "1,2,3,4"
```

#### (5)并行流（大数据量）

```java
long sum = numbers.parallelStream()
    .mapToLong(Long::longValue)
    .sum();
```

#### (6)Optional 防止空值

```java
User first = users.stream()
    .filter(u -> u.getAge() > 18)
    .findFirst()
    .orElse(null);  // 或 orElseThrow(), ifPresent()
```

### 7.Optional 常用方法

```java
Optional<String> opt = Optional.ofNullable(str);

opt.isPresent();           // 是否有值
opt.ifPresent(System.out::println);  // 有值则消费
opt.orElse("default");     // 无值返回默认值
opt.orElseGet(() -> "default");     // 无值时惰性提供
opt.orElseThrow(() -> new RuntimeException("空值"));
opt.map(String::toUpperCase);       // 有值则转换
opt.filter(s -> s.length() > 3);    // 有值则过滤
```

### 8.数值专用流（避免装箱拆箱）

```java
List<Integer> list = Arrays.asList(1, 2, 3);

// 基本类型流（性能更好）
int sum = list.stream().mapToInt(Integer::intValue).sum();  // IntStream
long count = list.stream().mapToLong(Long::valueOf).count(); // LongStream
double avg = list.stream().mapToDouble(Double::valueOf).average().orElse(0); // DoubleStream

// 转回对象流
IntStream.range(1, 100).boxed();  // Stream<Integer>
```

### 9.注意事项 ⚠️

| 注意点 | 说明 |
| -------- | ------ |
| **流只能消费一次** | 收集后不能再次遍历，需要重新 `stream()` |
| **避免在流中修改外部变量** | Lambda 要求变量 effectively final |
| **谨慎使用并行流** | 数据量小、有线程安全问题、需有序时不要用 `parallelStream()` |
| **不要用 Stream 处理 checked 异常** | Lambda 不支持直接抛 checked exception，需包装 |
| **复杂逻辑拆分** | 链式调用过长时，拆成多步提高可读性 |
| **优先使用方法引用** | `map(User::getName)` 比 `map(u -> u.getName())` 更简洁 |

---

### 10.方法引用速查

| 形式 | 示例 | 等效 Lambda |
| ------ | ------ | ------------- |
| 静态方法 | `String::valueOf` | `x -> String.valueOf(x)` |
| 实例方法（对象） | `System.out::println` | `x -> System.out.println(x)` |
| 实例方法（参数） | `String::toUpperCase` | `x -> x.toUpperCase()` |
| 构造方法 | `User::new` | `() -> new User()` |
| 数组构造 | `int[]::new` | `len -> new int[len]` |

---

> [!TIP]
> Stream = 数据源 → 中间操作（过滤/映射/排序） → 终结操作（收集/消费），用声明式语法替代繁琐的 for 循环，代码更简洁、可读性更强。
