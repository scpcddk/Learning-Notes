# Java 核心语法速览

## 一、Java 与 C++ 的本质区别（先破后立）

| 维度 | C++ | Java | 差异影响 |
| ------ | ----- | ------ | ---------- |
| 内存管理 | 手动指针（`new/delete`） | JVM 自动管理（无指针，GC 回收） | 彻底告别内存泄漏/野指针，但失去了==底层控制权== |
| 继承机制 | ==多继承==（`class A : B, C`） | ==单继承 + 多实现==（`class A extends B implements C`） | 结构更清晰，避免菱形继承灾难 |
| 程序入口 | 任意函数 `main` | 必须在类中 `public static void main` | 一切皆对象，纯面向对象 |
| 基础类型 | `int`, `char`, `bool` | 8 种基本类型 + 8 种包装类 | 提供了自动装箱/拆箱，兼顾效率与对象特性 |
| 编译运行 | 编译为机器码 | 编译为字节码（JVM 解释/编译） | 跨平台（`Write Once, Run Anywhere`） |

## 三、基础语法速览

### (一). 包 (Package) 与导入 (Import)

#### 1.包的概念

- Java 使用包（package）来组织类，相当于文件系统中的目录（文件夹）
- **包声明**必须位于 Java 源文件的第一行（注释除外），语法为：`package 包名;`
- 包名通常全小写，用点号分隔，例如：`com.mycompany.project.module`
  - 为了防止包名冲突，国际上统一采用公司域名的倒序作为包前缀，如：`com.baidu.map`

---

#### 2.目录结构对应

- 类的物理位置必须与包名一致。例如声明了`package com.example;`的类文件`Hello.java`应放在目录`com/example/`下
- 编译后生成的`.class`文件同样需要放在对应目录结构中，JVM 才能找到它

---

#### 3.包的作用

- **分类管理**：将功能相近的类组织在一起，项目结构更清晰
- **避免命名冲突**：不同包下可以有同名的类（如`java.util.Date`和`java.sql.Date`）
- **访问控制**：default（包级私有）访问权限允许同包类访问，不同包的类无法访问

---

#### 4.import 语句

- 用于**简化类名的书写**，避免每次写全限定名
- 写在`package`声明之后，类定义之前，格式：`import 包名.类名;`或 `import 包名.*;` （导入该包下所有类，但不包括子包中的类）
  > **注意**：`*`只影响**编译期**查找范围，**运行期零性能损耗**。不推荐滥用的真正原因是**可读性差**和**命名冲突风险**（如同时`import java.util.*;`和`import java.sql.*;`，使用`Date`会编译报错
- `java.lang` 包下的所有类由编译器自动导入（如 `String`, `System`, `Math` 等）

---

#### 5.静态导入 (import static)

- JDK 1.5 引入，用于导入类的静态成员（字段/方法），可直接使用静态成员名：`import static java.lang.Math.PI;` 或 `import static java.lang.Math.*;`
  - **滥用静态导入**（如`import static java.lang.Math.*;`）会导致代码极难阅读，因为分不清`abs()`是静态方法还是本地方法
  - **最佳实践**：**只导入常量**，如`import static java.lang.Math.PI;`，并在代码中直接写 PI，这样代码简洁且不影响可读性

---

#### 6.与 C++ 的核心区别

| 特性 | C++ | Java |
| ------ | ----- | ------ |
| 模块组织 | 头文件 + 命名空间 | 包 (package) |
| 导入机制 | `#include` 文本替换 | `import` 让编译器定位类，无重复包含问题 |
| 目录关系 | 无强制对应 | 源文件和目录结构必须与包名一致 |
| 默认可见性 | 无包概念，使用命名空间 | default 访问权限：同包可见 |

---

#### 7.完整示例

```java
// 文件路径：com/game/util/Helper.java
package com.game.util;

import java.util.Scanner;  // 导入单个类
import java.util.*;        // 导入整个包（不建议滥用）

public class Helper {
    public static void print(String msg) {
        System.out.println(msg);
    }
}

// 另一个文件使用上述类
package com.game.main;

import com.game.util.Helper;  // 导入自定义包中的类
// 或者 import com.game.util.*; 

public class Main {
    public static void main(String[] args) {
        Helper.print("Hello from package!");
    }
}
```

### (二). 数据类型（重点对比）

Java 分为 基本类型（8种） 和 引用类型（类、数组、接口等）

#### 1.基本类型

| Java 类型 | 字节 | C++ 对应 | 说明 |
| ----------- | ------ | ---------- | ------ |
| `byte` | 1 | `char` (通常) | 字节型 |
| `short` | 2 | `short` | 短整型 |
| `int` | 4 | `int` | 最常用整型 |
| `long` | 8 | `long long` | 长整型 |
| `float` | 4 | `float` | 单精度浮点 |
| `double` | 8 | `double` | 双精度浮点 |
| `char` | **2** | `char` (1字节) | Unicode 编码，可存中文 |
| `boolean` | 1/4 | `bool` | 仅 `true` / `false`，**不能用 0/1 替代** |

---

#### 2.引用类型

##### (1)什么是引用类型

- Java 中除了 8 种基本类型，其他全部是**引用类型**（类、数组、接口、枚举等）
- 引用类型的变量**存储的是对象的地址**，而不是对象本身，非常类似 C/C++ 的指针

##### (2)与 C++ 指针的核心异同

| 特性 | C++ 指针 | Java 引用 |
| ------ | ---------- | ----------- |
| 存储内容 | 内存地址 | 内存地址（但对程序员透明） |
| 运算 | 可进行 `p++`、`p--` 等算术运算 | 完全禁止，不能改地址值 |
| 空值 | `NULL` / `nullptr` | `null` |
| 类型转换 | 强制转换 `(Target*)` | 只能转为兼容类型（向上转型自动，向下转型强制） |
| 内存回收 | 手动 `delete` | JVM 自动 GC 回收 |

##### (3)引用类型的特点

- **声明后类型不可变**：`Employee e;` 声明的 `e` 只能引用 Employee 或其子类对象，不能变成 String
- **默认值**：所有引用类型的成员变量默认值都是 `null`（局部变量未初始化不能使用）
- **兼容性**：父类引用可以指向子类对象（多态的基础）

##### (4)示例

```java
// site 是引用变量，存储了 Site 对象在堆中的地址
Site site = new Site("Runoob");
// 可指向另一个对象，但不能改变 site 的类型
site = new Site("Google");
```

#### 3. 方法参数传递机制

> [!NOTE]
> **铁律**：**Java 中只有"传值调用"，没有真正的"传引用调用"**
> 但基本类型和引用类型传值后的表现截然不同，因此常被通俗称为"传值"和"传引用"

##### (1) 基本数据类型作为参数（传值 / 复制副本）

- **传递内容**：实际数值的**副本**（如 `10`）
- **特点**：方法内部修改参数，**完全不影响**外部原始变量
- **原因**：栈内存中的值被复制了一份递给方法，方法操作的是"替身"

---

##### (2) 类的对象作为参数（传引用 / 传递引用的副本）

- **传递内容**：对象在堆内存中的**地址副本**（如 `0x1234`）
- **表现效果**：方法内部通过该地址，**可以直接修改堆中对象的属性**，外部能看到变化
- **内存真相**：虽然传递的是地址的"副本"，但副本和原件指向的是**堆里的同一个对象**

---

##### (3) ⚠️ 最大陷阱：形参重新赋值

- 如果在方法内部把引用副本指向**新对象**（重新 `new` 或赋值），外部引用**完全不受影响**
- 因为外部的引用还指着原来的对象，你只是改了方法内局部变量的指向
- 经典失败案例：试图交换两个对象

```java
public class Test {
    // 陷阱：形参重新赋值，外部不受影响
    public static void changeDog(Dog d) {
        d = new Dog("泰迪"); // 只改了局部副本的指向，myDog 纹丝不动
    }

    // 同理：交换对象也是徒劳
    public static void swap(Dog d1, Dog d2) {
        Dog temp = d1;
        d1 = d2;   // 交换的是局部变量里的地址值
        d2 = temp; // dog1 和 dog2 手里的门牌号没变
    }

    public static void main(String[] args) {
        Dog myDog = new Dog("金毛");
        changeDog(myDog);
        System.out.println(myDog.name); // 金毛（没变！）

        Dog dog1 = new Dog("旺财"), dog2 = new Dog("来福");
        swap(dog1, dog2);
        System.out.println(dog1.name + " " + dog2.name); // 旺财 来福（没换成！）
    }
}
```

**内存原理解释**：`d1` 拿到了 `dog1` 的地址副本，`d2` 拿到了 `dog2` 的地址副本。在方法里交换的是 `d1` 和 `d2` 这两个**局部变量**里的地址值，相当于在两张纸上交换了门牌号，而 `dog1` 和 `dog2` 手里的门牌号纹丝不动

---

##### (4) **对比表**

| 对比维度 | **基本数据类型传值** | **对象引用传值（俗称传引用）** |
| :--- | :--- | :--- |
| **传递的内容** | 数据的**数值副本**（如 10） | 对象在堆内存的**地址副本**（如 0x1234） |
| **能否改变外部变量** | **不能**。方法内修改不影响外部 | **能**。修改对象属性，外部会变 |
| **能否交换外部对象** | **不能**。无法交换两个基本变量 | **不能**。无法交换外部的两个对象引用（因为传进来的是副本，重新赋值无效） |
| **经典示例** | `int a=5; change(a);` a 不变 | `dog.name="新名";` 外部狗的 name 变了 |

> [!TIP]
> **基本传值不相干，对象传址改属性；形参重新 new 一下，外部引用绝不慌**

### (六).new 创建对象流程

#### 1.核心结论

构造方法**不创建对象**，仅负责初始化；`new`是创建对象的入口

---

#### 2.==7步执行流程==

以`Student stu = new Student();`为例：

- **加载字节码**：加载`Student.class`到方法区
- **栈中声明变量**：在栈内存声明`stu`变量，初始为`null`
- **堆中开辟空间**：在堆内存为对象分配空间
- **默认初始化**：成员变量赋系统默认值（如`0`、`null`）
- **显示初始化**：执行成员变量定义时的直接赋值（如`int age = 18;`）和初始化块的执行
- **构造方法初始化**：执行构造方法，完成业务初始化
- **赋地址值**：将堆中对象地址赋值给`stu`，`stu`指向该对象

## 四、==**面向对象（OOP）核心**==

### (一). 类与对象（Class & Object）

#### 1. 类

##### (1) 类的定义（蓝图）

- **类是对象的模板**，使用`class`关键字定义。它封装了**数据**(属性)和**行为**(方法)

```java
// 定义格式：修饰符 + class + 类名（大驼峰命名法）
public class Student {
    // 1. 属性（成员变量）定义区域
    // 2. 方法定义区域
}
```

- **注意**：一个`.java`文件中可以有多个类，但**只能有一个`public`类**，且该类的类名必须与文件名完全一致
- **外部类修饰符限制**：**顶层类只能是**`public`或`default`（不写），**不能用`private` / `protected`**。因为外部类不存在"只给自己看"或"只给子类看"的场景，这两种权限是留给内部类（作为成员）使用的

---

##### (2) 类中属性的定义（成员变量 / 字段）

属性定义在**方法外部、类内部**，用于描述对象的**静态特征**

- **语法**：`[修饰符] 数据类型 属性名 [= 初始值];`
- **⚠️ 默认初始化（核心考点）**：如果你没有显式给属性赋值，JVM在创建对象时会**自动赋予默认值**。这是类属性和局部变量最大的区别之一

| 数据类型 | 默认值 |
| :--- | :--- |
| `byte`, `short`, `int`, `long` | `0` (long为`0L`) |
| `float`, `double` | `0.0f` / `0.0d` |
| `char` | `'\u0000'`（空字符） |
| `boolean` | `false` |
| **引用类型**（String、数组、自定义类） | `null` |

```java
public class Student {
    // 显式赋值 与 默认初始化
    String name;        // 默认 null
    int age;            // 默认 0（即使不写 = 0）
    double score = 95.5; // 显式赋值
}
```

---

##### (3) 类中方法的定义（行为）

- 方法用于描述对象**具备的功能**。它将一段可复用的代码封装起来
  - **语法**：`[修饰符] 返回值类型 方法名(参数列表) { // 方法体 }`
  - **分类**：实例方法（无`static`）和静态方法（有`static`）
  - **核心机制**：方法内可以访问该类的属性（成员变量），也可以通过`return`返回结果

```java
public class Student {
    String name;
    
    // 无返回值方法
    public void sayHello() {
        System.out.println("Hello, I'm " + name);
    }
    
    // 有返回值、有参数的方法
    public int addScore(int extraPoints) {
        return this.age + extraPoints; // this 指代当前对象
    }
}
```

| 关键字 | 调用目标 | 位置要求 | 核心规则 | 使用场景 |
| -------- | --------- | --------- | --------- | --------- |
| `this(...)` | 本类其他构造方法 | 必须是构造方法**第一行** | 不能循环调用；与 `super()` 互斥 | 减少构造方法间的重复代码，集中初始化逻辑 |
| `super(...)` | 父类构造方法 | 必须是构造方法**第一行** | 子类构造默认隐含 `super()`；手动调用则必须第一行 | 子类初始化时先完成父类部分 |

---

##### (4) 方法中的局部变量（必须手动初始化）

- 定义在**方法内部**或**代码块内部**（如 `for` 循环内）的变量叫局部变量
  - **生命周期**：方法被调用时创建，方法执行结束立即销毁（保存在栈内存中）
  - **⚠️ 致命规则**：**Java 不会给局部变量赋予任何默认值！** 你**必须**在首次使用它之前显式地给它赋一个初始值，否则编译报错（报错信息：`Variable 'xxx' might not have been initialized`）

```java
public void testMethod() {
    int count;          // 声明了，但未初始化
    // System.out.println(count); // ❌ 编译报错！未初始化
    
    count = 10;         // 显式赋值
    System.out.println(count); // ✅ 正确，输出 10
    
    // 注意：在 if 分支中赋值也要确保所有路径覆盖
    int result;
    boolean flag = true;
    if (flag) {
        result = 1;
    } else {
        result = 0;    // 必须保证 else 也赋值，否则编译器认为可能未初始化
    }
    System.out.println(result); // ✅ 安全
}
```

---

##### (5) **核心对比总结表**（面试高频）

| 比较维度 | **成员变量（属性）** | **局部变量（方法内）** |
| :--- | :--- | :--- |
| **定义位置** | 类内部，方法外部 | 方法内部 或 代码块内部（如`for`内） |
| **默认初始化** | **有默认值**（0, false, null） | **无默认值**，**必须手动赋值** |
| **生命周期** | 随对象的创建而存在，随对象被GC回收而销毁 | 随方法的调用而创建，方法结束出栈销毁 |
| **存储位置** | 堆内存（Heap）中，属于对象的一部分 | 栈内存（Stack）中 |
| **修饰符** | 可以用 `public`、`private`、`static`、`final` 等 | **不能使用**任何访问修饰符（如`public`） |

##### (6) 综合实战案例（一网打尽）

```java
public class Person {
    // 1. 成员变量（有默认初始化）
    public String name;      // 默认 null
    private int age;         // 默认 0
    
    // 2. 方法定义
    public void setInfo(String personName, int personAge) {
        // personName 和 personAge 是方法参数（属于局部变量）
        // 局部变量必须已赋值（参数由调用方传入，已保证初始化）
        this.name = personName;
        this.age = personAge;
    }
    
    public void display() {
        // 局部变量（必须手动初始化！）
        String greeting; 
        greeting = "Welcome"; // 如果注释掉这行，编译报错
        
        // 成员变量可以直接使用（因为有默认值）
        System.out.println(greeting + " " + name + ", age: " + age);
    }
    
    public static void main(String[] args) {
        Person p = new Person();
        p.setInfo("Alice", 25);
        p.display(); // 输出：Welcome Alice, age: 25
    }
}
```

> [!NOTE]
> **特别提醒**：如果你在方法中写 `int i; if(x > 0) { i = 1; } System.out.println(i);`，即使你逻辑上觉得 `x` 一定大于0，编译器依然会报错，因为它进行的是**编译期语法检查**，不执行代码逻辑。务必保证所有执行路径都完成了局部变量的赋值

#### 2.对象

> [!TIP]
> 把“类”比作**建筑设计图**，那么“对象”就是**按照这张图纸真实建造出来的房子**。图纸只有一份，但可以根据它建出无数栋房子，每栋房子都有自己的门牌号和内部状态

##### (1) 对象的定义

在Java中，使用`new`关键字来创建对象。这步操作会在内存的**堆(Heap)**中开辟一块空间，并执行构造方法来完成初始化

- **语法**：`类名 对象引用变量名 = new 构造方法();`

```java
// 假设我们有之前定义的 Student 类
public class Student {
    String name;   // 默认 null
    int age;       // 默认 0
    
    public void study() {
        System.out.println(name + " is studying.");
    }
}

// 在 main 方法中定义（创建）对象：
public class Test {
    public static void main(String[] args) {
        // 1. 声明并创建对象
        Student stu1 = new Student(); 
        // stu1 是一个引用变量，存储在栈内存中，它“指向”了堆内存中的真实对象
        
        // 2. 可以创建多个独立的对象
        Student stu2 = new Student();
    }
}
```

- **内存关键点**：`stu1` 和 `stu2` 是两个**完全独立**的空间。修改 `stu1` 的属性，完全不会影响 `stu2`

---

##### (2) 匿名对象（Anonymous Object）

**new 了对象，但不给它起名字**，直接当场使用，用完即弃

```java
// ① 直接调用方法（一次性使用）
new Dog("旺财").bark();  // 输出：旺财 汪汪叫
// 无法再次调用，因为没有引用变量保存它

// ② 作为参数传递（最常见）
feed(new Dog("大黄"));  // 传入匿名对象

public static void feed(Dog dog) {
    System.out.println("喂了 " + dog.name);
}
```

| 对比 | 匿名对象 | 有名对象 |
| ------ | --------- | --------- |
| **语法** | `new 类名()` | `类名 变量 = new 类名()` |
| **使用次数** | 只能一次 | 可以多次 |
| **生命周期** | 用完即回收 | 直到引用失效 |
| **典型场景** | 传参、打印、触发事件 | 需要反复调用方法 |

---

##### (3) 点运算符（`.`）的本质

点运算符（`.`）在Java中被称为**成员访问运算符**。它的作用非常直观：**通过对象的引用（即栈中的地址），找到堆中对应的那个对象，并操作里面的具体属性或方法**

> [!TIP]
> 你可以把它理解为“**的**”字——`stu1.name` 就是“stu1 的 name 属性”，`stu1.study()` 就是“让 stu1 执行 study 方法”

---

##### (4) 通过`.`访问对象的**属性**（赋值与取值）

对象创建后，属性会有默认值（前面讲过的默认初始化）。通过点运算符可以**修改**或**读取**这些属性

```java
public static void main(String[] args) {
    Student stu = new Student();
    
    // 1. 访问属性（取值）—— 此时输出默认值 null 和 0
    System.out.println(stu.name); // 输出 null
    System.out.println(stu.age);  // 输出 0
    
    // 2. 通过点运算符修改属性（赋值）
    stu.name = "Alice";
    stu.age = 22;
    
    // 3. 再次访问，输出修改后的值
    System.out.println(stu.name); // 输出 Alice
    System.out.println(stu.age);  // 输出 22
}
```

---

##### (5) 通过`.`访问对象的**方法**（执行行为）

访问方法同样使用点运算符，但**必须带上小括号 `()`**，即使方法没有参数

```java
public static void main(String[] args) {
    Student stu = new Student();
    stu.name = "Bob";
    
    // 调用实例方法（无参）
    stu.study(); // 输出：Bob is studying.
    
    // 如果方法有返回值，可以接收
    // 假设有方法 public int getAge() { return this.age; }
    // int currentAge = stu.getAge(); 
}
```

---

##### (6) 深入内存模型

- **栈内存（Stack）**：存放`stu`这个变量，它存储的是一个**内存地址编号**（比如 `0x1234`）
- **堆内存（Heap）**：存放真正的`Student`对象，里面有`name`、`age`和指向方法区中`study()`代码的指针

- 当你执行`stu.name`时，JVM 的**执行流程**是：
  1. 找到栈中的变量`stu`，取出其保存的地址`0x1234`
  2. 顺着地址去堆中找到对应的对象实例
  3. 在该对象实例中定位到`name`属性，进行读写操作

---

##### (7) **核心避坑指南**（面试+开发常见报错）

| 常见误区 | 正确解析 | 报错/后果 |
| :--- | :--- | :--- |
| **NullPointerException（空指针）** | 只声明了引用变量（`Student stu;`），但没有用`new`创建对象就尝试访问属性或方法 | 编译通过，**运行时报错**并终止程序。必须`stu = new Student();`才能使用 |
| **静态成员（static）误用** | 用对象名去访问静态变量/方法（如`stu.schoolName`） | 虽然语法允许，但**强烈不推荐**。静态成员属于“**类**”而非“**对象**”，应该用`类名.静态成员`访问，否则容易造成代码混乱 |
| **封装性破坏（实际开发规范）** | 直接用`对象.属性`（如`stu.age = -10`）随意赋值 | 在大型项目中，属性通常设为`private`（私有），**不允许**外部通过点直接访问。必须通过`setAge()`等公共方法赋值，以便在方法内做逻辑校验（如判断年龄不能为负数） |

> [!TIP]
> **总结一句口诀**：`new` 出来的是实体，`.` 是用来找东西的钥匙；别忘了先 `new` 再用点，否则空指针找上你

#### 3.构造方法

> [!TIP]
> 把“类”比作**建筑设计图**，“对象（`new`出来的实例）”比作**建成的房子**，那么**构造方法**就是那个**施工队**——它的唯一使命就是：**把图纸变成实实在在的房子，并且在交付前完成内部的“初始装修”（即初始化对象的属性）**

##### (1) 构造方法的定义（特殊的方法）

- 构造方法是一种特殊的方法，专门用于**创建对象时初始化对象的成员变量**
- **它的三大语法铁律：**
  1. **方法名必须与类名完全一致**（包括大小写）
  2. **没有返回值类型**（连 `void` 都不能写）
  3. 不能被`static`、`final`等修饰，通常使用`public`

```java
public class Student {
    String name;
    int age;

    // 1. 构造方法的定义（无参构造）
    public Student() {
        System.out.println("施工队开始干活，创建了一个学生对象！");
    }

    // 2. 构造方法的重载（有参构造）
    public Student(String n, int a) {
        name = n;   // 用传入的参数给属性赋值（初始化）
        age = a;
        System.out.println("创建了一个有名有姓的学生：" + n);
    }
}
```

---

##### (2) 默认构造方法

- 如果你在类中**没有显式定义任何构造方法**，Java 编译器会在编译时**自动**为你添加一个**无参数的、方法体为空的默认构造方法**
  - **默认构造方法的形态**：`public Student() {}`
- **⚠️ 核心陷阱（面试高频）：一旦你手动定义了构造方法，编译器就不再赠送默认构造方法了！**

```java
public class Teacher {
    String name;
    
    // 手动定义了一个有参构造
    public Teacher(String n) {
        name = n;
    }
    
    public static void main(String[] args) {
        // Teacher t = new Teacher(); // ❌ 编译报错！因为有了有参构造，无参的默认构造被覆盖了
        Teacher t = new Teacher("张三"); // ✅ 必须匹配已有的构造方法
    }
}
```

---

##### (3) 使用 `new` 运算符调用构造方法（执行流程详解）

- `new`关键字是触发构造方法的“扳机”。在执行`new Student("Alice", 18)`时，JVM 在背后做了三步关键动作：
  1. **开辟内存空间**：在堆（Heap）中为对象分配一块足够的内存，此时成员变量被赋予**默认值**（`name=null`,`age=0`）
  2. **调用构造方法**：将传入的参数（`"Alice"`,`18`）传递给构造方法，执行方法体内部的赋值逻辑（`name = "Alice"`,`age = 18`），**覆盖掉默认值**
  3. **返回引用地址**：构造方法执行完毕后，`new`运算符将堆中这块内存的地址值返回，赋值给左边的引用变量（如`stu`）

```java
public class Test {
    public static void main(String[] args) {
        // new 运算符触发了构造方法
        Student stu = new Student("Alice", 18);
        // stu 现在指向堆中一个 name="Alice", age=18 的对象
        
        System.out.println(stu.name); // 输出 Alice
        System.out.println(stu.age);  // 输出 18
    }
}
```

---

##### (4) **构造方法的核心要点与避坑指南**

- **对比表**:

| 对比维度 | **构造方法** | **普通成员方法** |
| :--- | :--- | :--- |
| **方法名** | 必须与类名**相同** | **随意**（符合命名规范即可） |
| **返回值** | **无**返回值类型（`void`也不能写） | **必须有**返回值类型（如`void`、`int`） |
| **调用方式** | **只能用`new`调用**（或本类中用`this()`） | 通过**对象或类名**直接调用 |
| **执行时机** | 对象创建时**自动执行**，且只执行一次 | 对象创建后**手动调用**，可执行多次 |
| **作用** | 给属性赋初始值 | 描述对象的行为功能 |

- **进阶语法**（了解即可，后期常用）：
  - **构造方法重载**：可以定义多个参数列表不同的构造方法（如无参、一个参、两个参），根据`new`时传递的参数个数自动匹配
  - **`this()`调用**：在一个构造方法中，可以使用`this(参数)`调用另一个构造方法，且**必须写在第一行**

```java
public class Car {
    String brand;
    double price;

    // 无参构造
    public Car() {
        // this() 调用下面的有参构造，并传入默认值
        this("未知品牌", 0.0); 
    }

    // 有参构造
    public Car(String b, double p) {
        brand = b;
        price = p;
    }
}
```

> [!TIP]
> **总结一句口诀**：`new` 一下开空间，构造方法把值填；若问默认有没有，没写构造它就有；一旦自己写了参，无参构造不再有

#### 4. 类之间的关系（UML 核心）

##### (1) 关联（Association）

- **定义**：一个类的对象与另一个类的对象之间的**引用关系**
- **代码表现**：一个类将另一个类作为**成员变量**
- **方向性**：
  - **单向关联**：A 引用 B，`class A { B b; }`
  - **双向关联**：A 引用 B，B 也引用 A

```java
// 单向关联：学生 关联 班级
class Student {
    String name;
    ClassRoom room;  // 学生知道自己在哪个班
}

class ClassRoom {
    String roomNo;
}

// 双向关联：学生知道自己在哪个班，班级也知道有哪些学生
class Student {
    String name;
    ClassRoom room;  // 学生知道自己在哪个班

    public void setRoom(ClassRoom room) {
        this.room = room;
        room.students.add(this);  // 自动维护双向关系
    }
}

class ClassRoom {
    String roomNo;
    List<Student> students = new ArrayList<>();  // 班级知道有哪些学生

    public void addStudent(Student s) {
        students.add(s);
        s.room = this;  // 自动维护双向关系
    }
}
```

---

##### (2) 多重性（Multiplicity）

表示一个类的多少个实例与另一个类的多少个**实例**相关联

| 表示法 | 含义 | 示例 |
| -------- | ------ | ------ |
| `1` | 恰好 1 个 | 一个人有 1 个身份证 |
| `0..1` | 0 或 1 个 | 一个员工可能有 0 或 1 个直属经理 |
| `*` / `0..*` | 0 到多个 | 一个班级有多个学生 |
| `1..*` | 1 到多个 | 一个订单至少有 1 个商品 |
| `m..n` | m 到 n 个 | 一个小组 3~5 人 |

---

- ① 一对一（1 : 1）

```java
// 一个人 对应 一个身份证
class Person {
    String name;
    IDCard idCard;  // 1
}

class IDCard {
    String number;
    Person owner;   // 1
}
```

---

- ② 一对多（1 : *）

```java
// 一个班级 有 多个学生
class ClassRoom {
    String roomNo;
    List<Student> students = new ArrayList<>();  // *
}

class Student {
    String name;
    ClassRoom room;  // 1
}
```

---

- ③ 多对多（\*:\*）

```java
// 一个学生 选 多门课，一门课 被 多个学生选
class Student {
    String name;
    List<Course> courses = new ArrayList<>();  // *
}

class Course {
    String name;
    List<Student> students = new ArrayList<>();  // *
}
```

---

#### (3) **聚合 vs 组合**（关联的两种特殊形式）

| 维度 | 聚合（Aggregation） | 组合（Composition） |
| :--- | :--- | :--- |
| **关系** | 弱 Has-A（" has-a "） | 强 Has-A（" contains-a "） |
| **生命周期** | 部分可以**脱离整体**独立存在 | 部分**不能脱离**整体，同生共死 |
| **代码表现** | **外部传入，Setter 注入** | **内部创建，构造注入** |
| **UML** | 空心菱形 ◇ | 实心菱形 ◆ |
| **示例** | 部门有员工，员工换部门照样活 | 汽车有引擎，汽车报废引擎也报废 |

```java
// ========== 聚合：弱关系，可独立 ==========
class Department {
    List<Employee> employees;  // 外部传入，可以换部门
    
    public void addEmployee(Employee e) {
        employees.add(e);
    }
}

// 员工可以脱离部门存在
Employee emp = new Employee("张三");
Department dept = new Department();
dept.addEmployee(emp);
// emp 还可以加入别的部门

// ========== 组合：强关系，同生共死 ==========
class Car {
    Engine engine;  // 构造时创建，不可更换
    
    public Car() {
        this.engine = new Engine("V8");  // 内部创建
    }
}

// engine 随 Car 创建而创建，随 Car 销毁而销毁
```

---

#### (4) 关系强度总结

```java
依赖 < 关联 < 聚合 < 组合 < 继承
          （弱 → 强）
```

| 关系 | 特点 | 代码特征 |
| ------ | ------ | --------- |
| **依赖** | 临时使用 | 方法参数、局部变量 |
| **关联** | 长期持有引用 | 成员变量 |
| **聚合** | 整体-部分，可分离 | 外部传入成员 |
| **组合** | 整体-部分，不可分离 | 内部创建成员 |
| **继承** | is-a 关系 | `extends` |

#### 5.组合

> [!TIP]
> 把“类”比作“积木”，**组合**就是“**把一块积木嵌套进另一块积木里**”。在Java中，就是在A类的属性位置上，声明B类的对象

##### (1) 什么是组合（Has-A 关系）

组合体现的是 **“有一个”**（Has-A）的关系

- **语法**：直接在类中定义另一个类的引用变量作为属性
- **核心意义**：通过组合，旧类（如`Engine`）可以成为新类（如`Car`）的一部分，**直接复用**旧类的功能，而**无需修改**旧类的代码

---

##### (2) 基本语法与定义

```java
// 1. 定义零部件类（被组合的类）
class Engine {
    String type;
    
    public Engine(String type) {
        this.type = type;
    }
    
    public void start() {
        System.out.println(type + "引擎启动了");
    }
}

// 2. 定义整车类（组合类）
class Car {
    String brand;
    
    // ★★★ 核心：把 Engine 类的对象作为 Car 的一个属性 ★★★
    Engine engine; 
    
    // 构造方法（通常通过外部传入，或者在内部 new）
    public Car(String brand, Engine engine) {
        this.brand = brand;
        this.engine = engine; // 将传入的引擎对象赋值给当前车的引擎属性
    }
    
    public void drive() {
        System.out.print(brand + "正在行驶：");
        engine.start(); // 通过 . 运算符，调用引擎的方法
    }
}
```

---

##### (3) **致命陷阱：初始化**

> [!WARNING]
> 请回顾我们之前讲过的“成员变量默认初始化”。`Car`类中的`Engine engine;`仅仅是一个引用，**默认值是`null`**
> 如果你忘记给`engine`赋值，就调用`engine.start()`，**100% 会抛出`NullPointerException`（空指针异常）**

- **正确的初始化方式（三种常见写法）：**

| 初始化方式 | 代码示例 | 特点 |
| :--- | :--- | :--- |
| **构造方法传入（最推荐）** | `public Car(Engine e) { this.engine = e; }` | 解耦，灵活，测试方便（依赖注入思想） |
| **在内部直接 new（强耦合）** | `this.engine = new Engine("V8");` | 简单，但 Car 和 Engine 绑死，不灵活 |
| **使用 Setter 方法后置注入** | `public void setEngine(Engine e) { this.engine = e; }` | 允许创建对象后再装配 |

```java
public static void main(String[] args) {
    // 正确做法：先造好引擎
    Engine v8 = new Engine("V8");
    // 造车时把引擎装进去
    Car myCar = new Car("BMW", v8);
    myCar.drive(); // 输出：BMW正在行驶：V8引擎启动了

    // ❌ 错误示范（会报错）：
    Car badCar = new Car("Tesla", null);
    // badCar.drive(); // 运行时抛出 NullPointerException！
}
```

---

##### (4) 通过点运算符（`.`）的“链式调用”

当你访问组合对象内部的属性或方法时，需要**连续使用点运算符**，像链条一样层层深入

```java
class Address {
    String city;
    public Address(String city) { this.city = city; }
    public String getCity() { return city; }
}

class Student {
    String name;
    Address address; // 组合 Address
    
    public Student(String name, Address address) {
        this.name = name;
        this.address = address;
    }
    
    public void showInfo() {
        // 链式调用：先拿到 address 对象，再调用 address 的 getCity()
        System.out.println(name + " 住在 " + address.getCity()); 
        // 等价于：
        // Address addr = this.address; 
        // System.out.println(addr.getCity());
    }
}
```

---

##### (5) **组合 vs 继承**

| 对比维度 | **组合（Has-A）** | **继承（Is-A）** |
| :--- | :--- | :--- |
| **关系** | “有一个” (Car has an Engine) | “是一个” (Dog is an Animal) |
| **耦合度** | **低**（汽车不关心引擎内部怎么点火，只调用方法） | **高**（子类依赖父类的实现细节） |
| **代码复用** | 复用现有类的功能，且可以随时更换内部对象 | 复用父类代码，但修改父类可能影响所有子类 |
| **设计原则** | **优先使用组合**（Effective Java 极力推荐） | 仅在明确的“父子”层次结构时使用 |

> [!TIP]
> **类里套类为组合，`new`好传参防空指针；一层一层点下去，`Has-A`复用稳如山**

### ==(二). 三大特性==

#### 1. ==**封装**== (Encapsulation)

##### (1)**封装核心思想**

- **隐藏内部细节，通过接口访问**

---

##### (2) **优点**

- 良好的封装能够**减少耦合**
- 类内部的结构可以**自由修改**
- 可以对成员变量进行更**精确的控制**
- 隐藏信息，实现细节

- 示例:

``` java
class Student {
    private int score; // 私有化变量，外部无法直接访问

    // 提供公共方法访问和修改
    public void setScore(int s) {
        if (s >= 0 && s <= 100) {
            score = s;
        } else {
            System.out.println("分数非法！");
        }
    }

    public int getScore() {
        return score;
    }
}
```

#### 2. ==**继承**== (Inheritance)

##### (1)**继承核心思想**

- **代码复用, extends 关键字**

```java
// 父类
class Animal {
    public void eat() {
        System.out.println("动物在吃东西");
    }
}

// 子类继承父类
class Dog extends Animal {
    // 重写方法 (Override)
    @Override
    public void eat() {
        System.out.println("狗在吃骨头");
    }
}
```

---

##### (2)操作

将多个子类中**重复的代码抽取**到父类，子类可以直接使用父类中的这段代码

---

##### (3) **好处**

- **减少代码冗余**，避免重复编写相同逻辑
- **提高代码复用性**，让代码更简洁易维护

---

##### (4) 子类真正能继承父类的是什么？

- **构造方法**：不能被子类继承，可以利用 `super` 关键字调用
- **成员变量**：可以被子类继承，`private` 私有的也可以，但是私有的无法直接调用
- **成员方法**：
  - 虚方法可以被继承
  - `final` 修饰的最终方法可继承，不可重写，可以被调用
  - `static` 修饰的静态方法可继承，不可重写（只能被隐藏），可以被调用
  - `private` 修饰的私有方法不能被继承，不能被调用

---

##### (5) 继承的特点

- **继承类型规则**：Java 只支持**单继承**，不支持**多继承**，但支持**多层继承**
  - *单继承*：一个子类只能继承一个父类
  - *不能多继承*：子类无法同时继承多个父类
  - *多层继承*：子类可以继承父类，父类又可继承更上层的父类，形成继承链（如 `C extends B`，`B extends A`）

- **父类分类**：
  - *直接父类*：子类直接继承的类
  - *间接父类*：子类间接继承的上层类（如“爷爷类”）

- **顶级父类**：
  - Java 中的顶级父类是 `java.lang.Object`
  - 所有类都直接或间接地继承自 `Object` 类

---

##### (6) **继承中的成员变量**

- **书写规则**:
  **抽取共性**：将重复的成员变量提取到父类，子类保留独有变量
- **访问规则**:
  **就近原则**：按「局部位置 → 本类成员 → 父类成员」的顺序逐级往上找
- **重名变量处理**:

| 写法 | 含义 |
| ----------- | -------------------- |
| name | 遵循就近原则访问 |
| this.name | 明确访问**本类**成员变量 |
| super.name | 明确访问**父类**成员变量 |

---

##### (7) **继承中的方法重写**

- **什么是方法重写？**
  - 在继承体系中，子类出现了和父类中**一模一样的方法声明**，就称子类的这个方法是重写的方法
  - 重写的方法上需要加`@Override`**注解**，用于校验重写的语法是否正确

- **什么时候使用方法重写？**
  - 当父类的方法不能满足子类要求的时候，需要进行方法重写

- **重写方法的基本要求**
  - 子类重写的方法**声明**跟父类**保持一致**
  - `private` 私有方法、`static` 静态方法、`final` 最终方法 **不能被重写**

- ==**示例代码**==

```java
// 父类
class Animal {
    public void eat() {
        System.out.println("动物会吃东西");
    }

    private void sleep() {
        System.out.println("动物会睡觉");
    }

    public static void breathe() {
        System.out.println("动物会呼吸");
    }

    public final void move() {
        System.out.println("动物会移动");
    }
}

// 子类
class Dog extends Animal {
    // 重写父类的eat方法
    @Override
    public void eat() {
        System.out.println("狗吃骨头");
    }

    // 错误示例：不能重写private方法
    // @Override
    // private void sleep() {
    //     System.out.println("狗睡觉");
    // }

    // 错误示例：不能重写static方法
    // @Override
    // public static void breathe() {
    //     System.out.println("狗呼吸");
    // }

    // 错误示例：不能重写final方法
    // @Override
    // public void move() {
    //     System.out.println("狗跑");
    // }

    public void testCall() {
        // this调用：先找本类，再找父类
        this.eat();
        // super调用：直接找父类
        super.eat();
    }
}

// 测试类
public class Main {
    public static void main(String[] args) {
        Dog dog = new Dog();
        dog.eat(); // 输出：狗吃骨头
        dog.testCall(); // 输出：狗吃骨头；动物会吃东西
    }
}
```

##### (8) 继承中的构造方法

- **继承中构造方法的核心规则**
  - **父类构造方法不可继承**：父类的构造方法不会被子类继承，只能通过 `super` 关键字在子类构造器中调用。必须手动编写 `super(参数列表)`，不可省略
  - **默认 `super()` 机制**：如果子类构造方法中没有手动书写 `super(...)`，JVM 会自动在子类构造器第一行添加 `super()`，用于调用父类的**无参构造**方法
  - **执行顺序**：创建子类对象时，**先执行父类构造方法**，再执行子类构造方法

- **示例代码**

```java
// 父类
public class Fu {
    String name;
    int age;

    // 父类无参构造
    public Fu() {
        System.out.println("父类无参构造执行了~");
    }

    // 父类带参构造
    public Fu(String name, int age) {
        this.name = name;
        this.age = age;
        System.out.println("父类带参构造执行了~");
    }
}

// 子类
public class Zi extends Fu {
    // 子类无参构造（默认隐含 super()）
    public Zi() {
        // super(); // JVM 自动添加，调用父类无参构造
        System.out.println("子类无参构造执行了~");
    }

    // 子类带参构造（手动调用父类带参构造）
    public Zi(String name, int age) {
        super(name, age); // 必须手动编写，调用父类带参构造
        System.out.println("子类带参构造执行了~");
    }
}

// 测试类
public class Test {
    public static void main(String[] args) {
        // 调用子类无参构造：先执行父类无参构造，再执行子类无参构造
        Zi zi1 = new Zi();
        // 调用子类带参构造：先执行父类带参构造，再执行子类带参构造
        Zi zi2 = new Zi("张三", 20);
    }
}
```

##### (9) **==Java 继承结构设计==**

- **核心条件**:
  - **存在共性内容**：多个类之间有相同的属性（成员变量）和行为（成员方法）
  - **满足 is-a 关系**：子类是父类中的一种（逻辑上属于父类的子类，如“`猫 is a 动物`”）

- **普通继承设计思路**:
  - 抽取所有相关类的**共性代码**（属性 + 方法）到父类中
  - 子类通过 `extends` 关键字继承父类
  - 子类在复用父类共性功能的基础上，实现自身特有的功能

- **复杂继承设计步骤**
  - **利用画图法解决**：通过画图梳理类与类之间的层级关系
  - **分类**：将具有相似特征的类归为一组，明确逻辑边界
  - **抽取共性内容（从下往上画）**：从最底层子类开始，逐层向上抽取重复的属性和方法到上层父类
  - **编写代码（从上往下写）**：按照父类→子类的顺序，从顶层父类开始逐层实现代码

#### 3. ==**多态**== (Polymorphism)

##### (1) **多态核心思想**

- **同一接口，多种实现**

- **核心代码形式**：父类类型 变量名 = new 子类对象()

- **调用**：变量调用的方法如果被子类重写了，实际执行子类的方法

---

##### (2) **前提**

- 父类引用指向子类对象(necessary)
- 有继承/实现关系(necessary)
- 有方法重写(optional)

---

##### (3) **多态的好处**

- **提高代码扩展性**
  方法中使用父类型作为参数，可接收父类对象 + 所有子类对象，无需为每个子类单独编写方法
- **灵活性**
  在运行时动态绑定具体对象的行为，使程序能够适应变化，例如通过配置或参数传入不同子类
- **消除类型之间的耦合关系**
  多态允许针对抽象类型（父类或接口）编程，而不是具体实现类，从而降低模块间的依赖
- **可替换性**
  任何子类对象都可以在不改变调用代码的前提下替换父类对象
- **可扩充性**
  新增子类或实现类时，无需修改依赖抽象类型的既有代码，系统易于扩展
- **实现动态绑定**
  若子类重写了父类方法，通过多态调用时，会自动执行对应子类中重写的方法，做到“同一接口，多种实现”
- **接口性**
  多态通过统一的接口（父类或接口定义）对外暴露行为，具体实现隐藏在子类中
- **简化性**
  调用者只需知道抽象类型的方法，不必关心细节，代码更简洁、易读

---

##### (4)**多态调用成员的特点**

- **变量调用**：**编译看左边，运行也看左边**
  - 编译：检查引用类型（父类）是否存在该变量
  - 运行：执行引用类型（父类）的变量值，不被子类覆盖
- **方法调用**：**编译看左边，运行看右边**
  - 编译：检查引用类型（父类）是否存在该方法
  - 运行：执行实际对象类型（子类）的重写方法
  
---

##### (5) 多态的弊端

- **弊端**：多态环境下，父类引用无法直接调用子类的独有功能
- **原因**：编译时只检查引用类型（父类），子类独有方法不在父类定义中，编译报错
- **解决方案**：向下转型(强制类型转换)

- ==**示例**==:

```java
// 格式：子类类型 变量名 = (子类类型) 父类引用;
if (父类引用 instanceof 子类类型) {
    子类类型 子类变量 = (子类类型) 父类引用;
    子类变量.子类独有方法();
}
```

- **解决的问题**
将父类引用转换为真实的子类类型，从而调用子类的独有功能（弥补多态的弊端）
- **注意事项**
  - **类型不匹配会报错**：转换类型与对象真实类型不一致时，抛出 `ClassCastException`
  - **必须先判断类型**：使用 `instanceof` 关键字校验后再转换

---

### (三)抽象类和抽象方法

#### 1.**抽象方法**

##### (1) 定义

当父类知道子类需要完成某个功能，但不确定子类怎么实现时，父类将该方法定义为**抽象方法**，具体实现交给子类

##### (2) **抽象方法格式**

```java
修饰符 abstract 返回值类型 方法名(参数列表);
```

##### (3) **抽象方法特点**

- **只有方法声明，没有方法体**
- 必须用`abstract`修饰

---

#### 2. **抽象类**

##### (1) 抽象类定义

包含抽象方法的类，必须定义为抽象类

##### (2) **抽象类格式**

```java
修饰符 abstract class 类名 {
    // 成员变量
    // 构造方法
    // 普通方法
    // 抽象方法
}
```

##### (3) **抽象类特点**

- **抽象类不能实例化**（不能 new 对象）
- **抽象类可以有**：成员变量、构造方法、普通方法、抽象方法
- 抽象类的构造方法是给**子类创建对象时使用**的

---

#### 3. **抽象类的使用规则**

- 子类**继承**抽象父类
- 子类**必须重写**所有抽象方法，否则子类也必须是抽象类
- 最终**必须**有一个子类**重写全部抽象方法**，才能创建对象

---

#### 4. **示例代码**

```java
// 抽象父类
abstract class Animal {
    private String name;

    public Animal(String name) {
        this.name = name;
    }

    // 抽象方法
    public abstract void eat();
    public abstract void sleep();

    public String getName() {
        return name;
    }
}

// 子类
class Dog extends Animal {
    public Dog(String name) {
        super(name);
    }

    @Override
    public void eat() {
        System.out.println("狗吃骨头");
    }

    @Override
    public void sleep() {
        System.out.println("狗躺着睡");
    }
}

// 测试
public class Test {
    public static void main(String[] args) {
        Dog dog = new Dog("旺财");
        dog.eat();
        dog.sleep();
    }
}
```

---

#### 5.==**抽象类的意义总结**==

- **强制规范**：规定子类必须具备哪些功能，统一结构
- **提高扩展性**：父类只定义标准，不关心实现，便于扩展不同子类
- **代码复用**：把共性内容抽到抽象类，子类只需实现个性化部分
- **多态基础**：抽象类可作为父类引用，指向子类对象，便于统一管理

### (四)接口

> [!NOTE]
> 继承(extends) -> 继承[**本质特性**]
> 接口(implements) -> 赋予[**行为能力**]

#### 1.**接口基础概念**

- **本质**：独立于继承体系的**行为规则**

- **定义**：

```java
public interface 接口名 {
    // 成员变量（常量）
    // 抽象方法
}
```

- **使用**：类与接口是**实现关系**，用  implements  关键字：

```java
public class 类名 implements 接口名 {
    // 重写接口中所有抽象方法
}
```

---

#### 2.**核心规则**

- 接口**不能实例化**
- 实现类**必须重写所有抽象方法**，否则自身为抽象类
- 一个类可**实现多个接口**，也可继承类+实现多个接口

---

#### 3.**成员特点**

- **成员变量**：
  - 默认`public static final`，只能是**常量**
  - 必须在定义时赋值，且**不可修改**
- **构造方法**：无构造方法,**不能创建**对象
- **成员方法**：
  - 本质是**抽象方法**，默认 `public abstract`（抽象方法）
  - JDK 版本演进：
    - JDK 7 及以前：只能定义抽象方法
    - JDK 8 新特性：可定义有方法体的默认方法、静态方法
    - JDK 9 新特性：可定义私有方法（用于代码复用）

---

#### 4. ==**关系总结**==

- **类与类**：单继承，可多层继承
- **类与接口**：
  - **实现关系**：可以单实现、多实现，也可在继承一个类的同时实现多个接口
  - **注意**：多个接口中若有**重复**抽象方法，实现类只需**重写一次**
- **接口与接口**：
  - 可以单继承，也可多继承（一个接口可继承多个接口）
  - 注意：接口继承多个接口时，会继承**所有抽象方法**，实现类需**重写全部**

---

#### 5. **示例代码**

```java
// 1. 定义接口（规则）
interface Swim {
    // 常量：默认 public static final
    int MAX_DEPTH = 100;

    // 抽象方法：默认 public abstract
    void swim();
}

interface Fly {
    void fly();
}

// 2. 父类
class Animal {
    public void eat() {
        System.out.println("动物会吃饭");
    }
}

// 3. 子类：继承类 + 实现多个接口
class Duck extends Animal implements Swim, Fly {
    // 重写Swim接口的抽象方法
    @Override
    public void swim() {
        System.out.println("鸭子会游泳，最深下潜" + MAX_DEPTH + "米");
    }

    // 重写Fly接口的抽象方法
    @Override
    public void fly() {
        System.out.println("鸭子会低空飞行");
    }
}

// 4. 测试
public class InterfaceDemo {
    public static void main(String[] args) {
        Duck duck = new Duck();
        duck.eat();    // 继承自Animal
        duck.swim();   // 实现自Swim接口
        duck.fly();    // 实现自Fly接口
    }
}
```

---

#### 6.接口在JDK 8和9 的新增特性

##### (1) 默认方法（JDK 8）

- **作用**：接口升级时不破坏现有实现类代码
- **格式**：`public default 返回值类型 方法名(参数列表) {}`
- **注意**：
  - 不是抽象方法，不强制重写；重写时需去掉 `default`
  - `public` 可省略，`default` 不可省略
  - 多接口同名默认方法时，实现类必须重写

---

##### (2) 静态方法（JDK 8）

- **作用**：接口级工具方法
- **格式**：`public static 返回值类型 方法名(参数列表) {}`
- **注意**：
  - 只能通过**接口名**调用，不能用实现类/对象调用
  - `public` 可省略，`static` 不可省略

---

##### (3) 私有方法（JDK 9）

- **作用**：抽取默认/静态方法中的重复代码，实现复用
- **格式**：
  1. **实例私有**：
     - 作用：为了抽取**默认方法**中重复代码而出现的
     - 格式：`private 返回值类型 方法名(参数列表) {}`
  2. **静态私有**：
     - 作用：为了抽取**静态方法**中重复代码而出现的
     - 格式：`private static 返回值类型 方法名(参数列表) {}`
- **注意**：仅接口内部可见，供默认/静态方法调用

---

##### (4) **示例代码**

```java
// 接口定义
interface MyInterface {
    // 1. 默认方法
    default void defaultMethod() {
        System.out.println("默认方法");
        commonCode(); // 调用私有方法
    }

    // 2. 静态方法
    static void staticMethod() {
        System.out.println("静态方法");
        staticCommonCode(); // 调用静态私有方法
    }

    // 3. 私有方法（JDK9+）
    private void commonCode() {
        System.out.println("公共代码（实例）");
    }

    private static void staticCommonCode() {
        System.out.println("公共代码（静态）");
    }
}

// 实现类
class MyImpl implements MyInterface {}

// 测试
public class Test {
    public static void main(String[] args) {
        MyImpl impl = new MyImpl();
        impl.defaultMethod(); // 调用默认方法
        MyInterface.staticMethod(); // 调用静态方法
    }
}
```

### (五)内部类

#### 1. 什么是内部类

一个类定义在另一个类的内部

---

#### 2. **四种内部类对比**

| 类型 | 修饰符 | **能否访问外部类私有成员** | 创建方式 |
| ------ | -------- | --------------------- | ---------- |
| 成员内部类 | 无 | ✅ | `外部类实例.new 内部类()` |
| 静态嵌套类 | `static` | ❌（只能访问静态成员） | `new 外部类.内部类()` |
| 局部内部类 | 无（方法内） | ✅ | 只能在定义它的方法内创建 |
| 匿名内部类 | 无（表达式） | ✅ | `new 父类/接口() { 方法实现 }` |

---

#### 3.成员内部类  

##### (1)成员内部类特点

- **依赖外部类对象**，持有外部类 `this` 引用,必须先有外部类对象，才能创建部类对象

---

##### (2)成员内部类访问规则

- **同名成员冲突**:内部类拥有和外部类同名的成员变量或者方法时，会发生隐藏象，内部类**默认访问自己的成员**，需要以下面的形式进行访问:
  - `外部类.this.成员变量`
  - `外部类.this.成员方法`
- **外部类访问内部类**:必须创建一个成员内部类的对象，通过指向这个对象的引用访问
- **内部类无条件访问**外部类的**所有成员**(包括 private 和静态成员)

---

##### (3)成员内部类代码示例

```java
class Circle {
    private double radius = 0;
    public static int count = 1;

    public Circle(double radius) {
        this.radius = radius;
        // 外部类中访问内部类：先创建对象
        new Draw().drawShape();
    }

    class Draw {   // 成员内部类
        private double radius = 10;  // 同名变量，隐藏外部类的radius

        public void drawShape() {
            System.out.println(radius);        // 10（内部类自己的）
            System.out.println(Circle.this.radius); // 0（外部类的）
            System.out.println(count);         // 1（外部类静态成员）
        }
    }
}
```

---

##### (4)**创建内部类对象**

前提是必须存在一个外部类的对象

```java
// 方式1：通过外部类实例 .new
Circle outer = new Circle(5.0);
Circle.Draw draw = outer.new Draw();

// 方式2：由外部类提供一个返回内部类对象的方法
Circle.Draw draw2 = outer.getDrawInstance();
```

---

##### (5)**成员内部类访问权限**

- **成员内部类**：可以`private`、默认、`protected`、`public`（共4种）
- **含义与普通成员一致**：`private`仅外部类内；默认同包；`protected`同包 + 子类;`public`任意
- **顶层外部类**：外部类只能`public`或默认，不能`private`/`protected`
- **原因**：==内部类**本质是外部类的成员**==，享有成员级别的权限控制

---

#### 4.局部内部类

- 定义在**方法内部**，作用域仅限该方法，**和成员内部类的区别**在于局部内部类的访问仅限于方法内或者该作用域内
- 访问方法的局部变量时，该变量**必须**是`final`或`effectively final`
- 局部内部类就像是**方法里面的一个局部变量**一样，是不能有`public`、`protected`、`private`以及`static`修饰符的

#### 5.匿名内部类

- **匿名内部类 = 创建对象 + 实现接口/继承类，写在表达式中，没有名字，没有构造器**

##### (1)匿名内部类定义

- 没有名字的内部类
- 在创建对象的同时，实现接口或继承父类的方法
- **想用一个类，但又懒得给它起名字，直接在用它的地方把类给写了**

---

##### (2)匿名内部类典型场景

```java
// 按钮事件监听（Android / Java Swing）
button.setOnClickListener(new OnClickListener() {
    @Override
    public void onClick(View v) {
        // 处理点击
    }
});
```

**效果**：直接生成一个实现了 `OnClickListener` 接口的对象，无需单独定义类

---

##### (3) **特点**

- **没有构造器**（因为没名字，无法定义构造方法）
- **不能有访问修饰符**（`private`、`protected`、`public` 都不行）
- **不能有 `static` 修饰**
- 编译后文件名：`外部类$编号.class`（如 `Outter$1.class`）

---

##### (4)与“单独定义一个类”的对比

| 方式 | 代码量 | 可维护性 | 适用场景 |
| ------ | -------- | ---------- | ---------- |
| 匿名内部类 | 少（就地实现） | 高（紧贴使用处） | **一次性使用**，逻辑简单 |
| 单独定义一个类 | 多（需额外类文件） | 低（分散） | 多个地方重复使用 |

---

##### (5) **使用限制**

- 主要用于**接口回调**或继承抽象类
- 通常只重写或实现**已有方法**，不额外定义新方法（因为无法用子类特有的类型去调用新方法）

---

##### (6) **深入理解**

- 假设有一个打招呼的接口

```java
interface Greeting {
    void sayHello();
}
```

- 正常写法（需要单独起个类名）

```java
// 单独写一个类，实现接口
class EnglishGreeting implements Greeting {
    public void sayHello() {
        System.out.println("Hello");
    }
}

// 使用时
Greeting g = new EnglishGreeting();
g.sayHello();
```

- **匿名内部类写法**（不取名，直接用）

```java
Greeting g = new Greeting() {
    public void sayHello() {
        System.out.println("Hello");
    }
};
g.sayHello();
```

### (七) **Override/Overload**

#### 1. **Override**

##### (1) Override定义

子类中定义一个与父类方法名、参数列表、返回值类型完全相同的方法，并且子类方法的实现覆盖了父类方法的实现，**外壳不变，核心重写**

---

##### (2) Override特点

- 子类可以根据需要，定义特定于自己的行为
- 使用子类对象调用该方法时，执行子类中的方法

---

##### (3) **方法的重写规则**

- **参数列表**与被重写方法的参数列表必须**完全相同**
- **返回类型**可以不相同，但是必须是父类返回值的**派生类**
- **访问权限**不能比父类中被重写的方法的访问权限更低
- 父类的成员方法只能被它的子类重写
- 声明为`final`的方法不能被重写
- 声明为`static`的方法不能被重写，但是能够被再次声明
- 子类和父类在**同一个包**中，除了声明为`private`和`final`的方法,子类可以重写父类所有方法
- 子类和父类**不在同一个包**中，那么子类只能够重写父类的声明为`public`和`protected`的非`final`方法
- 重写的方法能够抛出任何非强制异常，无论被重写的方法是否抛出异常。重写方法不能抛出新的检查异常或者比被重写方法申明更加宽泛的异常,反之则可以
- **构造方法不能被重写**
- 如果不能继承一个类，则不能重写该类的方法
- 当需要在子类中调用父类的被重写方法时，要使用`super`关键字

---

##### (4) 代码示例

```java
class Parent {
    public void say() {
        System.out.println("Parent");
    }
}

class Child extends Parent {
    @Override
    public void say() {      // 方法签名完全相同
        System.out.println("Child");
    }
}
```

---

#### 2. **Overload**

##### (1) Overload定义

同一个类中定义**多个方法名相同，参数列表不同**的方法

---

##### (2) **方法重载规则**

- 被重载的方法必须改变参数列表:参数**个数**或**类型**不一样
- 被重载的方法可以改变**返回类型**和**访问修饰符**
- 被重载的方法可以声明新的或更广的**检查异常**
- 方法能够在同一个类中或者在一个子类中被重载
- 无法以返回值类型作为重载函数的区分标准

---

##### (3)代码示例

```java
class Calculator {
    public int add(int a, int b) {
        return a + b;
    }

    public double add(double a, double b) {   // 参数类型不同
        return a + b;
    }

    public int add(int a, int b, int c) {     // 参数个数不同
        return a + b + c;
    }
}
```

---

#### 3. **重写与重载之间的区别**

| 对比点 | **Override（重写）** | **Overload（重载）** |
| -------- | ---------------- | ------------------ |
| **发生位置** | 子类与父类之间 | 同一个类中 |
| **方法名** | 必须相同 | 必须相同 |
| **参数列表** | 必须相同 | 必须不同（个数、类型、顺序） |
| **返回值类型** | 相同或是其子类（协变返回） | 可以不同 |
| **访问修饰符** | 不能比父类更严格（可变大） | 无关 |
| **异常** | 不能抛出新的或更宽泛的受检异常 | 无关 |
| **静态方法** | 不能被重写（可声明同名的静态方法，但不是重写） | 可以重载 |
| **注解标记** | `@Override`（推荐） | 无专用注解 |

| 构造方法 | 说明 |
| :--- | :--- |

| :--- | :--- | :--- |

| **内存位置** | 字符串常量池 | 堆内存 |

| **内存效率** | 高（复用对象） | 低（可能创建冗余对象） |
| **适用场景** | 推荐使用，大多数情况下的最佳实践 | 需要强制创建新对象时使用 |

### （四）. **异常处理**(Exception)

        └── ...

#### 3. **多个`catch`块**

```java
try {
// 写的时候预感到可能会崩的那几行核心代码，只包高危区，不包全场
} catch (NullPointerException e) {      // 子类异常在前
    System.out.println("空指针");
} catch (RuntimeException e) {          // 父类异常在后
    System.out.println("运行时异常");
} catch (Exception e) {                 // 更通用的父类放最后
    System.out.println("其他异常");
}
```

- **规则**：catch 顺序必须从**具体（子类）到通用（父类）**，否则编译报错

---

#### 4. `finally`与`return`的注意事项

- `finally`块中**不要使用`return`**，否则会覆盖`try/catch`中的返回值
- 即使`try`中有`return`，`finally`仍会在返回**之前**执行（除非 `System.exit()` 终止了 JVM）

```java
public int test() {
    try {
        return 1;
    } finally {
        return 2;  // 最终返回 2，覆盖了 1（极不推荐）
    }
}
```

---

#### 5. `try-with-resources`

- 自动释放实现了`AutoCloseable`接口的资源(如流、数据库连接)，比`finally`更简洁安全

```java
// 资源在 try 后的括号中声明，多个用 ; 隔开
try (FileInputStream fis = new FileInputStream("a.txt");
     BufferedReader br = new BufferedReader(new InputStreamReader(fis))) {
    // 使用资源
    String line = br.readLine();
} catch (IOException e) {
    e.printStackTrace();
}
// fis 和 br 会自动关闭（无论是否异常）
```

#### 6. 自定义异常

```java
// 受检异常：继承 Exception
class MyCheckedException extends Exception {
    public MyCheckedException(String message) {
        super(message);
    }
}

// 非受检异常：继承 RuntimeException
class MyUncheckedException extends RuntimeException {
    public MyUncheckedException(String message) {
        super(message);
    }
}
```

---

#### 7. **最佳实践&易错点**

- **捕获具体异常**：不要直接 `catch (Exception e)`（除非顶层兜底），应捕获具体子类以便**针对性处理**
- **不要吞掉异常**：`catch` 块中至少打印日志或重新抛出，避免空 catch 导致问题被掩盖
- **使用日志代替 `printStackTrace()`**：生产环境推荐用 `Logger` 记录
- **受检异常的选择**：如果调用方无法恢复，可考虑包装成非受检异常再抛出（如 `throw new RuntimeException(checkedException)`）
- **性能**：异常创建开销大，避免用异常控制正常流程（如循环中用 `if` 判断边界，而非捕获 `IndexOutOfBoundsException`）

## **六、C++ 转 Java 避坑指南**

### **(一).Java中`==`与`equals`核心区分笔记**

#### 1.为什么不能混用？

- `==`：比较**栈内存中的值**。对于对象引用，比较的是内存地址（两个引用是否指向同一块堆内存）
- `equals`：比较**对象的内容**（需要类正确重写`equals`方法）。所有类都继承自`Object`，默认`equals`内部也是用`==`**比较地址**，因此自定义类必须重写`equals`才能比较内容

---

#### 2. **不同场景精准用法一览表**

| 场景 | 用什么运算符/方法 | 原因与备注 | 正确示例 | 错误示例（可能翻车） |
| ------ | ------------------- | ------------ | ---------- | --------------------- |
| **基本数据类型**（int, double, char 等） | `==` | 它们不是对象，直接比较值 | `if (hp <= 0)`<br>`if (count == 10)` | 无需使用`equals`，**基本类型没有方法** |
| **枚举类型**（enum） | `==` | 枚举是**天生单例**，JVM 保证每个常量全局唯一实例。使用 `==` 安全且高效 | `if (state == EntityState.DEAD)` | 不建议用`equals`，虽然效果相同但多一次调用，且如果变量为`null`会抛 `NullPointerException` |
| **判断是否为 null** | `== null`<br>`!= null` | `null`表示**没有对象**，**无法调用任何方法**。必须用 `==` 比较引用是否为空 | `if (closestEnemy != null)` | **绝对禁止**用`equals`：`if (closestEnemy.equals(null))`，如果`closestEnemy`本身是`null`，立即崩溃 |
| **字符串内容比较** | `equals` | `==` 比较的是字符串对象的**内存地址**，不保证内容相同 | `if (name.equals("骑士"))` | `if (name == "骑士")`：可能因为 JVM 字符串池侥幸成立，但读取、拼接、`new String`时必然失败 |
| **其他对象内容比较** | `equals（需重写）` | **自定义类必须重写 equals 和 hashCode，否则默认比较地址** | `if (card1.equals(card2))`<br>（假设 Card 类已正确重写） | **未重写时使用`equals`等同于`==`**，无法按业务逻辑（如卡牌名称）判等 |
| **包装类型内容比较**（如 Integer, Long） | `equals()` | JVM 为了省内存，对 Integer 自动缓存了 **-128 到 127** 之间的对象。在此区间内 `==` 侥幸成立，超出区间 `==` 必然失败 | `Integer gold1 = 200;`<br>`Integer gold2 = 200;`<br>`if(gold1.equals(gold2))` | `if(gold1 == gold2)`当金币为100时成立，当金币变成200时判定为假！ |

- **只要是包装类，哪怕是比大小，也一律用 equals()**

---

#### **3. equals重写**

> [!IMPORTANT]
> **`hashCode()`负责“分区定位”、`equals()`负责“精确匹配”**
> **重写`equals`必须同步重写`hashCode`**
> **`equals`相等的两个对象，其`hashCode`必须相等**

##### (1) **原理：图书馆找书**

| 步骤 | 动作 | 比喻 |
| ------ | ------ | ------ |
| 第一步 | 用 `hashCode()` 定位 | 算书在哪个书架 |
| 第二步 | 用 `equals()` 比对 | 在书架上**挨个书**找目标书 |

- 只重写 `equals` 不重写 `hashCode`：
  - `hashCode`只认“书架号”（默认按内存地址瞎算）→ 两个内容相同的对象，被管理员硬生生塞进了完全不同的书架
  - 这一步跑偏，直接导致`HashSet`去重机制原地报废——明明是两个一模一样的元素，却因为不在同一排书架而堂而皇之地共存

##### (2) **代码示例**

```java
// ==================== 错误示例（只重写 equals，不重写 hashCode） ====================
class User {
    int id;

    User(int id) {
        this.id = id;
    }

    // 重写 equals：按照 id 判断内容是否相等
    @Override
    public boolean equals(Object obj) {
        // 1. 如果是同一个对象引用，直接返回 true（提高效率）
        if (this == obj) return true;
        // 2. 如果传入的不是 User 类型（或其子类），直接返回 false
        //    这里用 instanceof 做类型安全检查（防止强转报错）
        if (!(obj instanceof User)) return false;
        // 3. 安全强转后比较核心字段 id
        return id == ((User) obj).id;
    }

    // ❌ 注意：没有重写 hashCode()！
    //    默认的 hashCode() 根据对象的内存地址计算，所以 new User(1) 的两个不同对象
    //    虽然 equals 返回 true，但它们的 hashCode 大概率不同
}

public class Test {
    public static void main(String[] args) {
        Set<User> set = new HashSet<>();

        // 添加第一个 User 对象
        set.add(new User(1));
        // 添加第二个 User 对象（id 也等于 1，内容相同）
        set.add(new User(1));

        // HashSet 的去重逻辑：先根据 hashCode 定位到“桶”（书架），
        // 如果该桶内已有元素，再调用 equals 逐一比对。
        // 因为两个对象的 hashCode 不同，它们被分配到不同的桶，
        // HashSet 认为它们不在同一个位置，永远不会触发 equals 比对，
        // 因此认为它们是两个不同的元素，都添加成功
        System.out.println(set.size()); // 输出 2 ❌ （去重失败！）
    }
}

// ==================== 正确示例（同时重写 equals 和 hashCode） ====================
class UserCorrect {
    int id;
    
    UserCorrect(int id) {
        this.id = id;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (!(obj instanceof UserCorrect)) return false;
        return id == ((UserCorrect) obj).id;
    }

    // ✅ 重写 hashCode：保证内容相同的对象返回相同的哈希值
    //    原则：equals 为 true 的两个对象，hashCode 必须相同。
    //    这里直接用 id 作为哈希值（或使用 Objects.hash(id)），
    //    这样 new UserCorrect(1) 无论创建多少次，hashCode 都相同。
    @Override
    public int hashCode() {
        return Objects.hash(id); // 或者简单 return id;
    }
}

public class TestCorrect {
    public static void main(String[] args) {
        Set<UserCorrect> set = new HashSet<>();

        set.add(new UserCorrect(1));
        set.add(new UserCorrect(1));

        // 现在两个对象的 hashCode 相同 → 被分配到同一个桶，
        // HashSet 会在该桶内用 equals 逐个比对，发现已有相同元素，
        // 因此第二个添加失败，去重成功。
        System.out.println(set.size()); // 输出 1 ✅
    }
}
```

### (二)杂项

#### 1. 没有指针运算

不能  `int* p = &a`; p++ ，Java 没有指针概念

#### 2. 文件名与类名

一个`.java`文件中**只能有一个**`public class`，且文件名必须和这个类名**完全一致**（大小写敏感）

#### 3. 没有析构函数

不需要写`~Person()`，垃圾回收器 GC 会自动回收不再使用的对象

#### 4. 没有goto

Java移除了`goto`关键字，虽然保留为保留字，但不能使用
