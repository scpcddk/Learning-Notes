# 《数字设计与计算机体系结构》第七章：CPU 设计

> [!note] 本章主线与阅读约定
> 对应本目录课件《Chapter 7 MicroArchitecture》。主线：**指令语义 → 状态组件 → 单周期数据通路 → 控制器 → 性能分析 → 多周期与流水线**。
>
> 本章采用课件的 32 位、按字节编址 MIPS 教学模型。基础单周期处理器只实现 **`lw`、`sw`、`beq` 和 `add/sub/and/or/slt` 五种 R 型运算**，不含跳转、乘除法及完整异常机制。第十一、十二节的多周期与流水线为扩展理解，课件仅在第 60～62 页给出概览和结构图，本文补足其基本工作过程。

> [!important] 本章的三个核心问题
> 1. **数据怎样走？** 指令中的字段选择哪些寄存器，ALU 算什么，结果写到哪里？
> 2. **谁决定这样走？** 控制器怎样产生 MUX 选择信号、ALU 功能码与写使能？
> 3. **多久能完成？** 怎样从部件延迟得到时钟周期，再计算整个程序的执行时间？

## 一、从 ISA 到 CPU：把“规定的结果”变成“真实的状态更新”

### 1. 一台处理器的两部分

| 部分 | 工作 | 本章中的模块 |
|---|---|---|
| 数据通路（Datapath） | 读取、运算、传送和保存数据 | PC、寄存器堆、ALU、存储器、加法器、MUX |
| 控制器（Control Unit） | 根据指令产生控制信号 | 主译码器、ALU 译码器、分支控制逻辑 |

数据通路像已经接好的路线，控制信号决定本次走哪条路线、做哪种运算、哪些位置允许写入。**控制器不需要搬运每一位运算数据，它主要决定数据通路的行为。**

### 2. 体系结构状态与内部临时状态

课件第 5 页关注的体系结构状态包括：

- **PC**：当前要执行的指令地址。
- **通用寄存器堆**：32 个 32 位寄存器，`$zero` 恒为 0。
- **内存**：保存程序与数据；本模型不讨论自修改代码。

处理器执行一条指令，就是从旧状态推导出新状态。不同实现可以增加内部寄存器，但不能擅自改变指令规定的结果。

| 指令 | 关键状态变化 | 下一 PC，基础模型 |
|---|---|---|
| `add rd,rs,rt` | $R[rd]\leftarrow R[rs]+R[rt]$ | PC+4 |
| `lw rt,imm(rs)` | $R[rt]\leftarrow M_{32}[R[rs]+\operatorname{SignExt}(imm)]$ | PC+4 |
| `sw rt,imm(rs)` | $M_{32}[R[rs]+\operatorname{SignExt}(imm)]\leftarrow R[rt]$ | PC+4 |
| `beq rs,rt,label` | 不写通用寄存器与数据内存 | 相等则到分支目标，否则 PC+4 |

课件的简单数据通路不实现 `add/sub` 的完整溢出异常处理。讨论它们的有符号 ISA 语义时，应假设没有溢出；只看加法器低位结果不能替代完整异常语义。

### 3. 三种实现，区别在时间组织

| 方案 | 一条指令怎样完成？ | 不同指令是否重叠？ | 主要代价 |
|---|---|---|---|
| 单周期 | 一整个长周期内完成 | 否 | 短指令也等待最长指令的周期 |
| 多周期 | 分成几个短周期，逐步完成 | 基本多周期模型不重叠 | 需要中间寄存器与多状态控制 |
| 流水线 | 分阶段，多条指令同时处于不同阶段 | 是 | 需要处理资源、数据和控制冲突 |

**ISA 规定“每条指令最后应得到什么”，不规定必须花几个周期。**

## 二、先认清数据通路上的部件、接口与时钟

### 1. 状态组件和组合组件

| 组件 | 输入与输出 | 何时改变状态 / 结果？ |
|---|---|---|
| PC 寄存器 | 输入 `PCNext`，输出 PC | 有效时钟沿装入下一地址 |
| 指令存储器 | 地址 PC，输出 Instr | 本模型为组合读，地址稳定后读出 |
| 寄存器堆 | 两个读地址、一个写地址与写数据 | 组合读；写使能有效时，在时钟沿写入 |
| ALU | SrcA、SrcB、ALUControl | 组合计算 ALUResult 和 Zero |
| 符号扩展器 | 16 位 imm → 32 位 SignImm | 组合变换，复制符号位 |
| 加法器 | PC+4；分支目标计算 | 组合计算 |
| MUX | 多路数据与选择信号 | 组合选出一路 |
| 数据存储器 | 地址、写数据、写使能，输出读数据 | 本模型组合读、时钟沿写 |

组合读不等于“零延迟”。每个模块都需要传播时间；整个单周期必须足够长，让边沿前需要写入的数据稳定。

### 2. 寄存器堆：5 位地址，32 位数据

| 端口名 | 位宽 | 功能 |
|---|---|---|
| A1 / A2 | 各 5 位 | 两个独立读寄存器编号 |
| RD1 / RD2 | 各 32 位 | 两个被选寄存器的内容 |
| A3 | 5 位 | 写入目标寄存器编号 |
| WD3 | 32 位 | 待写入的数据 |
| WE3 | 1 位 | 写使能，对应 RegWrite |

常见连接：`A1=Instr[25:21]=rs`、`A2=Instr[20:16]=rt`。两路同时读出，不需要先读完 rs 再花一个周期读 rt。

**A1=16 表示选中 `$s0`，不是说 RD1 的值一定等于 16。** 写 0 号寄存器时还需要屏蔽写入，或通过等效电路保证其读值恒零。

### 3. 一个周期内部发生了什么？

```text
起始有效沿                         下一个有效沿
    │                                  │
    ├─ PC 输出新地址                    │
    ├─ 取指 → 译码、读寄存器            │
    ├─ ALU 计算 → 必要时读取数据内存     │
    └─ 写入数据与控制信号稳定 ──────────┤ 统一更新状态
                                       ├─ PC 载入 PCNext
                                       ├─ 允许时写寄存器
                                       └─ 允许时写数据内存
```

所谓取指、译码、执行、访存、写回，是**功能步骤**。在单周期处理器中，它们不是五个独立时钟周期；组合逻辑会在同一周期内传播，某些分支还会并行计算。

边沿到来时，各状态组件采样由**旧状态**推导的值。例如 `lw $s0,0($s0)` 用旧 `$s0` 作为基址，在结束边沿才将读取结果写入 `$s0`。

### 4. 为什么图中有两组存储器、多个加法部件？

- `lw` 在同一周期既要取指，又要读取数据。若只有一个单端口存储器，两个访问会争用接口；课件用分开的指令 / 数据存储器解决。
- 同一周期内，ALU 可能计算有效地址或做减法比较，同时还要计算 PC+4 和分支目标，因此课件完整图中有**一个主 ALU 和两个专用加法器**。
- 这不是说所有真实 CPU 必须有两片独立物理内存；多端口、分离缓存等组织也可以提供所需访问能力。

> [!tip] 读图顺序
> 先找矩形中的状态组件，再沿数据箭头追踪；最后查看 MUX 的选择信号与写使能。不要一开始同时追踪所有连线。实线传数据和地址，控制线决定选择与写入；具体颜色以图例为准。

## 三、先搭出 `lw`：沿最完整的数据路径理解单周期 CPU

### 1. 指令语义与字段

```mips
lw $t0, -4($s0)
```

$$R[t0]\leftarrow M_{32}[R[s0]-4]$$

| 字段 | 数值 | 用途 |
|---|---|---|
| opcode | `100011` | 控制器识别为 lw |
| rs | 16，`$s0` | 读取基地址 |
| rt | 8，`$t0` | 指定写回寄存器 |
| imm | `0xFFFC` | 符号扩展后作为 -4 使用 |

### 2. 六步追踪数据

![lw数据流](<阅读资源/lw数据流.svg>)

1. **取指**：PC 接指令存储器地址端，得到 Instr。
2. **读基址**：Instr 的 rs 接寄存器堆 A1，RD1 得到 $R[rs]$。
3. **扩展偏移**：imm 从 16 位符号扩展成 32 位 SignImm。
4. **算地址**：ALU 输入 A 取 RD1，输入 B 选 SignImm，执行加法。
5. **读内存**：用 ALUResult 作为数据存储器地址，得到 ReadData。
6. **写寄存器**：写地址选 rt，写数据选 ReadData，RegWrite=1，在周期末写入。

与此同时，另一条路径计算 **PCPlus4=PC+4**，准备在周期末更新 PC。

### 3. 一个具体数值例

初态：`$s0=0x10010004`，`M32[0x10010000]=0x12345678`。

| 信号 | 值 | 为什么？ |
|---|---|---|
| A1 | 16 | rs 字段选 `$s0` |
| RD1 / SrcA | `0x10010004` | 基址内容 |
| SignImm / SrcB | `0xFFFFFFFC` | -4 的 32 位补码 |
| ALUResult | `0x10010000` | 基址加 -4 |
| ReadData / Result | `0x12345678` | 从数据内存读出的字 |
| A3 / WriteReg | 8 | rt 字段选 `$t0` |
| 周期末 | `$t0=0x12345678` | RegWrite=1，写回成功 |

> [!important] 写回的是“地址中的数据”
> ALUResult 是有效地址 `0x10010000`，ReadData 是该地址中的数据 `0x12345678`。`lw` 的写回选择器必须选后者；若误选 ALUResult，执行效果就变成了把地址写入寄存器。

### 4. 为什么要增加三个选择器？

为了让同一套硬件还支持其他指令，不能把 `lw` 的所有连接永久固定。

| 选择器 | 0 路 | 1 路 | `lw` 选择 |
|---|---|---|---|
| ALUSrc | RD2，第二寄存器内容 | SignImm | 1，使用偏移 |
| RegDst | rt，`Instr[20:16]` | rd，`Instr[15:11]` | 0，写 rt |
| MemtoReg | ALUResult | ReadData | 1，写内存读出值 |

选择编码是本课件电路的约定，不是 ISA 要求所有 CPU 内部都采用相同的 0/1。

## 四、在同一套硬件上支持 `sw` 和 R 型运算

### 1. `sw`：地址用 rs，待写数据用 rt

```mips
sw $t0, 12($s0)
```

$$M_{32}[R[s0]+12]\leftarrow R[t0]$$

| 路径 | 数据从哪里来？ | 到哪里去？ |
|---|---|---|
| 地址路径 | RD1 与 SignImm | ALU 做加法，接数据内存 A |
| 写数据路径 | RD2，即 rt 中的内容 | 直接接数据内存 WD |
| 写控制 | MemWrite=1 | 允许周期末更新数据内存 |
| 通用寄存器 | RegWrite=0 | 不写回寄存器 |

**ALUSrc=1 只改变 ALU 的第二输入，不会截断 RD2 到内存 WD 的独立支路。** `sw` 同时需要偏移量和寄存器待写数据，二者作用不同。

例如 `$s0=0x10010000`、`$t0=99`：ALUResult=`0x1001000C`，WriteData=99。结束边沿将 99 写入该地址；`$t0`、`$s0` 不变，PC 前进 4。

### 2. R 型：两路寄存器内容进入 ALU

```mips
add $t0, $s0, $s1
```

$$R[t0]\leftarrow R[s0]+R[s1]$$

1. rs 和 rt 分别接两个读端口。
2. ALUSrc=0，使 SrcB=RD2。
3. ALUControl 由 funct 决定，本例选择加法。
4. RegDst=1，使 WriteReg=rd。
5. MemtoReg=0，使 Result=ALUResult。
6. RegWrite=1，MemWrite=0；周期末更新 rd，PC 前进 4。

`sub/and/or/slt` 使用相同的主要路径，仅 ALU 功能不同。即使数据存储器组合读端产生了某个值，**只要没有选入写回路径且 MemWrite=0，它就不会改变这条指令的结果**。

### 3. R 型与访存指令的联系

| 比较项 | R 型运算 | `lw` | `sw` |
|---|---|---|---|
| SrcA | RD1 | RD1 | RD1 |
| SrcB | RD2 | SignImm | SignImm |
| ALU 的工作 | 按 funct 运算 | 算有效地址 | 算有效地址 |
| 数据内存 | 不参与最终结果 | 读取 | 写入 |
| 寄存器目的编号 | rd | rt | 无 |
| 寄存器写回数据 | ALUResult | ReadData | 无 |

硬件复用的关键是**保留所需的支路，在交汇点用 MUX 选择，再用写使能决定是否保存**。

## 五、实现 `beq`：比较结果与目标地址并行准备

### 1. 比较相等：利用 ALU 做减法

```mips
beq $s0, $s1, target
```

令 SrcA=RD1、SrcB=RD2，ALU 执行减法：

$$D=R[s0]-R[s1]\pmod{2^{32}}$$
$$Zero=(D=0)$$

同位宽两个位串相等，当且仅当其模 $2^{32}$ 的差为 0。这里做相等判断不需要用减法结果的符号位，也不会仅因为减法发生有符号溢出就把“不等”误判成“相等”。

### 2. 另一条支路计算分支目标

$$SignImm=\operatorname{SignExt}_{32}(Instr[15:0])$$
$$PCBranch=PCPlus4+(SignImm\ll2)$$

- PC+4 使用一个专用加法器。
- 偏移左移 2 位，在这个固定移位场景下可用连线重排和低位补零实现，不必等同于一个通用桶形移位器。
- 分支加法器与主 ALU 的减法比较**并行进行**。

### 3. `PCSrc=Branch AND Zero`

$$PCSrc=Branch\land Zero$$

$$PCNext=\begin{cases}
PCBranch,&PCSrc=1\\
PCPlus4,&PCSrc=0
\end{cases}$$

| Branch | Zero | PCSrc | 效果 |
|---|---|---|---|
| 0 | 0 | 0 | 普通指令顺序执行 |
| 0 | 1 | 0 | 即使 ALU 结果为 0，也不分支 |
| 1 | 0 | 0 | beq 比较不相等，顺序执行 |
| 1 | 1 | 1 | beq 比较相等，选择分支目标 |

> [!warning] Zero 不能单独决定跳转
> 普通加法也可能得到 0。Branch 由指令类别产生，Zero 由本次运算数据产生；只有两者同时有效，才是“这是一条 beq，并且条件成立”。

### 4. 完整例：相等时向后跳

`beq $s0,$s1,loop` 位于 `PC=0x00400020`，立即数字段 `0xFFF9`，且 `$s0=$s1=5`。

| 部分 | 结果 |
|---|---|
| 主 ALU | $5-5=0$，Zero=1 |
| 符号扩展 | `0xFFF9` → `0xFFFFFFF9`，即 -7 |
| 顺序地址 | PCPlus4=`0x00400024` |
| 分支目标 | `0x00400024 + (-7)*4 = 0x00400008` |
| 控制选择 | Branch=1，PCSrc=1 |
| 结束边沿 | PC 更新为 `0x00400008`，不写寄存器和数据内存 |

若只把 `$s1` 改成 6，PCBranch 仍会被计算出来，但 PCSrc=0，实际 PCNext 为 `0x00400024`。**一条内部支路算出了值，不代表它最终一定被采用。**

## 六、完整单周期数据通路：用四个选择问题读懂全图

![课件第 27 页：完整单周期 MIPS 数据通路与控制器](<阅读资源/单周期数据通路.png>)

*上图取自课件 PDF 第 27 页。先找 PC、寄存器堆与数据内存，再检查 ALU 两个输入、写回和 PC 更新路径。*

### 1. 四个选择点

| 问题 | 对应信号 | 0 的含义 | 1 的含义 |
|---|---|---|---|
| ALU 第二输入从哪来？ | ALUSrc | 第二寄存器 RD2 | 符号扩展立即数 |
| 写哪个通用寄存器？ | RegDst | rt | rd |
| 写回什么数据？ | MemtoReg | ALU 结果 | 内存读出值 |
| 下一条指令在哪里？ | PCSrc | PC+4 | 分支目标 |

前面三个通常由指令译码决定；PCSrc 还需要结合 Zero。主 ALU 功能由 ALUControl 决定。

### 2. 两个写使能

| 信号 | 置 1 的效果 | 本章哪些指令会置 1？ |
|---|---|---|
| RegWrite | 在结束沿写通用寄存器 | lw、支持的 R 型运算 |
| MemWrite | 在结束沿写数据内存 | sw |

在基础单周期模型中，PC 每拍都更新，只是在两个候选地址间选择。因此 **PCSrc 不是 PC 的写使能**。后面的多周期处理器才需要让 PC 在部分周期保持。

### 3. 控制信号总表

为便于阅读，将写入与选择信号、ALU 与分支信号分开列出。

| 指令 | RegWrite | RegDst | ALUSrc | MemWrite | MemtoReg |
|---|---|---|---|---|---|
| `lw` | 1 | 0 | 1 | 0 | 1 |
| `sw` | 0 | X | 1 | 1 | X |
| `beq` | 0 | X | 0 | 0 | X |
| 支持的 R 型 | 1 | 1 | 0 | 0 | 0 |

| 指令 | ALUOp | ALUControl | Branch | PCSrc |
|---|---|---|---|---|
| `lw` | `00` | `010`，加法 | 0 | 0 |
| `sw` | `00` | `010`，加法 | 0 | 0 |
| `beq` | `01` | `110`，减法 | 1 | Zero |
| 支持的 R 型 | `10` | 按 funct 译码 | 0 | 0 |

X 表示在这条指令下该信号的值**不会影响规定的状态变化**。例如 `sw` 的 RegWrite=0，写寄存器地址和写回数据就都无关。

但写使能不能随意填 X：若误把 `beq` 的 MemWrite 置 1，仍然可能破坏内存。硬件真值表中的 don't care，也不等于仿真器中的未知电平 x。

### 4. 为什么课件没有单独的 MemRead？

本模型的数据内存按地址组合读，读出的数据在需要时由写回 MUX 选用，所以不另列 MemRead 控制。其他教材或真实接口可能需要读使能、请求握手、等待信号；**控制表必须与正在分析的电路一致**。

## 七、控制器：从 opcode 到具体电路动作

### 1. 为什么拆成两级译码？

![两级控制器](<阅读资源/两级控制器.svg>)

`lw/sw` 都要求加法算地址；`beq` 固定要求减法；R 型再看 funct。先分类、后细分，可以减少主译码器直接处理的情况，也与指令格式的层次对应。

### 2. 主译码器：opcode 决定大方向

| 指令类别 | opcode | 主译码器的核心决定 |
|---|---|---|
| lw | `100011` | 写 rt；立即数作 ALU 输入；读内存值写回；ALU 做加法 |
| sw | `101011` | 不写通用寄存器；立即数作 ALU 输入；写数据内存；ALU 做加法 |
| beq | `000100` | 不写两类数据状态；用两个寄存器相减；允许条件分支 |
| R 型 | `000000` | 写 rd；用两个寄存器运算；ALU 结果写回；按 funct 决定功能 |

若记 $L,S,B,R$ 分别表示“识别为 lw、sw、beq、支持的 R 型”，在这个合法子集内可写：

$$RegWrite=L\lor R,\qquad MemWrite=S$$
$$ALUSrc=L\lor S,\qquad Branch=B$$
$$RegDst=R,\qquad MemtoReg=L$$
$$ALUOp_1=R,\qquad ALUOp_0=B$$

这组式子给无关项选定了具体的 0/1，是一种有效实现，不是要求所有设计都逐门照搬。真实实现还要识别非法 opcode 和不支持的 funct，不能对任意 `op=0` 都无条件执行写回。

### 3. ALU 译码器：ALUOp 与 funct 共同确定功能

| ALUOp | funct | 最终 ALUControl | 运算 |
|---|---|---|---|
| `00` | 无关 | `010` | 加法 |
| `01` | 无关 | `110` | 减法 |
| `10` | `100000` | `010` | add |
| `10` | `100010` | `110` | sub |
| `10` | `100100` | `000` | and |
| `10` | `100101` | `001` | or |
| `10` | `101010` | `111` | slt |

> [!important] 三种编码处在三个不同层次
> opcode 是机器指令中的 ISA 编码；ALUOp 是主译码器给出的内部分类；ALUControl 是直接送给 ALU 的功能选择。以 `add` 为例：**opcode=`000000`，ALUOp=`10`，ALUControl=`010`**，三者不能互换。

`slt` 要输出 32 位的 0 或 1。若通过补码减法实现有符号比较，应使用：

$$less=(A-B)_{31}\oplus Overflow_{sub}$$

仅取差的符号位，在减法溢出时可能判断错误。例如 $A=-2^{31}$、B=1，低 32 位差为正数，但 A 显然小于 B。这里与第五章的 ALU 有符号比较规则相衔接。

### 4. 组合控制器与状态机控制器

基础单周期控制器主要是组合译码：当前指令和 Zero 决定本周期的控制动作。**它并没有一个每拍轮转 IF→ID→EX→MEM→WB 的五状态 FSM**，因为这些步骤在同一个长周期内完成。

多周期处理器则需要记住“当前指令执行到了哪一步”，控制器通常是 FSM：输出不仅依赖指令，还依赖当前微状态。

## 八、自己设计数据通路：从状态变化反推连线

### 1. 五步设计法

1. **写语义**：该指令读哪些状态、写哪些状态、怎样更新 PC？
2. **列资源**：需要几个读端口、什么 ALU 运算、是否访问数据内存？
3. **画路径**：数据能否从来源到目标？是否存在单周期资源争用？
4. **加选择与使能**：不同指令共享连线时怎样选择？哪些写入必须关闭？
5. **检查时序**：数据、写地址和控制信号是否都能及时稳定？

### 2. 补充例：怎样增加 `addi`？

`addi rt,rs,imm` 要求：

$$R[rt]\leftarrow R[rs]+\operatorname{SignExt}(imm)$$

现有数据通路已经有 rs 读出、符号扩展、ALU 加法、写 rt 及 ALU 结果写回，所以无需仅为基本数据流增加新运算部件。

| 信号 | RegWrite | RegDst | ALUSrc | MemtoReg | MemWrite | Branch |
|---|---|---|---|---|---|---|
| addi | 1 | 0 | 1 | 0 | 0 | 0 |

再让主译码器识别 opcode=`001000`、输出 ALUOp=`00` 即可完成基本无溢出情况。若要实现完整 ISA，还需处理有符号溢出异常；不能把“路径已经具备”当作完整实现的全部工作。

### 3. 为什么增加 `ori` 不能只改 ALUControl？

`ori` 需要**零扩展**立即数，现有基础电路只有符号扩展。还应增加扩展方式选择，或能按控制切换的扩展单元；写回仍是 rt、ALU 结果。

类似地：增加 `j` 需要新的 PC 候选来源；增加 `jal` 还需要将链接地址写入 31 号寄存器的路径。设计新指令时，同时检查**数据、地址和控制**三方面。

## 九、性能分析：必须把指令数、CPI 与时钟周期一起看

### 1. 响应时间与吞吐量

| 指标 | 问的问题 | 常见单位 |
|---|---|---|
| 响应时间（Response Time） | 一个任务从开始到结束需要多久？ | 秒、毫秒 |
| 吞吐量（Throughput） | 单位时间能完成多少工作？ | 任务/秒、请求/秒 |

为多个独立任务增加处理器，通常能提高吞吐量，但不保证某个不可并行任务的计算时间缩短。流水线也主要提高连续处理指令的吞吐能力，不保证单条指令的延迟降低。

CPU 执行时间与总响应时间也要区分：CPU time 统计 CPU 为程序执行而花费的时间；用户实际等待的墙钟时间还可能包含 I/O、调度等待等。下面公式针对 **CPU 执行时间**。

### 2. 核心公式及单位

$$\boxed{T_{CPU}=IC\times CPI_{avg}\times T_c=\frac{IC\times CPI_{avg}}{f}}$$

| 符号 | 含义 | 单位 / 注意点 |
|---|---|---|
| IC | 动态执行的指令总数 | 条；循环按实际执行次数累计 |
| CPI | 平均每条指令所需时钟周期数 | 周期/条；可以不是整数 |
| $T_c$ | 时钟周期 | 秒/周期，$T_c=1/f$ |
| f | 时钟频率 | Hz，即周期/秒 |
| $IC\times CPI$ | 总时钟周期数 | 周期 |

单位校验：条 × 周期/条 × 秒/周期 = 秒。`1GHz=10^9Hz`，`1ps=10^{-12}s`，`1000亿=10^{11}`，计算前最好先换成同一单位。

### 3. 加权平均 CPI：权重是动态使用比例

若第 i 类指令执行 $IC_i$ 次，每条需要 $CPI_i$ 个周期：

$$Cycles=\sum_iIC_iCPI_i$$
$$CPI_{avg}=\frac{\sum_iIC_iCPI_i}{\sum_iIC_i}=\sum_i p_iCPI_i$$

其中 $p_i=IC_i/IC$，满足 $\sum_i p_i=1$。

课件第 45、48～49 页：

| 指令类别 | 动态比例 | CPI | 对平均 CPI 的贡献 |
|---|---|---|---|
| 算术逻辑 | 40% | 2 | 0.80 |
| Load/store | 30% | 4 | 1.20 |
| Compare | 8% | 2.5 | 0.20 |
| Branch | 22% | 3 | 0.66 |
| **合计** | **100%** | — | **2.86** |

不能直接取 $(2+4+2.5+3)/4$，因为四类指令的使用次数不同。

### 4. 速度比较：先确定比较的是同一项工作

$$\text{A 相对 B 的加速比}=\frac{T_B}{T_A}$$

课件第 43 页：A 的 $T_c=250ps$、CPI=2；B 的 $T_c=500ps$、CPI=1.2。**假设执行同一个机器程序，IC 相同**：

$$T_A=IC\times500ps,\qquad T_B=IC\times600ps$$

$$T_B/T_A=1.2$$

A 的性能是 B 的 **1.2 倍**；执行时间比 B 少 $1-1/1.2\approx16.7\%$。只比较 CPI，会错误地选择 B。

> [!warning] 相同 ISA 不自动保证 IC 相同
> 若编译选项、编译器或算法不同，即使 ISA 相同，也可能生成不同的指令序列。上述消去 IC 的依据是“同一机器程序或题目明确指定指令数相同”，不能只凭 ISA 相同就断言任何程序的 IC 都相同。

**课件第 41 页练习：** A 主频 2GHz、执行 10s；B 的总周期数变为 A 的 1.2 倍，要求 6s 完成。

$$Cycles_A=10\times2\times10^9=20\times10^9$$
$$f_B=\frac{1.2\times20\times10^9}{6}=4\times10^9Hz=4GHz$$

### 5. 性能指标 MIPS：指令执行速率不等于完成工作的速度

这里的 **MIPS 指标**指 Million Instructions Per Second，与本课程使用的 **MIPS 指令集名称**应根据语境区分。

$$MIPS=\frac{IC}{T_{CPU}\times10^6}=\frac{f}{CPI_{avg}\times10^6}$$

主频用 MHz 表示时，可简写为 $MIPS=f(MHz)/CPI_{avg}$。它统计每秒执行多少条指令，不统计每条指令做了多少有用工作，因此不能跨不同指令序列随意判断程序性能。

### 6. 完整例：MIPS 下降，程序却更快

**原方案：** 主频 100MHz，IC=$10^7$，沿用上表。

$$CPI_{old}=2.86$$
$$T_{old}=\frac{10^7\times2.86}{100\times10^6}=0.286s$$
$$MIPS_{old}=100/2.86\approx34.97$$

**改进条件，课件第 50～52 页：** 将独立 Compare 合并到分支操作，移除占原指令数 8% 的比较指令；原有分支条数保留，合并后的分支 CPI 仍为 3，主频降低 5%。这是题目给定的工作负载和代价模型。

先用原 IC 为基准计算剩余周期贡献：

$$IC_{new}=0.92\times10^7,\qquad f_{new}=95MHz$$
$$Cycles_{new}=10^7(0.4\times2+0.3\times4+0.22\times3)=2.66\times10^7$$

新的平均 CPI 需要按新总数归一化：

$$CPI_{new}=\frac{2.66}{0.92}\approx2.891304$$
$$MIPS_{new}=\frac{95}{2.66/0.92}\approx32.86$$
$$T_{new}=\frac{2.66\times10^7}{95\times10^6}=0.280s$$

| 指标 | 原方案 | 改进后 |
|---|---|---|
| 主频 | 100MHz | 95MHz |
| 动态指令数 | $10^7$ | $0.92\times10^7$ |
| 平均 CPI | 2.86 | 约 2.8913 |
| MIPS | 约 34.97 | 约 32.86 |
| **CPU 时间** | **0.286s** | **0.280s** |

主频降低、CPI 增大、MIPS 降低，但完成相同工作所需的总指令数也下降，最后时间仍减少约 **2.10%**，加速比约 **1.0214**。

> [!note] 对课件计算式的补充核对
> 第 51 页平均 CPI 的展开式仍写出了已删除的 `0.08×2.5` 项，但结果的分子使用 2.66；一致的写法应删除该项，如上所示。课件再把 CPI 提前舍入成 2.9，得到约 32.76 MIPS；本文保留中间精度，最后统一舍入。改进还改变了指令与译码能力，不能只理解为纯软件优化。

### 7. 性能优化的判断顺序

先保证完成同一项工作，再计算新 IC、各类指令次数和 CPI，最后使用新主频求时间。**不要只优化公式中的一个因子，却默认其他因子完全不变。**

算法、语言、编译器、ISA、微体系结构都会影响结果；缓存未命中、分支等额外开销也可以体现在相应工作负载的实际 CPI 中。

## 十、单周期关键路径：925ps 是怎样算出来的？

### 1. 为什么 `CPI=1` 仍不一定快？

本章单周期 CPU 每条指令占一个周期，所以 CPI=1。但固定周期必须容纳所有支持指令的最慢路径：

$$T_c\ge\max_{\text{所有有效状态更新路径}}T_{path}$$

在课件参数与简化条件下，最长路径是 `lw`：

**PC → 指令存储器 → 寄存器读取 / 立即数扩展 → ALU → 数据存储器 → 写回 MUX → 寄存器堆。**

R 型虽然不读数据内存，仍占用同样长的固定周期，剩余时间不能自动拿去执行下一条指令。

### 2. 串行路径相加，并行输入取最大值

ALU 开始得到稳定结果前，两个数据输入都必须准备好。对 `lw`：

- A 路：寄存器堆读出基址，延迟 $t_{RFread}$。
- B 路：符号扩展后经过 ALUSrc MUX，延迟 $t_{sext}+t_{mux}$。

在控制信号足够早到达的课件模型下，等待时间是两者最大值，不能把这两条并行支路相加。

$$\begin{aligned}
T_{lw}={}&t_{pcq,PC}+t_{IMem}\\
&+\max(t_{RFread},\ t_{sext}+t_{mux})\\
&+t_{ALU}+t_{DMem}+t_{mux}+t_{RFsetup}
\end{aligned}$$

如果两组存储器的读延迟相同，且寄存器堆读支路更慢，则：

$$T_{lw}=t_{pcq,PC}+2t_{mem}+t_{RFread}+t_{ALU}+t_{mux}+t_{RFsetup}$$

> [!tip] 为什么公式中没有简单数出所有 MUX？
> `lw` 的 ALUSrc MUX 在立即数支路上，它的延迟已经放在 max 内；如果这条支路仍早于基址读出，它不会再串行加到关键路径上。写回 MUX 位于两路汇合之后，则必须另算。应追踪信号到达时间，不能只数图中经过了几个方框。

### 3. 课件第 56～58 页参数

| 参数 | 延迟 | 作用 |
|---|---|---|
| $t_{pcq,PC}$ | 30ps | 时钟沿到 PC 输出稳定 |
| $t_{mem}$ | 250ps | 每次存储器读取 |
| $t_{RFread}$ | 150ps | 寄存器堆读出 |
| $t_{mux}$ | 25ps | 一次多路选择 |
| $t_{ALU}$ | 200ps | ALU 运算 |
| $t_{RFsetup}$ | 20ps | 写寄存器前的建立时间 |

题目未单列符号扩展延迟；沿用课件简化，认为立即数支路不慢于寄存器读出支路，即 $t_{sext}+25ps\le150ps$，并忽略控制译码与布线等额外延迟。

$$T_c=30+250+150+200+250+25+20=\boxed{925ps}$$

用“稳定时刻”再检查一遍：

| 从周期起始沿计时 | 到此时已完成什么？ |
|---|---|
| 30ps | PC 输出稳定 |
| 280ps | 指令读出 |
| 430ps | 较慢的基址输入准备好 |
| 630ps | ALU 算出有效地址 |
| 880ps | 数据内存读出 |
| 905ps | 写回 MUX 输出稳定 |
| 925ps | 满足 20ps 建立时间，可以写入 |

因此最高频率约为：

$$f_{max}\approx\frac1{925\times10^{-12}}\approx1.081GHz$$

若程序执行 $10^{11}$ 条指令：

$$T_{CPU}=10^{11}\times1\times925\times10^{-12}=\boxed{92.5s}$$

### 4. 公式适用前提与完整时序检查

925ps 是**给定部件参数、给定数据通路及课件简化条件**下的结果，不是所有单周期 CPU 的固有周期。

完整设计还应检查控制线、写地址和 PC 更新路径是否更慢，以及保持时间和时钟偏斜等条件。MUX 必须等被选数据与选择信号都有效；如果控制译码较慢，也要计入 max 比较。

与第三章连接，在零时钟偏斜的寄存器到寄存器模型中：

$$T_c\ge t_{pcq}+t_{pd,comb}+t_{setup}$$
$$t_{ccq}+t_{cd,comb}\ge t_{hold}$$

建立约束决定数据不能来得太晚，保持约束防止本拍新数据来得太早。降低频率可以缓解部分建立时间问题，**不能自动修复保持时间违例**。

## 十一、扩展理解：多周期 CPU 怎样复用硬件？

> [!note] 阅读范围
> 课件第 60～61 页给出多周期动机和数据通路。本节按经典非重叠多周期实现补充解释中间寄存器、执行步骤与控制状态；周期数取决于这种具体划分，并非 ISA 固定规定。

### 1. 把一个长周期拆成若干短周期

单周期要求“一个周期内什么都做完”，因此同一资源有时必须提供多个实例或端口。多周期每拍只完成一部分，可以让同一个 ALU 先算 PC+4，再算地址，或再做运算。

![课件第 61 页：多周期 MIPS 数据通路](<阅读资源/多周期数据通路.png>)

*红框中的新增寄存器保存不同周期之间仍需使用的数据；一组指令 / 数据存储器在不同周期承担不同访问。*

### 2. 为什么必须增加中间寄存器？

| 新增状态 | 保存什么？ | 为什么不能一直依赖组合输出？ |
|---|---|---|
| IR（Instruction Register） | 当前指令 | 共享存储器随后可能转去读取数据 |
| MDR / Data | 从内存读出的数据 | 下一周期仍需写回寄存器 |
| A、B | 寄存器堆读出的两个操作数 | 后续周期需要稳定保存 |
| ALUOut | 本次 ALU 计算结果 | ALU 下一周期可能改做其他计算 |

这些是实现内部状态，通常不作为普通程序可直接访问的寄存器出现。它们说明：**将组合路径切成多拍，必须同时安排“结果存在哪里”**。

### 3. 典型阶段与周期数

| 阶段 | 主要工作 | 关键结果 |
|---|---|---|
| 取指 IF | 共享内存按 PC 读指令；ALU 算 PC+4 | IR 保存指令，PC 前进 |
| 译码 / 读寄存器 ID | 读取 rs、rt；可预计算分支目标 | A、B 和分支目标暂存 |
| 执行 EX | 算地址、做 R 型运算或比较分支 | ALUOut 或 PC 更新 |
| 访存 MEM | lw 读取数据；sw 写入数据 | MDR 保存读取值，或完成写入 |
| 写回 WB | 把需要的结果写回寄存器 | 更新 rt 或 rd |

按这一经典划分：

| 指令 | 实际经过的步骤 | 周期数 |
|---|---|---|
| lw | IF → ID → 地址计算 → 读内存 → 写回 | 5 |
| sw | IF → ID → 地址计算 → 写内存 | 4 |
| R 型 | IF → ID → ALU 运算 → 写回 | 4 |
| beq | IF → ID → 比较并选择 PC | 3 |

不是每条指令都必须经过五拍；也不是把单周期的 925ps 机械除以 5，就能得到多周期时钟。

### 4. 控制器变成有限状态机

![多周期控制状态](<阅读资源/多周期控制状态.svg>)

新增控制信号的含义：

| 信号 | 解决的问题 |
|---|---|
| IorD | 共享存储器地址选 PC，还是已计算的数据地址？ |
| IRWrite | 本拍是否把内存输出存入 IR？ |
| ALUSrcA | ALU 第一输入选 PC，还是已保存的操作数 A？ |
| ALUSrcB | 第二输入选 B、常数 4、SignImm，还是移位后的偏移？ |
| PCSrc | PC 的输入选本拍 ALU 结果，还是以前保存的目标？ |
| PCWrite / Branch | 无条件更新 PC，或满足分支条件时更新？ |

对应图中的使能可理解为：

$$PCEn=PCWrite\lor(Branch\land Zero)$$

取指之后，PC 已经前进；译码时若用当前 PC 计算分支目标，它已代表原指令地址加 4，**不能再不加区分地多加一次 4**。这与单周期中 PC 整个周期保持当前指令地址的情形不同。

### 5. 多周期是否更快，要用平均 CPI 判断

若程序 lw/sw/R/beq 比例依次为 25%、10%、45%、20%：

$$CPI_{multi}=0.25\times5+0.10\times4+0.45\times4+0.20\times3=4.05$$

假设多周期时钟为 250ps，则平均每条指令耗时为 $4.05\times250=1012.5ps$，比前面的单周期 925ps 更慢；若能做到 200ps，则为 810ps，才更快。

这里的 250ps、200ps 是用于比较的假设参数，不是对课件电路重新计算的结论。**资源复用、周期缩短与 CPI 增大必须一起计入，不能仅凭多周期主频更高就断言更快。**

## 十二、扩展理解：流水线为什么提高吞吐量？

### 1. 多条指令错开一个阶段执行

经典五级：**IF 取指 → ID 译码 / 读寄存器 → EX 执行 → MEM 访存 → WB 写回**。

| 指令 / 周期 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| I1 | IF | ID | EX | MEM | WB | — | — |
| I2 | — | IF | ID | EX | MEM | WB | — |
| I3 | — | — | IF | ID | EX | MEM | WB |

第 5 拍可以同时处理五条不同指令的五个不同阶段。它们共用流水线，但各自的结果仍要送回各自的目的位置。

![课件第 62 页：单周期与五级流水线的数据通路对照](<阅读资源/单周期与流水线对照.png>)

*下半图加入 IF/ID、ID/EX、EX/MEM、MEM/WB 流水寄存器。图中的分支判定路径位于其特定阶段，不能直接套用另一种实现的固定分支罚时。*

### 2. 流水寄存器必须保存什么？

不仅要保存数据，还要让**目的寄存器编号和控制信号随对应指令一起前进**。

例如 I1 的结果到 WB 时，IF 可能已经取到 I5。若写回地址直接使用当前新指令的 rt/rd，就会把 I1 的结果写入 I5 指定的寄存器。

| 跨阶段内容 | 示例 |
|---|---|
| 数据 | 寄存器操作数、ALUResult、内存读出值 |
| 指令相关编号 | 目的寄存器、需要比较的源寄存器编号 |
| 控制信号 | RegWrite、MemtoReg、MemWrite 等 |
| 地址与上下文 | 后续阶段需要的 PC+4、分支相关信息 |

### 3. 理想时钟、延迟与总执行时间

设 k 级流水线的组合延迟为 $d_1,\ldots,d_k$，每级寄存器与相关时钟开销合计为 $d_{reg}$：

$$T_{pipe}\ge\max_i(d_i)+d_{reg}$$

流水线按最慢级确定周期，不能只把总组合延迟除以级数；分段不均衡和流水寄存器开销都会限制收益。

执行 N 条指令，无停顿、无冲刷、单发射且每拍可推进一条时：

$$Cycles_{ideal}=N+k-1$$
$$T_{total}=(N+k-1)T_{pipe}$$
$$CPI_{finite}=\frac{N+k-1}{N}\longrightarrow1\quad(N\to\infty)$$

单条指令仍需经过约 k 个流水周期，延迟约为 $kT_{pipe}$；改善的是连续执行的完成间隔。**理想 CPI 接近 1，不等于每条指令只经过一个阶段。**

**独立练习模型：** 五段组合延迟为 180、120、200、160、140ps；段间寄存器开销 20ps。

- 未流水化的简化执行时间：每条 $180+120+200+160+140=800ps$，忽略额外端点开销。
- 流水周期：$200+20=220ps$。
- 20 条指令：未流水化耗时 $20\times800=16000ps$；流水耗时 $(20+4)\times220=5280ps$。
- 加速比约 **3.03**，小于五级的理想上限；首条指令延迟为 $5\times220=1100ps$，并未比 800ps 更短。

本例仅用于解释填充与分段开销，不是把前面 925ps 的实际路径直接分成这五段。

### 4. 三类冒险（Hazards）

| 类型 | 冲突来自哪里？ | 示例 | 常用处理 |
|---|---|---|---|
| 结构冒险 | 同一时刻争用同一硬件资源 | 取指与数据访存共用一个单端口内存 | 增加资源 / 端口、分离指令与数据接口、停顿 |
| 数据冒险 | 后指令需要尚未可用的前指令结果 | `add` 后紧接使用其结果的 `sub` | 前递、停顿、合理调度 |
| 控制冒险 | 还不知道后续正确取指位置 | 分支尚未判定，却已取入顺序指令 | 停顿、预测、判定后冲刷等 |

**数据相关不一定造成停顿**：若结果可以及时前递到使用位置，相关可以由硬件处理。

```mips
add $t0, $s0, $s1
sub $t1, $t0, $s2         # 可在合适的实现中用 ALU 结果前递解决
```

典型五级、load 数据到 MEM 结束才可用、下一条指令在 EX 使用操作数的实现中：

```mips
lw  $t0, 0($s0)
add $t1, $t0, $s1         # 常见 load-use：即使有前递，仍需停顿一拍
```

停顿几拍取决于结果产生时刻、使用位置和前递路径。若增加特殊旁路或改变阶段划分，结论也可能改变，不能把“一拍”套到所有 CPU。

### 5. 停顿、气泡与冲刷

| 名称 | 作用 |
|---|---|
| Stall 停顿 | 暂停部分指令或流水寄存器的推进，等待条件满足 |
| Bubble 气泡 | 注入一个不产生有效状态写入的空操作占位 |
| Flush 冲刷 | 清除错误路径或应取消的指令，使其不能提交写入 |

错误路径指令的 RegWrite/MemWrite 等副作用必须被取消，不能只改变 PC 却放任已取入的错误指令继续修改状态。

若流水执行额外耗费 S 个周期，包括停顿、重新填充等，且不重复计数：

$$Cycles=N+k-1+S$$
$$CPI=1+\frac{k-1+S}{N}$$

### 6. 三种方案最终怎样比较？

| 维度 | 单周期 | 基本多周期 | 五级流水线 |
|---|---|---|---|
| 一条指令占用周期 | 1 | 通常 3～5，随划分变化 | 经过五级 |
| 稳态平均 CPI | 1 | 按指令比例加权 | 理想接近 1，冒险会增加 |
| 时钟由谁决定？ | 最慢的完整指令路径 | 最慢的一个微步骤 | 最慢流水级及寄存器开销 |
| 多条指令是否重叠？ | 否 | 否 | 是 |
| 资源组织重点 | 支持一拍内的并行需求 | 跨周期复用 | 支持各阶段同时工作 |
| 控制重点 | 组合译码与选择 | FSM 与中间结果保存 | 随行控制、前递、停顿、冲刷 |

比较同一项工作时，最终仍回到 $T_{CPU}=IC\times CPI\times T_c$。

## 十三、核心公式与易错点速查

### 1. 公式卡片

| 问题 | 公式 / 结论 |
|---|---|
| 访存有效地址 | $EA=R[rs]+\operatorname{SignExt}(imm)$ |
| 分支目标 | $PCBranch=PC+4+(\operatorname{SignExt}(imm)\ll2)$ |
| beq 是否选中分支 | $PCSrc=Branch\land Zero$ |
| 有符号小于判断 | $less=(A-B)_{31}\oplus Overflow_{sub}$ |
| CPU 时间 | $T=IC\times CPI_{avg}\times T_c$ |
| 总时钟周期数 | $Cycles=\sum_i IC_iCPI_i$ |
| 平均 CPI | $CPI_{avg}=\sum_i p_iCPI_i$ |
| A 相对 B 的性能倍数 | $T_B/T_A$ |
| MIPS 指标 | $f/(CPI_{avg}\times10^6)$，f 以 Hz 计 |
| k 级理想流水线 | N 条指令需要 $N+k-1$ 个周期 |
| 含额外开销的流水线 | $Cycles=N+k-1+S$ |

### 2. 易错点对照

| 常见误解 | 应怎样理解？ |
|---|---|
| 单周期有五个步骤，所以 CPI=5 | 五个功能步骤在一个周期中完成，CPI=1 |
| 时钟一到，指令立即完成 | 边沿后还需经过部件传播，末端还要满足建立时间 |
| CPU 所有连线都在传当前有效结果 | 未选中的组合支路也可能活动，关键在最终选择与使能 |
| `lw` 把 ALUResult 写回 | ALUResult 是地址，应把 ReadData 写回 |
| `sw` 选择立即数后就不再读 rt | rt 仍通过独立支路提供内存写数据 |
| beq 的 ALU 要做加法算目标 | 主 ALU 做减法比较，独立加法器并行算目标 |
| Zero=1 就应该跳转 | 还必须 Branch=1 |
| PCSrc 是 PC 写使能 | 单周期中它选择 PC 输入来源；多周期才另有 PCEn |
| opcode、ALUOp、ALUControl 是同一编码 | 分别属于指令、内部分类和 ALU 功能选择 |
| 控制表 X 可以任意出现在写使能上 | 只有确认不会影响语义的信号才可标无关 |
| 主频越高、CPI 越低就一定快 | 必须同时比较 IC、CPI、周期时间 |
| 平均 CPI 是各类型 CPI 的简单平均 | 按动态执行次数加权 |
| 指令删掉后，其余比例仍直接相加当新权重 | 新比例要除以剩余总指令数重新归一化 |
| 并行支路延迟全部相加 | 汇合前取到达时间最大值，汇合后才串行相加 |
| 多周期就是流水线 | 基本多周期不重叠执行不同指令，流水线会重叠 |
| 流水线让每条指令只花一个短周期 | 单条指令经过多级；稳态可以每拍完成一条 |
| 前递消除所有数据停顿 | 结果必须及时可用；典型 load-use 仍可能停顿 |

## 十四、自测练习题与解析

### 题 1：从语义识别数据路径

`lw $t0,8($s0)` 中，ALUResult、ReadData、WriteReg 各表示什么？

**答案：** ALUResult 是有效地址 `$s0+8`；ReadData 是该地址中的一个字；WriteReg 是 rt 字段中的寄存器编号 8，不是数字 8 作为运算结果写回。结束边沿将 ReadData 写入 `$t0`。

### 题 2：推导 `sw` 控制信号

写出 `sw` 的 RegWrite、ALUSrc、MemWrite、ALUControl；RegDst 与 MemtoReg 为什么是 X？

**答案：** 分别为 0、1、1、`010`。ALU 用基址加偏移算地址，RD2 提供写数据；因为不写通用寄存器，写寄存器编号与寄存器写回数据选择对语义没有影响。

### 题 3：Zero 与分支

执行 `sub $t0,$s0,$s1`，若 `$s0=$s1`，Zero=1，处理器会分支吗？

**答案：** 不会。它是 R 型运算，Branch=0，所以 PCSrc=0，PC 仍加 4。只有 beq 的 Branch=1 才允许 Zero 参与改变控制流。

### 题 4：立即数与分支目标

PC=`0x00400010`，beq 字段 imm=`0xFFFE`，比较结果相等。下一 PC 是多少？

**答案：** `0xFFFE` 按 16 位补码为 -2，目标 `0x00400014-8=0x0040000C`。先符号扩展再左移两位，最后由 PCSrc 选中目标。

### 题 5：两级译码

`or $t0,$s0,$s1` 的 opcode、funct、ALUOp、ALUControl 各是什么？

**答案：** opcode=`000000`，funct=`100101`，ALUOp=`10`，ALUControl=`001`。前两个来自 ISA 编码，后两个来自课件内部控制约定。

### 题 6：有符号比较边界

若 $A=-2^{31}$、B=1，低 32 位 $A-B$ 的符号位为 0，能因此说 A≥B 吗？

**答案：** 不能。减法发生有符号溢出，V=1，$less=0\oplus1=1$，因此 A<B。直接使用差的符号会出错。

### 题 7：加权 CPI 与执行时间

某程序执行 $10^8$ 条指令，其中 60% 的 CPI=1、30% 的 CPI=3、10% 的 CPI=2，主频 2GHz。求平均 CPI 和 CPU 时间。

**答案：** $CPI=0.6+0.9+0.2=1.7$；$Cycles=1.7\times10^8$；$T=1.7\times10^8/(2\times10^9)=0.085s$，即 **85ms**。

### 题 8：频率提高是否一定更快？

新方案主频提高 20%，但总周期数增加 30%，执行相同任务。时间如何变化？

**答案：** $T_{new}/T_{old}=1.3/1.2\approx1.0833$，耗时增加约 **8.33%**。频率提升不足以抵消总周期增长。

### 题 9：关键路径与 max

沿用课件参数，但符号扩展延迟为 180ps，控制仍足够早到达。`lw` 数据写回路径需多久？

**答案：** ALU 前两路取 $\max(150,180+25)=205ps$。总延迟为：

$$30+250+205+200+250+25+20=\boxed{980ps}$$

925ps 的简化式不再适用；若这仍是全电路最长路径，则时钟至少取 980ps。

### 题 10：单周期执行时间

时钟周期 925ps 的单周期 CPU 执行 $10^9$ 条指令，需要多久？

**答案：** $10^9\times1\times925\times10^{-12}=\boxed{0.925s}$。注意这里是十亿条，课件 92.5s 的例子是千亿条，两者相差 100 倍。

### 题 11：多周期加权

多周期实现中 lw/sw/R/beq 各需 5/4/4/3 拍，比例为 20%/10%/50%/20%。平均 CPI 是多少？

**答案：** $0.2\times5+0.1\times4+0.5\times4+0.2\times3=\boxed{4.0}$。再乘具体时钟周期，才能与单周期方案比较。

### 题 12：流水线填充与额外周期

五级流水线，周期 250ps，执行 100 条指令，额外停顿及冲刷共耗 8 拍。总时间和实际 CPI 是多少？

**答案：** 周期数 $100+4+8=112$；总时间 $112\times250ps=\boxed{28ns}$；CPI=$112/100=\boxed{1.12}$。不能漏掉填充开销，也不能把已计入的冲刷再次计算。

### 题 13：数据相关与前递

为什么 `add` 后接使用结果的 ALU 指令可能无需停顿，而 `lw` 后接使用结果的 ALU 指令常需停顿？

**答案：** 典型五级模型中，加法结果在 EX 结束已产生，可前递到下一条的 EX；load 数据到 MEM 结束才产生，赶不上紧随指令原本的 EX 使用时刻。判断依据是产生与使用时刻，不是是否出现相同的寄存器名。

### 题 14：增加一条指令

在已有单周期数据通路上增加 `ori`，只增加 opcode 译码并把 ALU 功能改为 OR，是否足够？

**答案：** 不足。基础立即数支路是符号扩展，`ori` 要求零扩展，还需增加或选择扩展方式。同时设置写 rt、ALU 结果写回、关闭内存写入与分支等控制。
