## 一、全章框架：从“电路能做什么”到“程序怎样使用电路”

### 1. 体系结构与微体系结构

前几章研究加法器、寄存器、存储器等模块。本章把视角提高一层：**程序员怎样通过指令使用这些硬件能力？**

| 层次 | 解决的问题 | 示例 |
|---|---|---|
| 指令集体系结构（ISA） | 软件能看到哪些状态，可以要求机器执行什么操作？ | 有 32 个通用寄存器；`lw` 从内存读取一个字 |
| 微体系结构（Microarchitecture） | 用什么数据通路、控制器和时序实现这些操作？ | 单周期、多周期、流水线处理器 |
| 数字逻辑与电路 | 怎样实现具体的运算和存储模块？ | 加法器、MUX、D 触发器、SRAM |

例如，ISA 规定 `add` 的计算结果；实现者可以选择不同的加法器，甚至不同的指令执行周期数。只要遵守约定的软件可见行为，就可以实现同一套 ISA。

> [!tip] 把 ISA 理解成软硬件共同遵守的接口
> 程序说明“执行哪条指令、使用哪些操作数”；CPU 按接口定义更新寄存器、内存和 PC。同一 ISA 有利于二进制兼容，但完整程序能否直接运行，还与操作系统、ABI、扩展指令等环境有关。

### 2. 汇编语言与机器语言

| 表示层次 | 例子 | 谁使用它？ |
|---|---|---|
| 高级语言 | `a = b + c;` | 程序员、编译器 |
| 汇编语言（Assembly Language） | `add $s0, $s1, $s2` | 人和汇编器 |
| 机器语言（Machine Language） | `0x02328020` | 处理器译码电路 |

汇编语言是指令的可读写法，机器语言是它的编码。**CPU 不会直接理解变量名 `a` 或标号 `loop`**；这些名字需要由编译器、汇编器、链接器处理。

一行高级语言也不一定对应一条指令。例如：

```c
a = (b + c) - d;
```

```mips
# 约定：$s0=a，$s1=b，$s2=c，$s3=d
add $t0, $s1, $s2       # 临时结果 t0 = b + c
sub $s0, $t0, $s3       # a = t0 - d
```

这里假设结果不发生有符号溢出；寄存器分配是编译器或程序员作出的约定。

### 3. MIPS 的四个设计准则

| 准则 | 在本章中的体现 | 带来的好处与代价 |
|---|---|---|
| 简单有利于规整 | 常见算术指令采用两个源、一个目的操作数 | 字段位置固定，便于译码和接线 |
| 加快常见功能 | 常用运算直接实现，复杂操作可组合完成 | 简化常见路径；复杂任务可能需要更多指令 |
| 越小的设计往往越快 | 通用寄存器数量有限 | 读写和选择电路较小；更多数据要放内存 |
| 好的设计需要折中 | 统一 32 位指令长度，同时保留 R/I/J 三种格式 | 在规整性、立即数范围和跳转范围间平衡 |

这些是设计思路，不是脱离工艺与实现条件的绝对定律。RISC 的理解重点是规则、易译码的指令及 load/store 风格，不宜只背成“总指令数一定少”。

## 二、操作数与寄存器：先分清“编号、内容、地址”

### 1. 操作数可能在哪里？

| 位置 | 指令中的写法 | 含义 |
|---|---|---|
| 寄存器 | `$s1` | 使用该寄存器当前保存的 32 位内容 |
| 指令内部 | `-12`、`0x00FF` | 立即数（Immediate），按指令规则解释和扩展 |
| 内存 | `12($s0)` | 先算有效地址，再访问对应内存数据 |

下文统一使用：

- $R[r]$：编号为 r 的通用寄存器内容。
- $M_{32}[A]$：从字节地址 A 开始的一个 32 位字，按约定端序组装。
- $M_8[A]$：字节地址 A 上的一个字节。
- `PC`：当前指令的字节地址；不是通用寄存器堆中的某个编号。
- `SignExt` / `ZeroExt`：符号扩展 / 零扩展。

> [!example] 三个不同层次
> `$s0` 的寄存器编号是 16；若 `$s0=0x10010000`，它的内容可以被解释为内存地址；而该地址中的数据还要通过 `lw` 等指令读取。**寄存器编号 16、地址 `0x10010000`、地址中的数据，不能相互替代。**

### 2. 32 个通用寄存器

每个寄存器 32 位，共 32 个，因而一段寄存器编号字段需要：

$$\log_2 32=5\text{ bit}$$

| 名称 | 编号 | 课件中的用途 | 记忆要点 |
|---|---|---|---|
| `$zero` / `$0` | 0 | 常数 0 | 读取恒为 0，写入不改变其值 |
| `$at` | 1 | 汇编器临时寄存器 | 伪指令展开时可能使用 |
| `$v0`～`$v1` | 2～3 | 返回值 | 本章主要用 `$v0` |
| `$a0`～`$a3` | 4～7 | 前四个参数 | 超出的参数需要额外约定 |
| `$t0`～`$t7` | 8～15 | 临时变量 | 调用者按需要保护 |
| `$s0`～`$s7` | 16～23 | 保存变量 | 被调用者若修改，应恢复 |
| `$t8`～`$t9` | 24～25 | 临时变量 | 与前面的 t 寄存器同类 |
| `$k0`～`$k1` | 26～27 | 内核使用 | 普通示例不使用 |
| `$gp` | 28 | 全局指针 | 可用于访问附近的静态数据 |
| `$sp` | 29 | 栈指针 | 指向当前栈帧的低地址端 |
| `$fp` | 30 | 帧指针 | 部分约定也称 `$s8` |
| `$ra` | 31 | 返回地址 | `jal` 写入，`jr $ra` 使用 |

这些名字主要体现软件使用约定；例如 `$t0` 并不具备“只能保存临时变量”的特殊硬件限制。`$zero` 的恒零规则则是体系结构行为。

此外还有 **PC、HI、LO 等专用状态**。HI/LO 不属于上表中的 32 个通用寄存器，不能把 `$32` 当作 HI 使用。

### 3. 算术指令的书写顺序

```mips
add  $s0, $s1, $s2      # R[s0] = R[s1] + R[s2]
sub  $s0, $s1, $s2      # R[s0] = R[s1] - R[s2]
addi $s0, $s1, -12      # R[s0] = R[s1] + SignExt(-12)
```

**汇编通常把目的寄存器写在最前面**，但机器码不按这个顺序排列字段，后面会专门区分。

`addi` 的 16 位立即数按有符号补码解释，范围为：

$$-2^{15}\le imm\le2^{15}-1\quad\Rightarrow\quad-32768\sim32767$$

因此减去一个可表示的常数，可以写成加上其相反数，不需要单独设置基础指令 `subi`。

> [!warning] 指令名称中的 unsigned 不等于“立即数零扩展”
> 补充理解：`add/addi/sub` 在有符号溢出时可触发异常；`addu/addiu/subu` 保留低 32 位、不触发这种溢出异常。`addiu` 的立即数仍然是**符号扩展**。零扩展主要见本章的 `andi/ori/xori`，要按指令分别记忆。

## 三、内存与 load/store：地址每加 1，前进一个字节

### 1. 字节编址、字长与对齐

MIPS 教学模型按字节编址，一个 word 为 4 字节。

| 数据对象 | 长度 | 连续对象的起始地址示例 |
|---|---|---|
| Byte | 1 字节 | 0、1、2、3…… |
| Halfword | 2 字节 | 0、2、4、6…… |
| Word | 4 字节 | 0、4、8、12…… |

对于从基地址 B 开始的 32 位整数数组：

$$\operatorname{Address}(array[i])=B+4i$$

课件第 20～23 页先借用“字编址”说明原理，第 24 页转为真正的 MIPS 字节编址。读例题时要辨清模型，不能把前面临时使用的字地址规则一直沿用下去。

> [!important] 普通 `lw/sw` 的有效地址应满足字对齐
> 本章普通字访问要求 $EA\bmod4=0$，即地址最低两位为 `00`。半字访问通常要求地址是 2 的倍数，字节访问没有这项对齐限制。`lw` 的偏移字段可以是任意 16 位有符号数，但**最终计算出的地址**必须满足该指令的对齐条件。

### 2. 基址加偏移：`lw` 与 `sw`

$$EA=R[rs]+\operatorname{SignExt}_{32}(imm_{16})$$

| 指令 | 状态变化 | `rt` 的身份 |
|---|---|---|
| `lw rt, imm(rs)` | $R[rt]\leftarrow M_{32}[EA]$ | 目的寄存器 |
| `sw rt, imm(rs)` | $M_{32}[EA]\leftarrow R[rt]$ | 待写入数据的源寄存器 |

```mips
lw $t0, 12($s0)         # 从 s0+12 读取一个字，送入 t0
sw $t0, 16($s0)         # 把 t0 的一个字写入 s0+16
```

> [!tip] 最容易多乘一次 4 的地方
> **`lw/sw` 中的立即数已经是字节偏移，不再乘 4。** 数组下标 i 是“第几个元素”，所以要先转成字节偏移 4i；但写成 `lw $t0, 12($s0)` 后，12 已经代表 12 字节。

**完整例：** 已知 `$s0=0x10010010`，地址 `0x1001000C` 中的字为 `0x12345678`。

```mips
lw $t0, -4($s0)
```

1. 立即数 -4 的 16 位补码为 `0xFFFC`。
2. 符号扩展后为 `0xFFFFFFFC`，仍表示 -4。
3. $EA=\texttt{0x10010010}-4=\texttt{0x1001000C}$。
4. 地址末两位为 `00`，满足字对齐。
5. `$t0=0x12345678`，`$s0` 和该内存单元不变。

### 3. load/store 结构为什么要“先取出，再运算”？

常见算术逻辑指令直接操作寄存器。若 a、b、c 都在内存中，`a=b+c` 可以拆成：

```mips
# 假设 s0 指向三个连续的字：a、b、c
lw  $t0, 4($s0)        # 读取 b
lw  $t1, 8($s0)        # 读取 c
add $t2, $t0, $t1      # 在寄存器间做加法
sw  $t2, 0($s0)        # 将结果保存为 a
```

load 是“内存 → 寄存器”，store 是“寄存器 → 内存”。**`sw` 不会把数据写回某个通用寄存器。**

### 4. 字节读写：`lb`、`lbu`、`sb`

| 指令 | 操作 | 结果的高位怎样处理？ |
|---|---|---|
| `lb rt, imm(rs)` | 读取一个字节 | 符号扩展到 32 位 |
| `lbu rt, imm(rs)` | 读取一个字节 | 零扩展到 32 位 |
| `sb rt, imm(rs)` | 写入 `rt` 的最低 8 位 | 只改一个字节，相邻字节不变 |

若某字节为 `0x89`：`lb` 得到 `0xFFFFFF89`（-119），`lbu` 得到 `0x00000089`（137）。**读入长度相同，解释与扩展规则不同。**

### 5. 大端与小端：改变的是字节的排列

把字 `0x23456789` 从地址 A 开始存放：

| 字节地址 | 大端（Big-Endian） | 小端（Little-Endian） |
|---|---|---|
| A | `23`，最高有效字节 | `89`，最低有效字节 |
| A+1 | `45` | `67` |
| A+2 | `67` | `45` |
| A+3 | `89`，最低有效字节 | `23`，最高有效字节 |

口诀：**大端低地址放“大头”，小端低地址放“小头”**；这里的“大、小”指字节在数值中的位权。

课件第 30 页：

```mips
# t0 初值为 0x23456789
sw $t0, 0($zero)
lb $s0, 1($zero)
```

- 大端读到 `0x45`，结果 `$s0=0x00000045`。
- 小端读到 `0x67`，结果 `$s0=0x00000067`。
- 若改读偏移 0，小端读到 `0x89`，`lb` 会得到 `0xFFFFFF89`，不能漏掉符号扩展。

这个例子用于说明地址与字节排列，假设地址 0 可访问；实际运行环境可能保留低地址。采用同一种端序写入再用 `lw` 读回，数值仍为 `0x23456789`；当拆字节、跨系统交换数据时，端序差异就需要显式处理。

## 四、机器指令编码：固定 32 位，字段各司其职

### 1. R / I / J 三种格式总览

```text
位编号    31      26 25    21 20    16 15    11 10     6 5       0
R 型      | op:6  | rs:5   | rt:5   | rd:5   |shamt:5 | funct:6 |
I 型      | op:6  | rs:5   | rt:5   |        imm:16           |
J 型      | op:6  |                index:26                  |
```

| 字段 | 位数 | 作用 |
|---|---|---|
| `op` / opcode | 6 | 初步识别指令类别 |
| `rs` | 5 | 常见的第一源寄存器或基址寄存器 |
| `rt` | 5 | 第二源寄存器，或部分 I 型指令的目的寄存器 |
| `rd` | 5 | 常见 R 型运算的目的寄存器 |
| `shamt` | 5 | 立即移位量，可表示 0～31 |
| `funct` | 6 | 在本章 `op=0` 的 R 型中进一步确定操作 |
| `imm` | 16 | 常数、访存偏移或分支偏移，解释取决于指令 |
| `index` | 26 | J 型跳转索引，需要参与地址拼接 |

> [!warning] R 型并不表示每条指令都使用三个寄存器
> 普通 `add/sub` 使用 rs、rt、rd；立即移位用 rt、rd、shamt；`jr` 主要使用 rs。格式规定字段在哪里，具体指令规定哪些字段有效。本章常用 R 型 `op=0`，不能把这一简化判定扩展为所有 MIPS 版本的完整译码规则。

### 2. 常用操作码与功能码

| 指令 | 格式 | opcode（二进制） | funct（十六进制） |
|---|---|---|---|
| `add` / `sub` | R | `000000` | `20` / `22` |
| `and` / `or` / `xor` / `nor` | R | `000000` | `24` / `25` / `26` / `27` |
| `slt` | R | `000000` | `2A` |
| `sll` / `srl` / `sra` | R | `000000` | `00` / `02` / `03` |
| `jr` | R | `000000` | `08` |
| `addi` | I | `001000` | — |
| `andi` / `ori` / `xori` | I | `001100` / `001101` / `001110` | — |
| `lui` | I | `001111` | — |
| `lw` / `sw` | I | `100011` / `101011` | — |
| `beq` / `bne` | I | `000100` / `000101` | — |
| `j` / `jal` | J | `000010` / `000011` | — |

先掌握字段和编码方法，具体代码可查表。**funct 的 `0x20` 是十进制 32，不要把它误填为十进制 20。**

### 3. R 型完整例：`add $s0, $s1, $s2`

汇编顺序为 `add rd, rs, rt`；机器码顺序为 `op, rs, rt, rd, shamt, funct`。

| 字段 | op | rs | rt | rd | shamt | funct |
|---|---|---|---|---|---|---|
| 十进制值 | 0 | 17 | 18 | 16 | 0 | 32 |
| 二进制 | `000000` | `10001` | `10010` | `10000` | `00000` | `100000` |

拼接后，再从最高位起每四位分组：

```text
000000 10001 10010 10000 00000 100000
0000 0010 0011 0010 1000 0000 0010 0000
   0    2    3    2    8    0    2    0
```

所以机器码是 **`0x02328020`**。

也可按位权校验：

$$W=(op\ll26)+(rs\ll21)+(rt\ll16)+(rd\ll11)+(shamt\ll6)+funct$$

这里各字段互不重叠，因此相加等效于按位 OR。

### 4. I 型完整例：`addi $t0, $s3, -12`

| 字段 | op | rs | rt | imm |
|---|---|---|---|---|
| 值 | 8 | 19 | 8 | -12 的 16 位补码 |
| 二进制 | `001000` | `10011` | `01000` | `1111111111110100` |

$$W=(8\ll26)+(19\ll21)+(8\ll16)+\texttt{0xFFF4}=\texttt{0x2268FFF4}$$

**负数立即数只在 16 位字段内求补，再由执行硬件扩展到 32 位**，不能把 32 位负数直接塞进 16 位槽位。

同类例子：

| 汇编 | 机器码 | 核对点 |
|---|---|---|
| `addi $s0, $s1, 5` | `0x22300005` | I 型目的寄存器在 rt |
| `lw $t2, 32($zero)` | `0x8C0A0020` | rs=0，rt=10，偏移 32 字节 |
| `sw $s1, 4($t1)` | `0xAD310004` | rs=9，rt=17，rt 是待存数据 |

### 5. 反向译码：先切字段，再解释数值

以 `0x2237FFF1` 为例：

1. 最高 6 位为 `001000`，识别为 `addi`。
2. rs=17 → `$s1`；rt=23 → `$s7`。
3. 立即数字段 `0xFFF1` 的最高位是 1，按 16 位补码解释为 $65521-65536=-15$。
4. 得到 **`addi $s7, $s1, -15`**。

> [!tip] 编码题通用检查法
> 先写指令格式 → 列字段表 → 检查位数之和为 32 → 拼接 → 每四位转十六进制 → 再反向译码一次。寄存器内容不参与编码，参与编码的是**寄存器编号**。

## 五、常用指令：逻辑、移位、常数和乘除法

### 1. 按位逻辑与掩码（Mask）

| 操作 | 典型用途 | 示例 |
|---|---|---|
| AND | 保留指定的位，其余清零 | `x AND 0x000000FF` 保留最低字节 |
| OR | 将指定的位设为 1 | `x OR 0x00000020` 将第 5 位设为 1 |
| XOR | 翻转指定的位 | `x XOR 0x00000020` 翻转第 5 位 |
| NOR | 组合取反 | `x NOR 0` 得到逐位 NOT x |

```mips
andi $t0, $s0, 0x00FF  # 保留 s0 的最低 8 位
ori  $t1, $s0, 0x0020  # 将第 5 位设为 1，最低位编号为 0
xori $t2, $s0, 0x0020  # 翻转第 5 位
nor  $t3, $s0, $zero   # 对整个 32 位字取反
```

**`andi/ori/xori` 将 16 位立即数零扩展**。例如：

```mips
ori  $t0, $zero, 0xFFFF    # t0 = 0x0000FFFF
addi $t1, $zero, -1        # t1 = 0xFFFFFFFF
```

两条指令末尾的低 16 位相同，结果却不同，因为扩展规则不同。

逐位取反与求相反数也不同。补码求负可用 `subu $t0, $zero, $s0`；若使用“取反再加 1”，则仍应留意最小负数的数学相反数无法在同位宽中表示。

### 2. 移位：回填规则比名称更重要

| 指令 | 变化 | 空出的位置 |
|---|---|---|
| `sll rd, rt, shamt` | 逻辑左移 | 低位补 0 |
| `srl rd, rt, shamt` | 逻辑右移 | 高位补 0 |
| `sra rd, rt, shamt` | 算术右移 | 高位复制原符号位 |
| `sllv/srlv/srav rd, rt, rs` | 由寄存器给出移位量 | 教学 MIPS32 使用 rs 内容的低 5 位 |

```mips
# s0 = 0xFFFFFFF8，按 32 位补码解释为 -8
srl $t0, $s0, 2         # 0x3FFFFFFE
sra $t1, $s0, 2         # 0xFFFFFFFE，即 -2
```

- 固定位宽左移丢弃移出的高位，不能无条件当作无溢出的数学乘法。
- 补码算术右移相当于除以 $2^k$ 后向负无穷取整。例如 -7 算术右移 1 位得到 -4；有符号整数除法通常向零截断，-7/2 为 -3，二者不能任意互换。
- 立即移位的 shamt 为 5 位；`sll $t0,$t1,32` 不能按本格式直接表示。

### 3. 生成 32 位常数：`lui + ori`

`lui rt, imm` 把立即数放入寄存器高 16 位，低 16 位清零：

$$R[rt]\leftarrow imm_{16}\ll16$$

课件第 69 页的 `0xFEDC8765`：

```mips
lui $s0, 0xFEDC          # s0 = 0xFEDC0000
ori $s0, $s0, 0x8765     # s0 = 0xFEDC8765
```

> [!warning] 低半字最高位为 1 时，不要随意把 `ori` 换成 `addi`
> `0x8765` 若按 `addi` 的立即数规则解释，会符号扩展成负数，使高半字也受加法影响。`lui+ori` 是按字段拼接；`lui+addiu` 则可能需要调整高半字，不能机械替换。

伪指令 `li`、`la`、`move`、`not` 可以提高可读性，但不是本章基础 ISA 中独立的固定机器码；展开条数与具体用法有关。尤其 `la` 取得的是地址，`lw` 取得的是地址中的数据。

### 4. 乘除法与 HI/LO

| 指令 | 结果位置 |
|---|---|
| `mult rs, rt` | 64 位有符号积：HI 保存高 32 位，LO 保存低 32 位 |
| `multu rs, rt` | 同位宽操作数按无符号数解释，结果仍在 HI/LO |
| `div rs, rt` | 有符号商在 LO，余数在 HI |
| `divu rs, rt` | 无符号商在 LO，余数在 HI |
| `mflo rd` / `mfhi rd` | 将 LO / HI 内容复制到通用寄存器 |

```mips
# 假设 s0=17，s1=5
div  $s0, $s1
mflo $t0                # t0 = 3
mfhi $t1                # t1 = 2
```

用 $17=3\times5+2$ 验算。对可正常表示的有符号除法，商向零截断，余数与被除数同号或为 0。除数为 0、最小负数除以 -1 等边界不能按普通例题直接推断。

HI/LO 会被后续相关运算覆盖，**需要的结果应及时读取或保存**。第七章的基础单周期 CPU 不包含这组乘除法指令，学习 ISA 与设计一个指令子集是两件不同层次的事。

### 5. 字符也是编码：ASCII

| 字符 | ASCII 十六进制 |
|---|---|
| `'0'` / `'9'` | `0x30` / `0x39` |
| `'A'` / `'Z'` | `0x41` / `0x5A` |
| `'a'` / `'z'` | `0x61` / `0x7A` |
| 空格 | `0x20` |

数字 5 与字符 `'5'` 的编码不同：前者的数值是 5，后者是 `0x35`（53）。ASCII 使用 7 位编码，常存放在一个字节中；相应英文字母大小写相差 `0x20`，但这种规律不能不加检查地用于任意字符。

## 六、控制流与寻址：下一条指令究竟在哪里？

### 1. 顺序执行与 PC

在本章 32 位定长指令模型中：

$$PC_{next}=PC+4$$

PC 保存的是**指令地址**，不是指令本身。取指时用 PC 访问指令存储器，得到机器码；跳转改变的是后续取指地址。

### 2. `beq/bne`：比较寄存器，再决定是否跳转

```mips
beq $s0, $s1, target     # 相等则跳转
bne $s0, $s1, target     # 不相等则跳转
```

分支采用 **PC 相对寻址（PC-relative Addressing）**：

$$PC_{branch}=PC+4+\bigl(\operatorname{SignExt}_{32}(imm_{16})\ll2\bigr)$$

$$imm_{16}=\frac{\text{目标字节地址}-(PC+4)}{4}$$

三个要点：**基准是 PC+4；机器码中的偏移以指令字为单位；执行时先符号扩展再左移 2 位。**

**正向例：** 课件第 107 页，分支指令位于 `0x10`，目标 `else` 在 `0x20`。

$$imm=(\texttt{0x20}-\texttt{0x14})/4=3$$

所以偏移字段为 `0x0003`。若条件不成立，下一条仍在 `0x14`。

**反向例：** 分支位于 `0x00400020`，循环入口在 `0x00400008`。

$$imm=(\texttt{0x00400008}-\texttt{0x00400024})/4=-7$$

字段为 `0xFFF9`；验证 $PC+4+(-7)\times4=\texttt{0x00400008}$。

16 位带符号偏移可覆盖相对于 PC+4 的 $-131072\sim+131068$ 字节，目标仍须字对齐。它是“附近跳转”，不是任意 32 位地址。

### 3. `j/jal`：26 位索引拼成 32 位地址

J 型使用 **伪直接寻址（Pseudo-direct Addressing）**：

$$PC_{jump}=\operatorname{concat}\bigl((PC+4)_{31:28},\ index_{25:0},\ 00\bigr)$$

```text
32 位跳转地址 = [ PC+4 的高 4 位 ][ 指令内的 26 位 index ][ 00 ]
                  同一地址区域       省略对齐低位        字对齐
```

这里是**拼接**，不是把“高 4 位的数值”与 index 做普通加法。跳转索引不做符号扩展，目标必须位于由 PC+4 高四位确定的同一 256MiB 区域。

**课件第 108 页例：** `jal sum` 的目标为 `0x004000A0`。

$$index=\texttt{0x004000A0}\gg2=\texttt{0x00100028}$$

$$W=(3\ll26)+index=\texttt{0x0C100028}$$

> [!tip] 汇编目标地址与机器字段不要混写
> 汇编通常写 `jal sum` 或目标字节地址；机器码中才存右移两位后的索引。不能为了手算编码，把汇编操作数也提前右移一次。位于区域边界时应使用 **PC+4 的高四位**，不能偷换成当前 PC 的高四位。

### 4. `jr`：完整目标地址来自寄存器

```mips
jr $ra                  # PC_next = R[ra]
```

`jr` 是 R 型指令，目标取自 rs 的完整内容，不使用 J 型的 26 位索引；在本章模型中目标需要 4 字节对齐。它可以返回函数，也可以跳转到提前装入寄存器的地址。

| 指令 | 跳转条件 | 目标来源 | 是否自动写 `$ra`？ |
|---|---|---|---|
| `beq/bne` | 寄存器相等 / 不等 | PC+4 加带符号偏移 | 否 |
| `j` | 无条件 | PC+4 高四位与 index 拼接 | 否 |
| `jal` | 无条件 | 同 `j` | 是，本章为 PC+4 |
| `jr` | 无条件 | rs 中的完整地址 | 否 |

### 5. `slt`：先产生布尔值，再配合分支

```mips
slt $t0, $s0, $s1       # 按有符号数比较：s0<s1 时 t0=1，否则 t0=0
bne $t0, $zero, less    # 比较结果为真则跳转
```

补充：`sltu` 按无符号数比较；`slti` 使用符号扩展的立即数。比较结果是整个寄存器中的 0 或 1，不是修改某个通用的独立标志寄存器。

> [!warning] 本章的延迟槽约定
> 课件函数例使用 `$ra=PC+4`，本文按“分支或跳转后直接转向目标”的教学模型推导。传统带延迟槽的 MIPS 会执行控制转移后的一条指令，经典 `jal` 的链接地址为 PC+8。将本文代码放入模拟器时，要确认其延迟分支选项；不能仅改变返回地址而忽略整个控制流语义。

## 七、把高级语言翻译为指令：判断、循环与数组

### 1. `if/else`：条件不成立时，跳过 then 部分

```c
if (i == j)
    f = g + h;
else
    f = g - h;
```

```mips
# s0=f，s1=g，s2=h，s3=i，s4=j
bne $s3, $s4, else_part    # 不满足 i==j，则进入 else
add $s0, $s1, $s2          # then 部分
j   done                  # 避免继续落入 else
else_part:
sub $s0, $s1, $s2
done:
```

汇编采用反向条件是一种便于布局的写法：正常向下执行 then，条件不满足时跳走。它不是规定所有 if 都必须反向翻译；也可以重排分支，保证语义一致即可。

### 2. 循环的四部分：初始化、判断、循环体、更新

课件第 81 页累加 0～9：

```c
int sum = 0;
for (int i = 0; i != 10; i++)
    sum += i;
```

```mips
addi $s0, $zero, 0         # sum = 0
addi $s1, $zero, 0         # i = 0
addi $t0, $zero, 10        # 终止值
loop:
beq  $s1, $t0, done        # i==10 则退出
add  $s0, $s0, $s1         # sum += i
addi $s1, $s1, 1           # i++
j    loop
done:
```

| 时刻 | i | sum |
|---|---|---|
| 初始化后 | 0 | 0 |
| 完成第 1 轮 | 1 | 0 |
| 完成第 2 轮 | 2 | 1 |
| 完成第 10 轮 | 10 | 45 |
| 下一次判断 | 10 | 45，退出 |

**循环体执行 10 次，循环条件检查 11 次。** 第七章计算动态指令数时，这个差别十分重要。

若要求 `i<10` 而不是 `i!=10`，通用翻译应使用大小比较；只有能够证明 i 从 0 单调加 1 到 10、不跳过终止值时，两者才等价。

### 3. 数组元素地址：先把下标变成字节偏移

对 32 位整数数组：

$$EA=B+4i=B+(i\ll2)$$

```mips
# s0 为数组基地址，s1 为下标 i
sll  $t0, $s1, 2           # t0 = 4*i，单位为字节
addu $t0, $s0, $t0         # t0 = &array[i]
lw   $t1, 0($t0)           # t1 = array[i]
```

这里用补充指令 `addu` 做地址加法，保留 32 位结果；本例假设地址有效、没有越界。数组访问本身不会自动检查 i 是否越界。

**完整例：把 1000 个数组元素分别乘以 8。**

```mips
# s0 = array 基地址，此前已准备好
addi $s1, $zero, 0         # i = 0
addi $t2, $zero, 1000      # 元素数量
array_loop:
slt  $t0, $s1, $t2         # i < 1000？
beq  $t0, $zero, array_done
sll  $t0, $s1, 2           # 字节偏移 = i*4
addu $t0, $s0, $t0         # 元素地址
lw   $t1, 0($t0)
sll  $t1, $t1, 3           # 左移 3 位，保留低 32 位结果
sw   $t1, 0($t0)
addi $s1, $s1, 1
j    array_loop
array_done:
```

若要求与 C 的有符号 `int` 乘法在数学上完全一致，还要保证没有有符号溢出；不能因为移位指令总能产生一个位串，就认为任意有符号乘法都有效。

> [!tip] 数组题只问自己三个问题
> 一个元素多少字节？下标怎样变成字节偏移？最终是在求地址，还是在读取内容？对于 `char` 数组偏移通常是 i；对于本章 `int` 数组则是 4i。

## 八、函数调用：传入参数、保存现场、带着结果返回

### 1. 一次调用需要完成什么？

| 阶段 | 调用者（Caller） | 被调用者（Callee） |
|---|---|---|
| 准备 | 放好参数；保存调用后仍需要的易失寄存器 | — |
| 进入 | 执行 `jal function` | 从入口开始执行 |
| 工作 | 等待返回 | 分配栈帧；按需保存寄存器；计算 |
| 返回 | — | 将结果放入 `$v0`；恢复现场；`jr $ra` |
| 继续 | 读取返回值，恢复自己保存的数据 | — |

![函数调用流程](<阅读资源/函数调用流程.svg>)

### 2. 参数与返回值：简单叶函数

```c
int sum(int a, int b) {
    return a + b;
}
```

```mips
# 调用端片段
addi $a0, $zero, 42
addi $a1, $zero, 17
jal  sum
addu $s0, $v0, $zero       # 返回后 s0 = 59
# 此处继续调用者代码；实际布局应避免顺序落入函数体

# 函数放在独立位置
sum:
add $v0, $a0, $a1
jr  $ra
```

叶函数（Leaf Procedure）不再调用其他函数。上述 `sum` 不修改 s 寄存器，也不覆盖 `$ra`，因而不必仅为“形式完整”而压栈。

### 3. 栈：向低地址增长的临时存储空间

分配空间是减小 `$sp`，释放空间是增大 `$sp`：

```mips
addiu $sp, $sp, -8         # 先取得 8 字节空间
sw    $s0, 0($sp)          # 在已分配范围内保存数据
# ... 使用栈帧 ...
lw    $s0, 0($sp)          # 先恢复数据
addiu $sp, $sp, 8          # 再归还空间
```

假设进入时 `$sp=0x7FFFFFF8`，分配后变为 `0x7FFFFFF0`；新取得的字节范围为 `0x7FFFFFF0`～`0x7FFFFFF7`。最终必须恢复到原来的 `0x7FFFFFF8`。

栈增长方向是地址方向；**入栈不是移动整块内存，而是移动栈指针并读写相应地址**。返回时释放栈帧也不等于把那片物理内存清零。

### 4. 哪些寄存器由谁保护？

| 状态 | 保护责任 | 具体规则 |
|---|---|---|
| `$s0`～`$s7`、使用时的 `$fp` | 被调用者 | 修改前保存，返回前恢复；没修改就不必保存 |
| `$sp` | 被调用者维护平衡 | 返回时恢复为调用前的值 |
| `$t0`～`$t9` | 调用者 | 若跨调用仍有用，应在调用前保存 |
| `$a0`～`$a3`、`$v0`～`$v1` | 通常视为易失 | 参数和返回值寄存器可被调用过程覆盖 |
| `$ra` | 取决于当前函数是否继续调用 | 当前函数再次执行 `jal` 前，若仍要返回上一层，必须保留原链接地址 |

> [!important] “要保护”不等于“每次都保存所有寄存器”
> 保护的是**调用后仍需要的值**。课件第 99～100 页先把 t、s 都保存以演示栈，第 101～102 页再引入责任划分。按调用约定实现时，通常只保存被修改的 s 寄存器和确实需要保留的其他状态。

课件对 `$ra` 的表格分类和调用者说明需要结合使用：`jal` 本来就会写 `$ra`。最实用的判断是，**一个函数若再调用子函数，而之后还要返回自己的调用者，就必须先保住自己的返回地址**。

### 5. 完整叶函数：`(f+g)-(h+i)`

下面沿用课件 `diffofsums`，只保护实际修改的 `$s0`，t 寄存器按易失处理。假设入栈前 `$sp` 已按 8 字节对齐，算术结果不溢出。

```mips
# a0=f，a1=g，a2=h，a3=i；返回值放 v0
diffofsums:
addiu $sp, $sp, -8
sw    $s0, 0($sp)          # 只保存本函数会修改的保留寄存器

add   $t0, $a0, $a1
add   $t1, $a2, $a3
sub   $s0, $t0, $t1
addu  $v0, $s0, $zero      # 在恢复 s0 以前，取走返回结果

lw    $s0, 0($sp)
addiu $sp, $sp, 8
jr    $ra
```

输入 2、3、4、5，得到 $(2+3)-(4+5)=-4$，返回 `$v0=0xFFFFFFFC`；调用者原来的 `$s0` 被恢复。**如果先恢复 `$s0` 再复制返回值，就会返回旧值。**

### 6. 非叶函数为什么必须保存 `$ra`？

```c
int sum_plus_one(int a, int b) {
    return sum(a, b) + 1;
}
```

```mips
sum_plus_one:
addiu $sp, $sp, -24        # 保持 8 字节对齐；前 16 字节预留参数区
sw    $ra, 20($sp)         # 保存返回上一层所需的地址
jal   sum                 # 这条指令会覆盖 ra
addi  $v0, $v0, 1          # 使用子函数返回值
lw    $ra, 20($sp)
addiu $sp, $sp, 24
jr    $ra
```

若不保存 `$ra`，最后的 `jr $ra` 可能又跳回本函数内 `jal` 后的位置，无法返回上一层。递归同理：每一层调用需要独立保存自己的返回地址和必要局部数据。

这里展示的是教学用栈帧和常见对齐习惯；完整 ABI 还规定参数区、更多参数及保存区布局。课件出现的 4/12 字节栈帧用于说明基本过程，不宜直接当作所有环境的 ABI 模板。

## 九、程序怎样变成正在运行的机器指令？

### 1. 编译、汇编、链接、装载

![编译与运行](<阅读资源/编译与运行.svg>)

| 工具 | 主要工作 | 此时哪些事情可能还未确定？ |
|---|---|---|
| 编译器 | 将高级语言转成低层操作；分配寄存器、优化 | 外部函数与数据的最终地址 |
| 汇编器 | 处理助记符、标号和伪指令，生成机器码 | 需要链接后重定位的地址 |
| 链接器 | 合并目标文件和库；解析符号、安排布局、修正引用 | 动态链接程序仍可能保留运行时解析任务 |
| 装载器 | 将程序映射或装入地址空间，准备入口和运行环境 | 实际物理页分配可按需发生 |

课件按“先产生汇编，再产生 obj”的流程讲解；实际工具链也可以直接产生目标代码，不要求一定留下 `.asm` 文件。

### 2. 标号、伪指令与汇编器指示

```mips
.data
f: .word 2
g: .word 3
y: .word 0

.text
sum:
add $v0, $a0, $a1
jr  $ra
```

- `sum:`、`f:` 是符号名，用于标识位置，不各自占一条机器指令。
- `.text`、`.data` 是汇编器指示，选择代码或数据区域；CPU 不执行它们。
- `.word 2` 分配并初始化一个字，与“只写一个标签”不同。
- 汇编器可以先记录符号，再补全引用；外部符号可能仍需链接器解析。
- 一条伪指令可能展开成多条机器指令，计算地址时应按**展开后的实际长度**前进。

### 3. 内存布局：代码、静态数据、堆、栈

| 区域 | 典型内容 | 课件示意 |
|---|---|---|
| Text 代码段 | 机器指令 | 示例入口 `0x00400000` |
| 静态数据段 | 全局变量、静态变量等 | 示例从 `0x10000000` 开始 |
| Heap 堆 | 运行时分配的数据 | 示意向高地址扩展 |
| Stack 栈 | 保存寄存器、局部数据、调用相关信息 | 示意从高地址向低地址扩展 |
| 保留 / 内核区域 | 系统用途、特定映射 | 用户程序不能随意使用 |

这些地址是课件和模拟器的示例布局，**不是所有 MIPS 操作系统固定采用的地址**。例如初始 `$sp` 的具体值应由运行环境给出并满足对齐；不能从课件某处的 `0x7FFFFFFF` 文本直接推导它适合执行 `sw`。

32 位字节地址共有 $2^{32}$ 个取值，即 **4GiB 地址空间**；这不表示机器必然安装 4GiB 物理内存，也不表示这些地址都对用户程序开放。

**`$gp` 与带符号偏移的联系：** 若 `$gp=0x10008000`，则 `0x10000000` 与它相差 -32768，恰可放入有符号 16 位偏移。机器字段 `0x8000` 在这种访存指令中解释为 -32768，不能当作 +32768。

### 4. 存储程序原理（Stored-program Concept）

指令也能以二进制内容存放在存储器中。更换程序，主要是更换指令与数据，不需要为了每个新算法重新接线。

**同一位串是什么，取决于使用方式**：从取指路径读出时按指令编码解释，从数据路径读出时可能按整数、字符或地址解释。

第七章为实现单周期并行访问，将指令存储器与数据存储器分开绘制。这与存储程序思想并不矛盾：它们仍保存机器指令与数据；这里讨论的是访问接口和硬件组织。

## 十、综合速查：用一套步骤追踪程序

### 1. 五类寻址方式

| 寻址方式 | 典型指令 | 找到的是什么？ | 计算规则 |
|---|---|---|---|
| 寄存器寻址 | `add rd,rs,rt` | 运算数据 | 读取寄存器内容 |
| 立即数寻址 | `addi`、`ori` | 指令中的常数 | 按具体指令符号扩展或零扩展 |
| 基址寻址 | `lw/sw` | 数据的字节地址 | $R[rs]+\operatorname{SignExt}(imm)$ |
| PC 相对寻址 | `beq/bne` | 分支目标 | $PC+4+(\operatorname{SignExt}(imm)\ll2)$ |
| 伪直接寻址 | `j/jal` | 跳转目标 | 拼接 PC+4 高 4 位、index 和 `00` |

`jr` 的指令目标由寄存器直接给出。不同教材对这种控制转移寻址的名称可能不同，解题时写出 **$PC_{next}=R[rs]$** 比只写名称更清楚。

### 2. 一个小程序的完整执行记录

初态：`$s0=0x10010000`、`$t1=5`，`M32[0x10010004]=7`。代码在 `0x00400000` 开始：

```mips
lw  $t0, 4($s0)
add $t0, $t0, $t1
sw  $t0, 8($s0)
beq $t0, $t1, target
```

| 当前 PC | 指令效果 | 执行后下一 PC |
|---|---|---|
| `0x00400000` | 地址 `0x10010004` 读取 7，写 `$t0` | `0x00400004` |
| `0x00400004` | `$t0=7+5=12` | `0x00400008` |
| `0x00400008` | 将 12 写到地址 `0x10010008` | `0x0040000C` |
| `0x0040000C` | 12≠5，分支不成立 | `0x00400010` |

追踪时每条指令只记录**发生改变的状态**：目的寄存器、写入的内存、下一 PC。`sw` 不改 `$t0`，`beq` 不改被比较的寄存器。

## 十一、常见陷阱与考点总结

| 易错点 | 正确理解 |
|---|---|
| 把 `$s0` 的编号当作操作数数值 | 编码放编号，执行时读取该编号对应的内容 |
| 所有 I 型立即数都符号扩展 | `addi/lw/sw/beq` 使用符号扩展；`andi/ori/xori` 零扩展 |
| `lw` 偏移再乘 4 | 访存偏移已是字节数；数组下标才需按元素大小缩放 |
| `lw` 与 `sw` 的 rt 都是目的寄存器 | `sw` 的 rt 是待写数据来源 |
| 偏移量整除 4 就一定可访问 | 检查最终有效地址、权限和合法范围 |
| `lb` 总在高位补 0 | `lb` 符号扩展，`lbu` 才零扩展 |
| 大小端改变寄存器内部位序 | 它规定多字节数据在内存中的字节排列 |
| 机器字段顺序与汇编顺序相同 | `add rd,rs,rt` 的机器字段是 rs、rt、rd |
| 分支偏移相对于当前 PC | 相对于 PC+4，字段以 4 字节为单位 |
| J 型字段就是完整目标地址 | 必须拼接 PC+4 高四位和对齐低两位 |
| `jr` 是 J 型 | 它是本章 op=0、funct=08 的 R 型指令 |
| 每个函数都必须保存所有寄存器 | 根据调用约定，只保护会被覆盖且必须保留的值 |
| `jal` 自动把返回地址压入栈 | 它写 `$ra`，是否入栈由软件决定 |
| `li/la/move/not` 都对应一条固定机器指令 | 它们通常由汇编器按需要展开 |
| 同一 ISA 就保证所有程序直接运行 | 还要匹配 ABI、操作系统、扩展与运行环境 |

## 十二、自测练习题与解析

### 题 1：立即数扩展

分别执行下列指令，两个寄存器是什么值？

```mips
addi $t0, $zero, -1
ori  $t1, $zero, 0xFFFF
```

**答案：** `$t0=0xFFFFFFFF`，`$t1=0x0000FFFF`。差别来自符号扩展与零扩展，不是十进制和十六进制写法本身。

### 题 2：有效地址与对齐

`$s0=0x10010010`，执行 `lw $t0,-8($s0)`，有效地址是多少？若改为偏移 -7 呢？

**答案：** 前者为 `0x10010008`，满足字对齐；后者为 `0x10010009`，普通 `lw` 不满足对齐要求。偏移可以编码，不代表访存一定有效。

### 题 3：大小端与 `lb/lbu`

将 `0x89ABCDEF` 存入 A 开始的四个字节，A 已对齐。分别在大端和小端下，从 A 用 `lb` 与 `lbu` 读取，结果如何？

**答案：** 大端首字节 `89`：`lb=0xFFFFFF89`、`lbu=0x00000089`；小端首字节 `EF`：`lb=0xFFFFFFEF`、`lbu=0x000000EF`。先确定字节，再应用扩展规则。

### 题 4：R 型编码

编码 `sub $t0,$t3,$t5`。

**答案：** op=0、rs=11、rt=13、rd=8、shamt=0、funct=`0x22`，得到 **`0x016D4022`**。注意目的寄存器 `$t0` 写在 rd 字段。

### 题 5：I 型反向译码

`0x2268FFF4` 对应什么指令？

**答案：** op=8 为 `addi`，rs=19 为 `$s3`，rt=8 为 `$t0`，`0xFFF4=-12`，即 **`addi $t0,$s3,-12`**。

### 题 6：反向分支

`beq $t0,$zero,loop` 位于 `0x00400020`，loop 位于 `0x00400008`。求立即数字段和完整机器码。

**答案：** $imm=(8-36)/4=-7$，字段 `0xFFF9`；op=4、rs=8、rt=0，机器码 **`0x1100FFF9`**。

### 题 7：J 型编码

在 `0x00400024` 处编码 `j 0x00400024`，机器码是多少？

**答案：** index=`0x00400024>>2=0x00100009`；op=2，机器码 **`0x08100009`**。机器字段是 26 位索引，汇编操作数仍写目标地址。

### 题 8：伪直接寻址的边界

若当前 `PC=0x0FFFFFFC`，某 `j` 的 index=0，目标是多少？

**答案：** PC+4=`0x10000000`，取其高四位 `1`，再拼接全零索引及 `00`，目标为 **`0x10000000`**。直接取当前 PC 高四位会得到错误结果。

### 题 9：数组地址

32 位整数数组基地址 `0x10010000`，求 `array[7]` 地址，并写读取指令。

**答案：** 偏移 $7\times4=28=\texttt{0x1C}$，地址 **`0x1001001C`**。若 `$s0` 保存基地址，可写 `lw $t0,28($s0)`，不用再缩放 28。

### 题 10：函数现场保护

函数 f 会修改 `$s1`、`$t0`，并调用 g。f 的调用者在返回后仍需原 `$s1`；f 也需要在 g 返回后继续使用某个临时值。应保护什么？

**答案：** f 应保存并恢复自己修改的 `$s1`；为返回上一层，调用 g 前保留原 `$ra`；跨 g 调用仍要使用的 t 类临时值由 f 自己保存。f 同时是上一层的 callee 和 g 的 caller，责任随角色而定。

### 题 11：循环的动态指令数

本章累加 0～9 的循环，三条初始化、循环头一条 `beq`，循环体三条 `add/addi/j`。不计 done 后代码，共执行多少条机器指令？

**答案：** 初始化 3 条，判断 11 条，循环体 $10\times3=30$ 条，总计 **44 条**。这是动态执行次数，不是源文件中的静态行数。

### 题 12：工具链与地址

`la $t0,array` 与 `lw $t0,0($s0)` 有何不同？链接器主要解决什么问题？

**答案：** 前者取得符号 array 对应的地址，通常由伪指令展开；后者取得 s0 所指内存中的一个字。链接器合并目标文件和库、解析符号并修正需要重定位的地址引用。
