#### 第一轮：继承、构造方法与final陷阱（约10分钟）

##### Q1：（主题14、16、18）继承中的构造调用与final空白变量

阅读以下代码，回答问题（1）~（3）：

```java
class Parent {
    String name;
    public Parent(String n) {
        name = n;
        System.out.println("Parent有参构造");
    }
}

class Child extends Parent {
    final int AGE;        // 行①：空白final（声明时未赋值）
    
    public Child() {
        System.out.println("Child无参构造");
    }
    
    public Child(String n) {
        super(n);
        AGE = 20;          // 行②
        System.out.println("Child有参构造");
    }
}

public class Test {
    public static void main(String[] args) {
        Child c = new Child();        // 行③
        // Child c2 = new Child("张三"); // 行④（已注释）
    }
}
```

**问题：**

（1）这段代码编译能通过吗？如果报错，指出所有错误行并分别说明原因。

（2）如果将行③注释掉，取消行④的注释（即只执行 `new Child("张三")`），编译能通过吗？为什么？

（3）要想让 `new Child()`（行③）编译通过，在不改动 `Parent` 类的前提下（即 `Parent` 只有有参构造），应该对 `Child` 的无参构造做怎样的修改？请写出完整的修改代码。

---

**【参考答案与踩分点】**

**（1）编译报错，共有两处编译错误：**

| 错误行 | 原因 |
|:------:|:-----|
| **行②**（间接） | `AGE` 是 `final` 空白变量，必须在**每一个**构造方法中完成首次赋值。有参构造中赋值了，但**无参构造中没有赋值**，编译器报错："变量 AGE 可能尚未初始化" |
| **行③** | `Child` 的无参构造中没有显式调用 `super(...)`，编译器默认插入 `super()`。但父类 `Parent` **没有无参构造**（只有有参构造），导致编译错误 |

> **踩分点**：必须同时答出两点——空白 `final` 要求**所有构造方法**都初始化，以及父类无无参构造导致默认 `super()` 失败。

**（2）如果只执行 `new Child("张三")`（行④）：**

编译**仍然报错**，但只剩**一处**错误：

| 错误行 | 原因 |
|:------:|:-----|
| **行②**（依然报错） | `AGE` 虽然在有参构造中赋值了，但 `Child` 的**无参构造中依然没有赋值**。编译器要求**所有构造方法**都必须覆盖空白 `final` 变量的初始化——因为任何一个构造方法都有可能被调用。即使本次只调用了有参构造，无参构造的"未赋值"问题依然会被编译期检查出来。 |

> **踩分点**：`final` 空白变量的初始化要求是**全局的**，所有构造方法都必须确保初始化，与"实际调用哪个构造方法"无关。

**（3）让 `new Child()` 编译通过的修改方案：**

在 `Child` 的无参构造中，必须同时解决两个问题：
- 显式调用父类有参构造（传默认值）
- 给空白 `final` 变量 `AGE` 赋值

```java
public Child() {
    super("默认名");   // ① 显式调用父类有参构造
    AGE = 0;           // ② 给空白final赋值
    System.out.println("Child无参构造");
}
```

或者更简洁的写法——通过 `this()` 委托给有参构造：

```java
public Child() {
    this("默认名");    // 调用本类有参构造，由它去调super和给AGE赋值
}
```

> **踩分点**：修改必须同时包含 `super(参数)` 或 `this(参数)` 以及 `AGE` 的赋值逻辑，缺一不可。

##### Q2：（主题15、17、21）多态、方法重写与instanceof

阅读以下代码，回答问题（1）~（3）：

```java
class Animal {
    public void shout() {
        System.out.println("动物叫");
    }
}

class Dog extends Animal {
    @Override
    public void shout() {
        System.out.println("汪汪汪");
    }
    public void guard() {
        System.out.println("看家护院");
    }
}

class Cat extends Animal {
    @Override
    public void shout() {
        System.out.println("喵喵喵");
    }
}

public class Test {
    public static void main(String[] args) {
        Animal a1 = new Dog();
        Animal a2 = new Cat();
        
        a1.shout();
        a2.shout();
        
        // a1.guard();          // 行⑤（已注释）
        
        if (a1 instanceof Dog) {
            Dog d = (Dog) a1;
            d.guard();
        }
        
        if (a2 instanceof Dog) {
            Dog d2 = (Dog) a2;
            d2.guard();
        } else {
            System.out.println("a2不是狗");
        }
    }
}
```

**问题：**

（1）`a1.shout()` 和 `a2.shout()` 分别输出什么？体现了多态的哪个特性？

（2）如果取消行⑤的注释，编译能通过吗？为什么？

（3）整个程序最终完整的控制台输出是什么？

---

**【参考答案与踩分点】**

**（1）`a1.shout()` 输出 `汪汪汪`，`a2.shout()` 输出 `喵喵喵`。**

体现了多态的**动态绑定（运行时多态）**：编译时类型是 `Animal`，运行时真正执行的是子类重写后的 `shout()` 版本。

> **踩分点**：必须提到"运行时决定"或"动态绑定"，仅说"多态"不够精准。

**（2）取消行⑤注释后编译报错。**

原因：`a1` 的编译时类型是 `Animal`，而 `Animal` 类中没有定义 `guard()` 方法。这正好对应了**多态的弊端**——父类引用无法直接调用子类独有方法。

> **踩分点**：必须点明"编译时检查引用类型，而非运行时对象类型"。

**（3）完整控制台输出：**

```
汪汪汪
喵喵喵
看家护院
a2不是狗
```

> **踩分点**：`instanceof Dog` 对 `a2`（实际是 `Cat`）判断为 `false`，进入 `else` 分支，输出 `a2不是狗`。

#### 第二轮：抽象、接口、静态与Object类方法（约10分钟）

##### Q3：（主题19、22）抽象类、静态方法与equals/toString

阅读以下代码，找出其中**所有编译错误**的行（忽略逻辑错误，只找语法错误），并说明理由：

```java
abstract class Shape {
    private String color;
    
    public abstract double area();
    
    public static void printColor(Shape s) {
        System.out.println(s.color);    // 行②
    }
}

class Circle extends Shape {
    private double radius;
    public Circle(double r) { radius = r; }
    
    @Override
    public double area() {
        return 3.14 * radius * radius;
    }
}

public class Test {
    public static void main(String[] args) {
        Shape s = new Shape();          // 行③
        Circle c1 = new Circle(5.0);
        Circle c2 = new Circle(5.0);
        
        System.out.println(c1.equals(c2));   // 行④
        System.out.println(c1.toString());   // 行⑤
        
        Shape.printColor(c1);                // 行⑥
    }
}
```

**问题：**

找出所有编译错误行，并逐行说明原因。

---

**【参考答案与踩分点】**

| 行号 | 是否报错 | 原因 |
|:----:|:--------:|:-----|
| **行②** | ✅ **不报错** | `private` 是**类级别**访问权限，同一个类 `Shape` 中的静态方法可以通过对象引用 `s` 访问其私有属性 `color`。**这不是错误！** |
| **行③** | ❌ **报错** | `Shape` 是**抽象类**，不能实例化（不能 `new Shape()`）。 |
| **行④** | ✅ **不报错** | `Circle` 继承自 `Object`，未重写 `equals`，编译通过。**（运行时输出 `false`，但不影响编译）** |
| **行⑤** | ✅ **不报错** | `Circle` 继承自 `Object`，未重写 `toString`，编译通过。 |
| **行⑥** | ✅ **不报错** | 静态方法可以通过 `类名.方法名` 调用，传入子类对象自动向上转型。 |

> **踩分点**：行②是本题的**核心易错点**——静态方法访问同类中实例的私有成员是合法的，很多学生会误判为错误。

##### Q4：（主题22、24）接口实现与受检异常

定义一个接口 `Calculator`，包含抽象方法 `int divide(int a, int b) throws Exception;`。

**问题：**

（1）写出该接口的定义。

（2）编写一个实现类 `SafeCalculator`，实现 `divide` 方法。如果 `b == 0`，手动抛出一个**受检异常（Checked Exception）**，异常信息为"除数不能为0"。

（3）在 `main` 方法中调用 `divide` 方法时，编译器会强制要求做什么？请写出调用的标准代码模板。

---

**【参考答案与踩分点】**

**（1）接口定义：**

```java
interface Calculator {
    int divide(int a, int b) throws Exception;
}
```

**（2）实现类关键代码：**

```java
class SafeCalculator implements Calculator {
    @Override
    public int divide(int a, int b) throws Exception {
        if (b == 0) {
            throw new Exception("除数不能为0");
        }
        return a / b;
    }
}
```

> **踩分点**：方法声明必须保留 `throws Exception`，因为抛出了受检异常，不声明会导致编译报错。

**（3）调用标准模板：**

编译器强制要求**捕获（try-catch）**或**继续抛出（throws）**。

```java
public static void main(String[] args) {
    Calculator calc = new SafeCalculator();
    try {
        int result = calc.divide(10, 0);
        System.out.println(result);
    } catch (Exception e) {
        System.out.println("捕获异常：" + e.getMessage());
    } finally {
        System.out.println("计算结束");
    }
}
```

> **踩分点**：必须写出 `try-catch`（或 `throws` + 调用处捕获）。`finally` 块非强制，但写出会加分（体现对异常处理结构的完整理解）。

#### 第三轮：设计模式、IO流与综合识别（约12分钟）

##### Q5：（主题23）设计模式识别

阅读以下代码，回答问题（1）~（3）：

```java
interface DiscountStrategy {
    double calcPrice(double originalPrice);
}

class VipDiscount implements DiscountStrategy {
    @Override
    public double calcPrice(double price) {
        return price * 0.8;
    }
}

class SuperVipDiscount implements DiscountStrategy {
    @Override
    public double calcPrice(double price) {
        return price * 0.6;
    }
}

class Order {
    private DiscountStrategy strategy;
    private double amount;
    
    public Order(double amount) {
        this.amount = amount;
    }
    
    public void setStrategy(DiscountStrategy strategy) {
        this.strategy = strategy;
    }
    
    public double getFinalPrice() {
        return strategy.calcPrice(amount);
    }
}
```

**问题：**

（1）该代码应用了哪种设计模式？请指出代码中的"策略接口"、"具体策略"、"上下文类"分别对应哪个类/接口。

（2）`Order` 类通过 `strategy.calcPrice(amount)` 调用折扣计算，这种调用方式依赖于面向对象的哪个核心特性？

（3）请写出**单例模式（饿汉式）**的完整代码框架，类名取 `ConfigManager`。

---

**【参考答案与踩分点】**

**（1）策略模式（Strategy Pattern）。**

| 角色 | 对应类/接口 |
|:----:|:-----------:|
| 策略接口 | `DiscountStrategy` |
| 具体策略 | `VipDiscount`、`SuperVipDiscount` |
| 上下文类 | `Order` |

> **踩分点**：三个角色必须一一对应正确。

**（2）依赖于** **多态（向上转型 + 动态绑定）**。

`Order` 持有接口引用（编译时类型为 `DiscountStrategy`），运行时指向具体实现类，调用对应重写后的 `calcPrice` 方法。

> **踩分点**：仅答"多态"得一半分，须补充"接口引用指向实现类"的动态绑定过程。

**（3）饿汉式单例：**

```java
class ConfigManager {
    // 1. 私有构造方法
    private ConfigManager() {}
    
    // 2. 静态常量，类加载时立即创建（天然线程安全）
    private static final ConfigManager INSTANCE = new ConfigManager();
    
    // 3. 静态获取方法
    public static ConfigManager getInstance() {
        return INSTANCE;
    }
}
```

> **踩分点**：必须包含三要素——私有构造、静态常量实例、公共静态获取方法。缺一不可。

##### Q6：（主题25）文本流与字节流实战

**问题：**

（1）小明想用 Java 复制一张名为 `photo.jpg` 的图片到 `copy.jpg`，他写了如下代码。请问这段代码有什么严重问题？会导致什么后果？

```java
try (FileReader fr = new FileReader("photo.jpg");
     FileWriter fw = new FileWriter("copy.jpg")) {
    int ch;
    while ((ch = fr.read()) != -1) {
        fw.write(ch);
    }
} catch (IOException e) {
    e.printStackTrace();
}
```

（2）请使用 `FileInputStream` 和 `FileOutputStream` 重写一个正确的图片拷贝方法，要求使用 1024 字节缓冲区提升效率。

（3）在复制**文本文件**（如 `note.txt`）时，如果担心编码问题（如文件是 UTF-8 编码，而系统默认 GBK），应该分别使用哪两个流组合来**指定读取和写入编码**？请写出代码模板。

---

**【参考答案与踩分点】**

**（1）严重问题：用字符流（Reader/Writer）处理二进制文件。**

字符流会试图将每个字节按字符编码解码（涉及编码转换），对于非文本文件（图片），这会**破坏二进制数据格式**，导致生成的 `copy.jpg` **损坏无法打开**。

> **踩分点**：必须点明"图片是二进制文件"与"字符流做编码转换"的矛盾，以及"文件损坏"的后果。

**（2）正确的图片拷贝代码：**

```java
try (FileInputStream fis = new FileInputStream("photo.jpg");
     FileOutputStream fos = new FileOutputStream("copy.jpg")) {
    byte[] buffer = new byte[1024];
    int len;
    while ((len = fis.read(buffer)) != -1) {
        fos.write(buffer, 0, len);
    }
} catch (IOException e) {
    e.printStackTrace();
}
```

> **踩分点**：必须使用字节流 + 缓冲区（`byte[]`），且 `write` 要写 `0, len`（而非整个数组）。

**（3）指定编码读写文本文件的组合：**

| 操作 | 推荐组合 |
|:----:|:---------|
| **读取** | `InputStreamReader` 包装 `FileInputStream`，指定字符集 |
| **写入** | `OutputStreamWriter` 包装 `FileOutputStream`，指定字符集 |

```java
// 读取 UTF-8 文本
try (InputStreamReader isr = new InputStreamReader(
        new FileInputStream("note.txt"), StandardCharsets.UTF_8);
     BufferedReader br = new BufferedReader(isr)) {
    String line;
    while ((line = br.readLine()) != null) {
        System.out.println(line);
    }
}

// 写入 UTF-8 文本
try (OutputStreamWriter osw = new OutputStreamWriter(
        new FileOutputStream("out.txt"), StandardCharsets.UTF_8)) {
    osw.write("中文内容");
}
```

> **踩分点**：必须同时提到读取端（`InputStreamReader` + `FileInputStream`）和写入端（`OutputStreamWriter` + `FileOutputStream`），且都要指定字符集参数。遗漏任一端扣分。
