# 《MyBatis 基础篇辅助理解》

> **定位**：帮助读懂代码、区分概念、定位问题；完整 API 与原理放在专篇。
> **配套笔记**：[MyBatis 基础篇](MyBatis基础篇.md) · [MyBatis-Plus](MyBatis-Plus.md) · [错题与易错点](../../MyBatis错题与易错点.md)
> **示例环境**：Java 17+、Spring Boot 3.x、MySQL 8.x。沿用 `student` 表与 `Student` 实体，省略 import、getter / setter 等常规代码。

---

## 一、先分清：MyBatis、MP、Spring 各做什么

| 组件 | 主要负责 | 你需要写什么 |
|---|---|---|
| JDBC | 连接数据库、执行 SQL、读取结果 | 直接使用时，需自己处理 SQL、参数和结果 |
| MyBatis | 将 Java 方法、SQL、参数和结果关联起来 | Mapper 接口及 XML / 注解 SQL |
| MyBatis-Plus（MP） | 在 MyBatis 上增加通用 CRUD、Wrapper 和插件 | 实体映射、Mapper 继承关系及查询条件 |
| Spring | 管理 Bean、依赖注入与事务边界 | Service 业务方法及事务声明 |

```text
Service：校验参数、组织业务、划定事务边界
    ↓
Mapper 接口：声明数据库操作
    ↓
MyBatis 代理：找到对应的 SQL 映射
    ↓
JDBC 执行 SQL → 数据库返回结果 → 映射为 Java 对象
```

**Mapper 没有实现类，为什么能调用？** MyBatis 会创建代理对象。原生 MyBatis 从 XML / 注解取得 SQL；MP 则为通用方法提供 SQL 映射。两者最终仍通过 MyBatis / JDBC 执行。

## 二、参数、列名和返回结果，别混在一起

以 Java 属性 `className`、数据库列 `class_name` 为例：

```xml
INSERT INTO student (class_name)
VALUES (#{className})
```

`class_name` 是数据库列；`#{className}` 从传入的 Java 对象取属性值，最终通过 `?` 绑定参数，不能互换。

| 容易混淆的写法 | 应该怎样理解 |
|---|---|
| `@Param("name")` 与 `#{name}` | 前者给方法参数命名，后者引用该名称；多参数时建议显式命名 |
| `#{value}` 与 `${value}` | 前者绑定参数值；后者直接拼 SQL 文本，动态列名等必须先做白名单映射 |
| `namespace` 与 XML 的 `id` | 前者对应 Mapper 接口全限定名，后者对应方法名 |
| `resultType` 与 `resultMap` | 前者指定单条结果的 Java 类型；后者显式配置列到属性的映射 |
| `column` 与 `property` | 前者是查询结果列，后者是 Java 属性 |
| `association` 与 `collection` | 前者映射一个关联对象，后者映射一组关联对象 |
| `useGeneratedKeys` 与 `keyProperty` | 前者启用 JDBC 获取生成主键，后者指定回填的 Java 属性 |
| TypeHandler 与 Mapper XML | TypeHandler 处理 Java ↔ JDBC 类型转换，XML 定义 SQL 和映射 |

如果方法返回 `List<Student>`，XML 中 `resultType` 仍写 `Student`，不是 `List`。插入方法常见的 `int` 返回值是影响行数；主键需从回填后的实体属性中获取。

## 三、动态 SQL：掌握四个实际场景

动态 SQL 决定“哪些 SQL 片段需要出现”，不会替你判断业务是否允许无条件操作。下面是各 Mapper 方法对应的 XML 片段，需放在匹配的 `<mapper namespace="...">` 中。

### 1. 按已填写的条件查询

Mapper 方法：

```java
List<Student> selectByCondition(@Param("name") String name,
                                @Param("minAge") Integer minAge);
```

```xml
<select id="selectByCondition" resultType="Student">
    SELECT id, name, age, class_name FROM student
    <where>
        <if test="name != null and name != ''">
            AND name LIKE CONCAT('%', #{name}, '%')
        </if>
        <if test="minAge != null">
            AND age >= #{minAge}
        </if>
    </where>
    ORDER BY id
</select>
```

`<if>` 决定是否加入条件；`<where>` 在有内容时添加 `WHERE`，并移除开头多余的 `AND / OR`。所有条件为空时会查询全部记录，是否允许应由 Service 校验。

### 2. 只修改已提供的字段

对应方法：`int updateSelective(Student student)`。

```xml
<update id="updateSelective">
    UPDATE student
    <set>
        <if test="name != null">name = #{name},</if>
        <if test="age != null">age = #{age},</if>
    </set>
    WHERE id = #{id}
</update>
```

`<set>` 添加 `SET` 并移除末尾逗号。调用前要检查主键和至少一个更新字段；这种“跳过 null”的写法不能表达把列改成 SQL NULL。

### 3. 按主键集合删除

对应方法：`int deleteBatch(@Param("ids") List<Long> ids)`。

```xml
<delete id="deleteBatch">
    DELETE FROM student WHERE id IN
    <foreach collection="ids" item="id" open="(" separator="," close=")">
        #{id}
    </foreach>
</delete>
```

`collection` 引用集合参数，`item` 是每轮元素的名字；`open / separator / close` 控制括号与逗号。例如 `[1, 2, 3]` 生成 `IN (?, ?, ?)`。执行前应拒绝空集合。

### 4. 一次插入多条记录

对应方法：`int insertBatch(@Param("students") List<Student> students)`。

```xml
<insert id="insertBatch">
    INSERT INTO student (name, age) VALUES
    <foreach collection="students" item="s" separator=",">
        (#{s.name}, #{s.age})
    </foreach>
</insert>
```

这里 `s` 是当前学生对象，生成的是多组 `VALUES`。同样需检查集合非空；数据量大时分批处理。

**其他标签按需查：** `choose / when / otherwise` 用于选择一个分支；`trim` 自定义前后缀处理；`sql + include` 复用 SQL 片段。完整用法见主笔记的动态 SQL 部分。

## 四、加入 MP 后，哪些地方变简单了？

以下假设 `Student` 已配置表、主键及字段映射，并提供 getter / setter；Mapper 已被扫描。

### 1. 通用 CRUD：继承后直接调用

```java
public interface StudentMapper extends BaseMapper<Student> {
    // 简单 CRUD 无需重复声明方法，也无需再写对应 XML
}
```

下面是独立的调用示例，`student` 表示已准备好的实体：

```java
int rows = studentMapper.insert(student); // 返回影响行数；生成的主键按配置回填到实体
Student found = studentMapper.selectById(1L); // 查询不到时返回 null
int updated = studentMapper.updateById(student); // 根据 student.id 定位记录
```

`BaseMapper<Student>` 的泛型指定实体类型，MP 再依据实体映射确定表和列。MySQL 自增主键通常配 `@TableId(type = IdType.AUTO)`，不要把它与 MP 在应用侧分配 ID 混为一谈。

### 2. 条件查询：Wrapper 描述筛选范围

```java
LambdaQueryWrapper<Student> query = new LambdaQueryWrapper<>();
query.eq(Student::getClassName, "一班")
     .ge(Student::getAge, 18) // 两个条件默认 AND 连接
     .orderByAsc(Student::getId);

List<Student> students = studentMapper.selectList(query); // 此处才执行查询
```

相当于 `WHERE class_name = ? AND age >= ? ORDER BY id`。普通 `QueryWrapper` 写数据库列名字符串，如 `"class_name"`；Lambda 版引用 getter，由 MP 根据实体映射找到列。

动态筛选用 `.ge(minAge != null, Student::getAge, minAge)`；条件为 false 时跳过整条条件。范围、集合、模糊查询以及 `and / or / nested` 的用法统一查 [MP 条件构造器专篇](MyBatis-Plus.md)，这里不再重复列方法表。

### 3. 条件更新：分清 SET 与 WHERE

```java
LambdaUpdateWrapper<Student> change = new LambdaUpdateWrapper<>();
change.eq(Student::getId, 1L) // WHERE：改哪条记录
      .set(Student::getClassName, "二班"); // SET：改成什么值

int rows = studentMapper.update(null, change); // 更新值全部来自 Wrapper，无实体参数
```

`updateById(entity)` 根据实体主键定位；`update(entity, wrapper)` 根据 Wrapper 条件定位。默认字段策略下，实体中的 null 通常被忽略；显式 `set(..., null)` 则可把列设为 SQL NULL。

### 4. 分页：参数对象与插件各有分工

```java
// 假设使用上面的 query；实际接口应先校验页码和每页数量
Page<Student> page = new Page<>(2, 5); // 第 2 页，每页 5 条
IPage<Student> result = studentMapper.selectPage(page, query);

List<Student> records = result.getRecords(); // 本页记录
long total = result.getTotal(); // 符合条件的总数，前提是执行了 COUNT
```

`Page` 承载页码和结果，`PaginationInnerInterceptor` 处理分页 SQL；仅创建 `Page` 不会自动配置插件。依赖与插件 Bean 的完整配置见 [MP 分页专篇](MyBatis-Plus.md)。

原生 MyBatis 也可手写 `LIMIT #{offset}, #{pageSize}`，其中 `offset = (pageNum - 1) * pageSize`。分页针对结果集位置，与主键是否连续无关；应指定稳定排序。

### 5. 常见增强与使用边界

| 需求 | MP 提供什么 | 仍需注意什么 |
|---|---|---|
| 通用 Service 操作 | `IService / ServiceImpl` 等 | 业务规则与事务仍由自己的 Service 方法组织 |
| 自动填充时间 | `@TableField(fill) + MetaObjectHandler` | 依赖实体处理，不是数据库触发器 |
| 逻辑删除 | `@TableLogic` | 数据仍保留；手写 SQL 要自行处理删除条件 |
| 乐观锁 | `@Version + 插件` | 检查更新行数，并处理版本冲突 |
| 批量保存 | `saveBatch` 等 | 不代表必然只发送一条 SQL |

**选择方式：** 简单 CRUD 用通用方法，单表组合条件用 Wrapper，复杂 JOIN / 统计报表用手写 SQL。MP 与 XML 可以共存，继续使用 Spring 事务。

## 五、配置保留必要项，其余按需开启

原生 MyBatis Starter 的基础配置示例：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/school?serverTimezone=Asia/Shanghai
    username: dev
    password: ${DB_PASSWORD}
    driver-class-name: com.mysql.cj.jdbc.Driver

mybatis:
  mapper-locations: classpath*:/mapper/**/*.xml
  type-aliases-package: com.example.entity # 注册 Student 等类型别名
  configuration:
    map-underscore-to-camel-case: true
    # 仅开发排错时开启 SQL 输出
    # log-impl: org.apache.ibatis.logging.stdout.StdOutImpl
```

- `@MapperScan("com.example.mapper")` 扫描 **Java 接口**；`mapper-locations` 定位 **XML 文件**，两者不能互相替代。
- `type-aliases-package` 是可选项；未注册别名时，示例中的 `resultType="Student"` 应改用实体全限定名。
- 使用 MP Starter 时，将配置前缀改为 `mybatis-plus:`，数据源仍在 `spring.datasource` 下；不要重复叠加原生 MyBatis Starter。
- 二级缓存、延迟加载、自定义 TypeHandler 按业务需要配置，不要把所有开关都当成必开项。

## 六、读代码与排错，都沿着同一条链找

看到 `studentMapper.selectByCondition(...)` 时，按顺序确认：

1. **入口与参数**：哪个 Service 调用？传了什么？是否有校验与事务？
2. **方法来源**：自定义 Mapper 方法，还是 MP 通用方法？
3. **SQL 来源**：查 XML 的 `namespace + id`、注解，或 MP 实体映射与 Wrapper。
4. **实际执行**：看 SQL、绑定参数和最底层异常，不只看外层报错。
5. **返回结果**：核对返回类型、字段映射及查询不到记录时的处理。

| 现象 | 优先检查 |
|---|---|
| Mapper 无法注入 | `@Mapper / @MapperScan`、组件扫描、Starter |
| `Invalid bound statement` | XML 是否加载、namespace、statement id 与方法名 |
| `Parameter 'xxx' not found` | `@Param`、Java 属性名、XML 引用路径 |
| `Unknown column` | 真实表结构、SQL 别名和列名 |
| 查询有值但 Java 属性为 null | 查询列、列别名、驼峰映射、resultMap |
| `TooManyResultsException` | 单对象返回值与实际结果条数是否匹配 |
| 主键未回填 | 数据库主键策略、useGeneratedKeys / keyProperty，或 MP 的 IdType |
| 更新 null 不生效 | XML 是否跳过 null、MP 字段策略、是否显式 set |
| 更新或删除范围过大 | WHERE 是否遗漏、动态条件是否全部被跳过 |
| 分页未生效 | 原生 LIMIT 参数，或 MP 分页依赖、插件与 Page 参数 |
| 事务未按预期回滚 | 是否经过代理、异常传播、回滚规则、rollback-only 状态 |
| 重复 SQL 或结果陈旧 | 会话与事务范围、缓存命中条件、嵌套查询、外部数据修改 |

**生命周期只记三点：**

- 原生 `SqlSession` 不跨线程共享，手动创建后要关闭；Spring 项目通常通过注入的 Mapper、`SqlSessionTemplate` 管理调用。
- Spring 管理的 Bean 不代表内部状态自动线程安全；自定义插件、TypeHandler 应避免保存请求级可变状态，Wrapper 每次操作新建。
- Spring 事务中不要混用手动 `openSession()`、`commit()`、`rollback()` 来控制同一业务流程。

## 七、复习顺序

- **先会用**：Mapper 与 SQL 对应、参数绑定、结果映射、CRUD、动态 SQL。
- **再做业务**：关联查询、事务、分页、MP 通用方法与 Wrapper。
- **遇到问题再深入**：会话生命周期、缓存、TypeHandler、插件与执行链路。
- **源码与扩展开发按需学**：不必为了完成普通 CRUD 先掌握所有底层实现。
