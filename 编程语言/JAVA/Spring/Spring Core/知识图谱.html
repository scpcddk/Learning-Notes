Spring6 Core 复习速查图

IOC + AOP + 事务 | 纯注解 | SpringBoot3

一、IOC 核心
核心思想：控制权反转，向容器"要"对象，不再 new
BeanFactory: 懒加载 | ApplicationContext: 预加载 + 超集功能(企业级首选)
方式一：包扫描
@ComponentScan
+ @Component/@Service
/@Repository/@Controller
方式二：配置类
@Configuration
+ @Bean
第三方类/复杂初始化
常用注解：
@Autowired 按类型注入 | @Qualifier 按名称 | @Primary 首选 | @Value 配置值
@Scope 作用域(singleton/prototype) | @PostConstruct/@PreDestroy 生命周期
@Resource(JSR-250) 按名称→按类型 | @Inject(JSR-330) 同@Autowired
字段注入
最简洁
构造器注入
最规范(final)
Setter注入
可选依赖
生命周期：实例化 → 属性注入 → Aware → BeanPostProcessor前置 → @PostConstruct/InitializingBean → init-method → BeanPostProcessor后置 → 就绪 → @PreDestroy/DisposableBean → destroy
循环依赖解决：一级(成品) → 二级(半成品) → 三级(工厂)
构造器注入 ❌ | prototype作用域 ❌
二、AOP 核心
代理选择：有接口 → JDK动态代理 | 无接口 → CGLIB继承代理
@Before(前) → @Around(环绕) → 目标方法 → @AfterReturning(正常返回) → @AfterThrowing(异常) → @After(finally)
execution(修饰符? 返回值 包.类.方法(参数) 异常?)
* = 任意 | .. = 子包或任意参数
例：execution(* com.service.*.*(..))
@Pointcut 复用切点 | && || ! 组合 | 同类自调用失效 → AopContext.currentProxy()
AOP：垂直切面
"一刀切"给N个类
统一增强(日志/事务/权限)
Event：水平广播
"大喇叭"通知N个模块
解耦业务联动(订单→短信/邮件)
三、事务核心
@Transactional | 默认回滚 RuntimeException | 默认传播 REQUIRED
传播行为：
REQUIRED(默认): 有则加入,无则新建 → 同生共死
REQUIRES_NEW: 挂起当前,新建独立事务 → 独立王国(日志/审计必成功)
SUPPORTS: 有则蹭,无则非事务 | NOT_SUPPORTED: 挂起,非事务执行
MANDATORY: 强制有事务 | NEVER: 禁止事务 | NESTED: 嵌套savepoint(部分回滚)
DEFAULT → READ_UNCOMMITTED → READ_COMMITTED(解决脏读) → REPEATABLE_READ(解决不可重复读) → SERIALIZABLE(解决幻读)
事务失效清单：
非public | 同类自调用(this) | 异常被catch未抛出 | 类型不对(非RuntimeException)
final方法 | 多线程 | 未@EnableTransactionManagement | 类未进容器 | static方法
设计原则：边界要小 | 不做IO/HTTP/RPC | 不计算 | 异常要抛 | 只读标readOnly
编程式 TransactionTemplate：复杂场景 / 动态控制 / 部分回滚 / 分批提交
四、条件装配 & 自动配置
@ConditionalOnClass | @ConditionalOnMissingBean | @ConditionalOnProperty | @ConditionalOnExpression
@SpringBootApplication = @Configuration + @EnableAutoConfiguration + @ComponentScan
AutoConfigurationImportSelector → META-INF/spring/...imports → 条件过滤 → 注册Bean
@ConfigurationProperties(prefix="app") 结构化配置
@Profile("dev/prod") 多环境 → 激活: spring.profiles.active=dev
五、SpringBoot3 适配
javax.* → jakarta.* (servlet / persistence / validation / annotation)
JDK17+ | Tomcat10+ | Swagger/Knife4j 升级
六、核心口诀（面试速记）
IOC注册
自己写的扫描，三方的@Bean
注入方式
构造规范，字段方便，Setter可选
AOP代理
有接口JDK，无接口CGLIB
事务失效
非公、自调、吃掉、类型不对、final、多线程
生命周期
实例化→注入→Aware→PostProcessor前→初始化→PostProcessor后→销毁
循环依赖
三级缓存：成品→半成品→工厂
传播行为
REQUIRED同生共死，REQUIRES_NEW独立王国，NESTED部分回滚
AOP vs Event
AOP是"一刀切"，Event是"大喇叭"
七、避坑TOP5
1. @Autowired为null
类未进容器(没加@Component/@Service) 或 手动new
2. AOP/事务不生效
同类this调用绕过代理 → 用代理对象或抽离到另一个Bean
3. 单例注入Prototype
只创建一次 → @Scope(proxyMode=TARGET_CLASS) 或 ObjectFactory
4. @Bean互调重复创建
@Configuration必须用CGLIB代理，不能用@Component
5. @Around忘proceed()
pjp.proceed()是调用目标方法，忘了方法就"消失"
八、快速启动Demo
@SpringBootApplication public class App { public static void main(String[] args) { SpringApplication.run(App.class, args); } } @Service public class UserService { @Autowired private UserDao dao; } @Configuration public class Config { @Bean public DataSource ds() { return new HikariDataSource(); } } @Aspect @Component public class LogAspect { @Around("execution(* com.service.*.*(..))") public Object around(ProceedingJoinPoint pjp) throws Throwable { long s = System.currentTimeMillis(); Object r = pjp.proceed(); System.out.println("耗时:" + (System.currentTimeMillis()-s) + "ms"); return r; } }
