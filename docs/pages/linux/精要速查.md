## [commands] 命令大全

先明确要操作的对象，再选择命令。下面按原笔记分类整理命令卡片；卡片的用途、语法与参数从《命令大全》生成，可搜索，也可跳到完整用法。

| 需要做什么 | 先考虑 |
| --- | --- |
| 找文件、看内容 | `find`、`ls`、`cat`、`tail`、`grep` |
| 判断身份与权限 | `chmod`、`chown`、`sudo`；同时检查父目录 |

## [shell] Shell

## 写脚本先抓住这条主线

**读取参数 → 检查条件 → 组合命令 → 判断结果。** 本笔记采用 Bash，数组、`[[ ]]` 等语法不能直接假定兼容所有 `sh`。

| 核心语法 | 记住什么 |
| --- | --- |
| `name="value"` | 赋值的等号两侧不加空格 |
| `"$name"`、`"${arr[@]}"` | 引用变量，保留参数边界 |
| `$#`、`"$@"`、`$?` | 参数个数、全部参数、上一条命令状态 |
| `if`、`for`、`while`、`case` | 判断、遍历、重复与分支 |
| `>`、`>>`、`2>`、`\|` | 覆盖、追加、错误输出与管道 |

## 一个能串起基础语法的小例子

```bash
#!/bin/bash
if [ "$#" -eq 0 ]; then
    printf '用法：%s 文件...\n' "$0" >&2
    exit 1
fi
for file in "$@"; do
    if [ -f "$file" ]; then
        printf '普通文件：%s\n' "$file"
    fi
done
```

## 常见易错点

- Shebang 独占第一行，说明另起一行。
- 单引号内不展开变量；双引号仍会展开变量和命令替换。
- 管道默认只传标准输出；默认退出状态只看最后一条命令。
- `set -e` 有例外，重要步骤仍需检查；可选参数使用 `${1:-}` 等默认值。
- `bash -n script.sh` 检查语法；`bash -x script.sh` 会实际执行脚本并显示调试信息。

## [sticky-bit] 补充理解

## 粘滞位要解决什么问题

共享目录允许多人写入时，粘滞位进一步限制其中条目的**删除与重命名**。它不保护文件内容免遭修改，也不额外授予访问权限。

| 检查层次 | 要看什么 |
| --- | --- |
| 能否访问路径 | 路径各级目录的搜索权限 |
| 能否增删目录项 | 父目录的 `w+x` |
| 父目录有粘滞位 | 文件所有者、目录所有者或相应特权 |
| 能否修改文件内容 | 文件本身的写权限及其他限制 |

## 识别与设置

```bash
ls -ld /tmp
# drwxrwxrwt：有粘滞位，也有其他用户执行权限
# drwxrwxrwT：有粘滞位，没有其他用户执行权限

# 以下以已有的练习目录 /project 为例
chmod +t /project
chmod -t /project
chmod 1777 /project
```

四位八进制的首位是特殊权限：SetUID 为 4、SetGID 为 2、Sticky 为 1，可相加。不要将“粘滞位目录通常只能删自己的文件”理解为无条件保证。

## [linux-benefits] Linux优越性

## 从使用场景理解优势

| 优势 | 具体价值 |
| --- | --- |
| 开源生态 | 可研究与定制系统，但仍需遵守各组件许可证 |
| 无图形界面运行 | 适合通过终端与 SSH 管理服务器 |
| 脚本和开发工具 | 容易组合命令，适合部署、排障与自动化 |
| 可裁剪与可配置 | 可按服务器、容器或受限设备的需求选择组件 |
| 系统接口与资源管理 | 便于观察进程、文件、网络和资源使用情况 |

## 评估时保留条件

- 免费发行版不代表订阅、支持与运维都没有成本。
- 长期稳定运行依赖硬件、应用、配置和维护，更新有时需要重启。
- Linux 也会受到恶意软件和供应链攻击，需要持续维护。
- 性能取决于具体工作负载，不能直接凭系统名称下结论。

## [wsl-downloads] WSL 终端文件下载与安装使用笔记

## 下载与安装是两步

先确认下载地址、Linux 架构和文件格式，再决定如何使用文件。下载源码归档并不等于安装了软件。

| 文件或来源 | 常用处理方式 |
| --- | --- |
| 已配置的软件源 | `sudo apt install 包名`，自动处理可获取的依赖 |
| 本地 `.deb` | `sudo apt install ./包名.deb` |
| `.tar.gz` | `tar -tzf` 查看，`tar -xzf` 解压，后续按软件说明操作 |
| 二进制或脚本 | 核对架构、解释器、依赖与执行权限 |

## 下载模板

```bash
# example.com 地址是占位示例，使用时替换为实际下载地址
cd ~
curl -fL -o package.tar.gz https://example.com/package.tar.gz
tar -tzf package.tar.gz

# 服务器支持续传且远端文件未改变时，可继续下载
wget -c https://example.com/package.tar.gz
```

`-o` 自定文件名，`-O` 取 URL 文件名，`-L` 跟随重定向，`-f` 将常见 HTTP 错误视为失败。工具是否预装取决于镜像；权限不足也不一定只需加 `x`。

## [curl] curl命令图解

## 把选项分成三组记

| 请求 | 输出 | 诊断与连接 |
| --- | --- | --- |
| `-X` 方法、`-d` 数据、`-H` 头部 | `-o` 自定文件名、`-O` URL 文件名 | `-v` 通信细节、`-w` 统计信息 |
| `-G` GET 查询、`-F` 表单 | `-sS` 静默但显示错误 | `-I` HEAD 请求、`-L` 跟随重定向 |
| `-u` 认证、`-b` 读 Cookie | `-f` 将 HTTP 错误视为失败 | `--cacert` 指定可信 CA、`-x` 代理 |

## 三个常用模板

```bash
# GET 查询：对中文、空格等参数做 URL 编码
curl -G --data-urlencode 'q=Linux 学习' https://api.example.com/search

# JSON：-d 默认使 HTTP 请求使用 POST
curl -H 'Content-Type: application/json' \
  -d '{"name":"Alice"}' https://api.example.com/users

# 下载：HTTP 错误失败，跟随重定向，指定文件名
curl -fL -o package.zip https://example.com/package.zip
```

## 核对这些细节

- 示例地址需要替换；`-X` 只改变方法字符串，HEAD 应使用 `-I`。
- 默认收到 404/500 不一定返回非零退出码；脚本需检查状态或使用 `-f`。
- `-O` 默认取 URL 路径末尾名称，不自动采用响应头建议的名称。
- `-k` 会跳过证书验证，正常连接应修复证书信任问题。
- `-v` 输出、Cookie 文件和命令参数可能包含凭据，使用真实数据时需妥善处理。
