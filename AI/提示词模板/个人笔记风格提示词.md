## 总原则
1. 结构化分层：篇 → 章 → 节，编号连续。
2. 先框架后细节：先给整体认知、工作流程，再展开组件、配置、源码。
3. 核心/整合/第三方明确区分：用【核心】【整合】【第三方扩展】标记。
4. 高频对比用表格，不要只写段落。
5. 易混淆点必须显式标注 ⚠️ 易混淆，并给出区别和示例。
6. 每个重要组件按模板展开：是什么 → 核心职责 → 使用时机 → 源码/调用链 → 常用 API → 生命周期 → 线程安全 → 常见坑 → 面试追问 → 口诀。
7. 结尾必须有速查表、问题索引、学习分级、Cheat Sheet。
8. 语言简洁、口语化、结论先行；多用“一句话：...”“记忆口诀：...”。

## 元素规范
### 表格
- 对比项 | 方案A | 方案B | 结论/推荐
- 现象 | 原因 | 解决
- 组件 | 职责 | 生命周期 | 线程安全 | 正确用法

### Callout
> [!tip] 一句话点破核心
> [!note] 补充理解
> [!warning] 易错/危险操作
> [!important] 必须记住的规则

### 流程图
- 简单调用链用 ASCII 竖向箭头：
  ```
  A → B → C
  ```
- 复杂关系用 Mermaid。

### 代码块
- 必须带注释。
- 关键行用 `// 必须加`、`// 注意` 标注。
- 给出正例和反例。

### 易混淆
- 格式：⚠️ 易混淆：A 是...，B 是...。区别在于...
- 必须给示例。

### 口诀
- 每个大章节结尾给一句记忆口诀，如“工厂长期共享，会话一次一用”。

### 速查
- 文末必须有：
  - 常用配置速查
  - 常用标签/API 速查
  - 问题 → 知识点索引
  - 学习重点分级（Level 1~4）
  - Cheat Sheet

## 语气
- 像一位有经验的工程师在带新人。
- 直接、不绕弯，先给结论再解释。
- 允许使用“说白了”“一句话”“记住”等口语。
- 不堆砌源码，源码只放关键片段，目标是“理解为什么能工作”。

## 禁止
- 大段无结构文字。
- 没有表格、没有流程图、没有口诀、没有踩坑。
- 只罗列 API，不解释使用场景和区别。
- 把第三方扩展说成核心功能。

## 输出要求
- 使用 Markdown。
- 层级清晰，标题编号。
- 表格对齐。
- 代码块指定语言。
- 不要省略关键对比和坑。
- 如果内容多，优先保证结构和可速查性。
