# Python 异常处理学习笔记

**学习阶段：** Python 基础 + AI API 项目应用

## 一、什么是异常处理？

程序运行时，可能因为输入不合法、网络请求失败、数据格式错误等原因出现异常。

例如：

```python
result = 10 / 0
```

运行时会产生 `ZeroDivisionError`，导致程序无法正常执行后续代码。

异常处理的作用是：**发现程序运行中的错误，并按照预先设计的方式进行处理，让程序能够合理地恢复或结束。**

## 二、`try` 和 `except`

### 1. 基本结构

```python
try:
    result = 10 / 0
    print("计算成功")
except ZeroDivisionError:
    print("不能除以零")

print("程序继续运行")
```

输出：

```text
不能除以零
程序继续运行
```

执行过程：

1. 执行 `try` 中的代码。
2. 除法产生异常，跳过 `try` 中剩余的代码。
3. 匹配对应的 `except`，执行异常处理。
4. 异常被捕获后，继续执行后续代码。

### 2. 捕获不同类型的异常

```python
try:
    number = int("hello")
    result = 10 / number
except ValueError:
    print("转换失败")
except ZeroDivisionError:
    print("不能除以零")
```

输出：

```text
转换失败
```

原因是 `int("hello")` 首先触发 `ValueError`，因此第二个 `except` 不会执行。

**注意：** 多个 `except` 可以分别处理不同类型的异常。一次异常发生后，通常只执行第一个匹配的处理分支。

### 3. 使用 `as e` 获取异常信息

```python
try:
    number = int("hello")
except ValueError as e:
    print(e)
    print(type(e).__name__)
```

- `e`：保存异常对象，可以查看具体错误信息。
- `type(e).__name__`：获取异常类型的名称。

这样可以帮助我们定位问题，而不只是告诉用户“程序出错了”。

## 三、`raise`：主动抛出异常

当程序发现某种情况不应该继续执行时，可以主动抛出异常。

```python
try:
    raise ValueError("输入不合法")
except ValueError as e:
    print(e)
```

输出：

```text
输入不合法
```

需要区分：

| 语句 | 作用 |
|---|---|
| `raise` | 主动抛出异常 |
| `except` | 捕获匹配的异常 |
| `as e` | 获取异常对象，以便查看错误信息 |

在 AI API 项目中，如果 API 密钥不存在，可以主动抛出异常：

```python
import os

api_key = os.environ.get("DEEPSEEK_API_KEY")

if not api_key:
    raise RuntimeError("未设置 DEEPSEEK_API_KEY")
```

这里使用 `RuntimeError` 报告配置错误，避免程序带着无效配置继续运行。

## 四、`finally`：执行收尾代码

`finally` 中的代码通常无论 `try` 是否发生异常都会执行。

```python
try:
    print("A")
    raise ValueError("请求失败")
except ValueError:
    print("B")
finally:
    print("C")

print("D")
```

输出：

```text
A
B
C
D
```

执行顺序：

1. 执行 `try`，打印 `A`。
2. 主动抛出异常。
3. `except` 捕获异常，打印 `B`。
4. `finally` 执行，打印 `C`。
5. 程序继续执行，打印 `D`。

三个关键字的作用：

- `try`：执行可能出错的代码。
- `except`：处理匹配的异常。
- `finally`：执行收尾代码。

注意：如果进程被强制终止等特殊情况发生，不能保证 `finally` 一定执行。

### AI API 项目中的应用

项目使用了：

```python
with httpx.stream(
    "POST",
    url,
    headers=headers,
    json=data,
    timeout=60.0
) as response:
    ...
```

`with` 会在退出代码块时负责关闭流式响应，因此不需要为了关闭这个响应而额外添加 `finally`。

## 五、浅拷贝与消息备份

### 1. 使用 `copy()` 备份列表

```python
messages = ["旧消息"]
old_messages = messages.copy()

messages.append("新消息")

print(messages)
print(old_messages)
```

输出：

```text
['旧消息', '新消息']
['旧消息']
```

`copy()` 创建了一个新的外层列表。向 `messages` 追加元素，不会改变 `old_messages` 的长度。

### 2. 浅拷贝的局限

```python
messages = [
    {"role": "user", "content": "你好"}
]

old_messages = messages.copy()

messages[0]["content"] = "修改后的内容"

print(old_messages[0]["content"])
```

输出：

```text
修改后的内容
```

原因是：浅拷贝只复制外层列表，内层字典仍然是共享的。

| 操作 | 备份是否受到影响 |
|---|---|
| `messages.append(new_message)` | 不影响备份列表的长度 |
| `messages[0]["content"] = "新内容"` | 会影响备份中的同一个字典 |
| `messages = old_messages` | 让 `messages` 重新指向备份列表，但不能撤销字典内部已经发生的修改 |

如果需要独立备份嵌套字典，可以考虑深拷贝：

```python
import copy

old_messages = copy.deepcopy(messages)
```

`deepcopy()` 会递归复制嵌套对象，适用于需要隔离内部修改的情况。

## 六、异常处理在 AI API 项目中的应用

### 1. 整体处理流程

当前 `ask_ai()` 的核心流程可以概括为：

1. 备份历史消息。
2. 添加本次用户消息。
3. 发起 API 请求。
4. 接收并解析流式响应。
5. 判断响应是否正常结束。
6. 成功时保存助手回复；失败时恢复消息备份。

### 2. 为什么需要 `completed`？

代码中：

```python
completed = False
```

只有接收到流式结束标记时，才将它设置为 `True`：

```python
if content == "[DONE]":
    completed = True
    break
```

后续根据这个变量判断响应是否正常结束。

```python
if completed:
    messages.append({
        "role": "assistant",
        "content": answer
    })
else:
    messages = old_messages
    return None
```

- `completed == True`：保存助手回复。
- `completed == False`：恢复消息备份，并返回 `None`。

注意：这里的 `completed` 是当前代码用于判断流式响应结束的标记。实际项目还需要考虑服务端协议和其他异常情况。

### 3. 为什么异常时恢复消息？

当前项目中的异常处理结构：

```python
except (
    httpx.HTTPError,
    json.JSONDecodeError,
    KeyError,
    IndexError
) as e:
    messages = old_messages
    print(f"\n请求或解析失败：{e}")
    return None
```

常见异常及原因：

| 异常 | 常见原因 |
|---|---|
| `httpx.HTTPError` | 网络请求或 HTTP 状态错误 |
| `json.JSONDecodeError` | JSON 格式不合法 |
| `KeyError` | 访问不存在的字典键 |
| `IndexError` | 列表索引越界 |

发生这些异常时，程序恢复消息备份，避免将本次失败请求留下的消息继续作为后续对话历史。

### 4. 为什么返回 `None`？

```python
return None
```

这里的 `None` 是一种失败信号，表示本次请求没有成功返回完整答案。

- `None`：通常表示没有得到有效结果。
- `""`：表示字符串存在，但内容为空。

调用者可以根据返回值判断是否获得有效答案。

当前主循环尚未专门处理 `answer is None` 的情况，后续可以增加失败提示或重试机制。

### 5. 哪些异常还没有被捕获？

当前代码显式捕获了四类异常，但并不意味着所有错误都已覆盖。

例如：

```python
delta = None
text = delta.get("content", "")
```

这会产生 `AttributeError`，因为 `None` 没有 `.get()` 方法。

另外，`TypeError` 也可能由数据类型不符合预期引起。

处理原则：

1. 先确认实际数据结构。
2. 根据错误原因决定是校验数据、跳过异常数据，还是让异常继续向外传播。
3. 不要为了让程序看起来正常而随意捕获并隐藏所有异常。

## 七、异常捕获的基本原则

**优先捕获你知道如何处理的异常。**

例如：

```python
try:
    data = json.loads(content)
except json.JSONDecodeError as e:
    print(f"JSON 解析失败：{e}")
```

这种写法明确地处理了 JSON 解析失败的情况。

如果直接使用：

```python
try:
    data = json.loads(content)
except Exception:
    print("发生错误")
```

虽然能够捕获许多异常，但可能隐藏代码本身的问题，不利于调试。

这并不意味着绝不能使用 `except Exception`。在程序最外层，它可以用于记录意外错误，但应该保留必要的错误信息，并谨慎决定是否继续运行。
